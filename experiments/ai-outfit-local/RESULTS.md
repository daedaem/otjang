# 무료 로컬 AI 코디 착용샷 시험 — 2026-10-16

**판정: 실행 환경 문제로 중단, 품질 판정 보류. 최종 이미지 0/6장.** 첫 케이스에서 VAE 인코딩 후 텍스트 인코더를 불러오는 동안 C 드라이브 여유가 11.084 GiB에서 최저 0.031 GiB(약 32 MiB)까지 줄었다. 디스크 안전 조건에 따라 17.393초 만에 실행을 종료했다. Qwen DiT 로딩과 샘플링에는 도달하지 못했다. 요청의 "설치나 메모리 문제로 막히면 무리하게 우회하지 말고 정리해서 멈춘다"는 중단 규칙을 적용해 나머지는 실행하지 않았다.

결과 사진이 없어 비교판을 만들지 않았다. 이 실행으로 모델의 화질, Gemini와의 차이, 8GB VRAM에서의 생성 가능 여부를 판단할 수 없다. 이 문서는 사진을 포함하지 않는다.

## 시험 범위

- 기준 브랜치: `claude/fashn-vton-m1-test-3ox240`, 기준 커밋 `d444ac30c50f9ee80b8b67e082679ea87305883c`.
- 작업 브랜치: `codex/ai-outfit-test`.
- 개인 얼굴·몸 사진은 사용하지 않았다. 저장소의 `fetch_kit.py`를 그대로 실행해 공개 FASHN 예제 인물, 베이지 와이드 치노, 흰 옥스퍼드 셔츠, 네이비 해링턴 재킷을 받았다.
- 입력·결과·비교판·시험 로그는 저장소 밖 `~/ai-outfit/`에만 둔다. 상품 사진을 외부 생성 서비스에 보내지 않는다.
- 유료 API, 무료 체험 크레딧, 온라인 데모를 사용하지 않는다. 모델 파일 다운로드만 온라인으로 수행한다.
- 결과 용도는 코디 분위기 확인이다. 핏·사이즈를 판정하지 않는다.

## 계획과 계측 방법

최종 6장을 목표로 아래 세 케이스에 두 조건을 각각 적용하려 했다. 실제 실행은 케이스 1의 첫 시도 1회뿐이다.

1. 공개 인물 + 재킷 + 치노(왼쪽)·셔츠(오른쪽)를 나란히 붙인 참조 이미지.
2. 별도의 인물 입력 없이 재킷 + 셔츠 + 치노에서 새 성인 남성 모델 착용샷 생성. 상품 사진 자체에는 부분 인물이 포함되어 있다.
3. 공개 인물 → 셔츠 → 치노 → 재킷. 중간 생성물을 다음 단계의 입력으로 사용한다.

두 조건은 Lightning v2.0 r128 INT4의 **4단계·시드 42**, **8단계·시드 1234**다. 단계 수와 시드가 함께 바뀌므로 단계 수만의 효과를 분리한 비교가 아니다. 케이스 3에 중간 생성 2장이 더 필요하므로 전체 완료 시 실제 생성 호출은 10회다.

- 공식 Qwen 예제 그래프를 사용하며 Euler / simple, CFG 1, shift 3, denoise 1.
- CPU offload 활성화, `num_blocks_on_gpu=20`, `use_pin_memory=disable`.
- 인물 입력은 약 1 MP로 조정한다. 케이스 2는 832×1216의 빈 latent에서 시작하도록 준비했으나 실행하지 않았다.
- ComfyUI는 loopback 주소에서만 열며 `--lowvram --cache-none --disable-api-nodes`를 사용한다. Nunchaku 외의 사용자 노드는 비활성화한다.
- 추론 프로세스에 HF/Transformers/Diffusers 오프라인 플래그와 외부 Python socket 연결 차단 가드를 적용했다. 이는 PC 전체 네트워크를 끄는 설정은 아니다. 차단 가드의 자체 시험에서 외부 주소 3개가 거부되고 loopback 통신만 허용됐다. 실제 실행 중 추가 차단 로그는 없었으며, 8단계 파일 다운로드 프로세스도 먼저 종료했다.
- 시간은 로컬 API 제출부터 결과 저장 완료까지의 경과 시간이다. 케이스 3은 세 단계 시간을 합산한다. 첫 실행에는 모델 로딩이 포함된다.
- VRAM은 1초 간격 `nvidia-smi`의 **장치 전체 사용량** 최고값이다. Windows와 다른 앱의 사용량도 포함하며, PyTorch의 프로세스 단독 할당량과 다르다.
- 안전 중단 조건: 가용 RAM 384 MiB 미만 또는 C 드라이브 여유 3 GiB 미만이 12초 지속되거나, 한 생성이 20분을 넘는 경우. 해당 시험이 만든 서버만 종료하며 자동 재생성하지 않는다.

### 첫 로딩 시간과 자원 기록

- 실행 시각: 2026-10-16 18:04경(KST), 안전 중단 감지 18:04:48.
- 시작 시 가용 RAM 3,484 MiB, 실행 중 최저 2,459 MiB. RAM 384 MiB 미만 조건이 아니라 **C 드라이브 3 GiB 미만 지속 조건**에 걸렸다.
- 장치 전체 VRAM은 시작 2,001 MiB, 최고 5,147 MiB. CUDA out-of-memory 예외는 관측되지 않았다.
- VAE 로더 노드 39: 약 0.9초. VAEEncode 노드 88 시작 약 1.2초, 다음 노드 시작 약 3.5초.
- CLIPLoader 노드 38: 제출 후 약 3.5초에 시작해 약 17.4초 중단 때까지 완료되지 않았다. **텍스트 인코더 최초 로딩 완료 시간은 측정 불가**다.
- Nunchaku DiT 로더 노드 115와 KSampler 노드 3은 시작하지 않았다. **Qwen 생성 모델 최초 로딩 시간과 샘플링 시간은 측정 불가**다.
- 종료 직후 확인한 C 여유는 약 1.74 GiB였고, 이후 약 10.70 GiB로 회복했다. 런타임은 D 드라이브에 있지만 실행 중 C의 여유가 필요하다는 관측이다. 이 기록만으로 일시 사용량 전체가 페이지 파일 때문이라고 단정할 수 없다.
- 자동 종료 처리 중 이미 종료되는 자식 PID에 대한 `psutil.AccessDenied`가 추가로 기록됐다. 이후 별도 확인에서 이 시험의 서버·생성·다운로드 프로세스가 남아 있지 않고 해당 로컬 서버 포트도 닫혔음을 확인했다. 다른 앱은 종료하지 않았다.

### 통과 기준 적용

"옷 모양·색 통과 4/6 이상"과 "자연스러움 4점 이상이 절반 초과" 모두 **판정 보류**다. 완성 이미지가 0장이므로 통과율이나 자연스러움 점수를 계산하지 않는다. 앱에 적용할 근거를 확보하지 못했지만 모델 품질이 나쁘다는 증거도 얻지 못했다.

## 막힌 점과 처리

- 초기 pip 22.3.1이 패키지 이름 메타데이터를 처리하지 못해 설치가 실패했다. 격리 환경의 pip를 정식 업데이트하고 바이너리 휠만 설치해 해결했다.
- 최초 대용량 모델 다운로드가 2,147,483,071 bytes에서 조기 종료됐다. 공식 서버가 HTTP Range를 정확히 지원함을 확인한 뒤 512 MiB씩 이어받고 전체 SHA256을 확인하는 방식으로 전환했다. 잘린 파일로 추론하지 않는다.
- 실제 생성은 위의 C 드라이브 여유 부족으로 중단됐다. 사진 업로드, API 전환, 개인 사진 사용, 모델 소스 수정, 페이지 파일·드라이버 설정 변경, 안전 임계값 완화 등의 우회는 하지 않았다.

## 다음 선택지와 재개 위치

1. 같은 무료 로컬 시험을 다시 하려면 먼저 C 드라이브 여유와 가용 RAM을 확보한다. 예를 들어 C에 30 GiB 이상 여유를 두는 것은 이번 순간 사용량을 고려한 여유 제안이며, 성공 보장 사양은 아니다. 사용자가 필요 없는 앱을 닫으면 메모리 부담을 줄일 수 있다. 이번에는 임의 파일 삭제나 다른 앱 종료를 하지 않았다.
2. 같은 4단계·시드 42 케이스 1에서 먼저 재시험한다. 텍스트 인코더·DiT 로딩과 첫 결과 저장까지 성공하는지 확인한 다음 케이스 2·3과 8단계 조건으로 넘어간다. 한 번에 한 무거운 작업만 실행한다.
3. 8단계 부분 파일은 표준 HTTP Range로 이어받을 수 있다. 전체 크기와 SHA256을 검증한 뒤에만 사용한다. 이후 실제 추론 중에는 다운로드를 병행하지 않는다.

로컬 재개 자료는 `D:/ai-outfit-runtime/`의 격리 환경, `launch_comfy.py`, `run_trials.py`, `download_checkpoint.py`, `make_comparisons.py`와 `~/ai-outfit/logs/`에 보존했다. 현재 서버는 꺼져 있다. 사진은 `~/ai-outfit/inputs/`, 결과 폴더는 `~/ai-outfit/results/`이며 이번 결과 폴더에는 생성 이미지가 없다. 사진·런타임·로그를 Git에 추가하지 않았다.
