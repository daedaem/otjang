# 요청한 조건을 끝까지 지키기 (2026-10-18)

## 왜
- 전문가 역할 모의 평가(`expert-eval-20261018.md`)와 Codex 검토에서 공통으로 나온 가장 큰 문제는 디자인이 아니라 **요청한 조건이 화면마다 달라지거나 사라지는 것**이었다.
- 코드에서 확인한 원인은 두 가지다.
  - `engine.js` `search`: 요청한 종류가 현재 성별 상품에 없으면 **전체 종류로 다시 채웠다.** 그래서 '원피스'를 검색하면 남성 셔츠·니트가 나왔다.
  - `main.js` `itemSheet`: 상세의 대안과 코디가 검색 예산을 **전달받지 않았다.**

## 완료 기준과 확인 결과 (모바일 390×844, 첫 방문, 로컬 서버)
| 기준 | 결과 |
|---|---|
| '원피스'에 원피스만 나오는가 | 원피스 3개만 나옴. "원피스는 여성 상품에만 있어서 여성 상품에서 찾았어요" 안내 |
| 예산이 상세에서도 유지되는가 | '출근용 셔츠 10만원 이하' → 상세의 '같은 조건, 다른 선택'·브랜드 다른 아이템·코디 상품 모두 10만원 이하. 뺀 개수를 적음 |
| 옷장 없이 상품 확인까지 가능한가 | 옷장이 없으면 상세 고정 버튼이 '무신사에서 보기'. '내 옷 넣고 비교하기 (선택)'은 그 아래 |

## 바뀐 것
**조건 유지(먼저)**
- 종류를 말했는데 그 종류가 없으면 다른 종류로 채우지 않는다.
  - 성별을 말하지 않았고 다른 성별에만 있으면 그 성별에서 찾고 알린다.
  - "남자 원피스"처럼 성별을 말했으면 0건이다. 상품 목록에 아예 없는 종류(반바지·조거·레깅스·수영복)는 "상품 목록에 아직 ○○이 없어요"라고 쓴다.
  - 종류를 말하지 않은 요청("여름 데이트룩")은 전과 같이 여러 종류에서 고른다.
- 검색이 조건 객체(`criteria`)를 돌려주고, 상세 대안·브랜드 다른 아이템·코디가 같은 조건을 쓴다.
- 0건이면 조건을 몰래 풀지 않는다. 칩의 ×로 **사용자가 직접** 뺄 수 있고, 뺀 조건은 "뺀 조건 되돌리기"로 보인다.

**화면(다음)**
- 검색 결과는 상품이 먼저, 코디는 아래("이 조건으로 한 벌 맞춰 보면", 예산은 상품 한 벌 기준이라고 표시).
- 검색 중에는 서로 다른 값을 보이던 '추천 조건' 줄과 예시 옷장 배너를 숨긴다. 칩은 실제 적용 조건 한 곳에서 만든다.
- 예시 옷장일 때 '내 옷장' 탭 숫자 배지를 없앴다. 상세 이유 문장에서도 예시 옷을 보유처럼 쓰지 않는다.
- 이해하지 못한 요청에는 관계없는 상품 16개 대신 "아직 찾을 수 없어요"와 예시만 보여 준다.
- 카드 이유 첫 줄은 실제로 맞춘 조건("출근 · 10만원 이하에 맞춰 골랐어요"). 요청한 상황에 맞지 않는 종류(출근에 플란넬 등)는 "출근에는 덜 맞는 대안"으로 따로 묶는다.
- 헤더 문구를 "한 줄로 찾고, 내 옷과 비교해요"로 바꿨다.

**표현·이어 묻기·뒤로가기(이어서)**
- 후드티(‘티’가 티셔츠로 잡히던 문제), 빨강·핑크·노랑·보라·주황, "꾸민 티 안 나게"의 '티' 오인식을 고쳤다. "그레이"가 '그레'로 잘려 미인식으로 나오던 문제도 고쳤다.
- "편한": 착용감 자료는 없으므로 **보장하지 않는다.** 상품명에 밴딩·이지·와이드 표기가 있는 상품을 앞에, 생지·리지드를 뒤에 두고 그렇게 했다고 안내한다.
- "더 싼 걸로"/"더 비싼 걸로": 이전 조건(종류·상황·예산)을 그대로 두고 가격순으로 다시 찾으며, 그렇게 했다고 화면에 쓴다.
- 시트나 검색 결과가 열리면 기록 한 칸을 넣어 뒤로가기가 앱 안에서 닫기로 동작한다.

## 남은 한계
