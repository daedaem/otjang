# 검색의 제외 조건·상황을 상세와 코디까지 (2026-10-18)

대표 지시 1순위: "검색의 제외 조건·상황이 상품 상세와 코디에서도 일관되게 유지되게." Codex 검토에서 확인된 구간은 두 곳이었다.
- `search().criteria`에 뺀 종류("셔츠 말고")와 상황·계절·스타일이 없었다.
- `itemSheet`의 `recommendLooks`에 가격 조건만 넘어갔다.

## 조건을 두 묶음으로 나눴다
| 묶음 | 내용 | 어디에 쓰나 |
|---|---|---|
| 상품 조건 | 종류, 색, 뺀 색, 밝기, 가격, 브랜드 | 결과 목록, 상세의 "같은 조건, 다른 선택", 코디의 상품 하나하나 |
| 코디 전체 조건 | 상황, 계절, 스타일, 뺀 종류 | 결과의 코디, 상세의 "이 상품으로 만든 코디" |

- `productCriteria(cr)`가 상품 조건만 떼어 준다. 대안 안내 문구("검색 조건(10만원 이하)에 맞지 않는 같은 종류 N개는 뺐어요")는 이것만 쓴다.
- 코디에는 둘 다 쓴다. 상세 화면에 "검색 조건(격식·하객 · 10만원 이하)을 코디의 다른 옷에도 그대로 적용했어요. 예산은 옷 한 벌마다 같은 기준이에요"라고 적는다.
  - 모호한 부분을 밝힌 것: "셔츠 10만원 이하"의 예산을 코디의 코트에도 거는 것은 해석이다. 그래서 화면에 그렇게 했다고 쓴다. 몰래 풀지도, 몰래 넓히지도 않는다.

## 몰래 완화하던 곳을 막았다
- `recommendLooks`는 상황에 맞는 공식이 없으면 상황 없는 공식으로 **조용히 바꿨다**. `strictOccasion` 옵션을 넣어 검색에서 온 요청에는 바꾸지 않는다. 결과·상세 모두 "검색 조건(출근 · 셔츠 제외)을 지키면서 만들 수 있는 코디가 없어요. 조건을 풀지 않았어요"로 보인다.
- `fillLook`에 `excludeSlot`을 넣어 뺀 종류는 코디의 다른 자리(이너 등)에도 들어가지 않는다. 그 자리를 채울 종류가 없으면 그 공식은 쓰지 않는다.
- 상세의 코디에서 뺀 색은 `hidden`으로 걸러 어느 자리에도 나오지 않는다.

## "더 좋은 걸로"
비싼 순으로 바꾸지 않는다(Codex 로컬과 같은 방향). 이전 조건을 그대로 두고 "품질을 비교할 자료가 없어서 조건과 순서는 그대로 뒀어요(평점·후기는 참고만)"라고 알린다. "더 싼/비싼 걸로"만 가격순으로 바꾸고, 그렇게 했다고 쓴다.

## 코디 설명 한 줄 (Codex 로컬 0572caa와 겹침)
카드와 코디 시트의 설명을 공식의 고정 문구 대신 실제 배치된 옷으로 쓴다: "내 화이트 옥스퍼드·베이직 셔츠 + 내 라이트 블루 워시드 데님 + 후보 브라운 로퍼". 공식 설명은 시트에서 "공식 설명:"으로 한 줄 내렸다. 지금 보고 있는 옷(상세를 연 상품·내 옷)은 사진 4칸에서 빠지지 않는다(`focus`).
- Codex 로컬에도 같은 기능이 있다고 들었다. 합칠 때 한쪽을 고르면 된다. 이쪽은 `lookLine()` 한 함수와 `focus` 표시뿐이라 버리기 쉽다.

## 확인한 것 (모바일 390×844, 클라우드 Chromium)
| 확인 | 결과 |
|---|---|
| "셔츠 말고 출근 니트" | 니트만 3개. 상세 코디: "검색 조건(출근 · 셔츠 제외)을 지키면서 만들 수 있는 코디가 없어요. 조건을 풀지 않았어요". 셔츠 없음 |
| "하객룩 셔츠" → 상세 | 코디가 격식 공식(재킷·셔츠·슬랙스·더비). 안내 문구 표시 |
| "출근용 셔츠 10만원 이하" → 상세 (옷장 3벌) | 코디에 열어 본 셔츠 포함, 10만원 넘는 상품 없음 |
| "더 좋은 걸로" | 조건 유지, 순서 유지, 품질 자료 없음 안내 |
| 코디 한 줄 | 옷 상세·옷장 탭·코디 시트에서 실제 구성으로 표시 |

검사: `npm test` 595개 통과. 새 검사 2개(뺀 종류·상황이 코디까지, strictOccasion). 테스트 수는 완료 기준이 아니다.

## 미검증·한계
- 실제 기기(아이폰·안드로이드)와 Windows 미검증.
- 상황 적합성은 `data/looks.js`의 공식 `occ`와 `data/slots.js`의 `occ`에 의존한다. 공식이 적어 "출근 · 셔츠 제외"처럼 코디가 아예 없는 조합이 흔하다. 공식 추가는 패션 판단이라 하지 않았다.
- 예산을 코디의 다른 옷에 같은 기준으로 거는 해석은 화면에 밝혔지만, 사용자가 다르게 기대할 수 있다. 실제 사용자 반응으로 확인할 일이다.
- 저장·백업·동기화·구매 기록 형식은 바꾸지 않았다. 외부 전송·유료·공개 배포 없음.
