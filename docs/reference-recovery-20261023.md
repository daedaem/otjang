# 로컬 검토·설계 기록의 선별 복구 — 2026-10-23

이 문서는 현재 master에 빠져 있던 로컬 기록을 읽어, 공개해도 되는 결정과 근거를 보존한 인수인계다. 원본 파일을 그대로 공개하거나 과거 앱을 현재 앱에 합친 결과가 아니다. 원본의 개인 자료·실행 환경 정보는 옮기지 않았다.

현재 작업은 [문서 시작점](README.md), [대표 요구사항](owner-requirements.md), [사업 계획](business-plan.md), [개발 계획](development-plan.md), [시스템 인수인계](system-handover.md)를 먼저 따른다. 이 기록은 이전 판단의 이유를 찾는 자료이며, 최신 결정과 충돌하면 과거 날짜의 내용을 현행 요구로 적용하지 않는다.

## 복구 범위와 확인 방법

기준은 2026-10-23에 비교한 master `90889b7`과 이전 로컬 작업본이다. master에 없는 최상위 문서 13개와 연구 파일 3개를 읽고 원본 바이트의 SHA256을 계산했다. 원본 16개는 변경하지 않았다. 이번 문서 정리는 원래 기능·검사·수상·경쟁사 정보를 새로 실행하거나 인터넷에서 재검증한 작업이 아니다.

- 최상위 문서 13개 중 9개는 당시 로컬 Git 미추적, 4개는 이전 로컬 Git에서 추적되어 있었다. 연구 3개도 당시 미추적이었다.
- 이전 로컬 Git에서 추적된 문서는 **현 master에 없었다**는 뜻이다. 다른 GitHub 브랜치·이력 어디에도 없다고 단정하지 않는다.
- 이미 현행 요구사항에 옮겨진 결론은 다시 새 결정으로 만들지 않는다. 빠져 있던 관찰·판단 이유·검증 한계를 여기에 보완한다.
- 연구 이미지·캡처·제품 사진은 복구하지 않았다. 공개 출처와 AI의 작품별 관찰 241개는 별도 [디자인 참고 원장](research/design-reference-ledger-20261020.md)에 보존했다.

## 1. 경쟁사 확인에서 남길 판단

2026-10-16 기록은 Apple Silicon Mac에서 iPhone/iPad용 Acloset 6.41.1을 게스트로 조작한 시험이다. 현행 Acloset의 전체 평가나 실물 iPhone 시험이 아니다. 등록 방법의 표시와 라이브러리 추가, 날씨가 있는 추천, 속성 수정, 통계, 가상 피팅의 로그인 조건을 관찰했다. PC 확장·이메일 연결·구매내역 가져오기·유료 기능·착용 이미지 생성은 실행하지 않았다.

한 공개 재킷 상품의 웹 캡처 시험에서는 자동 스캔이 원단 설명 이미지를 골랐고, 직접 캡처 뒤에는 여러 의류 후보와 일반 속성이 나왔다. 그러나 정확한 브랜드·상품명·가격이 옷 정보로 이어지지 않았고 판매 색상명과 시각 추정 색도 달랐다고 기록됐다. **한 상품·한 가져오기 경로**의 관찰이므로 “Acloset은 브랜드를 인식하지 못한다”라는 전체 주장으로 바꾸지 않는다.

남길 제품 판단은 다음과 같다.

- 등록은 상품 링크·라이브러리·사진 등 여러 입구를 제공하고, 확인된 정보부터 채운 뒤 불확실한 부분만 묻는다.
- 사진의 일반 속성 추정과 판매 출처로 확인한 브랜드·품명·가격을 별도로 관리한다. 배경 제거, 의류 분할, 생성형 이미지 정리도 별개다.
- 기존 옷과 조합하는 기능은 경쟁사에도 있으므로 기능 존재 자체를 차별점으로 삼지 않는다. 실제 상품 확인 가능성과 구매 전후를 잇는 수고를 비교한다.
- 같은 옷·같은 구매 후보로 입력 수, 정보 오류·수정 횟수, 결정 시간과 자발적 재사용을 검증한다. 당시 게스트 시험이나 AI 점수로 경쟁 우위를 선언하지 않는다.

## 2. 옷장 선택형 정의와 조건 해석

10-17의 사용자 정정은 이미 [대표 요구사항](owner-requirements.md)에 반영되어 있다. 옷장 없이 질문하고 실제 상품을 받을 수 있어야 하며, 옷장은 조합·중복 판단을 더 정확하게 하는 선택 정보다. 장부나 링크 입력만 하는 서비스로 목표를 줄이지 않는다.

당시 `3e1704d` 코드와 891개 카탈로그를 별도로 실행한 기록은 다음 회귀 위험을 보여 준다. **현재도 같은 결함이 남아 있다는 판정이 아니다.**

| 입력의 유형 | 당시 문제 | 앞으로 확인할 계약 |
|---|---|---|
| “검정 말고 밝은 …” | 부정을 블랙 요청으로 해석 | 제외 조건이 긍정 조건보다 먼저 보호되어야 함 |
| “셔츠 말고 니트” | 제외한 셔츠도 반환 | 종류 제외가 결과와 대안에 유지되어야 함 |
| “아메카지 …” | 기존 클래식 취향이 요청 스타일과 섞임 | 명시한 요청이 저장 취향 때문에 바뀌지 않아야 함 |
| “구김 안 가는 …” | 일부 조건만 이해 | 소재·관리 특성을 모르면 미반영을 알리거나 질문해야 함 |
| 체형·인상 같은 모호한 말 | 미이해 뒤 기본 상품을 반환 | 부분 이해·미이해·조건 충족 결과를 구별해야 함 |
| 극히 낮은 예산·미지원 성별/종류 | 0건 또는 다른 스타일로 귀결 | 자동 완화 금지, 사용자가 고르는 다음 행동 제공 |

일반 추천에 “가진 옷에 없음”을 구매 필요의 근거로 붙이지 않는다. 옷장이 비었거나 일부만 등록된 상태에서 그 주장을 검증할 수 없기 때문이다. 상품을 선택하거나 검색한 것만으로 보유 등록·구매 기록을 만들지 않는다. 이 원칙은 화면 방향 변경과 별개로 유지한다.

## 3. 이전 로컬 베타에서 이어갈 데이터 보호 이유

아래는 10-12~13의 v0.4.4 및 Claude 0.8 기반 0.8.1-local 기록이다. **당시 Java/PostgreSQL 베타의 구현·실행법을 현재 Cloudflare 설치 앱의 구성이나 운영 절차로 제시하지 않는다.** 현재 저장소의 Node 자체 서버·Cloudflare 앱과 같은 실행본으로 합쳐 읽지 않는다. 새 코드에 실제로 구현되어 있는지는 현행 코드와 [시스템 인수인계](system-handover.md)로 판단한다.

- **대체 저장의 일관성:** IndexedDB 실패 뒤 localStorage에 저장한 최신 자료가 재실행 때 오래된 IndexedDB 값으로 되돌아가지 않도록, 유효성과 저장 순서를 비교했다. 연속 저장은 순서를 보장하고 양쪽 저장 실패는 성공으로 처리하지 않았다.
- **안전한 추가와 복원:** 기존 옷장에 추가할 때 같은 ID를 덮어쓰지 않고, 전체 교체와 분리했다. 취소·중복·한도 초과·손상 파일·저장 실패가 원본을 지우지 않아야 한다. 전체 백업과 공유용 내보내기는 목적과 포함 범위가 다르다.
- **모름의 보존:** 종류·색·밝기·격식·무늬가 확인되지 않으면 null로 남기고 사진 초안을 확정 상품으로 승격하지 않았다. 필요한 정보가 없으면 조합 수·중복·추천 점수를 확정하지 않는다. 같은 종류의 미확인 옷이 있으면 중복 구매 제안을 보류했던 이유도 이것이다.
- **후속 기록 호환:** Claude의 `follow`와 로컬 `followup`을 함께 보존하고 이전 마이그레이션을 바꾸지 않은 채 새 버전을 추가했다. 백업에서 과거 선택 필드가 없다는 이유로 사용자 자료 전체를 버리지 않는다. 당시 추천 설정/로그는 브라우저 전체 백업에만 포함돼 서버 백업과 범위가 달랐다.
- **로그인·충돌 경계:** 로그인만으로 개인 옷을 전송하지 않고 계정별 저장 공간을 나눴다. 오래된 일괄 저장 409와 버전 없는 저장 428 거절은 충돌 방지이며 기기간 자동 병합 완료를 뜻하지 않았다.
- **실사용 기록:** 구매 전 마음·판정 뒤 알게 된 점·구매·착용·후회는 사용자 동작으로 남겼다. 합성 QA나 ‘사기로 함’ 버튼을 거래·성과로 집계하지 않았다.
- **사진·추천의 한계:** 로컬 자르기·품질 안내·색 제안과 사용자 확인을 사용했다. 자동 의류 분할·OCR·정확한 브랜드/품명 인식·핏·실사 합성을 완성한 것으로 설명하지 않았다. 필요 종류 실루엣과 신발 보완 제안도 판매 상품이나 착용 정확도의 증거가 아니었다.
- **운영 안전:** 당시 런처는 loopback, 별도 합성 QA DB, 종료 후 데이터 보존, 프로젝트 소유 프로세스/컨테이너만 조작하는 원칙을 두었다. 초기 컴파일 대기와 건강 상태 확인을 분리했다. 이 원칙을 지키되 지금 없는 과거 런처·임시 도구 경로를 새 운영자가 그대로 실행하게 하지 않는다.

당시 기록의 검사 수는 별도 코드·환경의 역사다. 통합 전 JS64/Java28/브라우저154/UI60, 통합 직후 JS114/Java29/UI62, 이후 기능 추가 JS132라는 서로 다른 시점의 결과를 더하지 않는다. 이번에는 그 결과 파일을 다시 실행·검증하지 않았으며 현재 검사 수·사용자 수·효용·출시 완료로 사용하지 않는다.

## 4. Claude·Codex 인수 절차와 종료 조건

10-19 기록은 중단·사용량 소진 때 결과를 잃지 않기 위한 절차를 남겼다. 대화 UI의 브랜치 표시만 믿지 않고 실제 저장 커밋·파일 목록을 확인한다. 받은 파일은 Git blob/SHA로 대조하고, 원본 수신 사본과 작업 사본을 분리한다. 저장·수신·실행·시각 검증·병합·배포를 각각 기록한다.

당시 Claude의 03·08·09 시안과 Codex의 나머지 7개 구현 범위를 나눴고, 17개 중간 파일 인수 뒤 최종 검토 문서를 추가 수신했다. **그 시점의 인수 대기는 종료되었다.** 지금 옛 문서만 보고 Claude 응답을 다시 기다리거나 같은 7개 시안을 중복 제작하지 않는다. 당시 자동 확인 작업이 현재도 활성이라고 추정하지 않는다.

새 인수에서는 마지막 커밋, 미완성 코드, 자산 출처, 실행법, 실제 검사 결과, 남은 문제를 남긴다. 접근하지 못한 미커밋 클라우드 파일은 수신 완료로 표시하지 않는다. 같은 파일을 동시에 수정하지 않고, 기존 원본·미추적 자료·사용자 저장 공간을 전체 초기화하지 않는다. 참고 링크·시안 승인은 계약·유료 작업·사진 전송·외부 일반 공개 승인으로 넓히지 않는다.

## 5. 디자인 조사에서 보존할 근거와 판단

### 조사 수준의 구분

10-20 Codex 원장에는 Awwwards 전자상거래 160개+패션 50개, Apple 2022~2026 앱 31개, 합계 241개 수상/선정 이력이 있다. 그중 대표 이미지를 본 기록은 238개이고 이미지 미확보는 3개다. 이력의 본상·Honorable Mention·부문 Honors는 서로 다른 수준이다. 같은 브랜드의 별도 캠페인도 별도 작품이며 **238개 서비스를 설치·실사용한 것이 아니다.**

238개에 대한 관련도는 직접 참고 56·부분 참고 131·기본 흐름 제외 51로 기록되었다. 단일 AI의 설계 판단이며 독립 전문가 투표·산업 통계·우열 점수가 아니다. 대표 이미지 238개의 원본 해시가 서로 달랐다는 원본 메타데이터와 행 수를 확인했지만, 이번에 이미지 전체를 다시 열거나 수상 이력을 재조회하지 않았다. 241개 JSON 관찰과 원본 md 원장이 일치하는 것은 확인했다.

상세 관찰 12건은 웹 대표 이미지 확대 6건, 앱 추가 홍보 화면 6건이었다. Apple 화면은 스토어 홍보 이미지로 촬영 날짜·앱 버전이 불명이며 수상 당시 UI와 동일하다고 볼 수 없다. 실제 조작은 DVF 검색→셔츠 상세 등 제한된 흐름이었다. 결제·로그인·전체 접근성·전환율 시험이 아니다.

### 제품에 남길 원리

1. 사진·비율·글자·여백·행동을 함께 설계한다. 색상·모서리·배치만 바꾼 안을 독립적인 제품 경험이라고 제시하지 않는다.
2. 큰 단품 사진은 실루엣 확인에, 착용 사진은 맥락에, 확대는 소재·디테일 확인에 쓴다. 비슷한 다른 상품 사진이나 생성된 이미지를 실제 보유 상품으로 표시하지 않는다.
3. 사진 가까이에 브랜드·품명·출처와 확인 시점이 있는 가격·짧은 이유·주 행동을 둔다. 긴 판정문과 여러 동급 버튼으로 상품을 가리지 않는다.
4. 내 옷과 새 후보를 단품 사진으로 함께 보여 조합 관계를 설명하되, 이미지 배치가 정확한 핏·가상 착용의 증거가 되지는 않는다.
5. 입력은 결과에 바로 연결하고 모호한 부분만 하나씩 묻는다. 요청→상품→선택적 옷 비교→판매처/기록의 맥락을 유지한다. 예쁜 로딩으로 인식 실패를 숨기지 않는다.
6. 캠페인용 긴 인트로·3D·게임 장치를 반복 구매 도구의 기본 진입에 그대로 가져오지 않는다. 수상 이력은 후보 선정 근거이지 우리 사용성·사업 성과의 보증이 아니다.

10-19의 Patagonia Worn Wear·29CM 관찰에서는 같은 제품의 새 상품/중고, 사이즈·상태·대표 사진/개별 매물 사진을 구분해야 한다는 판단을 남겼다. Google 비교·Apple 검색·토스 입력 축소·Baymard 의류/0건 연구는 참고 자료이며 해당 회사가 우리 안을 검토했다는 뜻이 아니다. 과거의 배송비·관세 표시 제안은 이후 [대표 요구사항](owner-requirements.md)의 최신 결정으로 대체해 읽는다. 모르는 비용·재고·옵션을 0 또는 확인됨으로 만드는 것은 별개로 금지한다.

본문16px 전후·보조13px 이상·가격20~24px, 모바일2열·PC4열 같은 당시 수치는 **설계 시작 가설**이었다. 세계적 수상작의 공통 규격·최적값이나 현재 제품의 확정 디자인으로 쓰지 않는다. 원래 참고한 타사 화면·로고·사진을 복제할 권리도 생기지 않는다.

## 공개하지 않은 원본과 남은 경계

사진, 옷장 원본/전체 백업, 계정·초대 코드·비밀 설정, 개인 구매 후보/명명 자료, 원본 대화/세션 주소, 임시 터널과 기기별 절대 경로, 타사 참고 캡처/이미지 캐시는 원래의 비공개 위치에 남겼다. 원본 인수 파일·검증 증거 폴더가 Git에서 제외된 것은 이 원칙과 관계가 있으며 누락된 개인 파일을 업로드해 메우지 않는다.

이번 결과는 16개 **식별된 누락 기록의 공개 가능한 의미를 선별 보존**한 것이다. 과거 모든 대화·모든 미추적 코드·보관 폴더를 공개 복제하거나, 실행 불가한 과거 시안을 재배포한 완전 백업이 아니다. 누락 시안 코드를 다시 채택하려면 원본 보존·사진 권리·현재 상태 계약·현재 실제 과업을 별도로 검토한다. 원래 파일의 보관 위치와 private 자료는 공개 GitHub 문서가 대신하지 않는다.
