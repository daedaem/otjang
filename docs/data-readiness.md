# 상품·후기 확보 상태

- 확인일: 2026-10-11, 한국 시간
- 연결 요구: [PRD v0.4](PRD-v0.4.md) FR-15, FR-16
- 현재 상태: **실제 상품·후기 자료 확보 미완료**. 자동 수집 경로와 제공/이용 조건은 미확인이다.

## 1. 이번에 직접 관찰한 것

각 URL에 일반 HTTPS 요청을 1회씩 보냈다. 모두 프록시 CONNECT 단계에서 실패했고 원본 서버의 HTTP 응답을 받지 못했다.

| 대상 | 관찰 결과 | 아직 확인하지 못한 것 |
| --- | --- | --- |
| [무신사 robots.txt](https://www.musinsa.com/robots.txt) | `Tunnel connection failed: 403 Forbidden` | robots 규칙 |
| [무신사 공식 홈페이지](https://www.musinsa.com/) | 동일 | 상품·후기의 실제 공개 접근, 공식 이용 안내, 이미지 조건 |
| [네이버 개발자센터 쇼핑 검색 API 문서](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md) | 동일 | API 제공 상태·필드·인증·쿼터·비용·저장/표시 조건 |

이 결과로 판매처가 자동 수집을 금지했다거나 API가 종료됐다고 결론 내리지 않는다. 사용자 화면의 인터넷 설정과 런타임 상태 조회가 일치하지 않은 사례가 있어, 설정 이름만으로 원인을 단정하지 않는다. 원문을 읽지 못했으므로 해당 페이지 내용을 사실 근거로 인용하지 않는다.

GitHub API 연결과 PR 쓰기는 별도로 성공했다. 한 호스트의 성공이 상품 사이트의 접근 가능성을 보장하지는 않는다. 접근 우회·로그인·비공개 API 조사·대량 수집은 수행하지 않았다.

## 2. 첫 사례에 필요한 최소 근거

아래는 조사 양식이며 채워진 실제 카탈로그가 아니다. 프로젝트 측이 확인 가능한 경로로 조사하고, 사용자가 모든 후보와 후기를 찾아오게 하지 않는다.

| 묶음 | 기록할 정보 | 정보가 없을 때 |
| --- | --- | --- |
| 상품 식별 | 판매처·상품명·모델/SKU·색·사이즈 옵션·원문 URL | 동일 상품 여부 미확인 |
| 가격 | 금액·통화·옵션·확인 시각·회원/할인 조건·확인 가능한 배송비 | 가격/총지출 조건 충족을 확정하지 않음 |
| 재고 | 해당 옵션의 확인 상태와 확인 시각 | 미확인; 품절로 바꾸지 않음 |
| 공식 특징 | 소재·실루엣·치수 등 원문에 실제 있는 사실과 근거 위치 | 추정치를 공식 정보처럼 채우지 않음 |
| 후기 | 원문 링크·다시 찾을 수 있는 위치·동일 모델/버전 여부·관련 주장·확인 시각 | 후기 자료 부족 |
| 후기의 맥락 | 원문에 명시된 사이즈·사용 기간·착용 조건·상반된 의견 | 작성자 특성을 추정하지 않음 |
| 개인화 해석 | 연결된 개인 조건·보유 옷·상품/후기 근거·추천/보류 이유 | 근거 없는 맞춤 설명을 만들지 않음 |

원문·이미지의 저장과 공개 재배포 조건은 별도 확인한다. 원문에 접근할 수 있거나 robots가 허용해도 이용 권한 전체가 확인된 것은 아니다. 접근 가능한 자료의 출처·사실·요약을 필요한 범위로 기록하고, 실제 제공 화면에 필요한 사용 조건을 조사한다.

## 3. 자료 준비 상태와 완료 기준

| 상태 | 의미 | 검증에서의 처리 |
| --- | --- | --- |
| 비교 가능 | 실제 후보가 식별되고, 해당 고민과 관련된 상품·후기 주장을 원문으로 추적 가능 | 그 범위의 비교 수행. 후보 수와 미확인 항목은 함께 기록 |
| 부분 근거 | 상품은 확인했지만 후기 접근이나 핵심 조건이 일부 부족 | 가능한 비교만 제공. 후기 비교/개인화의 미충족 범위를 별도로 기록 |
| 자료 확보 실패 | 상품을 식별할 수 없거나 비교 근거를 확보하지 못함 | 원스톱 검증 완료로 세지 않음. 화면 구조와 데이터 양식 작업은 계속 가능 |

근거가 없는 후보를 억지로 세 개 채우지 않는다. 후기 링크만 확보한 상태는 관련 후기 비교 완료가 아니다. ‘검증 실패’와 ‘자료를 구하지 못해 검증하지 못함’도 구분한다.

## 4. 자동화 전 운영 가능성 검증

첫 사례에서 `후보 탐색 → 모델/옵션 확인 → 관련 후기 읽기 → 개인화 비교 → 변동 정보 재확인`의 작업 시간을 각각 기록한다. 사용자에게 줄어든 검색·이동·중복 입력과 프로젝트 측 준비 시간을 함께 보고한다.

0원 운영 목표만으로 지속 가능한 조사를 입증할 수는 없다. 비용·유지 시간을 측정한 뒤 자동화할 구간을 고른다. 검색 API가 확인되더라도 후기 근거 확보가 가능한지는 별도 확인한다.

다음 접근 확인은 환경 적용 변화나 지원되는 경로를 확인한 뒤 수행한다. 같은 실패 요청을 반복하거나, 읽지 못한 내용을 추정해서 API/수집 설계를 확정하지 않는다.
