# UX/UI 개선 시안 10개 검토와 추천 (2026-10-19)

> 문서 시점: 2026-10-19. 당시의 검토·구현 기록을 보존한 자료입니다. 현재 결정·우선순위·운영 상태는 [최신 문서 목차](README.md)를 확인합니다. 아래의 “지금·완료·다음”은 별도 갱신 표시가 없으면 당시 기준입니다.

**실제 전문가가 참여한 결과가 아니다.** AI가 디자이너·프론트엔드 개발자 10팀과 검토자 3명의 역할을 맡았다.
시안은 `app/mockups/ux10/`에 있고, 기존 앱(`app/src`)과 저장 데이터는 바꾸지 않았다. 살까말까 버전은 대표 정정에 따라 중단했고 기존 파일(`app/mockups/salmal/`)만 보존했다.

## 1. 어떻게 만들었나
- **같은 판단, 다른 화면.** 현재 앱 엔진(검색·구매 비교·코디·구매 기록)을 그대로 묶은 공통 코어(`shared/eoul-mock.js`)를 10개 시안이 함께 쓴다. 판정 문장은 현재 앱의 구매 비교 화면과 같은 순서로 정해진다(실제 앱에서 같은 상품·같은 옷으로 "비슷한 옷이 이미 있어요"가 똑같이 나오는 것을 확인).
- **정직성 규칙.** 목업·AI 역할 표시, 수집가 표기(현재가·최저가 아님), 규칙 기반 해석(대화형 AI 아님), 사진 대신 종류·색 그림(상품 사진 권리 미확인), 외부 요청 0, 체험용 옷은 내 옷과 구분.
- **같은 시나리오 검사.** 흐름 검사 도구(`tools/flowcheck.mjs`)가 10개를 같은 순서로 직접 누른다: 옷장 없이 "출근용 셔츠 10만원 이하" → 첫 상품 판정 → 사기로 함 → 흰 셔츠 한 벌 넣기 → 판정이 바뀌는지 → 조건 빼기 → 못 읽는 말 → 기록, PC는 체험용 옷장.
- **독립 검토 3개.** 처음 쓰는 사람(UX 리서처), 신뢰·정직성(콘텐츠 검토), 이식성·접근성(프론트 아키텍트). 검토자에게는 Claude의 결론을 주지 않고 파일과 화면만 줬다. 지적은 모두 각 팀에 돌려보내 고쳤다.

## 5. 추천 순위 (Claude 판단)
한 시안을 통째로 고르지 않는다. 현재 앱을 갈아엎지 않고 조각을 옮기는 순서다.

1. **01 답 먼저 — 결과 맨 위 첫 후보 카드.** 현재 앱의 가장 큰 문제(옷장 없으면 판정 없음, 판정까지 8번)를 바로 푼다. 처음 쓰는 사람·신뢰 검토에서 상위. 이식: `renderSearch()` 결과 머리 아래에 카드 하나, 판정은 첫 상품만 계산.
2. **10 엄지 하나 — 판정 서랍.** 아래 고정 결정 버튼, 이전·다음 후보, 닫으면 제자리. 작은 휴대폰(360×667)에서도 결정 버튼이 첫 화면. 이식: 현재 `openSheet()` 구조와 같아 구매 비교 시트의 결정 묶음을 판정 바로 아래로 올리고 아래에 고정.
3. **06 한 화면 — 옷 넣기 시트만.** 신뢰 검토 1위. 판정에서 여는 넣기(종류 미리 선택 → 색 → 넣기 → 같은 판정으로 복귀, '바뀌기 전' 표시)가 가장 짧다. 여러 층 시트 전체는 무거워 넣기 시트만 가져온다.
4. **03 비교함 — 다음 단계.** 후보끼리 비교하는 유일한 정면 해결. 비교함 전체는 새로 만들어야 해 1~3 뒤에.
5. **02 세 번 탭 — 보조 입구.** 타일로 시작하는 길과 "이미 있나요? 없어요/있어요" 한 번 누르기. 주 입구는 한 줄 요청 유지.
- **보류:** 05(실제 사진 권리 확보 뒤 재검토), 09·07(고친 뒤에도 길거나 비유가 낯섦), 08(레일이 화면을 늘 차지), 04(결정을 쉽게 만들어 충동 구매 위험, 보조 모드로만).

## 6. 현재 앱에 옮기는 첫 순서 (제안, 구현은 Codex 담당)
| 순서 | 조각 | 출처 | 완료 기준 |
|---|---|---|---|
| 1 | 결과 맨 위 첫 후보 카드(판정·결정 3개·옷 넣기는 보조) | 01 | 옷장 없이 판정까지 2~3번, 판정 문장은 기존 compareCandidate 그대로 |
| 2 | 구매 비교 시트의 결정 버튼을 판정 바로 아래로, 아래 고정 | 10·06 | 360×667에서 결정 버튼이 첫 화면 |
| 3 | 판정 안 옷 넣기: 종류 미리 선택 → 색 → 넣기 → 같은 판정 복귀 | 06·01 | 사진 없이 3~4번, '바뀌기 전' 표시 |
| 4 | "중고로도 찾아보기" 링크 묶음 | 공통(`usedSearch`) | 외부 검색 결과로 이동, "매물 확인 안 함" 문장 |

저장 형식은 바꾸지 않는다. 판정 쪽 강조는 테두리만, 체험용 옷은 내 옷과 구분, 판매처는 "보기"로 쓴다(4장 기준을 그대로 적용).

## 7. 중고 매물 목표 반영
모든 시안의 판정 화면에 "중고로도 찾아보기"(국내 번개장터·당근·중고나라·후루츠패밀리, 해외 eBay·메루카리 일본)를 넣었다. 외부 사이트의 공개 검색 결과로 보내는 링크이고, 어울은 매물·가격·재고를 확인하지 않는다고 함께 쓴다. 앱 안 실제 매물 통합은 공식 경로가 승인·계약 전이라 "연동 전"이다. 판단과 근거는 `docs/used-market-review-20261019.md`.

## 8. 한계
- 실제 사용자 관찰이 아니라 AI 역할 검토다. 대표 실기기 확인이 필요하다.
- 상품 사진 대신 그림이라 사진이 들어간 실제 모습과 다를 수 있다(특히 05).
- 누르는 횟수는 같은 시나리오 하나 기준이다.
- 공통 코어 묶음은 커밋 f174ecb의 엔진 스냅샷이다. 앱 엔진이 바뀌어도 목업은 자동으로 따라가지 않는다(`tools/build-core.mjs`로 다시 묶음).
