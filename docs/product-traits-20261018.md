# 추천 근거 보강: 상품명에서 읽은 것만 (2026-10-18)

대표 지시 2순위 "실제 상품과 추천 근거 보강" 중, 없는 정보를 만들지 않고 할 수 있는 부분이다.

## 문제 (전문가 역할 모의 평가에서)
- 이유가 종류별 고정 문구라 상품과 안 맞았다: 롱 기장 '로브 더블 코트'에 "짧고 묵직한 클래식 겨울 코트", 신발 16개가 전부 같은 문장.
- 러닝 안정화·키높이 더비가 스타일 추천 상위에 올라왔다.

## 한 것
- `productTraits(product)` (`catalog-policy.js`): **상품명에만** 있는 표기를 읽는다. 핏(오버사이즈·릴렉스·와이드·슬림), 기장(롱·하프·숏·크롭), 소매(반팔·긴팔), 소재(캐시미어·울·린넨·코듀로이·플란넬·스웨이드·레더·데님·코튼·헤비웨이트·테리), 기능성 표기(러닝·안정화·트레일·키높이·고어텍스).
  - "롱 슬리브"는 소매이지 기장이 아니다(검사로 고정).
  - 상품명에 없는 속성은 만들지 않는다. 사진·소재 분석 아님.
- 카드 두 번째 줄에 "상품명 기준: 롱 · 캐시미어"처럼 보여 준다. 상세의 추천 근거 목록 맨 위에도 같은 줄.
- `whyConflicts`: 종류 고정 설명이 기장과 어긋나면(짧은 코트 자리의 롱 코트) 고정 설명 대신 상품명 기준 줄을 쓴다. 상품의 종류(slot) 데이터는 바꾸지 않았다(자동 생성 파일).
- 기능성 표기 상품은 같은 종류 안에서 뒤로 보낸다(검색 점수 −3, 코디 채우기 −2, 목록 정렬 후순위). **빼지는 않는다.**
- 부수 수정: 두 벌 조합 제안이 같은 종류(같은 상품)를 두 조합에 겹쳐 권하지 않게 했다(`wardrobe-plan.js`). 겹치면 비교 화면이 어느 조합인지 모호해진다.

## 확인
- 검사 598개 통과. 새 `test/product-traits.test.mjs` 3개(상품명 기준 읽기, 롱 코트에 '짧은' 문구 대체, 기능성 신발 후순위).
- 화면: "겨울 데이트 코트" 카드에 상품명 기준 줄, "청바지에 어울리는 신발" 상위 5개에 안정화·키높이 없음.

## 하지 않은 것·한계
- 상품을 다른 종류로 재분류하지 않았다(생성 파일이라 수집 도구에서 고쳐야 한다). 롱 더블 코트는 여전히 피코트 자리에 있고, 설명만 바로잡았다.
- 상품명 표기는 판매처가 쓴 말이라 틀릴 수 있다. 화면에 "상품명 기준"이라고 밝힌다.
- 실기기 미검증.
