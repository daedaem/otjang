# 국내외 중고 매물 추가 목표 검토 (2026-10-19)

대표 요청: 원스톱 목표에 "새 상품뿐 아니라 국내외 중고 매물까지 검색·비교해서 구매 판단하기"를 더할지 판단한다. 옷장 없이 시작하고, 옷장이 있으면 비교가 정확해진다는 정의는 그대로다. 살까말까 버전은 제외한다.
이번 범위에서 계약·유료 가입·결제·외부 제휴 문의 발송은 하지 않았다.

## 1. 결론

**목표에 넣는 데 찬성한다. 다만 "검색 링크 연결"과 "앱 안 매물 통합"을 다른 단계로 나눈다.**

| 순위 | 할 일 | 비용·조건 | 지금 상태 |
|---|---|---|---|
| 1 | **중고 검색 링크 연결**: 판정 화면에 "중고로도 찾아보기"(국내 4곳, 해외 2곳) | 0원, 계약 없음 | 목업 10개에 반영함. 현재 앱에는 아직 없음 |
| 2 | **eBay Browse API 시험 설계**(sandbox) | 무료 구간, 운영은 파트너 승인제 | 설계만 가능. 계정 생성은 대표 결정 |
| 3 | **번개장터 파트너 API 확인** | 계약 후 키 발급, 요금·범위 비공개 | 문의 필요(이번 범위 밖) |
| 제외 | 라쿠텐 웹서비스 | 규약상 여러 판매처 비교 화면과 충돌 | 쓰지 않음 |

이유는 세 가지다.
- 지금 무료로 확실히 할 수 있는 것은 링크 연결뿐이다. 앱 안에 실제 매물을 보여 주는 공식 경로는 모두 승인·계약·약관 제약이 있고, 확보된 것이 없다.
- "해외 중고를 한국어로 찾기"는 이미 번개장터가 메루카리 제휴 "해외 탭"으로 제공한다(2024년 6월 보도). 매물을 모아 보여 주는 것만으로는 차별성이 약하다.
- 어울의 차별점은 매물 수가 아니라 **"내 옷장 기준으로 새 것·중고·안 사기 중 무엇이 맞는지"** 판단이다. 그래서 같은 판정 화면에 중고 연결을 붙인다.

## 2. 공식 경로 확인 결과

라쿠텐 규약은 영어 번역본으로 읽었고, 일본어 원문이 우선한다고 적혀 있다.
eBay의 "매물 국가 안 배송만 판매" 조건이 앱 안 결제(Order API)에만 해당하는지, eBay 상품 페이지로 보내는 방식에도 해당하는지는 해석 확인이 필요하다.

## 3. 검색 링크 연결과 앱 안 통합의 구분

| 구분 | 무엇을 하나 | 화면 표기 | 지금 가능 |
|---|---|---|---|
| 검색 링크 연결 | 사용자가 누르면 외부 사이트의 공개 검색 결과로 이동. 어울은 아무것도 읽거나 저장하지 않음 | "외부 사이트의 검색 결과로 이동해요. 어울은 매물·가격·재고·상태를 확인하지 않았어요." | 예 |
| 앱 안 매물 통합 | 공식 API로 매물 제목·가격·상태·배송비를 받아 판정과 함께 보여 줌 | 매물마다 출처·확인 시각·배송비 별도·중고 표시 | 아니요. 승인·계약 전 |
| AI 웹 검색 | 공개 링크를 찾는 보조 수단 | 매물 카드로 보여 주지 않음 | 실시간 재고·가격·재사용 권한을 보장하지 않음 |

연동되지 않은 것은 화면에서 "연동 전"으로 쓴다. 가짜 매물이나 추정 시세를 만들지 않는다.

## 4. UX: 어디에, 어떻게

- **판정 화면의 결정 버튼 근처**에 "중고로도 찾아보기"를 둔다. 결과 목록에는 넣지 않는다. 가격·상태를 모르는 링크가 상품처럼 보이면 혼동되기 때문이다.
- **검색어**: 국내는 "브랜드 + 상품명"으로 같은 상품을 찾는다. 해외는 영어·일본어 "색 + 종류"로 비슷한 옷을 찾는다. 해외 검색이 같은 상품이 아니라는 점을 화면에 쓴다.
- **해외 안내**: 배송대행·관세·반품 조건이 따로 있다고 쓴다. 개인 사용 면세 한도(일반 150달러, 미국발 200달러로 알려짐)는 관세청 공지로 확인이 필요하다.
- **옷장과의 관계**: 중고도 같은 판정을 쓴다. 이미 비슷한 옷이 있으면 새 것이든 중고든 "보류"가 먼저 보인다.
- **10팀 시안 반영**: 모든 시안의 판정 화면에 같은 링크 묶음(`data-flow="used-search"`)을 넣었다. 비교함(03)과 장부(07)는 중고 행·줄에 "연동 전"과 링크만 둔다.

## 5. 최소 구현 범위와 첫 연동안

**1단계: 링크 연결(지금, 0원, 계약 없음).**
- 목업 코어의 `usedSearch()`를 현재 앱의 상품 상세·구매 비교 시트에 블록 하나로 옮긴다. 저장 형식은 바꾸지 않고, 외부 요청도 없다(사용자가 누를 때만 이동).
- 완료 기준: 상품마다 링크 6개가 그 상품 검색어로 열리고, "확인하지 않았어요" 문장이 함께 보인다.
- 2026-10-19 확인: 번개장터·당근·중고나라·후루츠패밀리·메루카리 검색 주소는 응답 200. eBay는 봇 차단(403)이라 브라우저에서 확인이 필요하다.
- 현재 앱의 `main.js`는 Codex 담당이라 이식은 Codex가 한다.

**2단계: eBay 시험 설계(대표가 개발자 계정 생성을 결정한 뒤).**
- 서버 공급원(`server/src/supply.js`)에 `ebay-browse`를 "연결 전" 상태로 추가하는 설계만 먼저 한다.
- 화면 규칙에 eBay 요구사항을 반영한다: 재정렬 금지, 고정가만, 배송비 별도, 중고 표시, 판매자명, eBay 이미지·로고.
- 운영 키는 EPN 승인 뒤다.

**3단계: 번개장터 확인(대표 결정 사항).**
- 물어볼 것: 검색 API 제공 여부, 요금, 국내 비교 화면에서 쓸 수 있는지, 이미지·가격 표시 조건.
- 국내 패션 중고의 핵심이라 가능하면 우선순위가 eBay보다 높다.

**하지 않는 것**: 스크래핑, 가짜 매물, AI 웹 검색 결과를 매물처럼 보여 주기, 계약·가입·문의 발송.
