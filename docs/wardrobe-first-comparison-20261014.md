## 판단 기준

사용자가 제공한 Acloset 두 화면에서 앨범·카메라 중심 진입, 분석 완료 후 계속하기, 정리된 옷 사진 목록, 작은 브랜드 표시, 목록 안 추가 칸을 확인했다. 온라인 스토어·이메일·라이브러리 버튼은 보이지만 캡처만으로 계정 연결이나 가져오기 성능을 직접 검증한 것은 아니다. BARACUTA 표시가 자동 인식인지 직접 입력인지도 캡처만으로 알 수 없다.

Acloset 공식 [FAQ](https://www.acloset.app/support/)는 사진 배경 제거·속성 감지, 구매 내역·Gmail에서 선택적 등록, Smart Detector/Beautify의 개별 옷 추출을 안내한다. 지원 상점·이메일 형식은 지역·서비스에 따라 다르다고 명시한다. 이것은 경쟁사의 기능 안내이며 실제 정확도·처리 시간·동일 입력 비교 측정으로 취급하지 않는다.

현재 어울은 등록 UX·사진 처리·자동 가져오기에서 뒤처진다. 저장 검사와 모델 실험 통과를 제품 완성도나 경쟁 우위 점수로 표현한 판단은 철회한다. 원스톱 목표인 등록→부족 발견→취향·커뮤니티 탐색→조합·가상 착용→같은 상품/옵션 구매 비교→구매 후 환류는 유지한다.

## 이번 구현과 선택 이유

| 이전 | 이번 보정 | 이유 |
|---|---|---|
| 추가하면 종류 8개 이상과 입력 폼부터 표시 | 앨범·카메라를 먼저 표시, 사진 없이 종류 추가는 보조 | 사진을 넣으려는 사용자가 종류 폼부터 읽지 않게 함 |
| 작은 사진 옆 긴 설명, 분석 후보와 전체 종류 선택 중복 | 큰 사진과 후보를 먼저 표시, 직접 종류 선택은 접힌 대안 | 확인할 정보를 한 곳에 모음 |
| 사진만 있으면 이름·브랜드·색 폼이 펼쳐짐 | 선택 입력은 접고, 종류 확인 후 저장을 중심 행동으로 둠 | 모르는 정보를 찾느라 등록을 중단하지 않게 함 |

| 브랜드 없는 카드에 색 이름 표시 | 브랜드 미확인 표시 | 색을 브랜드처럼 읽는 혼동을 제거함 |
| 사진 잘림·예시와 등록 날짜 혼동 가능 | contain·일정한 여백, 참고 사진 캡션·예시 표시, 실제 등록일 | 실제 보유 옷·예시·사진 출처를 구분함 |

기존 종류 확인·정확한 상품 근거·색의 별도 확인과 저장 트랜잭션은 유지한다. 사진만으로 실제 보유 옷을 확정하지 않는다. 카메라는 실제 capture 파일 입력에 연결하지만 실기기 실행은 미검증이다. schema5와 기존에 보관한 사진 Blob을 유지하고 새 표시 상태 entryMode는 저장하지 않는다. 표시 실패는 기존 보관 Blob/photoId를 삭제하거나 다른 상품 사진으로 대체하지 않는다. 새 입력의 보관 사진은 기존의 긴 변1024px 이하 JPEG 준비 방식이며 업로드 파일 원본 전체를 별도로 저장한다는 뜻은 아니다.

## 현재 남는 격차

이번 변경은 사진 배경을 제거하지 않는다. 전체사진에서 여러 옷을 추출하거나 HEIC를 읽는 기능도 없다. 화면에 자동 가져오기·이메일·쇼핑몰 연결 버튼을 만들어 구현된 것처럼 표시하지 않는다. 약154MB의 로컬 모델은 선택적 실험 기능이며 고객용 분석 방식의 최종 결정이 아니다. 실제 모바일 화면, 카메라, 개인 옷과 라벨의 정확도, 등록 소요 시간·탭 수는 검증하지 않았다.

## 다음 등록 처리 검증의 설계

서비스용 처리 후보는 서버의 전경 분리·옷 대상 선택·속성/OCR 분석이다. 단일 옷은 [BiRefNet](https://huggingface.co/ZhengPeng7/BiRefNet) 전경 분리, 착용사진은 [SAM2](https://github.com/facebookresearch/sam2#license) 대상 선택, 속성·보이는 문자는 [Qwen2.5-VL-7B](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct) 비교 시험을 후보로 둔다. 공식 모델 카드의 MIT/Apache-2.0 라이선스를 확인했지만 실제 의류 처리 품질, 실행 자원·지연 시간·운영비는 확인하지 않았다. 설치·사진 전송·GPU 과금·서버 배포는 시작하지 않았다.

옷을 새로 생성해 원본 대신 저장하지 않는다. 원본·분리 이미지·사용자가 확인한 속성을 구분한다. 사진 속 브랜드·정확한 상품은 보이는 라벨·품번·상품 주소와 권리 있는 카탈로그 근거가 있을 때만 연결한다. 구매 내역 연동은 상점·이메일별 읽기 권한과 실제 가져오기·중복 제거·철회 흐름을 검증한 뒤 제공한다.

제안하는 첫 품질 시험은 같은 옷10벌을 단일 옷·복잡한 배경·착용 사진으로 각각 찍은30장이다. 예비 채택 기준은 종류27/30, 색24/30, 옷 형태·무늬를 훼손하지 않은 분리 이미지24/30, 근거 없는 브랜드 확정0건, 실기기 등록P95 10초 이내다. 이 숫자는 제안 기준이며 달성한 품질이나 경쟁사 성능이 아니다. 사용자 수정 횟수·탭 수·실패·분석당 비용도 함께 측정한다.

개인 사진을 특정 서버로 실제 전송하거나 비용을 활성화할 때만 대상 서비스·보관/삭제·예산 상한을 명시한 별도 결정을 받는다. 현재 로컬 사진을 검증했다고 추정해 새 서버로 보내지 않는다.


## 구현 검증의 범위

Node22.23.2 전체329개 검사는 통과했다. 새10개는 실제 번들 콜백과 IndexedDB 대역으로 첫 선택·앨범/카메라 파일 입력·필수 종류 확인·옵션 접힘·사진 원자 저장·quota 재시도·기존 수정 경로·옷 목록 우선 표시를 검사했다. 초기 두 실패는 기존 세부 종류 안내 문구 검사였고 문구를 유지해 회귀 경로를 다시 통과시켰다. 단일HTML 빌드와diff 검사도 통과했다. DOM·추론·사진 디코딩은 대역이며 시각 QA, 실기기 카메라, 고객 등록 시간이나 경쟁 우위의 증거가 아니다.

기존 미리보기는 보존하고 별도 wardrobe-first 경로에 검토용 화면을 게시한다. 두 경로는 같은출처의 schema5 옷장 자료를 읽으며 이미지 출처·예시/실제 보유·구매 여정 보유 상태를 유지한다. view=closet은 처음 보이는 탭만 선택하고 데이터에 저장하지 않는다.
