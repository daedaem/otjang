# 집중 계획: 서비스부터 제대로 (2026-10-14)

**사용자 결정** (2026-10-14)
- "일단 추천하는대로 해봐요."
- 이어서 "한달은 됐고 일단 서비스부터 제대로 만들어요." → **기간을 정하지 않고, 아래 순서대로 완료 기준을 넘을 때까지 만든다.** 파일럿은 서비스가 완료 기준을 넘은 뒤에 한다.

방향
- 원스톱 목표(등록 → 부족·중복 → 상품 → 조합·가상 착용 → 구매 비교 → 구매·착용·반품 환류)는 **장기 목표로 유지**한다.
- 지금은 아래 한 가지에 집중한다. 에이클로젯을 기능 전체로 이기려 하지 않는다. 기본기는 비슷하게 맞추고, 한 가지에서 확실히 낫는 것을 목표로 한다.

## 이길 한 가지 (가설, 미검증)

**온라인으로 옷을 자주 사는 사람이 구매 직전에 "이 옷이 내 옷장에 필요한가"를 빨리 판단하고, 산 뒤 착용·반품 결과를 남기면 다음 판단이 나아진다.**

- **첫 대상**: 아메리칸 클래식·아메카지 취향의 남성 구매자. 아직 옷장 앱을 쓰지 않는 사람.
  - 코디 공식이 이 취향에 맞춰져 있어 품질이 가장 높은 영역이다.
  - 이미 다른 앱에 옷을 다 넣은 사람은 다시 넣는 부담이 크다.
- **보조 강점**: 가입이 없고, 사진이 기기 밖으로 나가지 않는다. 이것만으로 앱을 바꾸는 사람은 적다고 본다(추론).
- **근거와 한계**
  - 구매 여정(후보 → 주문 → 수령 → 보유·반품) 코드는 이미 있다(schema 5).
  - 에이클로젯의 약점 근거는 경쟁사 블로그와 앱스토어 리뷰 몇 개뿐이다. 에이클로젯에도 쇼핑 중 옷장 확인 기능이 있다.

## 만드는 순서 (담당·완료 기준)

### 1. 기본기 맞추기 — Codex·Claude 구현

`98de4cc` 검토에서 나온 오류는 Claude가 고쳤다(PR #15).
- 이전 버전 옷에 지어낸 등록일("등록 2026. 10. 14.")이 표시됨 → "이전 버전에서 옮김"으로 표시
- 분석을 켜지 않은 기본 상태에서 종류 선택이 접힌 "다른 종류로 등록" 안에만 있음 → 분석 후보가 없으면 펼쳐서 보여 줌
- 사진 형식 오류에 저장소 복구 버튼이 붙음 → "다른 사진 / 카메라 / 사진 없이 종류로"
- 앨범·라벨 입력 `accept`를 JPEG·PNG·WebP로 제한, 앨범 아이콘 추가
- 철회: "옷장 격자에서 참고 사진이 구분되지 않는다"는 지적은 틀렸다. 사진 위에 이미 "비슷한 상품 사진" 표시가 있다. 이 표시가 유지되는지 확인하는 검사만 더했다.

남은 일
- 아이폰에서 HEIC 사진이 JPEG로 바뀌어 들어오는지 **사용자가 실기기로 확인**한다.
- 수동 자르기(사각형)를 넣는다(Codex). 착용 사진·여러 벌 사진을 모델 없이 처리하기 위해서다.
- 배경 분리는 **스파이크 1회(2일)만** 한다. 통과 기준을 먼저 고정한다: 라이선스, 다운로드 크기, 모바일 처리 시간, 실패 시 원본 유지. 통과하지 못하면 1·2를 끝낼 때까지 넣지 않는다.
  - 라이선스로 걸러 낸 후보와 숫자로 쓴 기준안은 `docs/toolkit-20261014.md` 3절에 있다. 1순위는 SlimSAM(누르면 오려 내기, Apache-2.0, 13.8MB)이다.

**완료 기준**: 실기기에서 "옷 5벌 넣기"(`docs/acloset-comparison-20261014.md` 과제 1)에 걸린 시간이 에이클로젯의 2배 이내. 측정은 사용자가 한다.

### 2. 구매 판단 경험 다듬기 — Codex 구현, Claude 검토

- **첫 판정까지 3분**: 첫 화면에서 바로 상품 링크를 붙여 넣을 수 있게 한다. 첫 옷 3벌 등록부터 첫 판정까지 3분 안에 끝나는 것이 목표다.
- **판정 화면에 보일 근거**
  - 가진 옷 몇 벌과 맞는지
  - 비슷한 옷이 이미 있는지
  - 사면 완성되는 코디
  - 수집일 기준 가격과 판매처 확인 안내
- **구매 뒤 기록 활용**: 착용·반품·"안 맞음" 기록이 같은 브랜드나 같은 종류의 다음 판정 화면에 보이게 한다. 단, 추천 순위를 몰래 낮추는 데 쓰지 않는다(기존 원칙 유지).

**완료 기준**: 사용자 본인이 실제 구매 고민 3건을 앱으로 끝까지 처리한다(판정 → 구매 또는 보류 → 착용 또는 반품 기록).

### 3. 파일럿 5명 — 1·2의 완료 기준을 넘은 뒤, 사용자 진행

진행 방법은 `docs/pilot-kit-20261014.md`를 따른다.

## 지금 하지 않을 것 (1·2 완료 전까지)

커뮤니티, 가상 착용(ADR-14 보류 유지), 여러 판매처 가격 비교, 서버·계정·동기화, 3D, 상품 대량 수집, 착용 사진에서 옷만 잘라 내는 분할 모델.

장기 목표에서 빼는 것이 아니라, 1·2를 끝내기 전에는 손대지 않는다는 뜻이다.

## 판정 기준 (미리 고정, 결과를 본 뒤 바꾸지 않음)

- 파일럿 5명 중 **3명 이상**이 "다음에 온라인으로 옷을 살 때 어울을 열겠다"고 답하면 이 방향을 계속 간다.
- **2명 이하**면 이길 한 가지를 다시 고른다. 다음 후보는 사생활을 지키는 옷장, 또는 취향 큐레이션이다.
- 기존 `prelaunch-evaluation-20261014.md`의 기준(50% 이상이 "판단이 바뀌었거나 확신이 생겼다")도 함께 본다.
- 데이터 유실, 예시와 실제 옷의 혼동, 선택한 옷이 바뀌는 문제가 한 번이라도 나오면, 원인을 고친 뒤 그 과제를 다시 시험한다.
- 이 결과로 점수, 사용자 수, 매출을 주장하지 않는다. 5명은 방향을 확인하는 규모이지 시장 검증이 아니다.
