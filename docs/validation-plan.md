# 개인판 검증 계획

- 상태: 제안. 아직 사용자 실험을 수행하지 않았다.
- 연결: [PRD v0.4](PRD-v0.4.md) §6·§10
- 현재 대상: 프로젝트 소유자 본인. 지인 모집과 공개 서비스 실험은 포함하지 않는다.
- 단계 구분: [첫 검증과 개인화 판단 기준](first-slice.md). S0 사진 기술 검증·한 사례 비교와 S2 개인판 전체 완료를 구분한다. [사진 온보딩](photo-onboarding.md)의 실제 평가는 아직 수행하지 않았다.

## 1. 먼저 확인할 기능

| 색 대비 선호를 톤온톤으로 변경 | FR-04, FR-13, FR-14 | 관련 조합 판단 재평가, 결과가 같으면 유지 이유 설명 |

## 2. 실제 사용 기록

먼저 사진으로 초기 옷장 한 묶음을 만들고 일부 확정·첫 활용·후속 추가를 기록한다. 평가 사진에서 사람이 표시한 보이는 옷/영역과 자동 결과를 비교하고, 누락·오탐·잘못된 분리/병합·수정/추가 개수와 전체 입력 시간을 기록한다. 수동 등록 기준선과 비교해 입력 수고가 줄었는지 확인한다. 합성 이미지 평가와 본인의 실제 로컬 사진 평가를 구분하며, 사진의 저장·전송 원칙을 유지한다. 세부 측정은 사진 온보딩 문서를 따른다.

코디 5회와 실제 옷장 보완 고민 3건은 초안의 임시 기준이다. 보완 고민 3건 안에서 상품 발견·후기 비교·구매 판단을 함께 본다. 후보를 이미 가져온 사례만으로 원스톱 흐름을 검증했다고 보지 않는다. 사용 기회가 생길 때 기록하며 검증을 위해 외출·구매를 만들지 않는다. 기간을 먼저 강제하지 않는다.

| 항목 | 코디 | 구매 판단 |
| --- | --- | --- |
| 사용 상황 | 용도·계절·사용 가능한 옷 | 원하는 스타일·개인 조건·보완 고민·용도·예산 |
| 기존 대안 | 실제 옷장이나 기억으로 고른 조합 | 커뮤니티/후기/판매처를 오간 과정, 찾은 근거와 시간 |
| 제품 결과 | 선택 가능한 조합과 근거 | 보완 우선순위·실제 상품·관련 후기·보유 옷 활용·구매처 |
| 유용성 | 입을 만한 조합이 있는지와 이유 | 새 근거가 생겼는지와 구체적인 내용 |
| 행동 | 저장/실제 착용/포기 | 구매 의향/실제 구매/보류/미구매 |
| 마찰 | 입력·수정 시간, 불편한 단계 | 제품 밖에서 다시 찾은 정보·이동·반복 입력, 운영자의 조사 시간 |
| 후속 | 착용 후 불편한 점 | 실제 산 옷을 입었는지, 판단과 차이 |

‘결정이 바뀜’만 성공으로 세지 않는다. 같은 결론이어도 새로 확인한 근거가 있을 수 있고, 결정을 바꿔도 잘못된 추천일 수 있다. 후속 사용을 함께 기록한다.

비교 기준은 같은 조건으로 평소처럼 커뮤니티·후기·판매처를 찾아보거나 보유 옷을 직접 고른 결과다. 가능하면 동일 시점의 상품 정보를 사용하고, 먼저 본 정보가 다음 판단에 영향을 주는 순서 효과를 기록한다. AI 비교를 추가하려면 사진 외부 전송 원칙을 지키는 별도 방법을 먼저 정한다.

상품 추천의 주장과 후기 요약을 원문에 대조한다. 같은 모델인지, 장단점이 모두 반영됐는지, 작성자의 조건을 지어내지 않았는지 확인한다. 가격·재고의 확인 시점과 미확인 항목을 기록한다. 자동화 도입 전에는 사람이 준비한 범위와 작업 시간을 공개 검증 기록에 명시한다.

개인화에 대해서는 같은 자료의 기본 비교와 개인 조건 반영 결과를 나란히 기록한다. 개인 조건 때문에 달라진 후보·순위·제외·주의점과, 문구만 달라진 부분을 구분한다. 결과가 실제 선호와 맞는지 사용자 선택을 기록하며 설득력 있는 설명만으로 품질을 통과시키지 않는다.

## 3. 검증 기록 양식

```text
날짜 / 익명 사례 ID:
유형: 사진 온보딩·후속 추가 | 옷장 보완·상품 탐색 | 코디 | 가져온 구매 후보
기록 상태: 사용 완료 | 사용 중단 | 실제 기회 없어 대기
입력 범위와 미확인 정보:
결과를 보기 전 선택과 이유(선택):
제품이 제공한 구체적 정보:
실제 상품·후기 출처의 확인일과 미확인 정보:
본인 조건을 반영한 근거와 일반 추천의 차이:
본인 조건으로 달라진 후보·순위·제외·주의점 / 문구만 바뀐 부분:
자료 준비 상태: 비교 가능 | 부분 근거 | 자료 확보 실패
도움: 있음 | 없음 | 판단 유보 / 이유:
저장·착용·구매 등 실제 행동:
입력·수정 시간(측정한 경우만):
사진의 보이는 옷/영역 기준 수, 자동 후보·누락·오탐·잘못된 분리/병합·수정·수동 추가 수:
사진 준비/초기 모델 준비/처리 대기/검토·수정/첫 활용까지 시간:
자동 성공 | 부분 성공 | 실패 / 수동 대안 사용 여부:
지원 기기·모델 버전·사진 조건 / 로컬 전송 검사 결과:
다시 외부에서 찾아본 정보와 그 이유:
수동 조사·큐레이션 여부와 준비 시간:
가장 불편했던 단계:
규칙/화면 버전:
후속 확인:
```

원본 사진·상품 링크·개인 기록은 로컬에 둔다. 공개 포트폴리오에는 익명화한 요약과 재현 가능한 합성 예시를 쓴다. 빈칸과 대기를 실패/성공으로 임의 처리하지 않는다.

## 4. 종료 후 의사결정

1. 필수 흐름의 결함이 있으면 수정한다.
2. 기능은 되지만 유용하지 않으면 입력·판단·취향·화면 원인을 구분한다.
3. 개인 사용 기준을 만족하면 공개 여부를 사용자가 결정한다.
4. 공개를 선택했을 때 별도의 커뮤니티 검증 문서를 작성한다. 그때 타깃·참여 규모·관찰 기간·반복 행동 기준을 정한다.

개인판 결과만으로 시장성·매출·타인의 반복 사용이 검증됐다고 결론 내리지 않는다. 실제 결제나 지인 모집은 이 계획의 완료 조건이 아니다.
