# 출시 전 평가와 파일럿 계획 — 2026-10-14

## 평가 원칙

사용자 결정: 아직 서비스를 시작하지 않았으므로 실제 사용자 수·거래·매출·재방문 실적으로 개발 초기 점수를 깎지 않는다. 대신 알파 완성도와 사업 가설의 준비도를 각각 100점 만점으로 평가한다. 실제 가설 검증 상태는 별도로 표시한다. 두 점수를 하나의 사업 성공 확률로 합치지 않는다.

이 문서는 준비한 판단 기준이다. 파일럿을 수행한 결과가 아니며 현재 총점을 확정하지 않는다. 코드·테스트가 있어도 실제 휴대폰 사용성, 고객 효용, 상품 공급 계약을 검증한 것으로 대체하지 않는다. 불명확한 항목은 0점의 실패와 구별하여 ‘증거 미확인’으로 둔다. 확인된 항목만의 분모를 줄여 100점처럼 보이게 하지 않는다.

## 현재 가설과 반증

첫 검증 대상은 온라인에서 옷을 고를 때 이미 가진 옷과의 중복·조합 때문에 여러 앱과 사진을 오가고, 최근 구매 후보 하나를 설명할 수 있는 사람으로 제안한다. 클래식 취향은 첫 시나리오이며 제품 전체를 남성 클래식으로 제한하는 결정이 아니다.

문제 가설: 사용자는 상품을 더 많이 보는 것보다, 후보 하나를 자신의 기존 옷과 놓고 ‘추가 가치가 있는지’를 확인하는 데 시간을 쓴다. 참가자가 이 상황을 최근 실제 경험으로 설명하지 못하거나 별도 도구 없이 충분하다고 하면 가설을 재검토한다.

차별화 가설: 같은 판매 상품 후보에서 본인의 옷 사진·종류와 연결된 이유가 있는 쪽이 일반 상품 목록/기존 방법보다 구매 여부를 정하기 쉽다. 단순 인기 상품 제안과 구별하지 못하면 기각 후보로 둔다. 현재 종류만으로는 색·핏을 검증할 수 없으므로 그 효용을 과장하지 않는다.

수익 가설: 추천 순위와 분리해 고지한 판매처 제휴 수수료. 클릭을 구매로 기록하지 않는다. 사지 않기로 결정하는 가치도 관찰하므로 클릭·구매를 늘리는 것만 목표로 삼지 않는다. 실제 제휴 프로그램·자격·조건은 확인 전이다.

상품 공급 가설: 허용된 판매처 피드/제휴 API 또는 명시적으로 허락받은 상품 자료로 갱신 가능한 목록을 운영한다. 현재 목록의 출처 URL·확인 날짜는 있으나 이미지·평점 등 재이용 범위는 확인 전이다. 소량 수집이나 공개 주소라는 사실만으로 이용 권리가 확인됐다고 쓰지 않는다.

비교 대안은 사용자가 현재 쓰는 무신사 등 판매 앱, Acloset/Whering 같은 옷장 앱, 일반 챗봇, 사진 나란히 보기다. 각 제품의 현재 기능에 대한 공식 근거와 동일 과제 비교표는 추가 조사 대상이다. 이 문서만으로 경쟁 앱에 특정 기능이 없다고 주장하지 않는다.

## 파일럿 제안 — 아직 실행하지 않음

5~10명 규모로 사용성 문제를 먼저 찾는다. 지인 모집 편향과 작은 표본을 기록하며 통계적 시장 검증으로 표현하지 않는다. 사용자의 사진·구매 내역을 연구자가 자동 수집하지 않는다. 참가자가 동의한 범위의 행동 관찰과 응답만 남긴다.

과제는 자신의 옷 3벌을 등록하고, 실제 고민 중인 구매 후보를 기존 방법과 앱으로 각각 판단하는 것이다. 순서는 참가자 간 번갈아 배정한다. 앱에 후보가 없는 경우 실패를 감추지 않고 별도로 기록한다. 3벌은 파일럿의 관찰 과제이며 제품의 최소 등록 조건이 아니다. 제품은 1벌로 시작한다.

사전 제안 기준:

- 70% 이상이 도움 없이 3분 안에 3벌 등록→추천 1개 확인.
- 60% 이상이 어떤 자기 옷 때문에 추천됐는지, 종류 규칙의 한계를 포함해 설명.
- 50% 이상이 실제 구매 고민에서 판단이 바뀌거나 확신이 생겼다고 응답. 거래 발생으로 대체하지 않는다.
- 데이터 유실·예시/개인 자료 혼동 0건, 사진/핏을 자동 인식했다는 오해 0명.
- 50% 이상이 등록 전에 포기하거나 과반이 일반 인기 목록과 차이를 느끼지 못하면 흐름/가설 수정. 데이터 유실·혼동이 1건이면 기능 사용을 멈추고 원인을 고친다. 2명 이상이 핏 보장으로 이해하면 표현과 제품 범위를 다시 설계한다. 1명이라도 오해하면 성공 기준 미달이며 수정 후 재검증한다.

입력 목표는 첫 방문 예시 추천 0입력, 사진 없는 한 벌 3탭·15초 이하, 사진 포함 5탭·30초 이하, 첫 개인 추천 60초 이하다. 권한 대화창 시간은 별도로 남긴다. 이는 Claude와 검토한 설계 목표이며 실측치가 아니다. 실제 iOS Safari와 Android Chrome에서 각각 3회 중앙값과 실패 사례를 기록해야 한다.

결과 기록에는 날짜·버전 SHA·기기/브라우저·조건·도움 여부·시간·탭 수·완료/실패·오해·예시 혼동·구매 판단 응답·원자료 보관 동의를 포함한다. 인터뷰·합성 데이터·자동 테스트 결과를 실제 참가자 결과 칸에 넣지 않는다. 초기 기준을 바꿀 때는 관찰 뒤 소급 적용하지 않고 새 실험 버전을 만든다.

## 남은 증거와 순서

1. 새 앱에서 구매 선택을 실제 옷 및 착용·반품 기록과 연결한다.
2. 실제 휴대폰의 등록·수정·삭제·재시작·백업·복원과 위 입력 목표를 검증한다.
3. 전용 서비스 origin/기존 동일 origin 코드, 상품 이용 권리·공급·제휴 가능성을 확인한다.
4. 경쟁 대안의 공식 기능을 확인하고 같은 과제로 파일럿을 준비한다.
5. 사용자의 동의 범위 안에서 파일럿을 수행한 뒤 준비도와 가설의 검증 상태를 각각 갱신한다.

이 항목들이 남아 있으므로 플랫폼 출시 완료 또는 두 평가가 100점에 가깝다고 보고하지 않는다. 3D·가상 착용의 자연스러움, 기존 사진 옷장 통합, 운영·개발 인수인계 요구도 완료로 바꾸지 않는다.
