- 대표 결정(2026-10-17)에 따른 다음 실행 단위다.

- 아직 하지 않는 것: 결제, 외부 사진 전송, 모델 교체 구현. 측정 이벤트도 인터뷰 뒤 필요한 항목만 구현한다.

  - 같은 사람에게 둘 다 할 때는 인터뷰를 먼저 한다.

## 1. 모집 글

### 1-1. 지인·메신저용

> 혹시 최근 한두 달 사이에 온라인으로 옷 사신 적 있으세요? 옷 살 때 어떻게 고르시는지 30분 정도 이야기를 듣고 싶어요. 제가 옷 고르는 걸 돕는 서비스를 준비하고 있는데, 뭘 만들지 정하기 전에 실제로 어떻게 사시는지부터 들어 보려고요. 뭘 팔거나 가입을 권하는 자리는 아니고, 사진이나 구매 내역도 받지 않아요. 편한 시간 알려 주시면 맞출게요.

### 1-2. 커뮤니티 게시용 (모집 글을 허용하는 게시판에만, 직접 작성해 1회 게시)

> **[인터뷰 참여자 모집] 최근 온라인으로 옷을 사 보신 분 (30분, 비대면 가능)**
>
> 옷 구매 고민을 돕는 서비스를 준비하는 개인 개발자입니다. 만들기 전에 실제로 어떻게 옷을 고르고 사시는지 듣고 싶어 인터뷰 참여자를 찾습니다.
>
> - 대상: 최근 2개월 안에 온라인으로 옷을 산 적이 있는 분 (성별 무관)
> - 방식: 30분 대화 (영상통화·전화·대면 중 편한 방식)
> - 내용: 최근 산 옷 한 벌을 어떻게 고르셨는지, 사고 나서 어땠는지
> - 받지 않는 것: 사진, 구매 내역 캡처, 연락처 외 개인정보
> - 감사 표시: [사례 내용 — 진행자가 정해 기입. 정하지 않았으면 이 줄 삭제]
>
> 참여를 원하시면 댓글이나 쪽지로 "최근에 산 옷 종류"만 짧게 남겨 주세요. 메모는 분석 뒤 삭제하고, 원하시면 언제든 지워 드립니다.

### 1-3. 모집 기준과 기록

- 필수: 최근 2개월 안에 온라인 옷 구매 1회 이상.
- 섞을 것:
  - 옷이 많은 편이라고 스스로 말하는 사람 6명 이상
  - 산 옷을 반품했거나 거의 안 입은 경험이 있는 사람 3명 이상
- 지인 비율과 모집 경로를 사람마다 기록한다. 지인은 반응이 좋게 나오기 쉽다.
- 사례 비용을 쓴다면 초기 30만원 예산의 "기타·예비비"에서 쓰고 금액을 기록한다. 지금 배분표에는 사례 항목이 없다.

## 2. 인터뷰 질문지 (최근 실제 구매 사례 중심, 30분)

### 원칙

- 앱을 보여 주지 않는다. 서비스 아이디어도 설명하지 않는다.
- "앞으로 ~하겠어요?"보다 "지난번에 실제로 어떻게 했어요?"를 묻는다.
- 가격·기능 선호를 묻지 않는다. 결제 의사는 실제로 돈을 쓴 경험으로만 본다.
- 사진·화면 캡처를 받지 않는다. 참가자가 보여 주려 하면 말로 설명해 달라고 한다.

### 시작 안내 (읽어 주기)

> 오늘은 ○○님이 최근에 옷을 어떻게 사셨는지 듣는 자리예요. 정답은 없고, 기억나는 만큼만 말씀해 주시면 돼요. 저는 메모만 하고 녹음은 하지 않아요. 원하시면 언제든 그만두셔도 되고, 메모도 지워 드려요.

녹음이 꼭 필요하면 이 자리에서 따로 동의를 받고, 거절하면 메모만 한다.

### A. 최근 구매 한 건 (15분)

1. 최근 온라인으로 산 옷 하나를 떠올려 주세요. 무엇이었나요? 언제 샀나요?
2. 그 옷을 사야겠다고 처음 생각한 건 언제, 어떤 계기였나요?
3. 사기 전에 무엇을 확인하셨나요? (가진 옷과 어울리는지, 비슷한 옷이 있는지, 가격, 후기, 사이즈 등)
   - 각각 어디서, 어떻게 확인했나요? (머릿속으로, 옷장을 직접 열어 봄, 사진첩, 다른 앱, 지인에게 물어봄)
4. 사기까지 망설인 시간은 얼마나 됐나요? 망설인 이유는 무엇이었나요?
5. 결국 사기로 한 결정적인 이유는 무엇이었나요?
6. 받고 나서 어땠나요? 지금까지 몇 번 입었나요?
7. 그 구매에 만족하나요, 후회하나요, 아직 모르겠나요? 이유는 무엇인가요?

### B. 실패·보류 사례 (7분)

8. 사고 나서 후회했거나 반품한 옷이 최근 1년 안에 있었나요? 그때 무엇을 미리 알았다면 안 샀을까요?
9. 반대로 사려다 그만둔 옷이 있나요? 무엇 때문에 그만뒀나요?
10. 집에 비슷한 옷이 있는 줄 모르고 또 산 적이 있나요? 몇 번 정도인가요?

### C. 지금 쓰는 방법과 쓴 돈 (5분)

11. 옷 고를 때 지금 쓰는 앱이나 방법이 있나요? (쇼핑 앱 장바구니, 사진첩 폴더, 옷장 앱, 메모 등)
    - 얼마나 자주 쓰나요? 마지막으로 쓴 건 언제인가요?
12. 옷장 앱을 써 본 적이 있다면, 왜 계속 쓰거나 그만뒀나요?
13. 옷 고르기나 코디와 관련해 돈을 낸 적이 있나요? (유료 앱, 스타일링 서비스, 수선, 렌탈 등) 무엇에 얼마를 냈나요?

### D. 마무리 (3분)

14. 오늘 이야기한 것 중 가장 번거로웠던 순간 하나만 고른다면 무엇인가요?
15. 나중에 만든 것을 직접 써 보는 시험에 참여하실 의향이 있나요? (예 / 아니오) — "예"면 연락 방법만 받는다.

### 기록표

| 참가자 | 모집 경로 | 지인 여부 | 최근 구매 품목 | 사기 전 확인한 것 (확인 방법) | 망설인 시간 | 결과 (만족/후회/모름) | 후회·반품 이유 | 중복 구매 경험 | 지금 쓰는 방법 | 관련해 낸 돈 (무엇·얼마) | 가장 번거로운 순간 | 시험 참여 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| I1 | | | | | | | | | | | | |

### 10명 뒤 보는 것 (해석 기준)

- **"가진 옷과 맞는지"를 사기 전에 실제로 확인한 사람이 몇 명인가.**
  - 확인하려 했지만 불편해서 못 한 사람과, 처음부터 신경 쓰지 않은 사람을 나눠 센다.
- 후회·반품 사례의 원인이 "가진 옷과 안 맞음·이미 비슷한 옷 있음"인 건이 몇 건인가.
  - 사이즈·품질·배송 문제와 구분한다. 사이즈·품질은 살까 말까가 해결하지 못한다.
- 관련해 실제로 돈을 낸 경험이 있는 사람이 몇 명이고, 무엇에 냈는가.
- 이 숫자들은 다음 단계를 정하는 근거다. 통과 기준은 이 문서에서 미리 정하지 않는다. 인터뷰 결과를 보기 전에 대표가 `focus-plan-20261014.md` 방식으로 따로 고정한다.

## 3. 측정 이벤트 명세 (초안, 구현 전)

### 원칙

- 인터뷰 뒤 필요한 항목만 구현한다. 이 초안 전체를 구현 목표로 보지 않는다.
- 사진, 상품 이미지, 옷 이름 원문은 이벤트에 담지 않는다. 종류·색 같은 분류값과 개수만 담는다.
- 기록 위치는 구현할 때 정한다.
  - 파일럿 기본안: 기기 안에 기록하고, 참가자가 동의할 때만 내보낸다.
  - 계정 동기화는 아직 미병합이라 서버 수집을 전제로 하지 않는다.
- **미응답은 미응답으로 집계한다.** 어떤 질문이든 무응답을 긍정이나 "후회 없음"으로 바꾸지 않는다.
- 모든 이벤트의 공통 필드: `event`, `at`(시각), `appVersion`(SHA), `pilotId`(참가자 임의 번호), `sessionId`.

### 3-1. 옷장 등록

| 이벤트 | 시점 | 필드 |
|---|---|---|
| `closet_add_start` | 등록 시작 | `method`: photo / photo_multi / link / manual / essentials |
| `closet_add_save` | 한 벌 저장 | `method`, `durationMs`(시작부터 저장까지), `fieldsEdited`(자동값을 사용자가 고친 항목 수), `autoKind`, `finalKind`, `autoColor`, `finalColor` |
| `closet_add_abandon` | 저장 없이 닫음 | `method`, `durationMs`, `step`(닫힌 단계) |

이 표로 수동 등록 대 자동 등록의 등록 시간, 수정 횟수, 실패율(포기)을 비교한다. 자동 등록 시험의 통과 기준이 이 비교다.

### 3-2. 살까 말까 판단

| 이벤트 | 시점 | 필드 |
|---|---|---|
| `judge_start` | 후보 입력 시작 | `source`: link / photo / share / manual |
| `judge_result` | 판정 화면 표시 | `judgeId`, `matchCount`(가진 옷과 맞는 수), `similarOwned`(비슷한 옷 수), `looksShown` |
| `judge_decision` | 판정 직후 질문 | `judgeId`, `decision`: buy / skip / hold / no_answer |
| `judge_helpful` | 같은 화면 둘째 질문 | `judgeId`, `helpful`: yes / somewhat / no / no_answer |
| `judge_hold_reason` | `hold`일 때만, 선택 | `judgeId`, `need`: size / price_wait / see_in_person / ask_someone / other / no_answer |

- 판정 직후 질문 문구:
  - "어떻게 하기로 했어요?" (산다 / 안 산다 / 보류)
  - "이 결과가 결정에 도움이 됐나요?" (도움 됐어요 / 조금 / 아니요)
  - 보류일 때 선택 질문: "무엇을 더 알면 정할 수 있을까요?"
- 보류는 실패로 세지 않는다. 필요한 정보를 알게 됐다면 유용한 결과로 본다. 이를 위해 `helpful`과 `need`를 함께 본다.

### 3-3. 7일 뒤 확인

| 이벤트 | 시점 | 필드 |
|---|---|---|
| `followup_shown` | 판정 7일 뒤 앱을 처음 열 때 1회 | `judgeId`, `daysSince` |
| `followup_answer` | 응답 | `judgeId`, `actual`: bought / not_bought / still_deciding, `feeling`: satisfied / regret / too_early / no_answer |

- `too_early`("아직 판단하기 어려워요": 배송 전, 아직 안 입어 봄)를 보기로 둔다.
- 7일 안에 앱을 열지 않아 `followup_shown`이 없으면 "확인 못 함"으로 따로 센다.
- 후회율 = `regret` ÷ (`satisfied` + `regret`)로 계산한다. `too_early`·`no_answer`·확인 못 함은 분모에서 빼고, 그 수를 함께 적는다.

### 3-4. 30일 재사용

| 이벤트 | 시점 | 필드 |
|---|---|---|
| `need_check` | 첫 판정 30일 뒤 앱을 처음 열 때 1회 | `hadNewDecision`: yes / no / no_answer ("지난 한 달 동안 새로 사려고 고민한 옷이 있었나요?") |
| `need_check_where` | `yes`일 때 | `usedApp`: yes / no, `whyNot`: forgot / other_method / not_worth / other / no_answer |

- 재사용률은 `hadNewDecision = yes`인 사람만 분모로 한다. 그중 30일 안에 `judge_start`가 다시 있었던 비율을 본다.
- 살 일이 없어 돌아오지 않은 사람(`no`)은 이탈로 세지 않는다. 고민이 있었는데 쓰지 않은 사람(`yes` + `usedApp = no`)은 별도로 세고 이유를 본다.
- 30일 안에 앱을 열지 않은 사람은 질문을 받을 수 없다. 이 사람들은 "확인 못 함"으로 두고, 파일럿에서는 진행자가 메신저로 같은 질문을 한 번 묻는다.

### 3-5. 제휴 (승인된 프로그램이 생긴 뒤에만)

| 이벤트 | 시점 | 필드 |
|---|---|---|
| `offer_shown` | 판정 화면에 구매처 표시 | `judgeId`, `offerCount`, `affiliate`: true / false |
| `offer_click` | 구매처 눌러 이동 | `judgeId`, `affiliate`, `program` |

- 구매, 취소, 확정 수수료는 앱에서 알 수 없다. 제휴 프로그램의 보고서로만 집계하고, 취소·반품 기간이 지난 확정 금액만 수익으로 센다.
- 제휴 링크에는 광고 표시가 필요하다. 문구는 공정위 기준을 확인한 뒤 정한다.
- 제휴 수익 가능성과 사용자가 직접 결제할 의사는 따로 검증한다. 클릭이 많다고 결제 의사가 있다고 보지 않는다.

### 3-6. 직접 결제 의사 (나중 단계, 지금 구현하지 않음)

- 기본 무료 원칙을 유지한다.
- 유료 후보는 인터뷰와 사용 결과에서 "무료 판단과 무엇이 다른 추가 가치인지" 한 문장으로 설명할 수 있을 때만 만든다.
- "판단 무제한 3,900원" 같은 안은 실험 후보 예시일 뿐이다. 가격과 한도는 정하지 않았다.
- 실제 결제로 확인한다. 결제 절차(증빙, 환불)가 갖춰지기 전에는 판매하지 않는다.

## 4. 자동 옷장 등록 재시험 메모 (구현 아님)

- 후보 조합(Grounding DINO + SAM 2 + CLIP)은 시험 후보다. 연결한다고 옷 한 벌이 정확히 분리되거나 종류·색이 확정되는 것은 아니다.
- 통과 기준은 3-1의 비교다. 기존 수동 등록보다 등록 시간, 수정 횟수, 실패율이 실제로 줄어야 한다.
- 라이선스는 코드, 가중치, 학습 데이터, 추가 의존성을 각각 기록한다. 하나라도 불명확하면 "상업 이용 가능"으로 확정하지 않는다.
- 2026-10-17 시험(공개 예제 6장)에 쓴 fashn-human-parser는 SegFormer 비상업 라이선스를 상속한다. 이 결과는 가능성 확인용이다.
