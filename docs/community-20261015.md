# 회원 코디 (커뮤니티) — 2026-10-15

원스톱 계약의 "탐색" 구간(취향과 옷장에 맞는 상품·사용자 코디 탐색)과 이후 작업 3번("옷·상품 ID와 연결되는 코디 탐색·커뮤니티를 만들고 사진 공개 동의/신고/운영을 연결한다. 초기 읽기 전용 큐레이션과 실제 사용자 게시를 구분한다")의 첫 구현이다.

## 사용자 제약과의 관계

- 사용자 결정은 "사진은 내 PC·로컬·내 클라우드에서만"이다. 그래서 이 기능은 **운영자 본인 서버 안에서만** 돈다. 외부 SNS 공유, 검색 노출, 외부 저장소는 없다.
- 사진은 기본으로 보내지 않는다. 회원이 글마다 옷 사진을 직접 고르고, 그 글의 공개에 동의해야만 같은 서버 회원에게 보인다.
- 서버는 기본 꺼짐이다(`EOUL_COMMUNITY=on`일 때만 켜짐). 공개 커뮤니티를 운영하려면 규칙, 신고 연락처, 처리 기간 같은 운영자 정보가 필요하기 때문이다.

## 흐름

1. 내 옷장 → "가진 옷만으로 만든 코디" → 코디 상세 → **"이 코디를 회원들과 나누기"**
2. 미리보기 화면에서 다음을 보여 준다.
   - 회원에게 보이는 내용
   - "보내지 않는 것: 구매 링크, 메모, 옷장 기록, 고르지 않은 사진"
   - 한마디 입력
   - 옷 사진 고르기(선택, 사진이 있는 옷만)
   - 사진을 하나라도 고르면 동의 체크가 나오고, 동의 전에는 올리기 버튼이 꺼져 있다.
3. 처음이면 규칙과 이름(이메일은 보이지 않음)을 먼저 받는다. 그 뒤 **같은 공유 화면으로 돌아오고**, 쓰던 한마디도 남아 있다.
4. 홈 "회원 코디"에서는 다음을 할 수 있다.
   - 전체 글과 내 글 보기
   - 사진은 "사진 n장 보기"를 눌렀을 때만 받기(데이터 절약)
   - 목록에 있는 상품은 "…보기"로 상품 상세를 열고, 거기서 **내 옷과 비교 → 구매 여정**으로 이어 가기
5. 신고와 삭제
   - 신고는 사유 5가지 중 하나를 고른다. 신고하면 신고한 회원에게는 바로 사라진다.
   - 서로 다른 회원 3명이 신고하면 운영자가 확인할 때까지 모두에게 숨겨진다.
   - 작성자는 두 번 눌러 글을 지운다. 커뮤니티를 나갈 때도 두 번 눌러야 하며, 나가면 내 글과 사진이 모두 지워진다.

## 데이터와 검증

- 저장 상한(디스크를 한 회원이 채우지 못하게 함)
  - 회원 한 명: 글 300개, 사진 120장, 사진 40MB.
  - 서버 전체: 회원 코디 사진 2GB(`EOUL_COMMUNITY_MAX_MB`로 조정).
  - 상한에 닿으면 사진 없는 글은 계속 올릴 수 있고, 예전 글을 지우면 공간이 생긴다.
- 운영자가 기능을 끈 뒤에도 회원은 다음을 할 수 있다.
  - 남긴 글 수를 프로필에서 본다.
  - 글 하나 또는 전부(나가기)를 지운다.
- 기능을 끄면 읽기와 올리기는 멈춘다.

- 앱과 서버는 같은 검증 함수(`app/src/community-post.js`의 `validateCommunityLook`)를 쓴다.
  - 키가 정확히 맞아야 하므로 옷 ID 같은 추가 키는 거절한다.
  - 종류와 세부 종류는 서로 맞아야 한다.
  - 색은 정해진 목록에서만 받는다.
  - 브랜드 칸에 링크나 주소가 들어가면 거절한다.
  - 상품 번호는 `ms-숫자` 형식만 받는다.
  - 사진 번호는 올린 사진과 하나씩 짝이 맞아야 한다.
- 이름 규칙
  - 2~20자이고, 글자·숫자·공백·`_.-`만 쓸 수 있다.
  - 이메일이나 전화번호처럼 보이면 거절한다.
  - 대소문자와 NFKC를 맞춘 뒤 중복을 막는다.
- DB 스키마 v3: `community_members`, `posts`, `post_photos`, `post_reports`.
  - 모두 `users` 외래 키에 연결되어 있어 계정을 삭제하면 함께 지워진다(`secure_delete`).
- 목록 커서는 `<작성 ms>.<글 ID>` 형식이다. 같은 밀리초에 올라온 글도 건너뛰지 않는다(테스트로 확인).
- 로그에는 경로와 결과 코드만 남긴다. 글 내용, 이름, 이메일은 남기지 않는다(테스트와 실제 서버 로그로 확인).

## 하지 않은 것 · 남은 일

| 항목 | 상태 | 필요한 것 |
|---|---|---|
| 운영 규칙·신고 연락처·처리 기간 | 외부 연결 필요(운영자 정보) | 운영자가 정해 앱 규칙과 처리방침에 적기 |
| 공개 서비스로 열기(가입 제한 없이) | 미구현·결정 필요 | 정보통신망법상 게시판 운영 의무, 청소년 보호, 임시조치 절차 확인. 지금은 초대 코드 사용을 권장함 |
| 차단(특정 회원 숨기기), 댓글, 좋아요, 팔로우 | 미구현 | 첫 실사용 피드백 뒤 결정 |
| 편집 큐레이션과의 통합 피드 | 미구현 | 지금은 "편집자 코디 공식"과 "회원 코디"를 분리해 표시함 |
| 사진 자동 검사(얼굴·개인정보) | 미구현 | 외부 API는 사용자 제약상 쓰지 않음. 로컬 모델 검토 필요 |
| 이미지 메타데이터(EXIF) 제거 | 구현됨 | 앱이 올리기 전에, 서버가 저장하기 전에 한 번씩 EXIF·XMP·IPTC·주석·제조사 구간을 지움(`app/src/jpeg-clean.js`). 그림 데이터는 그대로 둠. 읽을 수 없는 파일은 그대로 올리지 않고 거절함. EXIF 회전 정보도 함께 지워지므로, 이전 버전 사진 중 회전 정보에 의존하던 사진은 돌아가 보일 수 있음(이 앱에서 등록한 사진은 이미 회전을 반영해 다시 인코딩됨) |
| 실사용 검증 | 실사용 미검증 | 실제 휴대폰, 여러 회원, 신고 운영을 해 보지 않았음 |
