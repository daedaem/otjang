# 옷장 판정이 화면마다 같은 말을 하게 (2026-10-18)

전문가 역할 모의 평가(`expert-eval-20261018.md`)의 2주차 후보였던 "옷장 판정이 화면마다 다름"을 고쳤다.

## 고친 것과 확인 (모바일 390×844, 기본템 셔츠·청바지·흰 스니커즈 3벌로 시작)
| 증상 | 수정 | 화면 확인 |
|---|---|---|
| 옷 상세에는 "가진 옷 기본 조합"이 있는데 옷장 탭은 "가진 옷이 조금 더 있으면…" | 옷장 탭 "오늘 뭐 입지?"도 코디 공식이 없으면 같은 기본 조합을 보여 준다 | 3벌로 시작 → 옷장 탭에 "가진 옷 기본 조합 1"이 나온다 |
| 가진 청바지를 두고 생지 데님을 사라는 코디·구매 후보 | 세부 종류만 다른 사실상 같은 옷(워시드↔생지 데님)은 가진 옷으로 채우고, 구매 후보에서 뺀다 | 검사: 워시드 데님 보유 시 코디·구매 후보에 데님 구매가 없다(수정 전 코드에서는 실패) |
| 옷장에 넣은 옷과 같은 종류·색 상품을 봐도 보유 표시가 없음 | 상품 카드: 같은 상품이거나 같은 종류·색이면 "옷장에 같은 종류·색 ○○ N벌". 상세: 색이 다르거나 미확인이어도 한 줄로 알림. 비교 판정과 같은 계산(`quickCompare`)을 쓴다 | 청바지 보유 후 생지 데님 상세 "옷장에 청바지 1벌 · 색은 달라요" = 비교 판정 "청바지는 이미 1벌 있어요 · 색은 달라요" |
| 산 옷을 "계속 입을게요"로 옷장에 넣으면 자기 자신과 비교해 "같은 상품이 이미 있어요" | 받음·보유 단계에서는 연결된 옷(자기 자신)을 비교에서 뺀다. 제목은 "계속 입는 내 옷이에요"/"받은 옷이에요". 받은 뒤에는 총액 비교 버튼을 숨긴다 | 사기로 함 → 주문 → 받음 → 계속 입음 후 "계속 입는 내 옷이에요", "같은 상품이 이미 있어요" 없음 |
| 판정은 "이미 있어요"인데 진한 버튼은 "사기로 할게요" | 진한 버튼이 판정을 따른다: 이미 있음 → 보류, 새 코디가 생김 → 사기, 근거 부족 → 셋 다 같은 무게. "사기로 함" 뒤 판매처 링크는 하단에 한 번만 | 색만 다른 청바지 판정에서 세 버튼 모두 같은 무게 |

## 남은 한계
- "사실상 같은 옷" 묶음은 지금 데님(워시드·생지) 하나다. 다른 종류는 패션 판단이 필요해 넣지 않았다.
- 상품 카드에는 같은 종류·**같은 색**일 때만 보유 표시를 단다(색이 다르면 상세에서만 알림).
- 등록 경로마다 종류 목록이 다른 문제, 코디 설명문이 실제 구성과 다른 문제는 이번 범위가 아니다.
