# 원스톱 전체 목표를 유지한 후속 구현 — 2026-10-19

> **당시 구현 증거 보존:** 아래는 2026-10-19의 구현·검증 기록이다. 이후 비공개 Cloudflare 운영과 공식 공급원 연결이 추가됐다. 전체 목표와 미확보 완료 기준은 [현재 사업 계획](business-plan.md)·[개발 계획](development-plan.md), 최신 실행 증거는 [시스템 인수인계](system-handover.md)에서 확인한다. 당시 “개인 Mac 임시 서버”, 공급 미연결·대기 상태를 현재 상태로 재사용하지 않는다.

## 판단 기준

사용자는 개인 테스트판 배포가 아니라 전체 원스톱 목표 달성을 요청했다. Claude가 우선순위를 판단하고 Codex가 구현·검증한다. 기준은 `onestop-product-contract-20261014.md`와 이후의 ‘옷장 없이도 시작’ 정정이다. 첫 번째 Claude 판단 `35bd882`의 ‘사진 식별·가격 비교·확인된 주문·VTON을 범위 밖으로 확정’은 기존 계약과 모순되어 재검토를 요청했고, Claude가 `74441c4`에서 철회했다. 보류나 외부 의존성은 목표 삭제나 완료의 근거가 아니다. 자체 결제는 장기 확장으로 유지한다.

## 이번 구현과 이유

- 홈은 한 줄 요청을 먼저 보여 주고, 선택 옷장 입력과 아래 추천·코디·구매 후보를 기본적으로 접는다. 기존 기능·원문·설정·저장 형식은 유지하며 필요한 사람만 펼친다. 모바일 첫 방문에 검색을 찾기 위해 여러 화면을 내리지 않게 하려는 변경이다.
- 같은 브랜드·종류의 다른 상품을 반품한 기록을 비교 화면에 보여 준다. 반품 이벤트 당시의 상품·옵션·핏·사유만 사용한다. 이후 상품 수정이나 피드백 변경으로 과거 사실을 다시 쓰지 않는다. 동일 상품 경고와 구분하고, 브랜드 또는 종류가 미확인이면 연결하지 않는다. 이번 상품의 사이즈를 예측하거나 추천 점수를 낮추는 기능이 아니다.
- 옷장이 없는 경우와 실제 옷 3벌인 경우를 각각 요청→정확한 후보 ID→비교→구매 결정→직접 주문 기록→받음→보유 확정→착용→반품→다시 실행으로 검사한다. 수령만으로 보유로 세지 않고, 반품 뒤에는 추천 보유 목록에서 제외하되 원문과 기존 옷을 유지한다. 이 검사는 실제 거래나 배송·반품 API를 검증하지 않는다.
- 회귀 문장 50개는 요구사항 예시 2개와 AI가 작성한 사례 48개다. 수집한 실제 사용자 타이핑 문장은 0개이며, 50개 통과를 일반적인 자연어 정확도나 실제 사용자 통과율로 보고하지 않는다. 지원하지 않는 조건과 없는 상품도 확인한다. 뜻을 해석하지 못한 요청은 엔진에서도 빈 결과로 유지한다. 후드 요청에 여성용 일반 맨투맨이 섞이지 않도록 상품명 근거로 제한하고 상세 대안에도 유지한다.
- 종료된 네이버 쇼핑 검색 공급원은 키 유무와 관계없이 `discontinued`다. 네트워크 호출을 하지 않고 종료일·공식 공지를 표시한다. 저장된 과거 판매처 가격은 삭제하지 않는다. 예전 모의 정상 응답 검사는 실제 호출 불가 상태의 근거가 될 수 없어, 키가 있어도 호출 0회인 검사로 교체했다.

## 외부 공급 확인 근거

네이버의 [공식 종료 공지](https://developers.naver.com/notice/article/32564)는 쇼핑·책·전문자료 API의 종료일을 2026-07-31로 명시한다. [현행 약관](https://developers.naver.com/products/terms/) 부칙 제2조 제3항도 기존 이용자를 포함한 종료를 명시한다. 과거 레퍼런스 문서가 남아 있다는 이유로 새 키 발급·API Hub 이전으로 쇼핑 검색을 사용할 수 있다고 안내하지 않는다.

## Claude 코드 재검토 반영

Claude가 `8f00c12`를 받아 680개 검사와 홈·미이해·후드 화면을 확인하고 채택했다. 주소가 모두 비어 있을 때 동일 상품으로 오인하는 비교를 지적해, 실제 URL이 있을 때만 동일 주소로 판단하도록 고쳤다. 건강 상태 응답에도 종료일·안내·공식 공지 주소를 전달해 실제 가격 출처 화면에서 보이도록 보완했다.

공개 빌드에서 사진만 빼고 상품 글자를 남기자는 제안은 근거가 부족해 재검토를 요청했고 Claude도 철회했다. 카탈로그 단위 `rights: unverified`, `rightsEvidence: null`을 생성 도구와 생성 자료에 반영했다. 상품 891개와 가격·이미지·분류는 바꾸지 않았다. `EOUL_PUBLIC_BUILD=1`은 공개 사용 승인 상태(`verified-public`)와 근거가 없으면 출력 파일을 만들거나 덮어쓰기 전에 실패한다. 기본 개인 시험 빌드는 유지한다. 이 장치는 권리 미확인 자료의 공개 빌드 혼입을 막을 뿐, 공개 서비스 적합성을 판정하거나 실제 권한을 부여하지 않는다. 승인 자료 공급·교체는 남아 있다.
