# 비공개 AI 403 진단 및 수정 — 2026-10-22

## 요청과 범위

대표 요청: “AI 403 오류도 해결해서 실제로 추천받을 수 있게 마무리”. 최신 master `5251d4e`(Claude PR #45 포함)에서 작업했다. 키 교체·모델 변경·한도 확대·자동 재시도·인증 해제 없이 진단했다. 공개 출시나 사진 전송을 승인받은 것으로 해석하지 않는다.

## 확인한 사실

- 기본 배치에서 같은 공개 후보 비교 요청이 HTTP 403으로 실패했다. SDK 오류의 허용된 필드만 추려 보니 `type=forbidden`, JSON 응답, 제공자 `cf-ray`의 지역 접미사 `HKG`였다. `permission_error`나 401이 아니며 요청 ID도 없었다.
- Cloudflare 공식 배치 기능 `placement.region=aws:ap-northeast-2`를 지정해 서울 인근에서 실행하도록 변경했다. 실제 버전 메타데이터에서도 `placement_mode=targeted`, 해당 region을 확인했다.
- 진단 버전 `e5d91ef3-63b4-47d4-a42f-cf076b98a19b`에서 403을 재현했다. 서울 배치 버전 `c3d760c6-c624-40ad-a5ab-9952017dc8bf`에서 동일 공개 후보 비교 2회, 상담 1회, 이어 묻기 1회가 연속 성공했다.
- 공개 후보 비교: “유니클로 티셔츠”, 실제 모델 `claude-haiku-5-5`, 입력/출력 토큰 598/469 및 598/585. 서로 다른 실제 응답 ID를 확인했다.
- 상담: “출근용 셔츠 10만원 이하로 추천해줘”, 실제 모델 `claude-haiku-5-5`, 입력/출력 2425/872. 무신사 스탠다드·토마스모어의 실제 카탈로그 상품 카드가 표시됐다. 이어 “그중 하나만 골라줘. 5만원 이하로.”에 무신사 스탠다드 릴렉스 핏 옥스포드 셔츠 [블루], 수집가 33,890원 카드와 답변을 확인했다.
- 성공은 브라우저 화면의 실제 SDK 응답 메타데이터와 Anthropic Console 최신 성공 로그의 모델·토큰·요청 ID를 서로 대조했다. 4건 모두 성공 로그가 있고, 이어 묻기는 입력/출력 2705/887이었다. 정해 둔 문구나 가짜 응답으로 대체하지 않았다. 전체 응답·요청 ID는 공개 Git 문서에 넣지 않는다.

## 판단과 한계

HKG 경로의 거절 후 배치만 바꿔 반복 성공했으므로, 기본 실행/연결 경로가 이번 403의 원인이라는 가설을 지지한다. HKG 접미사는 제공자 응답 경로의 관찰값이다. 제공자 내부 차단 규칙이나 IP 지리 판정까지 확인한 것은 아니므로 “홍콩 IP 차단 확정”이나 “키 권한 문제 확정”이라고 쓰지 않는다. 배치 힌트는 물리 위치를 영구 보장하는 데이터 주권 기능도 아니다.

4건의 연속 성공은 현재 기능 검증이며 장기 가용성·실제 iPhone 검증은 아니다. 최초 상담 문장에는 50,960원을 10만원 예산보다 넘는 것처럼 설명한 오류가 있었다. 연결 성공과 추천 내용의 정확성을 구분해야 하며, 가격 조건 설명의 서버 검증은 별도 개선 과제다. 후속 5만원 질문의 33,890원 선택은 조건에 맞았다. 현재가·재고·핏은 보장하지 않는다.

## 운영 보존 및 재현

- 공식 Anthropic API와 기존 Secret 사용을 유지한다. 키 값을 읽거나 로그·Git·브라우저 코드에 넣지 않았다.
- `maxRetries=0`, 15초 SDK 제한, 기존 공유 D1 예산(일 100/월 300/분 5)을 유지한다. 실패 요청도 사용 예약에 포함된다.
- 실패 로그는 status, 허용된 오류 type, json/html 분류, 검증한 요청 ID, 검증한 3글자 지역 코드만 기록한다. 원문 오류·헤더 전체·질문·옷장·IP·키는 기록하지 않는다.
- 사용자의 원래 옷장·구매 기록·백업 형식·개인 사진은 수정하지 않는다. Claude #45의 상담 후보/이력/550자 처리도 유지한다.
- 403 안내를 “API 사용 권한을 확인”으로 단정하지 않도록 수정하고 상담에도 제공자 오류 안내를 추가한다.
- 재발 시 먼저 이 제한된 로그와 배포 version/placement를 대조한다. 무제한 재시도나 다른 프록시로 우회하지 않는다. 필요하면 허용된 요청 ID로 제공자에게 원인 확인을 요청한다(외부 문의 발송은 별도 사용자 지시).

## 자동 빌드 설정 정정

PR #47의 Cloudflare 기능 브랜치 빌드가 `/opt/buildhome/repo/package.json` 없음(ENOENT)으로 실패했다. 프로덕션 설정의 루트는 이미 `app/lite`였지만 프리뷰 기본 루트는 `/`였다. Cloudflare 설정에서 프리뷰 기본 루트를 `app/lite`, 명령을 `npx wrangler deploy --dry-run`으로 저장했다. 새 프리뷰 배포나 별도 접근 주소를 만들지 않고 빌드 검증만 하려는 설정이다. 프로덕션 `master`/`app/lite`/`npx wrangler deploy`와 프리뷰 URL 비활성화는 유지했다.
