# 첫 검증과 개인화 판단 기준

- 상태: PRD 보완 제안. 제품 구현·실제 상품 추천·사용자 검증은 아직 수행하지 않았다.
- 기준: [PRD v0.4](PRD-v0.4.md) FR-01~FR-18
- 첫 검증 스타일은 사용자 선택에 따라 아메리칸 클래식으로 정했다. 용도·예산·구체적 보유 상품은 아직 미확인이다. 상세 개인 취향은 로컬 사례 기록에 두며, 스타일 선택이 제품 전체의 장르 제한을 뜻하지 않는다.

## 1. 첫 검증은 사진 옷장 생성과 실제 고민의 비교 결과다

첫 진입은 [사진 온보딩](photo-onboarding.md)이다. 옷장·개별 옷 사진에서 초안을 만들고, 사용자가 일부를 확인해 첫 옷장으로 확정한다. 그 옷장으로 ‘어떤 상품을 사면 좋을까’를 검토한다. 사용자가 상품과 후기를 모두 찾아온 상태를 전제로 하지 않는다.

| 단계 | 최소 입력 | 결과 |
| --- | --- | --- |
| 사진 옷장 생성 | 옷장 전경 또는 개별 옷 사진, 간단한 검토 | 자동 초안, 확인한 보유 옷, 미확인 속성·등록 범위 |
| 맥락 정리 | 원하는 느낌, 주 사용 상황, 예산 또는 예산 미정 | 확인된 조건·선호·미확인 항목 |
| 옷장 확인 | 관련된 보유 옷, 등록 범위와 속성 확인 상태 | 이미 해결되는 것과 판단하기 어려운 부분 |
| 보완할 역할 | 위 맥락과 옷장 | 새 구매 없는 대안, 먼저 보완할 역할과 이유 |
| 상품 조사 | 역할과 확인된 조건 | 실제 후보 최대 3개, 모델·옵션·판매처·확인일 |
| 개인화 비교 | 확인된 상품 정보·관련 후기·보유 옷 | 후보별 추천/보류 이유, 활용 코디, 중복, 미확인 |
| 결정 지원 | 비교 결과 | 구매처 이동/보류/조건 수정, 저장 가능한 결과 |

‘최대 3개’는 결과를 억지로 채우라는 뜻이 아니다. 한 후보만 확인됐으면 1개와 조사 범위를, 하나도 없으면 자료 부족이나 필수 조건 불충족을 보여 준다. 대안 비교에 충분한 자료가 없으면 그 한계를 남긴다.

S0에서는 사진 자동 초안의 로컬 기술 검증과 실제 고민의 비교를 병행한다. 상품·후기 자료에는 수동 큐레이션이 가능하지만 사진 자동 생성은 별도 검증이 필요하다. 수동 옷 목록으로 비교 흐름을 준비해도 사진 기능 완료로 세지 않는다. 초안 검토·부분 확정·후속 추가와 비교 결과를 저장·수정·재방문하는 제품은 S1, 일상 코디와 전체 개인판 기능은 S2다. S0만 마친 상태를 개인판 완성으로 발표하지 않는다.

### 한 사례와 한 장르를 구분한다

하나의 실제 사례는 결과를 대조하기 위한 재료다. 한 장르 전용 제품으로 범위를 확정한다는 뜻이 아니다. 공통 옷장과 개인 정보를 유지하면서 고민마다 목표 스타일·용도·예산을 바꿀 수 있게 설계한다. 스타일 이름을 모르면 원하는 인상을 문장으로 적거나 여러 선호를 함께 둘 수 있다.

실제 추천을 수행하기 전에도 합성한 두 상황(예: 출근의 단정함과 주말의 편안함)에서 같은 옷장으로 판단이 어떻게 달라져야 하는지 검토한다. 이는 제품 구조 검증이며 사용자의 실제 용도나 추천 품질 검증 결과는 아니다.

### 첫 사례에 적용할 원칙

아메리칸 클래식이라는 이름과 선호 브랜드만으로 핏·색·상품을 확정하지 않는다. 사용자 확인이 있는 구체적인 옷과 목표 상황을 근거로 역할·중복·조합을 비교한다. 브랜드의 통상 가격을 사용자의 예산으로 추정하지 않는다. 브랜드 선호를 적용한 결과와 브랜드를 제외해도 남는 활용 근거를 구분한다.

첫 사례에서는 가까운 색 조합을 무조건 감점하는 기존 규칙이 취향과 충돌할 가능성도 확인한다. 이것이 톤온톤을 선호한다고 사용자가 답했다는 뜻은 아니다.

## 2. 보여 줄 비교 결과의 필수 내용

사용자는 다음을 한 흐름에서 확인한다. 화면에 기술 필드명을 그대로 표시할 필요는 없다.

- **왜 이 역할인가**: 원하는 상황/스타일과 보유 옷을 연결한 이유. 기본템 목록만으로 결론 내리지 않는다.
- **현재 가진 옷으로 가능한 대안**: 먼저 비교할 수 있게 제시한다.
- **실제 후보와 구매처**: 상품·모델·색·사이즈 옵션의 확인 상태와 확인 시점.
- **본인에게 관련된 이유와 단점**: 사용한 조건·원문 근거·제품의 해석을 구분한다.
- **함께 입을 보유 옷**: 존재하는 아이템을 참조하고, 미확인 속성이 판단에 미치는 영향을 표시한다.
- **후기에서 확인한 것**: 관련 원문과 상반된 의견. 판매처의 설명을 사용자 경험으로 바꾸지 않는다.
- **결정 전에 더 확인할 것**: 가격/재고, 사이즈, 후기 접근 등 남은 불확실성.

후기·핏의 근거가 없는 후보를 제외해야만 한다는 의미는 아니다. 해당 후보의 판단이 어느 범위까지 가능한지 보여 주고, 필수 조건을 확인할 수 없으면 추천 확정 대신 확인 대기로 둔다.

## 3. 개인화가 작동한다는 것의 의미

### 입력을 세 상태로 구분한다

| 상태 | 예시의 성격 | 처리 |
| --- | --- | --- |
| 필수 조건 | 사용자가 정한 예산 상한, 명시적으로 제외한 소재/디테일 | 확인된 충돌은 일반 추천에서 제외. 초과 대안을 보이려면 별도 구분하고 조건 변경을 사용자 선택으로 둠 |
| 선호 | 원하는 스타일·실루엣·색, 자주 입는 옷 | 우선순위와 설명에 반영. 선호 충돌은 장단점을 보여 주며 몰래 하나를 삭제하지 않음 |
| 미확인 | 입력하지 않은 체형, 누락된 치수, 조건부 할인 여부 | 알 수 없는 것을 적합으로 채우지 않음. 관련 판단만 유보 |

‘싫다’는 일반 의견을 어디까지 강한 제외 조건으로 쓸지는 사용자가 수정할 수 있게 한다. 금지 조건과 선호를 구현이 임의로 섞지 않는다.

### 순서를 정하는 기준 — 제안

1. 필수 조건의 충족·불충족·미확인을 판별한다.
2. 목표 상황과 원하는 스타일을 해결하는 후보인지 설명한다.
3. 가진 옷만으로 해결되는지, 새 후보가 더하는 역할이 무엇인지 비교한다.
4. 활용 가능한 보유 옷과 사용자 선호를 바탕으로 비교 우선순위를 제안한다.
5. 관련 후기와 실측으로 주장 범위를 보완하거나 판단을 유보한다.

일괄 점수의 가중치는 아직 정하지 않는다. 우선 사람이 같은 근거로 설명할 수 있는 기준선을 만들고, 조건을 바꾼 사례에서 결과가 일관적인지 확인한다. 상품 조건과 개인화 근거가 같은 경우의 정렬도 재현 가능하게 한다.

### 조건을 바꿔 확인할 사례

아래는 검증 설계용 합성 사례다. 사용자의 실제 취향·체형·상품 추천이 아니다.

| 사례 | 기대 동작 |
| --- | --- |
| 같은 후보 자료에서 예산 상한만 낮춤 | 초과 후보의 상태가 바뀜. 가격 미확인은 예산 충족으로 처리하지 않음. 가격과 무관한 후기 사실은 바뀌지 않음 |
| 강한 색 대비 선호를 톤온톤 선호로 바꿈 | 관련 색 조합 판단과 이유를 재평가. 같은 결과면 이유를 설명. 가까운 색이라는 이유만으로 고정 탈락하지 않음 |
| 비슷한 역할의 보유 옷을 추가함 | 새 구매의 필요성과 중복 설명을 재평가. 조합 수 증가만으로 계속 구매를 권하지 않음 |
| 얼굴·체형 정보를 모두 비움 | 해당 개인 특성을 분석했다는 문장이 나오지 않음. 옷장·예산·스타일 판단은 계속 가능 |
| 사이즈 측정 부위나 단위가 일치하지 않음 | 근거 없는 cm 차이를 계산하지 않고 비교 불가/추가 확인으로 표시 |
| 같은 상품에 상반된 후기 두 개가 있음 | 상반됨과 확인 가능한 조건을 모두 보존. 작성자 체형·신뢰도를 추정해 한쪽을 버리지 않음 |
| 조건을 바꿔도 결과가 같음 | 실제로 사용한 조건과 결과를 유지한 이유를 설명. 억지로 다른 순위를 만들지 않음 |
| 같은 옷장에서 사용 상황과 목표 스타일을 번갈아 선택 | 옷장 정보는 유지되고 이번 상황의 목표로 판단. 이전 상황의 예산/제외 조건이 사용자 선택 없이 섞이지 않음 |
| 선호 브랜드를 가진 후보의 역할이 보유 옷과 중복됨 | 브랜드 선호와 중복을 함께 설명. 로고/브랜드만으로 더 필요한 상품이라고 결론 내리지 않음 |

개인화 효과는 ‘개인화된 문구가 생겼다’와 ‘선택·제외·우선순위·주의점이 실제로 달라졌다’를 나눠 기록한다. 어느 쪽이든 유용성은 본인이 실제 선택 과정에서 평가한다.

## 4. 가격·옵션·근거 처리

- 가격에는 상품 옵션, 통화, 확인 시점, 할인/회원 조건, 확인 가능한 배송비를 연결한다. 조건부 최저가를 누구나 내는 가격으로 바꾸지 않는다.
- 상품 가격 상한인지 배송비 포함 지출 상한인지 기준을 기록한다. 처음부터 알 수 없다면 ‘상품 가격 기준, 배송비 미확인’처럼 판단 범위를 표시한다.
- 선택한 색/사이즈의 재고를 확인하지 못한 상태와 품절은 다르다. 갱신 주기와 운영 가능한 출처가 정해지기 전에는 실시간 재고를 약속하지 않는다.
- 사실에는 출처·모델/옵션·확인 시각을, 제품의 해석에는 연결된 사실과 사용한 개인 조건을 남긴다.
- 후기의 같은 모델 여부가 불명확하면 확정적인 추천 근거로 합치지 않는다. 요약의 근거 위치를 다시 찾을 수 있어야 한다.

## 5. 기존 개인판에서 확인한 차이

소스 정적 검토 결과이며 신규 동작을 구현하거나 브라우저에서 재현했다는 뜻이 아니다. 원본 소스는 로컬 인계본이고 아직 이 문서 PR에 포함하지 않았다.

| 관찰 | 새 요구와의 차이 | 후속 작업 |
| --- | --- | --- |
| `recommend.js`의 색·밝기·격식 규칙은 고정 | 목표 스타일을 바꾸어도 규칙이 바뀌지 않음 | 개인화 기준선과 조건 변경 검증 |
| `app.html`의 `cleanItem`은 누락 값을 회색·밝기 50·격식 2 등으로 채움 | 모르는 정보를 확인된 값처럼 판단에 쓸 수 있음 | 미확인 상태와 기존 데이터 변환 정책 |
| `judge.js`의 빈 계절은 모든 계절로 취급 | 미입력과 사계절 확인 상태가 같음 | 두 상태 구분과 추천 표시 |
| 같은 브랜드·이름을 `exact`로 분류 | 동일 제품 식별과 스타일 유사도 구분이 약함 | 상품 모델/옵션 근거 도입 |
| 내보내기 초기 선택에 이미지 포함이 켜짐 | 새 PRD의 공유용 기본 제외와 다름 | 개인 백업과 공유용 내보내기 분리 |
| 상품·후기 카탈로그와 목표 스타일 입력이 없음 | 새 원스톱 흐름의 중심 데이터가 없음 | 검증 가능한 자료와 개인 맥락 모델부터 준비 |

기존 규칙 테스트 19개 통과는 위 차이를 해결했다는 근거가 아니다. 원본 데이터를 변환할 때 기존 기본값을 사용자가 확인한 사실로 승격하지 않으며, 변환 전 백업과 복원 경로를 둔다.

## 6. 지금 정할 것과 나중에 정할 것

- 실제 추천 검증 전에 구체화할 개인 입력: 선택한 아메리칸 클래식 안에서 첫 고민의 사용 상황·한 벌 예산·관련 보유 옷. 현재 기획 단계에서는 미정인 항목을 두고 진행할 수 있다.
- 선택 입력: 피하고 싶은 스타일/핏, 잘 맞는 옷의 실측, 체형·얼굴 분위기 고민. 얼굴·전신 사진은 필수가 아니다. 옷 사진 자동 등록은 핵심 기능이며, 이용자에게 직접 기록하는 대안도 제공한다.
- 자율 진행할 일: 사진 온보딩의 시안·로컬 실행 가능성·평가 방법 검토, 상품·후기 접근 확인, 비교 결과의 정보 순서, 근거 양식, 합성 사례 검증 설계, 기존 코드와 요구의 차이 정리.
