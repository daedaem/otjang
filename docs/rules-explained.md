# 규칙 설명서 — 판정·코디가 무엇을 보고 어떻게 계산하나 (0.5.0-beta)

이 문서는 창업자가 투자자·면접관에게 "이 판정은 어떻게 나오나"를 코드 없이 설명할 수 있도록 쓴 것이다. 코드는 `app/src/recommend.js`, `app/src/judge.js`(앱)와 `server/src/main/java/otjang/domain/Recommend.java`, `Judge.java`(서버)가 같은 규칙을 갖고 있고, 골든 회귀 시험이 두 결과가 같은지 확인한다.

**정직하게 말할 것**: AI 모델이 아니라 사람이 정한 규칙이다. 문턱 숫자(밝기 차이 35·18, 겹침 15 등)는 **제안값**이고 실제 사용자 결과로 검증되지 않았다. 핏·소재·얼굴 분위기·유행은 보지 않는다. 그래서 "사라/사지 마라"나 확률을 말하지 않고, 본 사실과 근거 문장만 보여 준다.

## 1. 옷 한 벌을 무엇으로 보나

| 항목 | 값 | 예 |
|---|---|---|
| 분류(cat) | 아우터 · 상의 · 하의 · 원피스 · 신발 | 원피스는 위아래가 한 벌인 옷(원피스·점프수트) |
| 종류(kind) | 분류마다 6~10종 | 상의: 셔츠·티셔츠·니트·스웻셔츠·폴로·후디·블라우스·민소매·터틀넥 |
| 색 계열(family) | 18가지 | 흰색·아이보리·베이지·카키·브라운·올리브·그린·블루·네이비·인디고·그레이·블랙·레드·버건디·핑크·퍼플·옐로·오렌지 |
| 색 묶음(group) | 멀리서 한 색으로 읽히는 계열끼리 | 네이비·인디고 → 짙은 파랑, 베이지·카키 → 카키, 흰색·아이보리 → 흰색, 레드·버건디 → 레드 |
| 밝기(light) | 0(검정) ~ 100(흰색) | 흰 셔츠 95, 진청 데님 18 |
| 격식(formality) | 1 편한 차림 · 2 중간 · 3 단정한 차림 | 티셔츠 1, 블레이저 3 |
| 무늬(pattern) | 무지 · 줄무늬 · 체크 · 프린트 | |

## 2. 상의 + 하의 한 쌍의 점수

| 규칙 | 점수 | 화면 문장 |
|---|---|---|
| 밝기 차이 35 이상 | +2 | 위아래가 또렷하게 나뉩니다 |
| 밝기 차이 18~34 | +1 | 밝기가 적당히 다릅니다 |
| 밝기 차이 18 미만 + 같은 색 묶음 | −2 **주의** | 한 덩어리로 보일 수 있습니다 |
| 밝기 차이 18 미만 + 다른 색 묶음 | −1 **주의** | 밝기가 비슷합니다 |
| 격식 차이 1 이하 / 2 | +1 / −1 **주의** | |
| 무늬가 상의에만 | +1 | |
| 무늬가 위아래 모두 | −2 **주의** | |

**주의가 하나도 없는 쌍**을 "깨끗한 조합"이라 부르고, 판정의 "조합 N개"는 이 수다.

## 3. 아우터를 걸칠 때

상의와 색 묶음이 다르면 +1(같으면 −1 주의), 상의보다 12 넘게 어두우면 +1, 하의와 같은 묶음에 밝기 차이 12 미만이면 −1 주의, 상의와 격식 차이 1 이하 +1(넘으면 −1 주의), 셔츠 위 카디건 +1, 스웻셔츠 위 카디건 −2 주의, 아우터와 상의 모두 무늬면 −2 주의.

## 4. 원피스 (0.5.0-beta)

원피스는 **혼자서 차림 하나**다. 기본 점수 2(제안값: 무난한 상의·하의 한 쌍과 같은 수준). 원피스 위 아우터는 3번과 같은 생각으로 본다: 색 묶음이 다르면 +1(같으면 −1 주의), 원피스보다 12 넘게 어두우면 +1, 격식 차이 1 이하 +1(넘으면 −1 주의), 둘 다 무늬면 −2 주의. 코디 목록에서는 상의 자리에 원피스, 하의는 비어 있다.

## 5. 살까 말까 판정

1. **겹치는 보유 옷**: 같은 분류에서, 색 묶음이 같고 밝기 차이 15 이하이면서 종류가 같거나 무늬 여부가 같으면 "겹침". 종류·무늬가 같고 격식 차이도 1 이하면 "많이 겹침", 아니면 "일부 겹침".
2. **새로 생기는 조합**: 상의 후보는 가진 하의 하나하나와, 하의 후보는 가진 상의 하나하나와 짝지어 깨끗한 조합 수를 센다(전 → 후). 아우터 후보는 지금 깨끗한 차림 가운데 몇 개에 주의 없이 걸칠 수 있는지 센다. 원피스 후보는 차림을 하나 더하고, 걸칠 수 있는 아우터를 센다. 신발은 아직 조합 규칙이 없어 겹침만 본다.
3. **걸리는 점**: 짝이 안 되는 이유를 모아 "하의 3벌 중 2벌: 밝기가 비슷합니다"처럼 센다.
4. **대표 조합 3개**: 점수가 높은 것부터, 가능하면 서로 다른 옷과 짝지은 것으로 보여 준다.

**예시(자동 시험에서 실제로 나온 값)**: 흰 셔츠·네이비 니트·진청 데님·베이지 치노·검정 원피스를 가진 사람이 베이지 트렌치코트를 고민하면 — 깨끗한 차림은 4개(흰 셔츠+데님, 흰 셔츠+치노, 니트+치노, 검정 원피스. 니트+데님은 같은 짙은 파랑이라 제외). 트렌치는 그중 2개에 걸칠 수 있다(흰 셔츠+데님, 검정 원피스). 나머지 2개는 "아우터와 하의의 색이 겹칩니다"(베이지 치노와 같은 카키 묶음) 때문에 걸린다.

## 6. 코디 추천

가능한 모든 조합(아우터 없음 포함)에 점수를 매기고 높은 순으로 3개를 고른다. 같은 상의(원피스)는 두 번 쓰지 않고, 처음에는 하의·아우터도 겹치지 않게 고른다. 같은 옷장이면 언제나 같은 결과다(무작위 없음).

## 7. 상품 순위 (살 만한 옷)

사용자가 직접 넣은 상품만 순서를 매긴다. 새 조합 수만큼 +1(최대 +5), 조합이 하나도 안 생기면 −2, 많이 겹치는 보유 옷 한 벌마다 −2, 일부 겹침 −1, 견준 옷장에 있고 내게 없는 자리를 채우면 +3. 가격은 확인한 날이 14일(제안값)보다 오래되면 "재확인 필요"로 표시한다. 목록 밖의 상품을 지어내지 않는다.

## 8. 결정 2주 뒤 물음

결정을 기록하고 14일(제안값)이 지나면 옷장 탭에서 한 번 묻는다. 산다 → 몇 번 입었나(0번·1~2번·3번 이상·결국 안 샀다)와 만족(잘 샀다·그저·후회). 안 산다 → 아쉬움(안 사길 잘했다·모르겠다·아쉽다). 보류는 묻지 않는다. 이것이 "판정이 후회 구매를 줄였나"를 보여 줄 유일한 자료다.

## 9. 규칙을 바꾸는 법 (안전하게)

1. `app/src/recommend.js` / `judge.js` 를 고치고 `npm test` 로 단위 시험을 본다.
2. 일부러 바꾼 것이면 `node tools/golden.mjs` 로 골든 스냅샷을 다시 만들고, 바뀐 부분이 의도한 것인지 diff 로 확인한다.
3. 서버 `Recommend.java` / `Judge.java` 를 같이 고치고 `GoldenParity` 로 앱과 같은지 본다(server/README.md).
4. 화면 흐름은 `npm run check`, `npm run check:web` 으로 본다.
