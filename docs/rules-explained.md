# 규칙 설명서 — 판정·코디가 무엇을 보고 어떻게 계산하나 (0.5.0-beta)

이 문서는 창업자가 투자자·면접관에게 "이 판정은 어떻게 나오나"를 코드 없이 설명할 수 있도록 쓴 것이다. 코드는 `app/src/recommend.js`, `app/src/judge.js`(앱)와 `server/src/main/java/otjang/domain/Recommend.java`, `Judge.java`(서버)가 같은 규칙을 갖고 있고, 골든 회귀 시험이 두 결과가 같은지 확인한다.

**정직하게 말할 것**: AI 모델이 아니라 사람이 정한 규칙이다. 문턱 숫자(밝기 차이 35·18, 겹침 15 등)는 **제안값**이고 실제 사용자 결과로 검증되지 않았다. 핏·소재·얼굴 분위기·유행은 보지 않는다. 그래서 "사라/사지 마라"나 확률을 말하지 않고, 본 사실과 근거 문장만 보여 준다.

## 1. 옷 한 벌을 무엇으로 보나

| 항목 | 값 | 예 |
|---|---|---|
| 분류(cat) | 아우터 · 상의 · 하의 · 원피스 · 신발 | 원피스는 위아래가 한 벌인 옷(원피스·점프수트) |
| 종류(kind) | 분류마다 6~10종 | 상의: 셔츠·티셔츠·니트·스웻셔츠·폴로·후디·블라우스·민소매·터틀넥 |
| 색 계열(family) | 18가지 | 흰색·아이보리·베이지·카키·브라운·올리브·그린·블루·네이비·인디고·그레이·블랙·레드·버건디·핑크·퍼플·옐로·오렌지 |
| 색 묶음(group) | 멀리서 한 색으로 읽히는 계열끼리 | 네이비·인디고 → 짙은 파랑, 베이지·카키 → 카키, 흰색·아이보리 → 흰색, 레드·버건디 → 레드 |
| 밝기(light) | 0(검정) ~ 100(흰색) | 흰 셔츠 95, 진청 데님 18 |
| 격식(formality) | 1 편한 차림 · 2 중간 · 3 단정한 차림 | 티셔츠 1, 블레이저 3 |
| 무늬(pattern) | 무지 · 줄무늬 · 체크 · 프린트 | |

## 2. 상의 + 하의 한 쌍의 점수

| 규칙 | 점수 | 화면 문장 |
|---|---|---|
| 밝기 차이 35 이상 | +2 | 위아래가 또렷하게 나뉩니다 |
| 밝기 차이 18~34 | +1 | 밝기가 적당히 다릅니다 |
| 밝기 차이 18 미만 + 같은 색 묶음 | −2 **주의** | 한 덩어리로 보일 수 있습니다 |
| 밝기 차이 18 미만 + 다른 색 묶음 | −1 **주의** | 밝기가 비슷합니다 |
| 격식 차이 1 이하 / 2 | +1 / −1 **주의** | |
| 무늬가 상의에만 | +1 | |
| 무늬가 위아래 모두 | −2 **주의** | |

**주의가 하나도 없는 쌍**을 "깨끗한 조합"이라 부르고, 판정의 "조합 N개"는 이 수다.

## 3. 아우터를 걸칠 때

상의와 색 묶음이 다르면 +1(같으면 −1 주의), 상의보다 12 넘게 어두우면 +1, 하의와 같은 묶음에 밝기 차이 12 미만이면 −1 주의, 상의와 격식 차이 1 이하 +1(넘으면 −1 주의), 셔츠 위 카디건 +1, 스웻셔츠 위 카디건 −2 주의, 아우터와 상의 모두 무늬면 −2 주의.

## 4. 원피스 (0.5.0-beta)

원피스는 **혼자서 차림 하나**다. 기본 점수 2(제안값: 무난한 상의·하의 한 쌍과 같은 수준). 원피스 위 아우터는 3번과 같은 생각으로 본다: 색 묶음이 다르면 +1(같으면 −1 주의), 원피스보다 12 넘게 어두우면 +1, 격식 차이 1 이하 +1(넘으면 −1 주의), 둘 다 무늬면 −2 주의. 코디 목록에서는 상의 자리에 원피스, 하의는 비어 있다.

## 5. 살까 말까 판정

1. **겹치는 보유 옷**: 같은 분류에서, 색 묶음이 같고 밝기 차이 15 이하이면서 종류가 같거나 무늬 여부가 같으면 "겹침". 종류·무늬가 같고 격식 차이도 1 이하면 "많이 겹침", 아니면 "일부 겹침".
2. **새로 생기는 조합**: 상의 후보는 가진 하의 하나하나와, 하의 후보는 가진 상의 하나하나와 짝지어 깨끗한 조합 수를 센다(전 → 후). 아우터 후보는 지금 깨끗한 차림 가운데 몇 개에 주의 없이 걸칠 수 있는지 센다. 원피스 후보는 차림을 하나 더하고, 걸칠 수 있는 아우터를 센다. 신발은 아직 조합 규칙이 없어 겹침만 본다.
3. **걸리는 점**: 짝이 안 되는 이유를 모아 "하의 3벌 중 2벌: 밝기가 비슷합니다"처럼 센다.
4. **대표 조합 3개**: 점수가 높은 것부터, 가능하면 서로 다른 옷과 짝지은 것으로 보여 준다.

**예시(자동 시험에서 실제로 나온 값)**: 흰 셔츠·네이비 니트·진청 데님·베이지 치노·검정 원피스를 가진 사람이 베이지 트렌치코트를 고민하면 — 깨끗한 차림은 4개(흰 셔츠+데님, 흰 셔츠+치노, 니트+치노, 검정 원피스. 니트+데님은 같은 짙은 파랑이라 제외). 트렌치는 그중 2개에 걸칠 수 있다(흰 셔츠+데님, 검정 원피스). 나머지 2개는 "아우터와 하의의 색이 겹칩니다"(베이지 치노와 같은 카키 묶음) 때문에 걸린다.

## 6. 코디 추천

가능한 모든 조합(아우터 없음 포함)에 점수를 매기고 높은 순으로 3개를 고른다. 같은 상의(원피스)는 두 번 쓰지 않고, 처음에는 하의·아우터도 겹치지 않게 고른다. 같은 옷장이면 언제나 같은 결과다(무작위 없음).

## 7. 상품 순위 (살 만한 옷)

사용자가 직접 넣은 상품만 순서를 매긴다. 새 조합 수만큼 +1(최대 +5), 조합이 하나도 안 생기면 −2, 많이 겹치는 보유 옷 한 벌마다 −2, 일부 겹침 −1, 견준 옷장에 있고 내게 없는 자리를 채우면 +3. 가격은 확인한 날이 14일(제안값)보다 오래되면 "재확인 필요"로 표시한다. 목록 밖의 상품을 지어내지 않는다.

## 8. 결정 2주 뒤 물음

결정을 기록하고 14일(제안값)이 지나면 옷장 탭에서 한 번 묻는다. 산다 → 몇 번 입었나(0번·1~2번·3번 이상·결국 안 샀다)와 만족(잘 샀다·그저·후회). 안 산다 → 아쉬움(안 사길 잘했다·모르겠다·아쉽다). 보류는 묻지 않는다. 이것이 "판정이 후회 구매를 줄였나"를 보여 줄 유일한 자료다.

## 9. 규칙을 바꾸는 법 (안전하게)

1. `app/src/recommend.js` / `judge.js` 를 고치고 `npm test` 로 단위 시험을 본다.
2. 일부러 바꾼 것이면 `node tools/golden.mjs` 로 골든 스냅샷을 다시 만들고, 바뀐 부분이 의도한 것인지 diff 로 확인한다.
3. 서버 `Recommend.java` / `Judge.java` 를 같이 고치고 `GoldenParity` 로 앱과 같은지 본다(server/README.md).
4. 화면 흐름은 `npm run check`, `npm run check:web` 으로 본다.

## 10. 추천 탭 — 기준으로 딱 하나 (2026-10-13 3회차)

코드는 `app/src/pick.js`, 자료는 `app/data/picks.json`(검증 카탈로그, 정책은 [catalog-policy.md](catalog-policy.md)), 검사기는 `app/tools/validate-catalog.mjs`, 재확인 도구는 `app/tools/recheck.mjs`. 서버 쪽 Java 이식은 아직 없다(앱 전용).

**자료**: 공식 스토어·공식 판매처의 상품 페이지를 직접 열어 확인한 값만 넣는다. 값마다 출처 등급을 단다 — 공식(상세 문구), 상품정보제공고시(법정 표기), 상품명에만, 판매처 설명(자동으로 만든 문장일 수 있음), 상품 사진으로 본 판단. 가격·재고·배송비는 확인한 날의 값이고, 상품 사진은 가져오지 않는다. 스타일 분류는 어울의 편집 판단이다.

**지금 낼 돈과 한 장 값**: 지금 낼 돈 = 상품값(묶음 전체) + 아는 배송비(그 상품만 한 번에 주문할 때. 판매처의 무료 기준을 넘으면 0). 한 장 값 = 지금 낼 돈 ÷ 장 수. 해외는 그날 환율로 바꾸고, 배송비를 모르면 가성비를 중간(0.5) 이하로 본다.

**꼭 지킬 조건**(용도별, 끌 수 있음): 받쳐 입기(카디건·셔츠 안) → 로고 안 보이게 · 얇게 · 목 립 좁게. 한 장으로 → 비치지 않게. 판정은 다섯 가지다.

| 표시 | 뜻 | 점수 |
|---|---|---|
| ✓ 확인 | 공식·고시·공식 원단 무게·직접 입력으로 맞음. 로고는 상품 사진으로 봐도 확인 | 1 |
| ✓(회색) 약한 확인 | 판매처 설명·사진 판단·상품명으로만 맞음, 또는 '보통 두께'처럼 애매함 | 0.75 |
| ? 모름 | 값이 없음 | 0.5 |
| ! 어긋날 수 있음 | 약한 근거로 어긋나 보임(빼지 않고 경고, 대안으로는 내지 않음) | 0.25 |
| ✕ 어긋남 | 확인된 어김 → 1등·대안에서 빼고 순위에 이유를 남김 | — |

| 기준 | 계산 | 0~1로 바꾸는 법 |
|---|---|---|
| 가성비 | 한 장 값 ÷ 품질 점수 | 품목의 고정 기준선(흰 티: 2,500원~50,000원, 로그 눈금). 목록에 무엇이 있든 같은 상품은 같은 값 |
| 품질(공개된 근거) | 기본 3 + 면 100%(1) + 수피마·라일·피마(1.5) 또는 링스펀(0.75) + 루프휠(1.5, 통짜는 따로 안 셈) 또는 인터로크(0.75) 또는 통짜(0.75) + 바인딩 목(0.5). 판매처 설명이면 ×0.3, 상품명에만 있으면 ×0.5, 사진 판단 ×0.6 | (점수 − 3) ÷ 4.5, 최대 1 |
| 브랜드 | 고른 브랜드 1, 같은 계열(폴로 ↔ 퍼플 라벨) 0.5, 아니면 0 | 하나도 안 골랐으면 '중립'(0.5로 세되 결론·근거에 쓰지 않음) |
| 내 핏 | 잘 맞는 티 실측(가슴단면·총장·어깨)과 사이즈별 차이의 가중 평균(가슴 1, 총장·어깨 0.6). 실측으로 못 고르면 평소 사이즈의 판매·재고 | 1 − 평균 차이 ÷ 5cm(공개 치수가 하나뿐이면 최대 0.6). 재고 있음 1, 모름 0.6, 품절·안 팖 0. 둘 다 없으면 '중립' |
| 스타일 | 고른 스타일과 편집 분류가 겹치면 1 | 흰 무지 티는 무게를 0.3 이하로 묶어 동점 깨기에만 쓴다 |

**무게**: 누른 순서대로 3·2·1.5·1.2·1, 누르지 않은 기준 0.5, 용도 조건 2.5. 기준 점수 = 가중 평균 × 100(확률이 아니다). 동점이면 한 장 값이 싼 것.

**1순위 문턱**: 1순위 기준(값을 고른 경우)이 '보통'(0.5) 이상인 상품이 있으면 1등은 그 안에서 고른다. 그래서 품질을 1순위로 고르면 품질 근거가 약한 싼 상품이 1등이 되지 않는다. 문턱이 고정값이라 순위 밖 상품을 빼도 1등은 바뀌지 않는다(시험). 문턱 때문에 1등이 바뀌면 결론 첫머리에 그렇게 말하고, 문턱을 넘는 상품이 없으면 "○○이 보통 이상인 상품이 없어 다른 기준을 합해 골랐어요"라고 말한다.

**1등에서 빼는 것**: 조건 어김이 확인됨, 예산(지금 낼 돈) 초과, 고른 사이즈가 품절이거나 팔지 않음, 상품 전체 품절, 확인일이 미래이거나 없는 날짜, 확인한 지 30일이 지남. 순위에는 남기고 이유를 적는다. 점수는 날짜 때문에 바뀌지 않는다(14일이 지나면 "다시 확인 필요"를 붙이고 가성비를 이유로 말하지 않을 뿐).

**결론 한 문장**: 1순위부터 보며 '좋음'(0.66 이상)이고 고른 값이 있는 기준 하나를 이유로 든다. 고르지 않은 기준(중립)과 '보통' 이하는 이유로 쓰지 않는다. 그다음 조건 상태(확인 / 약한 근거 / 모름 / 어긋날 수 있음)를 한 문장씩.

**대안**: (1) 점수가 가까운(12점 안) 2위, (2) 조건이 더 확인된 것, (3) 1순위가 가성비가 아니면 한 장 값이 1등의 1/3 이하이고 가성비가 '좋음'인 것 하나("○○ 대신 값을 보면", 40점 안), (4) 더 쌈(85% 이하), (5) 다른 좋아하는 브랜드, (6) 품질 근거가 더 많은 것. (3) 말고는 1등보다 25점 넘게 낮으면 내지 않는다. 받쳐 입기에서는 1등이 루즈핏이 아니면 루즈·박스핏 대안을 내지 않고, 핏이 1순위면 사이즈가 평균 2.5cm 넘게 또는 한 군데라도 4cm 넘게 어긋나는 대안을 내지 않는다. 가성비가 1순위면 두 배 넘게 비싼 대안을 내지 않는다. 조건이 '어긋날 수 있음'인 상품도 대안으로 내지 않는다. 이름은 1등과의 차이로 붙이고 겹치지 않게 한다. 2위를 대안에서 뺐으면 그 이유를 2위 설명 줄에 적는다.

**지금 보는 상품**: 사용자가 보던 상품의 가격·치수·로고·두께·목 립을 적으면 출처 '직접 입력'으로 같은 기준에 넣어 몇 위인지, 1위와 값 차이, 잘 맞는 티와의 치수 차이를 보여 준다. 1등·대안은 어울이 확인한 상품 안에서만 고른다. 링크는 열지 않는다.

**결정 고리**: 판매처 링크를 누르고 이 화면을 떠났다가 돌아오면(또는 다음 방문에) 그 카드 안에서 "샀나요?"를 묻는다(7일 안, 같은 상품은 한 번만, "아직이요"는 하루 미룸). 샀으면 산 사이즈(추천 사이즈가 기본)를 받고, 원하면 그 사이즈의 치수와 함께 옷장에 넣는다. 산 지 14일이 지나면 사이즈(잘 맞음·작음·큼)와 만족을 묻는다. "잘 맞아요"면 그 치수를 다음 추천의 '잘 맞는 티'로 쓰고(되돌리기 있음), 작거나 크면 가슴을 2cm 옮길지 묻는다.

**사람이 판단할 자리**: 기준선(2,500·50,000원), 무게(3·2·1.5…, 2.5), 문턱(0.5), 조건 점수(1·0.75·0.5·0.25), 출처 가중(0.3·0.5·0.6), 품질 만점 7.5점, 대안 기준(12·25·40점, 1/3, 85%, 2배), 사이즈 눈금(5cm·2.5cm·4cm·2cm)은 모두 **제안값**이다. 실제 사용자의 "이걸로 할래요·샀어요·2주 뒤 사이즈 잘 맞음" 기록으로 고쳐야 한다.

**시험**(`app/test/pick.test.cjs`, `app/test/recheck.test.cjs`): 조건 격자(기준 순서·용도·브랜드·사이즈·예산을 섞은 수백 가지)에서 순위 밖 상품을 하나씩 빼도 1등이 바뀌지 않음, 15일이 지나도 1등이 같음, 1순위 문턱, 결론이 고르지 않은 기준을 말하지 않음, 대안 규칙, 조건 근거 강도, 품절·안 파는 사이즈와 실측·평소 사이즈 함께 넣기, 배송비·묶음·예산, 직접 넣은 상품, 제휴 수수료 같은 값이 순위에 영향 없음, 정리 단계가 사전의 기본 속성 이름·없는 날짜를 받지 않음, 재확인 도구의 robots·읽기·반영.
