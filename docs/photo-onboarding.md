# 사진으로 처음 내 옷장 만들기

- 상태: 사용자 요구를 반영한 설계·검증안. 자동 인식 모델 선정·실행·품질 검증은 아직 하지 않았다.
- 사용자 결정: 옷장이나 옷을 찍어 초기 옷장을 만들어 주는 경험을 초기 프로필 구성처럼 중요하게 다룬다.
- 연결: [PRD v0.4](PRD-v0.4.md) D-10, FR-01/03/08/09/10/11/12/18. 아래 화면·처리 방식·평가 항목은 구현 전 제안이다.

## 1. 사용자가 끝내려는 일

**사진 몇 장을 골라 생성된 옷 목록을 확인하고, 내 옷으로 첫 코디와 보완 제안을 받아 본다.**

한 벌씩 빈 양식을 채우는 수고를 줄이는 것이 목적이다. 사진을 첨부한 수동 양식만으로는 이 요구를 충족하지 않는다. 처음부터 옷장 전체 등록·브랜드·상품명·사이즈·체형·얼굴 사진을 요구하지 않는다.

| 단계 | 사용자가 하는 일 | 제품이 제공할 것 |
| --- | --- | --- |
| 사진 선택 | 옷장 전경·개별 옷 사진 촬영 또는 기존 사진 선택 | 여러 장 선택, 로컬 처리 안내, 직접 기록 대안 |
| 초안 생성 | 처리 상태 확인, 필요하면 취소 | 보이는 옷 후보와 원본 영역, 종류·색·무늬 초안, 일부 실패 구분 |
| 검토 | 잘못 잡은 영역 수정·제외, 누락 추가, 중복 확인 | 일괄 선택, 같은 옷/다른 옷/나중 확인, 모르는 값 유지 |
| 첫 옷장 | 선택한 항목을 보유로 확정 | 확정 항목과 미확정 초안 분리, 부분 등록 표시 |
| 첫 활용 | 원하는 스타일이나 지금 고민 선택 | 등록된 옷으로 가능한 코디·보완 제안, 부족한 근거 안내 |
| 이어 쓰기 | 중단한 초안 재개 또는 새 사진 추가 | 저장된 수정 보존, 기존 옷과 중복 검토, 변경된 옷장으로 판단 갱신 |

자동으로 탐지된 초안은 사용자 확인 전까지 보유 옷이 아니다. 일괄 보유 확정을 했다고 모든 추정 속성이 사용자 확인을 받은 사실로 바뀌지는 않는다. 해당 속성을 확인·수정한 이력을 별도로 남긴다.

## 2. 사진이 말해 주는 범위

- 옷장 전경과 개별 옷 사진을 모두 초기 검증에 포함한다. 전경 사진을 한 장의 옷으로 저장하는 방식은 여러 옷의 자동 등록이 아니다.
- 원본의 어느 영역에서 나온 후보인지 확인할 수 있다. 배경 제거의 완벽함이나 3D 복원을 첫 기록의 선행 조건으로 두지 않는다.
- 보이는 옷만 후보로 만든다. 가려진 옷·뒷면·정확한 치수·브랜드·소재를 생성해 채우지 않는다. 속성은 추정/미확인/직접 입력/사용자 확인으로 구분한다.
- 재촬영만 요구하지 않는다. 영역 수정, 직접 누락 추가, 미확인 상태로 보관, 나중 처리 경로를 둔다.
- 같은 옷의 여러 사진을 연결할 수 있다. 같은 색·분류라는 이유로 비슷한 다른 옷을 자동 병합하지 않는다. 병합을 취소할 수 있으며 관련 사진 연결을 보존한다.
- ‘등록된 옷 기준’으로 코디·중복·보완을 설명한다. 사진 한 장으로 실제 옷장 전체를 알고 있다고 결론 내리지 않는다.
- 옷을 찾아 종류와 속성 초안을 만드는 일, 정확한 판매 상품을 찾는 일, 몸에 입힌 모습을 만드는 일은 각각 별도 기능이다. 이 요구의 핵심은 첫 번째다.

## 3. 초안과 저장의 경계

작업 단위의 상태는 `처리 대기 → 처리 중 → 검토 가능(전체/일부) → 일부 확정/완료`로 구분한다. 실패·취소 상태에서도 이미 저장한 검토 결과와 기존 옷장을 보존한다.

후보 단위로 미검토·수정·제외·확정 상태와 확정된 옷 ID를 연결한다. 같은 후보의 확정을 재시도해도 보유 옷은 한 번만 생성된다. 비슷해 보이지만 별개라고 사용자가 확인한 두 벌은 각각 유지한다.

저장·재개·삭제·백업 범위는 원본, 잘라낸 이미지, 초안, 확정 옷을 구분해 안내한다. 확정 옷에 사용되는 사진을 초안 정리 과정에서 무심코 삭제하지 않는다. 사진을 사용자가 명시적으로 지우면 연결된 사본·표현도 제거하고, 사진 없는 옷 기록을 남길지 선택할 수 있게 한다. 저장 실패를 성공으로 표시하지 않는다.

새로고침·작업 중단·재시도·부분 실패로 기존 사용자 수정이 덮어써지지 않아야 한다. 한 사진의 실패 때문에 나머지 검토와 저장을 막지 않는다. 초기 묶음 크기·파일 제한은 지원 기기 평가 후 정하고 화면에 설명한다.

## 4. 먼저 확인할 기술 조건

개인 사진은 로컬에서 처리한다는 인계 기준을 유지한다. 원본·잘라낸 이미지·사진에서 추출한 표현을 외부 분석 API나 로그로 보내지 않는다. 이 클라우드 개발 공간을 사용자 사진의 로컬 저장소로 간주하지 않는다. 현재 개인 사진이 없는 인계본만 있으므로 사진 처리 성공을 주장할 근거는 없다.

브라우저 내 실행을 우선 검토하되, 아직 모델·라이선스·지원 기기·메모리·속도를 확인하지 않았다. 별도 로컬 프로그램이 필요하면 설치 부담과 모바일 사용 제약을 명시하고 화면 흐름과 함께 검토한다. 실패 시 외부 유료 API로 자동 전환하지 않는다.

기술 검증은 옷 탐지·영역 분리, 종류·색·무늬 초안, 중복 후보 제안으로 나눠 측정한다. 합성 또는 사용 권한을 확보한 비개인 평가 사진으로 시작하고, 본인 실제 옷 사진 평가는 사용자 로컬 환경에서 별도 수행한다. 합성 사진의 결과만으로 실제 옷장 품질을 통과시키지 않는다.

## 5. 최소 검증과 완료 기준

| 검증 재료/상황 | 반드시 확인할 동작 |
| --- | --- |
| 개별 옷과 여러 옷이 보이는 전경 | 사람이 영역·분류를 모두 입력하기 전에 옷 후보가 자동 생성됨. 원본 영역을 추적할 수 있음 |
| 겹침·접힘·어두운 조명·옷 아닌 물체 | 누락과 잘못 찾은 후보를 기록하고, 안 보이는 속성을 확정하지 않음 |
| 같은 옷의 두 사진, 비슷한 별개 옷 두 벌 | 중복 검토를 거치며 별개 옷이 사라지지 않음. 병합/취소와 원본 연결 보존 |
| 일부만 확정하고 재방문 | 확정 옷만 추천에 쓰고 나머지 초안은 유지. 모든 속성을 채우지 않아도 진행 |
| 처리 취소·부분 실패·저장 실패·확정 재시도 | 기존 옷장 손상·중복 생성·수정 유실 없음. 자동 성공/부분 성공/실패와 수동 대안 구분 |
| 지원 환경의 네트워크 관찰 | 사진·파생 이미지·추출 표현이 외부로 전송되지 않음. 필요한 모델 다운로드와 사진 업로드를 구분 |

사람이 평가 사진의 보이는 옷과 영역을 표시해 정답 기준을 만든다. 탐지 누락·오탐·잘못된 분리/병합은 기준 개수와 함께 기록하고, 속성별 정확성은 확인 가능한 항목에 한해 평가한다. 전체 사진에서 보이지 않는 실제 옷 개수를 탐지 성공률의 분모로 사용하지 않는다. 검토 보류를 정답으로 간주하지 않는다.

입력 수고는 **사진 준비 + 모델 초기 준비/다운로드 + 처리 대기 + 검토·수정 + 첫 활용까지의 시간**으로 나눠 기록한다. 자동 후보 수, 수정·제외·수동 추가 수, 중복 검토 수, 사용자가 계속 유지할 만한지도 함께 기록한다. 같은 옷 묶음의 수동 등록 기준선과 비교하며 순서 효과를 남긴다.

정확도·지연시간·지원 기기의 수치 문턱은 아직 정하지 않았다. 기술 조사와 최초 평가 후 제안값을 정하고 반복 평가에 적용한다. 현재 상태는 미검증이다. 수동 대안이 동작한다는 이유로 자동 온보딩을 완료 처리하거나 평가 범위를 넘어 모든 옷장을 지원한다고 소개하지 않는다.
