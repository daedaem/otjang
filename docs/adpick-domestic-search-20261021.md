# 애드픽 국내 상품 연결 인계 — 2026-10-21

상태: **코드·합성 검증 완료, 실제 계정/상품 검증·운영 연결 대기**. 대표가 지금 로그인할 수 없다고 답했다. 계정 접근이 없어 실제 품명/가격/검색 지원 몰을 검증하지 못했으므로 운영 배포 전 검토용 초안으로 유지한다. Issue #38.

## 확인한 공식 근거

- [공식 BIZ 소개](https://biz.adpick.co.kr/): Chrome에서 제휴몰 로고 이름으로 W컨셉·H패션몰·필웨이·포스티·교복몰·CJ온스타일·GS SHOP·Hmall·쿠팡 등을 확인했다. **제휴몰 소개는 상품 검색 API 지원 증거가 아니다.** 무신사·브론슨·리바이스 LVC·포터리의 실제 API 공급은 미확인이다.
- [공식 API 가이드](https://biz.adpick.co.kr/?ac=api&sub=guide): Chrome에서 현재 본문을 읽었다. 검색은 `GET /api/{apikey}/search?q=...&limit=...&cp_code=...`, 최대 20건·분당 10회다. cp_code는 최대 5개이고 검색 가능 몰은 로그인한 계정 기준으로 안내된다. 몰 목록은 `/malls`, 분당 60회다. 소개에 있는 몰이 모두 검색된다고 가정하지 않는다.
- 같은 가이드는 API 별도 요금이 없고 웹/앱의 제휴 판매용 상품 소개에 검색 결과의 commissionlink를 사용할 수 있다고 안내한다. 가격은 참고값이며 현재 판매가·재고·옵션·배송·판매 상태를 보증하지 않는다.
- 상품/사진 권리는 쇼핑몰·판매자에게 있고 애드픽이 저장·가공·재이용 권리를 허락하는 것은 아니라는 설명도 확인했다. 이번 구현은 호출 시 상품을 표시하고 원래 제휴 구매 링크로 연결하는 범위다. 판매처별 활동 가이드·표시 요건·계정 승인까지 모두 충족했다는 법률 판정은 아니다. 사진 저장/가공, 외부 AI 전송·학습·재정렬, 원본 카탈로그 복제는 하지 않는다.

## 구현한 범위

- 서버 `app/lite/functions/api/adpick.js`: 본인 인증 뒤의 `/api/adpick?q=`(검색)와 `/api/adpick/malls`(몰 이름/코드만)다. Worker와 Pages 입구 모두 인증 실패 시 닫힌다. 성과/정산/주문 보고 API는 호출하지 않는다.
- `ADPICK_API_KEY`는 런타임 Secret용이며 키 발급·복사·저장은 실행하지 않았다. 제공자 규격상 키가 요청 경로에 포함되므로 브라우저는 자체 `/api/adpick`만 호출하고 원래 API URL/키/오류 원문은 응답·앱 로그에 내보내지 않는다. HTTP redirect를 따라가지 않는다.
- 2~100자/UTF-8 300바이트 검색어, 8초/1MB 응답 상한, 초당 1회/검색 분당 10회 공유 D1 카운터다. 몰 조회는 별도 분당 60회 카운터다. 저장하는 것은 120초 후 만료되는 사용량 카운터뿐이며 상품·검색어·개인 옷장은 저장하지 않는다. 기존 D1의 다른 테이블/키/계정·백업 형식은 바꾸지 않는다.
- 공식 목록에서 확인한 국내 판매처 이름만 통과시킨다(쿠팡·11번가·CJ온스타일·GS SHOP·Hmall·H패션몰·W컨셉·필웨이·포스티·교복몰). 이는 공급 가능 목록이 아니라 해외/미확인 판매처 제외를 위한 보수적 표시 기준이다. 실제 응답 이름이 다르면 확인 후 추가한다. 국내 판매처라고 국내 재고/직배송을 보장하지 않는다.
- 공급자 최대 20건 안에서 표시 가능한 국내 상품을 최대 12개 제공 순서대로 표시한다. 이름·가격 문자열·판매처·commissionlink를 쓰며 브랜드/재고/정확한 상품 속성을 추정하지 않는다. 구매 링크는 애드픽의 HTTPS 링크 호스트만 허용하며, 외부/유효하지 않은 링크나 키를 포함한 값은 제외한다. 이미지는 원래 HTTPS 주소를 브라우저에서 표시하며 서버 프록시·다운로드·백업을 하지 않는다.
- 기존 검색/옷장 등록 검색의 라쿠텐 섹션 앞에 ‘국내 쇼핑몰에서 찾기’를 추가했다. 명시적으로 버튼을 눌러야 호출한다. 키워드 검색이며 앱의 예산·코디 조건 적용/AI 추천은 아니라고 밝힌다. 원화 참고가격과 확인 시각, 구매 링크 전에 제휴 수수료 표시를 둔다. 등록/구매를 자동 실행하지 않는다.
- 0건, 필수 정보/국내 판매처 미확인으로 모두 제외된 결과, 공급자 오류를 구분한다. 실패를 대체 상품이나 성공으로 표시하지 않는다. 외부 API 결과를 AI 추천 입력으로 보내지 않는다.

## 검증 사실

- lite **125/125**, 일반 앱 **688/688** 통과. build `de94e22c585f`, diff 공백 검사 통과.
- 합성 검사: 비밀값/DB/인증 누락, 길이/경로/메서드, 원래 링크/순서/가격, 해외·미확인 몰 제외, 키/원문 반사 방지, 리디렉션·크기·시간 제한, 실제 SQLite 동시 호출 카운터, 브라우저 동일-origin 호출, 로그인 복귀, 광고 표시 순서, 0건/제외/실패 구분을 확인했다.
- 격리된 Chrome 로컬 빈 옷장에서 ‘합성 셔츠’ 입력 → ‘국내 상품 불러오기’ → `[합성 QA]` 상품·원화 가격·제휴 표시를 확인했다. ‘없는 합성 상품’은 0건이고 자동으로 조건을 넓히지 않았다. 합성 구매 링크는 클릭하지 않았다. **합성 품명/가격은 실제 애드픽 상품이 아니다.**
- 실제 API 키, 계정별 검색 가능한 몰, 실제 상품명/가격/사진/링크, 공급자 승인/Whitelist, 원격 D1/운영 배포, iPhone 실기기는 미검증이다. 계정 로그인을 못 하는 상황을 코드 버그나 제공자 장애라고 단정하지 않는다.

## 다음 작업자가 끝낼 순서

1. 대표가 로그인할 수 있을 때 BIZ 계정의 검색 가능 몰 목록과 상품 검색을 확인한다. 키 관리 화면의 값을 읽거나 채팅/저장소에 출력하지 않는다. 공식 테스트 도구를 쓴다면 키가 포함된 원래 요청 URL·로그를 수집하지 않는다.
2. 실제 의류 질의를 소수 실행해 공급자 응답 스키마·실제 제목/원화 가격/사진/구매 링크를 대조한다. 0건이면 그대로 기록한다. 공개 소개 로고나 문서 예제를 실제 검색 증거로 대체하지 않는다.
3. 상품 표시/제휴 활동 범위를 확인하고 계정/키의 접근 조건이 Workers에서 사용 가능한지 확인한다. 제한을 임의로 해제하지 않는다. 서버 키는 대표가 Cloudflare 런타임 `ADPICK_API_KEY` Secret에 직접 입력·저장한다. 기존 4개 Secret을 바꾸지 않는다. 신규 자격증명 입력·제출은 사용자 인계가 필요한 브라우저 도구 규칙이다.
4. 실제 형식과 링크 호스트를 확인한 뒤 PR 검사를 마치고 master 비공개 배포를 진행한다. 배포 버전과 실제 앱 조회가 모두 확인돼야 연결 완료로 보고한다. 공개 출시·상품별 외부 AI 처리·가격/재고 보증·최저가 보장은 별도다.

대표가 현재 로그인할 수 없다고 했으므로 지금 추가 로그인·Secret 입력을 요구하지 않는다. 이 연결부를 먼저 운영에 올려 준비 중 버튼을 노출하거나 실제 상품을 확인한 것처럼 보고하지 않는다.
