## 확인한 공식 근거

- [공식 BIZ 소개](https://biz.adpick.co.kr/): Chrome에서 제휴몰 로고 이름으로 W컨셉·H패션몰·필웨이·포스티·교복몰·CJ온스타일·GS SHOP·Hmall·쿠팡 등을 확인했다. **제휴몰 소개는 상품 검색 API 지원 증거가 아니다.** 무신사·브론슨·리바이스 LVC·포터리의 실제 API 공급은 미확인이다.
- [공식 API 가이드](https://biz.adpick.co.kr/?ac=api&sub=guide): Chrome에서 현재 본문을 읽었다. 검색은 `GET /api/{apikey}/search?q=...&limit=...&cp_code=...`, 최대 20건·분당 10회다. cp_code는 최대 5개이고 검색 가능 몰은 로그인한 계정 기준으로 안내된다. 몰 목록은 `/malls`, 분당 60회다. 소개에 있는 몰이 모두 검색된다고 가정하지 않는다.
- 같은 가이드는 API 별도 요금이 없고 웹/앱의 제휴 판매용 상품 소개에 검색 결과의 commissionlink를 사용할 수 있다고 안내한다. 가격은 참고값이며 현재 판매가·재고·옵션·배송·판매 상태를 보증하지 않는다.
- 상품/사진 권리는 쇼핑몰·판매자에게 있고 애드픽이 저장·가공·재이용 권리를 허락하는 것은 아니라는 설명도 확인했다. 이번 구현은 호출 시 상품을 표시하고 원래 제휴 구매 링크로 연결하는 범위다. 판매처별 활동 가이드·표시 요건·계정 승인까지 모두 충족했다는 법률 판정은 아니다. 사진 저장/가공, 외부 AI 전송·학습·재정렬, 원본 카탈로그 복제는 하지 않는다.

## 구현한 범위

- 서버 `app/lite/functions/api/adpick.js`: 본인 인증 뒤의 `/api/adpick?q=`(검색)와 `/api/adpick/malls`(몰 이름/코드만)다. Worker와 Pages 입구 모두 인증 실패 시 닫힌다. 성과/정산/주문 보고 API는 호출하지 않는다.
- 최초 구현 단계에서 `ADPICK_API_KEY`는 런타임 Secret용으로 연결했고 키 발급·복사·저장은 실행하지 않았다. 이후 대표가 직접 저장한 사실은 아래 운영 기록과 구분한다. 제공자 규격상 키가 요청 경로에 포함되므로 브라우저는 자체 `/api/adpick`만 호출하고 원래 API URL/키/오류 원문은 응답·앱 로그에 내보내지 않는다. HTTP redirect를 따라가지 않는다.
- 2~100자/UTF-8 300바이트 검색어, 8초/1MB 응답 상한, 초당 1회/검색 분당 10회 공유 D1 카운터다. 몰 조회는 별도 분당 60회 카운터다. 저장하는 것은 120초 후 만료되는 사용량 카운터뿐이며 상품·검색어·개인 옷장은 저장하지 않는다. 기존 D1의 다른 테이블/키/계정·백업 형식은 바꾸지 않는다.
- 공식 목록에서 확인한 국내 판매처 이름만 통과시킨다(쿠팡·11번가·CJ온스타일·GS SHOP·Hmall·H패션몰·W컨셉/더블유컨셉코리아·필웨이·포스티·교복몰·SSG·롯데홈쇼핑·보리보리). 이는 공급 가능 목록이 아니라 해외/미확인 판매처 제외를 위한 보수적 표시 기준이다. 실제 응답 이름이 다르면 확인 후 추가한다. 국내 판매처라고 국내 재고/직배송을 보장하지 않는다.
- 공급자 최대 20건 안에서 표시 가능한 국내 상품을 최대 12개 제공 순서대로 표시한다. 이름·가격 문자열·판매처·commissionlink를 쓰며 브랜드/재고/정확한 상품 속성을 추정하지 않는다. 구매 링크는 애드픽 HTTPS 링크 호스트와 로그인한 공식 W컨셉 제휴몰 상세에서 확인한 `bitl.bz`만 허용하며, 외부/유효하지 않은 링크나 키를 포함한 값은 제외한다. 이미지는 원래 HTTPS 주소를 브라우저에서 표시하며 서버 프록시·다운로드·백업을 하지 않는다.
- 최초 연결에서는 검색/옷장 등록 검색의 라쿠텐 섹션 앞에 ‘국내 쇼핑몰에서 찾기’를 추가하고 명시적 불러오기 버튼으로 호출했다. **후속 변경:** 현재 찾기·등록은 검색 제출 한 번으로 호출하며 타이핑마다 조회하지 않는다. 상담의 없는 브랜드 조회 버튼은 누를 때만 호출한다. [한 번 검색 구현](automatic-search-open-catalog-20261022.md). 키워드 검색이며 앱의 예산·코디 조건 적용/AI 추천은 아니라고 밝힌다. 원화 참고가격과 확인 시각, 구매 링크 전에 제휴 수수료 표시를 둔다. 브랜드·상품명 검색어를 사용자가 바로 수정할 수 있다. 실제 공급자 검색이 여행·화장품·다른 브랜드까지 섞는 것을 확인했으므로 상품명에 입력 단어가 모두 있는 결과만 표시한다(NFKC/대소문자 정리 후 문자열 포함 검사). 동의어·한국어 조사·핏/예산 해석은 하지 않으며, 원래 상품명·제공 순서를 고치지 않는다. 등록/구매를 자동 실행하지 않는다.
- 0건, 필수 정보/국내 판매처 미확인으로 모두 제외된 결과, 공급자 오류를 구분한다. 실패를 대체 상품이나 성공으로 표시하지 않는다. 외부 API 결과를 AI 추천 입력으로 보내지 않는다.

## 최초 연결 전 실행 순서 기록 (이후 완료, 키 재입력 지시 아님)

1. 대표가 기존 애드픽 키를 Cloudflare 프로덕션 런타임 `ADPICK_API_KEY` Secret에 직접 입력·저장한다. Chrome 폼에 이름·비밀 체크만 준비했고 값은 비워뒀다. 기존 4개 Secret은 바꾸지 않았다. 새 인증정보 입력·제출은 브라우저 도구 규칙상 사용자 인계 사항이다. 대표가 창이 안 보인다고 하여 Chrome 창 메뉴에서 해당 설정 창을 앞으로 가져오고 값 칸에 커서를 놓았다.
2. 실제 API 상품명·가격·사진·commissionlink를 우리 인증된 경로에서 소수 조회해 대조한다. 키나 키를 포함한 제공자 URL/오류 원문은 수집하지 않는다. 코드의 허용 호스트/스키마가 실제 응답과 일치해야 한다.

### 다음 운영 시 직접 배포가 필요한 경우

먼저 master와 빌드 결과를 확인한다. 당시 Git 자동 빌드 지연 원인은 미확정이었지만 PR #47의 master 자동 빌드는 이후 성공했다. 항상 자동 배포가 고장 났다고 가정하지 말고 필요한 경우에만 공식 CLI를 사용한다. 현재 분기별 빌드 설정은 [시스템 인수인계](system-handover.md#6-빌드배포와-프리뷰를-구분하기)를 따른다. 비밀 키를 파일이나 명령에 넣지 않는다.

```bash
cd app/lite
npm run build
npx wrangler login --device --browser=false --use-keyring --scopes account:read user:read workers_scripts:write
# 계정 소유자가 표시된 공식 인증 페이지에서 직접 승인
npx wrangler deploy --keep-vars --strict
# 실제 버전/앱 조회를 확인한 뒤
npx wrangler logout
```

기존 owner 인증·D1 바인딩·Secret 이름을 보존한다. `workers:write`로 대체하면 이번 실제 배포 조회에서 거절됐으므로 재사용하지 않는다. 유료 전환이나 공개 접근 해제는 이 절차에 포함되지 않는다.
