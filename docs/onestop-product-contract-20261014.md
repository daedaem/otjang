## Claude Opus 5.5 교차 검토와 선택 이유

기존 사업 검토 대화에 새 원스톱 목표와 구현안을 전달했다. Claude의 첫 검토는 설명을 읽은 설계 검토이며 소스 실행·실기기·147개 기존 검사의 재현이 아니다. 대화: https://claude.ai/chat/edb94e33-80fa-4c8f-9175-a74a92c2e917

1. **같은 상품 페이지와 같은 옵션은 다르다.** 상품 번호를 일치시켜도 색/사이즈가 같다고 단정하지 않는다. originalUrl, 정규화 링크, productId, 확인한 색, 자유 입력 옵션과 정보 출처를 별도로 남긴다. 가격 출처는 색 출처와 별도다. 같은 종류/색은 유사성만, 같은 상품 번호와 확인한 색도 동일한 사이즈·핏 보장이 아니다.
2. **수령과 확정 보유는 다르다.** received에서 옷·여정을 한 번의 트랜잭션으로 보관하되 잠정 수령으로 보유 추천에서 제외한다. kept 버튼을 직접 누른 뒤에만 내 옷장과 다음 추천에 반영한다. returned는 다시 제외한다. 원래 옷과 사진을 삭제하지 않는다.
3. **있음/교체는 옷 ID로 연결돼야 한다.** 관련 옷 ID와 교체 대상 ID를 저장한다. 기존 옷 실제 처분은 별도로 확인하고 사진/원문은 보존한다. 새 옷을 반품해도 처분한 옛 옷이 저절로 부활하지 않는다. 사용자가 명시 복구할 때만 다시 보유로 표시한다.
4. **주문 줄 추가는 구매 단위 정의에 달려 있다.** 이번 journey는 상품·옵션 1개, 수량 1의 독립 기록이다. 여러 사이즈는 각 여정에 기록한다고 화면에 명시한다. 동일 상품 번호만으로 합치지 않는다. 다른 옵션을 기록할 때 새 여정을 생성하고 forkedFrom으로 처음 후보에 연결하며, 원래 결정·이력을 보존한다. 옵션을 모르는 사용자 직접 기록은 미확인으로 남기고 실제 옵션 비교·확인된 거래로 세지 않는다. 이를 주문 번호 전체나 여러 주문 줄을 관리하는 실제 주문 연동으로 표현하지 않는다. 다상품 주문 그룹은 향후 확인된 주문 서버 모델에서 추가한다.

- 후보 정보에 모르는 종류·색을 허용한다. 비교는 보류 사유를 반환한다. 확정한 실제 옷 ID·색·종류만 코디 공식 완성 수에 사용하며 예시 옷과 다른 구매 후보로 수를 부풀리지 않는다.
- 결정 buy/hold/skip와 단계 candidate/ordered/received/kept/returned는 분리한다. 판매처 방문은 상태를 바꾸지 않는다. 모든 주문·반품은 현재 사용자 직접 기록이다.
- 수령 생성 ID는 여정 기반으로 결정하고, 새 옷과 여정 상태를 동일 commit으로 저장한다. 용량/충돌 실패 시 둘 다 이전 상태를 유지한다. 다시 눌러도 같은 옷을 중복 생성하지 않는다.
- 원본 옷은 garments에 남고 실제 보유 목록 closet은 잠정 수령·반품·확정 교체 대상을 제외한 view다. 백업에는 원문과 사진이 남는다. 착용 기록은 kept 뒤에만 누적한다.

- 옵션·이유는 선택 입력이며 접힌 영역에 둔다. 개인 옷 사진은 외부 전송하지 않는다. 인증·결제·카드 정보는 이번 로컬 기록에 저장하지 않는다.
- 구현 코드는 Codex와 보조 에이전트가 작성했고, 제품의 원스톱 범위는 사용자 요구다. 사용자 검토와 실제 서비스 검증을 AI 구현으로 대체하지 않는다.

## 이후 작업의 순서와 의존성

1. 실제 모바일에서 같은 사용자·옷·후보로 전체 연결 흐름을 확인한다. 등록 시간/입력 수, 판단 이유, 원래 상품과 옵션 유지, 재방문·복원까지 관찰한다.
2. 권리와 범위가 확인된 상품 공급·현재 가격·옵션을 연결하고 서버 저장/계정·동기화를 설계한다. 임의 무료 API나 스냅샷 수집만으로 상용 이용권을 주장하지 않는다.
3. 옷·상품 ID와 연결되는 코디 탐색·커뮤니티를 만들고 사진 공개 동의/신고/운영을 연결한다. 초기 읽기 전용 큐레이션과 실제 사용자 게시를 구분한다.
4. 가상 착용 품질을 동일 사진·상품으로 비교해 채택한다. 실제 비용·권리·사진 전송 동의 및 삭제 정책을 결정한 뒤 제공한다. 불확실한 합성을 실제 핏/사이즈 보장으로 쓰지 않는다.
5. 확인된 주문·배송·반품 이벤트를 구매 여정에 연결한다. 장기적으로 직접 구매 플랫폼 확장을 검토한다. 유료 API/결제 계약·사용자 사진 외부 전송은 이번 개발만으로 승인된 것으로 취급하지 않는다.

각 단계의 실패 조건·완료 증거를 문서와 PR에 남긴다. 일부 연결 기능이 통과해도 원스톱 전체가 완성됐다고 표시하거나 목표를 완료 처리하지 않는다.
