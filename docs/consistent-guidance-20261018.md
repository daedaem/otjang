## 기준과 통합

Claude `bc348984718e7ae1e9dbcda3461e738f94376f8e`의 검색·옷장 수정과 기존 로컬 구매내역 가져오기 기능을 통합했다. 구매내역 기능은 먼저 로컬 `4effd4d`에 보존했고 통합 커밋은 `0835062`다. CSS 충돌은 두 기능의 스타일을 모두 보존해 해결했다. 개인 사진·13벌 원본·브라우저 보유 기록·DB는 통합 대상으로 쓰지 않았다.

## 수정 이유와 동작

### "더 좋은"은 높은 가격순이 아니다

기존 `followUpQuery`는 "더 좋은 걸로"를 높은 가격순으로 바꿨다. 가격은 소재·마감·착용감 품질을 입증하지 않으므로 이 해석을 제거했다. 이제 비교 자료가 부족하다고 알리고 이전 요청·순서·사용자가 뺀 조건을 보존한다. "더 싼/비싼 걸로"만 가격순으로 처리한다. 가격순 요청을 연속으로 바꿔도 원래 종류·예산·제외 조건을 잃지 않는다.

새 `src/search-follow-up.js`는 입력 해석만 담당한다. 실제 검색은 기존 엔진을 쓰며 유료 모델·외부 요청·새 저장 형식은 도입하지 않았다.

### 코디 설명은 실제 구성 옷에서 만든다

코디 공식에 쓰인 예시 제목·설명이 현재 선택된 내 옷과 다를 수 있었다. 새 `src/outfit-copy.js`는 구성 행의 옷 종류와 확인된 색으로 카드·상세 설명을 만든다. 예시 공식의 "흰 셔츠"나 "네이비 재킷"을 현재 구성에 없는 옷처럼 말하지 않는다. 세부 종류·색을 모르면 추측하지 않는다. 공식 ID·규칙·기존 착용 기록·공유 기록은 바꾸지 않는다.

### 등록 종류는 쇼핑 카탈로그와 분리한다

사진·수동 등록·링크 후보·빠른 비교가 동일한 `garmentKindChoices`를 쓴다. 성별은 첫 화면 정렬만 바꾸고 카탈로그에 없는 종류를 숨기지 않는다. 예를 들어 여성 카탈로그에 비니 상품이 없어도 비니를 등록할 수 있다. 기존 데이터가 이미 지원하던 `beanie`의 표시 이름을 추가했고 `sweat`은 실제 분류 범위에 맞게 "맨투맨·후드"로 표시한다. 저장된 종류 ID와 스키마 7은 유지한다.

세부 종류와 상품 ID는 사용자 확인이나 정확한 상품 연결이 있을 때만 남긴다. 해당 성별의 코디·상품 자료가 없으면 그 한계를 알리고 종류만 저장한다. 추천 가능한 종류와 실제 보유 가능한 종류를 같다고 가정하지 않는다.

- 기존 코디 복귀·최근 착용 정렬 검사는 고정된 예시 제목 대신 동일한 공식 ID로 복귀·정렬을 확인하게 했다. 여성 등록 검사는 보유 가능한 일반 종류와 성별별 카탈로그 세부 종류를 구분하도록 바꿨다. 사진 분석의 제안 목록에도 비니를 추가했으며, 제안은 사용자 확인 없이 저장하지 않는다. 비니 인식 정확도를 실사진으로 측정한 것은 아니다.
