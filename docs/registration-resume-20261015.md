## 보유 상품 검색을 분리한 이유와 저장 계약

이전 추가 버튼은 구매 추천으로 이동했고, 그 검색에는 예산·계절·취향 조건이 적용됐다. 이미 가진 옷의 등록에 구매 조건을 적용하면 실제 상품이 숨겨지고 사진·수동 초안을 잃을 수 있다.

새 경로는 추가 → 브랜드·품명·현재 목록의 상품 주소 검색 → 상품 선택 → 실제 보유 확인 후 저장이다. 검색에는 구매 추천 조건을 적용하지 않는다. 목록 밖 링크는 정보가 없다고 표시하고 사진·종류 등록으로 돌아간다. 새 상품을 외부에서 자동 수집했다고 표시하지 않는다.

- 검색·상품 선택만으로 보유 옷·구매 여정을 만들지 않는다.
- 색은 확인한 자기 옷 값만 유지한다. 상품 색은 별도 선택해야 복사하며, 사진 추정 색은 복사하지 않는다. 색을 모른 채 저장할 수 있다.
- 확인한 색과 상품의 근거 있는 색이 다르면 같은 상품 확인을 막는다. ‘다른 색·비슷한 옷’은 정확한 상품 ID·세부 종류·브랜드를 새로 추정하지 않는다.
- 직접 선택한 사진·입력 이름은 유지하며 외부로 보내지 않는다. 판매처 사진은 출처를 표시한다.
- 최종 확인은 기존 `saveGarmentDraft` → `set` → IndexedDB 트랜잭션을 이용한다. schema 5를 유지하고 검색·선택 UI 상태는 저장하지 않는다.
- 이미 연결한 상품이 있으면 한 벌 추가라는 사실을 확인 화면에 표시한다. 중복 클릭으로 조용히 새 옷을 만들지 않는다.
- 저장 실패 시 사진·검색어·선택 상품·색을 유지해 다시 시도한다.
