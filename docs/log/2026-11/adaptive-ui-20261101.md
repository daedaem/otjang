## 원문(2026-11-01 기록)

- 단계(`src/screen.html` 끝의 「다기기 대응」 CSS): 휴대폰(<600, 기존과 같음) · 중간(600~899, 본문 최대 760px, 여백 24px) · 넓음(≥900 본문 960px, ≥1200 1120px) · 낮은 가로 창(폭 ≥600·높이 ≤500). 이전의 ≥900 본문 920px·상세 2열·결과 4열은 이 규칙이 이어받는다.
- 왼쪽 메뉴 줄: 넓음과 낮은 가로 창에서 하단 탭(`#tabs`)이 왼쪽 88px 세로 줄이 된다(같은 요소, CSS만 바뀜). 칸 높이는 창 높이에 맞춰 44~60px(낮은 가로 창 44~52px)로 줄고, 그보다 낮은 창은 메뉴 줄 안에서 스크롤된다(높이 280px까지 여섯 칸이 잘리지 않음을 검사). 이때 `--tabs`는 0, `--navL`이 메뉴 폭이고 아래 고정 막대(띠·구매·상담 입력·핀·옷장 시트)는 `left: var(--navL)`. 탭이 숨는 화면(상세 등)은 메뉴 줄도 없다.
- 아래 막대 높이: `src/browser/viewport.js`(빌드가 `shared/viewport.<해시>.js`로 복사, 앱 `<main>` 바로 뒤와 독립 /c `<head>`에서 불러옴. /c는 CSP상 인라인 스크립트가 안 되고 `community-public.json` 허용 목록에 넣었다)가 화면 아래에 붙은 고정 막대 높이를 재어 `--chrome-b`·`data-chrome`을 두고, 본문 끝 여백을 그 높이 + 24px로 맞춘다(화면별 고정 여백 대신). 화면 변화(MutationObserver)에는 다음 그리기 전에 바로 잰다. 옷장 시트의 자체 여백은 이 규칙이 없을 때만 쓴다.
- 스크롤 위치: 같은 스크립트가 스크롤할 때 화면 위쪽(고정 머리 아래) 가운데의 요소를 기준으로 기억하고, 배치가 바뀌면 아래 여백을 먼저 새 크기로 잰 뒤 그 요소를 같은 높이로 되돌린다. 배치 열쇠는 창 폭(회전·펼치기·분할)과 짧은 창 단계(메뉴 줄 조건 `(min-width: 600px) and (max-height: 500px)`를 innerWidth·innerHeight로 직접 잼)다. 그래서 690×600 ↔ 690×480처럼 높이만 바뀌어도 메뉴 줄이 켜지고 꺼지면 되돌린다(Codex #149 검토, 브라우저 자체 스크롤 고정을 끈 Chromium에서 78px 밀림 재현 후 수정). 처음에는 matchMedia().matches로 쟀는데 #149 `2188b88`의 WebKit 두 실행에서 같은 78px로 실패했다. WebKit은 resize 처리 중 matches가 아직 이전 값이라는 추정으로, matches를 다음 프레임까지 이전 값으로 두는 모형으로 Chromium에서 재현한 뒤 창 크기로 직접 재게 했다. 첫 모형은 `Object.assign`이 getter를 옮기지 못해 "Cannot set property matches … which has only a getter" 예외로 viewport.js가 아예 돌지 않은 채 78px가 나온 것이라 증거가 못 됐다(검토 11-01, 확인함). 고친 모형(진짜 MediaQueryList를 감싼 보통 객체)은 페이지 예외 0, viewport.js 실행, resize 중 이전 값(false)→다음 프레임 새 값(true)을 검사로 확인하고, 그 조건에서 `2188b88`의 viewport.js는 78px로 실패, 수정본은 통과함을 로컬에서 확인했다. WebKit 실제 원인은 여전히 추정이며 최종 CI로만 확인한다. 되돌린 다음 프레임에 한 번 더 되돌려, 미디어 조건 변화로 다시 그려진 화면이 기준을 밀어도 바로잡는다. 배치가 그대로인 높이 변화(휴대폰 주소창 접힘)와 입력 중 키보드로 높이만 줄어든 변화(단계가 바뀌어도, 46px 움직임 재현 후 수정)에서는 스크롤을 건드리지 않는다. 되돌린 직후 0.5초 동안은 되돌린 위치 그대로이거나 내용이 짧아져 맨 끝으로 당겨진 스크롤 이벤트로 기준을 바꾸지 않고(연속 크기 변화 중 밀림 방지), 사람이 그사이 다른 곳으로 스크롤하면 바로 새 기준이 된다. 폭이 바뀌었는데 resize 이벤트가 아직 안 온 동안의 스크롤 이벤트도 기준을 바꾸지 않는다(11-01 후속 수정, 아래 「간헐 실패 해결」).
