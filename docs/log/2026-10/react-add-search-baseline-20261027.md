# 상품 검색 등록 React 전환 전 기준

담당은 Codex 한 곳이다. R22 B6b PR #86의 최종015219d를 기반으로 다음 화면의 기존 동작만 조사/검사했다. 이 기록은 #86 병합이나 검색 화면 전환 완료를 뜻하지 않는다. 거울의 최종244개/검토를 확인하고 병합한 뒤 검색 화면의 별도 PR을 진행한다. 새로운 사업/디자인 방향·상품 수집·사진 전송·배포는 포함하지 않는다.

## 이미 있는 검사와 빈 부분

`e2e/input.spec.ts`의 vanilla/react 두 모드는 직접 등록의 새로고침·저장 실패/재시도·기존 구매 기록 보존과, 카탈로그 검색→가지고 있어요→색 선택→옷장→상품 비교를 이미 확인한다. 같은 성공 경로를 복사하지 않는다. R22 옷장/편집/사진/백업 검사도 그대로 유지한다.

추가한 `e2e/add-search.spec.ts`의4개 상황은 현재 바닐라 검색 화면에서 두 브라우저8개가12.7초에 통과했다.

1. 이미 옷/구매 결정을 가진 상태에서 검색 입력/결과 조회만 하면 주 저장 원문·최근 요청을 쓰지 않는다.
2. 글자를 입력하는 동안 판매처 검색을 제출하지 않는다. 명시적으로 제출한 검색만 국내 API에 보내고, 글자가 달라지면 앞선 제출 결과를 비운다.
3. 공개 상품 검색의 뒤늦은 첫 응답이 두 번째 응답을 덮지 않는다. 고른 두 번째 정보만 기존 React 등록 초안에 들어가며, 정보 선택만으로 보유 옷이 생기지 않는다.
4. 카탈로그 보유 추가의 저장 실패가 검색어와0벌을 유지하고, 다시 누르면 같은 상품 한 벌만 저장되며 재실행 후에도 같다.

실제 API·키·개인 사진은 사용하지 않았다. API는 합성 응답으로 막고 공개 상품의 기존 draft 변환기를 재사용했다. 가상의 가격/재고를 만들어 사용 가능 데이터로 추가하지 않았다.

## 옮길 경계

현재 `screen.html`의 `V.add/A.add`, `renderAddResults`, 공개 상품/사용자 등록 결과와 판매처 결과가 이전 대상이다. 도메인 `findProducts`/`addOwnedProduct`, 기존 `Input`/등록 스키마·영수증·BK/사진·구매 command는 UI에서 다시 구현하지 않는다. 입력 중의 로컬 검색과 명시 제출의 서버 검색을 분리하고, 검색 세대와 수명으로 늦은 응답을 무효화한다.

카탈로그의 ‘같은 상품’, 사용자 등록의 확인 수, OPF의 코드/출처·가격/재고 없음, 국내 광고 고지, Rakuten의 JPY/지원 표기를 보존한다. 상품 원본 사진은 원격 그대로 표시하고 내 사진의 대체 이미지로 확정하지 않는다. OPF 선택은 기존 `registrationDraft`/`Input`으로 넘기고 구매 완료/보유로 바꾸지 않는다. 사용자 등록의 추가 정보 저장 실패는 이미 저장된 같은 옷으로 재시도하는 경계를 조사해 보존한다.

전환은 지연 React entry·기존 mount/routing 호스트로 나누고 작은 컴포넌트로 작성한다. 기존 결과·등록·다른 화면용 공급자 코드와 fallback은 확인 없이 제거하지 않는다. 직접 진입에서 홈 예시 검색을 먼저 쓰는 일이 없는지, 키보드/뒤로가기·글자 두 배·런타임 실패·방문 뒤 오프라인도 새 화면에서 확인한다. 같은 합성 자료/viewport의 전후 화면을 남기되 실물 휴대폰·상품 권리·실제 제공자 품질 검증으로 표시하지 않는다.
