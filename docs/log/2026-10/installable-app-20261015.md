# 설치형 앱(홈 화면에 추가) — 2026-10-15

> 문서 시점: 2026-10-15. 당시의 검토·구현 기록을 보존한 자료입니다. 현재 결정·우선순위·운영 상태는 [최신 문서 목차](../../README.md)를 확인합니다. 아래의 “지금·완료·다음”은 별도 갱신 표시가 없으면 당시 기준입니다.

어울 서버가 앱을 직접 보낼 때, 브라우저가 이 앱을 홈 화면 앱으로 설치할 수 있게 했다.

## 추가한 것

| 파일 | 역할 |
|---|---|
| `app/public/manifest.webmanifest` | 이름 "어울", 독립 창(standalone), 흰 배경, 아이콘 목록 |
| `app/public/icons/` | 옷걸이 아이콘. SVG 원본(`icon.svg`, `maskable.svg`)과 PNG(192·512·마스커블 512·애플 180) |
| `app/public/sw.js` | 연결이 없어도 앱을 열 수 있게 하는 서비스 워커 |
| `app/index.html` | manifest, favicon(SVG·PNG), apple-touch-icon 연결 |
| `app/tools/build.mjs` | `public/`을 빌드 결과 옆에 복사(`--fragment` 빌드는 제외) |
| `server/src/app.js` | 위 파일을 이름이 정해진 것만 보냄. 같은 폴더의 다른 파일은 보내지 않음. `/favicon.ico`에는 앱 아이콘을 보냄 |

아이콘은 무채색 바탕에 흰 옷걸이를 그리고 강조색 점 하나를 더했다. 수상작 조사에서 정한 "무채색과 강조색 하나" 규칙을 따른 것이다(`docs/design-system-20261015.md`). PNG는 SVG 원본을 Chromium으로 그려 만들었다. 다시 만들 때도 같은 SVG를 아무 SVG 렌더러로 그리면 된다.

## 서비스 워커가 저장하는 것과 저장하지 않는 것

- **저장함**: 앱 페이지(`./`), manifest, 아이콘 3개.
- **저장 방식**: 앱 페이지는 네트워크를 먼저 쓰므로 새 빌드가 바로 반영된다. 네트워크가 실패했을 때만 저장한 사본으로 연다.
- **저장하지 않음**:
  - 계정·옷장·사진 API(`/v1/…`): 연결이 없으면 실패한다.
  - 다른 사이트의 상품 사진
- 옷장 자료는 원래대로 브라우저의 IndexedDB에 있다. 서비스 워커는 그 자료를 읽거나 복사하지 않는다.
- 등록 조건이 맞을 때만 서비스 워커를 등록한다.
  - 어울 서버가 보낸 페이지(`eoul-api=same-origin` 표시가 있음)이고, https 또는 localhost여야 한다.
  - 다른 곳에 올린 페이지(미리보기·`--fragment`)는 지금처럼 일반 웹페이지로 동작한다.

## 설치 안내(내 설정 → 앱으로 쓰기)

- **Android·데스크톱 Chrome**: 브라우저가 설치를 제안하면 "홈 화면에 앱으로 설치" 버튼을 보여 준다. Chrome에 설치한 앱은 브라우저와 같은 저장 공간을 쓴다.
- **iPhone·iPad Safari**: "공유 → 홈 화면에 추가" 순서를 안내한다.
  - 홈 화면 앱은 Safari와 저장 공간이 따로일 수 있다. 그래서 먼저 사진 포함 백업을 받아 두고, 앱에서 백업 가져오기로 옮기라고 함께 안내한다.
  - 근거는 기존 보관 안내 화면과 같은 WebKit 문서(2020-03-24, 2023-08-10)다.
- **이미 홈 화면 앱으로 열려 있으면**: "홈 화면 앱으로 열려 있어요"만 보여 준다.

## 검증

- 서버 테스트 36개 통과(1개 생략). 새 테스트가 확인하는 것:
  - manifest·sw.js·아이콘의 종류와 캐시 헤더
  - `/favicon.ico` 응답
  - 빌드하지 않은 파일은 404
  - 같은 폴더의 다른 파일, `..` 경로는 404
- 앱 테스트 525개 통과.
- 실제 서버(`createApp`)와 Chromium으로 확인한 것:
  - 일반 프로필에서 설치 가능성 오류 0개(`Page.getInstallabilityErrors`). 시크릿 창에서는 "in-incognito"만 나온다.
  - manifest 파싱 오류 0개.
  - 서비스 워커 활성. 캐시에는 앱 페이지·manifest·아이콘만 들어 있다.
  - 연결을 끊고 새로 고쳐도 앱이 열린다. 연결이 없을 때 `/v1/health`는 캐시가 아니라 네트워크 오류로 끝난다.

## 확인하지 못한 것

- 실제 iPhone 홈 화면 추가, Android 설치 버튼, 설치 뒤 저장 공간 동작은 휴대폰에서 확인해야 한다.
- iOS 홈 화면 앱이 Safari의 7일 삭제 대상에서 빠지는지는 WebKit 문서를 근거로 안내하지만, 보장은 아니다(화면 문구에도 그렇게 적었다).
