# 검색 결과·공급처 공유 React 이전 (WO-03)

기준 master는 WO-02를 병합한 `1a96177`(#90)이다. 담당은 Claude 패션(Opus 5.5)이고, 브랜치는 `claude/wo-03-results-20261027`이다. WO-03은 작은 PR 두 개로 나눈다.

- **WO-03a:** 공급처 패널(국내 애드픽, 공개 상품 정보, 라쿠텐)을 공유 React 부품으로 만들고, 등록 화면이 이 부품을 쓰게 한다.
- **WO-03b:** 검색 결과 화면 본문(조건, 0건·미해석, AI 순위, 상품 카드, 걸기·묻기)을 React로 옮기고, 공급처 부품을 재사용한다.

이 문서는 상품 상세·구매 판단(WO-04)이나 상담 화면(WO-06)의 이전 기록이 아니다.

## 기준선 검사 (먼저 추가)

결과 화면에는 전용 브라우저 검사가 없었다. 그래서 바닐라의 현재 동작을 먼저 `e2e/results.spec.ts` 10개로 고정했다(`97ea51d`). 현재 화면에서 모두 통과했고, 3번 반복해도 같았다.

- AI 순위: 기다림 표시 → 순서 변경과 이유 표시, 상세에 갔다 돌아와도 다시 묻지 않음. 실패하면 엔진 순서와 이유 문구를 보여 준다.
- 조건: 조건 빼기, 0건일 때 직접 넓히기. 다른 옷으로 채우지 않는다.
- 미해석 요청과 일부만 이해한 요청은 상품을 채우지 않는다.
- 걸기: 처음 걸면 한 번 묻고, "없어요" 답이 카드에 반영되며, 5벌째는 한도 안내를 띄운다.
- 국내 상품: 제공 순서, 원래 가격 문자열, 광고 고지가 링크보다 먼저 나온다. 실패 후 다시 시도할 수 있고, 늦게 온 이전 검색 응답은 무시한다.
- 공개 상품 정보: 사실로만 보여 주며 출처(ODbL)와 기준일을 붙인다. AI 비교가 실패하면 코드 순서로 보여 준다.
- 라쿠텐: 버튼을 눌러야만 검색한다. AI 검색어는 고쳐서 쓸 수 있고, 엔화(JPY)·세전 표시와 라쿠텐 표기를 유지한다.
- 등록 화면: 제출한 말에만 공급처 패널이 나온다.

## WO-03a 공급처 패널

**무엇을 바꿨나.**

- `src/retail/`은 `DomesticPanel`, `OpenProductsPanel`, `RakutenPanel`과 이를 묶는 `RetailPanels`로 이뤄진다. 문구, 순서, 출처·광고 고지, 링크 `rel`(애드픽은 `sponsored` 포함)은 바닐라와 같다.
- 연결 함수(`EOUL_ADPICK`, `EOUL_RAKUTEN`, `EOUL_OPEN_PRODUCT_SEARCH`, `EOUL_SERVER_AI`)는 `screen.html`의 `retailHost()`가 화면을 열 때 읽는다. 바닐라도 화면을 그릴 때 같은 방식으로 판단한다.
- 국내 상품은 검색어마다 한 번 자동으로 시작한다. 100자를 넘는 검색어는 아무것도 보내지 않고 안내만 한다. 라쿠텐은 버튼을 눌러야 검색한다.
- 이전 검색어의 늦은 응답과 닫힌 패널의 응답은 반영하지 않는다.
- React 버튼에는 바닐라 전역 클릭 처리가 듣는 `data-adpick-search`, `data-rakuten-search`, `data-rakuten-plan` 속성을 붙이지 않았다. 그래서 다시 시도해도 공급처를 두 번 부르지 않는다(검사로 확인).
- 등록 화면은 `shoppingLinks` HTML을 `innerHTML`로 넣던 `RetailBridge` 대신 `RetailPanels`를 쓴다.
- 바닐라 `shoppingLinks`, `searchAdpick`, `planRakuten`, `searchRakuten`, `recommendOpenProducts`는 그대로 남아 있다. `?ui=vanilla` 화면, 아직 바닐라인 결과 화면(WO-03b 전), 상담 화면(WO-06)이 계속 쓴다. 이 함수들을 직접 읽는 Node 검사도 그대로 통과한다.

**발견해서 고친 것.** React 등록 화면의 `.as a { text-decoration: underline }` 규칙은 공개 정보 안의 짧은 링크용이다. 그런데 공급처 상품 줄과 라쿠텐 직접 검색 줄에도 밑줄을 넣고 있었다. 이 차이는 #88 이후 이미 있었다. 이번에 실패 테스트(`6537df0`)를 먼저 추가하고, 공유 패널 안에서는 밑줄을 빼도록 고쳤다(`.as [data-react-retail] a`).

## WO-03b 결과 화면

**무엇을 바꿨나.**

- **계산은 한 곳:** `screen.html`에 `resultsModel()`, `gridModel()`, `cardModel()`을 두었다. 각각 결과 화면 내용, 격자 항목(카드와 그 줄 아래의 묻기·안내 줄), 상품 카드 값을 만든다. 바닐라 `V.results`, `gridHtml`, `cardHtml`은 이 모델로 예전과 같은 HTML을 만든다. 바꾸기 전후의 바닐라 HTML을 12개 상태에서 비교했고 모두 같았다.
- **React 화면:** `src/results/`(`EOUL_RESULTS_LOAD` 섬). 같은 모델을 그린다.
  - 위 막대(뒤로, 다시 찾기, 판단 기준)
  - 조건 칩과 조건 빼기, 0건·미해석·일부 이해 화면, 넓히기, 대신 볼 것, 예시
  - AI 순위의 기다림·재정렬·실패. 재정렬 애니메이션은 줄인 동작 설정을 따른다.
  - 상품 카드와 걸기 버튼(처음 걸 때 튀는 표시 포함), 묻기 줄과 4벌 한도 안내 줄
  - 상황과 덜 맞는 옷 격자, 공유 공급처 패널(WO-03a)
- **공유 상태 유지:** AI 순위 결과는 예전처럼 화면 상태 `S.ai`, `S.aiOrder`, `S.aiSummary`에 저장한다. 그래서 상세 화면의 AI 이유와 다시 돌아왔을 때의 순서가 그대로이고, AI를 다시 부르지 않는다. 화면을 떠난 뒤 늦게 온 순위는 저장하지 않는다(바닐라와 같음).
- **이중 처리 방지:** React 버튼은 바닐라 전역 클릭 처리가 듣는 `data-pid`, `data-hang`, `data-own`, `data-drop`, `data-relax`, `data-q`, `data-edit`, `data-back`, `data-disclose`를 쓰지 않는다. 대신 호스트 함수를 부른다. 걸기는 바닐라 `toggleHang`의 코어 처리(4벌 한도 안내, 한 번 묻기 표시, 아래 띠)를 그대로 하되, 화면을 다시 그리는 일은 React가 맡는다.
- **스크롤 복원:** 상세에서 돌아오면 라우터가 다음 프레임에 스크롤을 되돌린다. 그런데 React 화면은 그보다 늦게 그려질 수 있다. 그래서 React 화면이 첫 렌더 때 같은 위치로 직접 되돌린다. 바닐라 기준선 검사를 먼저 추가했다(`0eebbf5`).
- **새로고침:** 체험용 옷장처럼 `K.refresh()`가 오면 화면을 다시 만들지 않고 그 자리에서 갱신한다.
- **바닐라 경로 유지:** `?ui=vanilla`이거나 섬을 불러오지 못하면 바닐라 결과 화면을 쓴다. 섬 로딩이 실패하면 "새 결과 화면을 열지 못해 기존 화면으로 열었어요."라고 알린다.

**남긴 경계.**

- 사진이 없을 때의 색 타일은 코어 템플릿(`photoHtml`) HTML을 그대로 넣는다. WO-01의 `ProductPhoto`와 같은 방식이다.
- "있어요"를 누르면 열리는 색 고르기 시트는 바닐라 시트 그대로다. 공통 시트는 WO-08에서 다룬다.

- 상담 화면의 국내 상품 버튼과 추천 카드(`recCard`)는 WO-06이다.
