# 설치 앱 갱신·인증 화면 캐시 보호 (WO-09 코드 마감)

기준 master `7fdb1273baac6220b556a1b9cff71ad8af204c7c`(#123). 담당 Codex 어울 개발. 대표의 나머지 전체 마감 지시에 따른 [이슈 #122](https://github.com/daedaem/otjang/issues/122) 후속이다. 실제 폰·Files/공유 검증 완료와 구분한다.

## 문제와 선택

1. 기존 워커는 설치 직후 `skipWaiting`을 호출하고 활성화 때 이전 캐시를 지웠다. 이전 탭이 나중에 불러올 해시 화면 파일을 보존할 수 없는 구조였다. React 파일도 방문 후에만 저장해 미방문 화면은 오프라인에서 열리지 않았다.
2. 모든 같은 출처 navigation의 성공 응답을 '/'에 저장했다. 로컬 재현에서 계정 화면의 합성 인증 HTML이 실제 앱 사본을 덮어썼다. 루트 로그인 이동을 따라간200 응답도 같은 위험이 있었다.
3. 워커 소스가 빌드 캐시 버전 계산에 포함되지 않아 워커만 바뀐 릴리스의 캐시 이름을 구분하지 못했다.

열린 탭을 강제 새로고침하거나 자료를 지우는 대신 다음을 선택했다.

- 새 워커는 기존 탭이 닫힐 때까지 기다린다. 처음 설치는 정상 활성화/claim으로 제어를 받는다. 이전 캐시는 새 워커가 실제 활성화할 때만 정리한다.
- React 실행 파일47개(574,856바이트)를 기존 앱 파일과 함께 처음에 보관한다. 설치 시 보관량을 약575KB 늘리는 대신 미방문 화면과 이전 탭의 지연 파일도 같은 버전으로 열 수 있게 한다. 실제 휴대폰 속도·공간은 별도 확인이다.
- API·본인/회원 인증·공개 커뮤니티 문서는 워커의 앱 캐시를 거치지 않는다. navigation은 '/'·'/index.html'의 성공한 비이동 HTML만 앱 사본으로 보관한다. JSON·로그인 이동·계정 문서는 보관하지 않는다.
- 오프라인 navigation은 그 워커의 루트 사본만 사용한다. 반환 HTML에 `hangit-offline=1` 표식을 붙이고, 내용이 바뀐 응답의 길이/인코딩/etag/수정일 헤더를 제거한다. 표식은 계정·오프라인 상태를 구분할 후속 경계이며 서버 인증을 대신하지 않는다.
- 워커 원본도 빌드 버전 계산에 포함한다. 캐시에는 정적 코드/예시 사진만 있으며 API·개인 옷장/사진·쿠키를 추가로 보관하지 않는다.
