# R22 B5b — 코디 화면·반응 저장·AI 비교

기준 master는 B5a #83의 headdb380397을 최종 CI11개·실제174개 두 작업/Node327개·미해결 검토0 확인 후 병합한 `24ed71e5514f4b1659d02132cca5ffd24cfdfb5d`다. 이 화면은 후속 후보이며 활성 배포·실기기·실제 모델 품질·대표 블라인드20을 확인한 것이 아니다. B6와 남은 전체 React 전환도 별도 완료 조건이다.

## 사용자 흐름과 유지한 동작

코디 탭 본문은 React로 옮겼다. 기본 요청이 들어 있어 실제 내 옷 조합이 있으면 추가 필수 입력 없이 ‘AI로 비교’를 누른다. 상황 칩과 계절/스타일은 선택이며 스타일은 최대3개다. 옷장이 비어 있어도 상품 찾기로 바로 돌아가고, 체험용 코디는 가진 옷/AI 입력/실제 반응과 분리한다. 반환된 순위가 없을 때는 순위 없는 조합 후보로 표시한다.

날씨 카드는 기존 기능을 없애지 않고 접어 열도록 했다. 큰 날씨/구매 후보 영역이 코디 입력을 아래로 미는 것을 줄이기 위한 선택이다. 연 뒤에 조회하며 날짜·지역·다른 조합·부족한 상품 통로를 유지한다. `WeatherSlot`의 기존 HTML/controller 연결은 별도 날씨 React 전환 전까지의 경계이며, 이 wrapper를 날씨 전체 전환 완료로 쓰지 않는다.

상황별 기본 공식과 ‘한 벌만 더 있으면’ 상품·현재 조건 더 보기 통로를 유지했다. 상품 사진은 원문 표시만 하고, 바로 걸기/내리기는 같은 ID의 기존 compareAdd/compareRemove를 사용한다. 버튼을 중첩하지 않고 저장 실패/한도 오류를 그 상품 옆에 표시한다. 실제 보유나 구매 기록으로 자동 확정하지 않는다.

## 저장·복구·여러 창

`reaction-session.js`는 B5a의 `outfit-reactions:v1`만 적는다. 구성/상황의 안정된 ID(SHA256)를 사용하고 같은 조합의 현재 선택을 다시 눌러 건수를 늘리지 않는다. 기존 임의ID의 같은 조합 기록은 재사용하고 다른 역사 기록을 지우지 않는다. 반응ID의 대상 옷/상황을 바꾸어 다른 기록을 대체하지 않는다.

원문 사전 검증·공유 저장 잠금·대상별 최초 비교 기준을 사용한다. 실패한 선택은 RAM에 남고 다른 반응의 성공이 그 기준을 새 값으로 바꾸지 않는다. 타창 최신 값을 거절하고, 쓰기는 됐으나 확인 읽기만 실패한 경우 정확히 같은 값의 재시도는 추가 쓰기/중복 집계 없이 확인한다. 최대500개에서 새 대상을 거절할 때도 과거 기록을 자동으로 버리지 않는다.

Back/이동은 미보관 반응을 확인한다. 기준 옷 편집창이 위에 열려도 부모 반응 보호가 유지되고, 닫으면 실제 호출 버튼으로 초점이 돌아온다. 날씨 갱신/공유 스타일 로딩은 React 본문을 다시 만들지 않아 입력과 RAM을 유지한다. 미래/손상 원문은 편집 대신 백업 경로로 안내하며 기존 BK 원문 격리/활성 보존·복원/undo를 재사용한다.

쿼리·선택 상황·날씨 펼침은 화면 세션의 메모리 상태다. 등록 초안과 같은 영속 입력이라는 약속을 추가하지 않는다. 새로고침 때 이전 AI 응답/미제출 검색어를 개인 백업에서 복원한 것으로 표시하지 않는다.

## AI 요청과 화면 출처

`ai-session.js`는 전송한 불변 JSON을 정확한 source/cache key로 사용한다. 비교에 쓰는 옷 속성·삭제·후보·상황·계절·스타일이 바뀌면 옛 결과를 새 후보에 붙이지 않는다. 늦은 응답은 해당 입력의 캐시에만 보관할 수 있고 현재 다른 입력에는 적용하지 않는다. 전역 저장 버전이 아니라 실제 전송 사실로 대조해 비교함처럼 관계없는 변화에 추가 요청을 만들지 않는다. 같은 입력의 중복 클릭은 한 호출로 묶고, 같은 입력에 이미 받은 응답은 이전 응답으로 표시한다. 실제 제공자 metadata가 없으면 모델/토큰을 추정하거나0으로 만들지 않는다.

좋아요 뒤 카드가 다시 정렬되는 불편은 실패 화면 검사로 재현해 고쳤다. 화면의 현재 반응과 AI에 실제 보낸 반응 snapshot을 분리한다. 새 반응은 다음 명시적 비교에서 보내고 안내를 유지하므로 카드와 이유가 갑자기 사라지거나 추가 유료 요청이 자동 발생하지 않는다. 이 예외는 반응에 한하며 옷 정보/상황 변경의 source 무효화는 유지한다. 비교한 후보 수와 현재 생성한 후보 수를 AI 결과 옆에도 표시해 이번 일부 비교의1위를 전체 최적 조합으로 설명하지 않는다.

이유는 AI 응답 그대로다. 속성 대조 줄은 `확인: {옷 이름}의 …` 접두어로 해당 코디 설명 아래에 붙이고, 연결하지 못한 줄과 부분 검증 한계는 별도로 둔다. 사용자 화면의 차원별 뜻은 한국어로, AI 입력용 enum은 기존 계약대로 보낸다. 이를 실제 핏/전체 답변 검증으로 바꾸지 않는다. 겹치는 옷을 포함한 과거 조합의 반응이라는 범위도 유지한다.

사진/사진ID/미디어URL은 요청에 넣지 않는다. 실제 내 사진은 IDB/썸네일에서 가시 영역만 읽고 원본은 보관한다. 판매처 사진을 합성/배경 제거하지 않는다. 미리보기는 메모리 저장을 써서 실제 개인 옷장·반응·사진 복구 표식을 읽거나 덮지 않고 실제 AI도 요청하지 않는다.

## 검증 기록

- 실패 우선2262a08의 새6개가 모두 미구현으로 실패했다. 최종 새9개 포함 Node336개·빌드가 통과했다. 미래/타창/교차대상/확인 읽기 실패/중복/해제/늦은 AI/metadata/500개 보존/수동 검색·조회 경계를 검사했다.
- 최초 코디24개, 반응 뒤 순서 유지26개, 빠른 걸기/한국어32개를 순서대로 확인했다. 확장42개 중39통과/3실패에서 사진2건은 origin 중단 전 화면 밖 카드의 지연 읽기를 기다리는 검사 조건이었다. 가시 영역만 읽는 구현을 없애지 않고 실제 카드를 스크롤한 뒤 검사했다. WebKit1건은 기본 버튼을 Tab이 건너뛰는 동작을 작은 합성 화면으로 확인했고 제출 버튼에 자연 순서 `tabIndex=0`을 명시했다. 기존 input→Tab→제출 focused 검사를 약화하지 않았다. 보완 집중6개가 통과했다.
- 기본 기능 전환의 로컬 전체216개는7.7분에 통과했다. 이후 코디별 사실 줄/비교 범위/미리보기 보호를 보강한 최종 코디46개가 통과했고 전체 구성은 기존174개+46개=220개다. 최종 head CI의220개와 앞선216개를 구분한다. 새로운 실제 AI 호출·키 조회·수동 배포는 하지 않았다.

실제 iPhone/Galaxy·외장 키보드/화면 읽기·실제 모델 답의 블라인드20은 미검증이다. 글자 두 배 검사는 현재 합성 화면의 계산된 글자/행높이를 각각 두 배로 한 로컬 검사이며 실물 접근성 인증이 아니다. 대표의 선택·납득도를 자동으로 채우지 않는다.
