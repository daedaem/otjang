# R22 B2a 사진 보관과 사진 포함 백업 — 2026-10-26

대표가 승인한 B1→B2a→B2b→B3·B4→B5→B6 순서를 계속한다. B1 #76은 CI11개/읽기 전용 검토와 head를 확인한 뒤 master469255a에 병합했다. 기존 임시 폴더에 원인 미확인 tracked41개 파일 누락이 있어 그 상태를 되돌리거나 stage하지 않고, 깨끗한 기존 worktree에서 새 브랜치를 시작했다. 개인 원본 폴더·사진은 사용하지 않았다.

## 보존 설계

사진은 SHA256 주소의 불변 Blob으로 IndexedDB에 보관한다. 같은 사진 재수입은 재사용하고 다른 사진으로 같은 ID를 덮지 않는다. 사진 묶음 백업은 기존 format2 글자 백업을 포함하되 별도 봉투다. 기존 글자5MB 한도는 유지하고 사진 묶음은 별도 크기·형식·해시·중복 검사로 제한한다. 누락 참조와 연결되지 않은 사진을 모두 알린다. 일반 JSON 복원과 되돌리기는 이전 사진 Blob을 삭제하지 않는다.

사진 복원은 IDB 복구 저널을 먼저 보관하고 동기 pending 표식을 남긴 뒤 진행한다. 표식이 있으면 코어/초안/개인 자료의 새 저장을 막고 복구 화면을 연다. 사진은 추가만 하며 이전 원문·STASH/NEXT를 복구 저널에 남긴다. 글자 적용·보관본 승격·표식 정리가 끝나기 전 완료로 표시하지 않는다. 재시작 시 끝난 거래는 정리만 하고, 미완료 거래는 이전 글자 원문/복구 지점으로 되돌린다. 새 사진은 연결되지 않은 보관본으로 남을 수 있다.

앱은 사진을 서버·AI로 전송하지 않는다. 상품 사진 URL을 사진 저장 함수에 받지 않는다. 이 단계는 사진 백업·복구 기반이며 실제 사용자 사진 입력·레일은 B2b에서 연다. 합성 PNG/가짜 저장소와 실제 브라우저 IndexedDB만으로 먼저 검증한다.

초기 새8개는 모두 실패했다. 구현 후 결과·최종 head와 실행/미실행을 갱신한다.
