# 회원별 기기 보관·계정 전환 보호

2026-10-28. 대표의 남은 전체 마감 지시로 WO-10에서 확인한 계정 혼합을 고친다. 기반 master는 #124 `9b36da1`, 실패 먼저 커밋은 `8dfa989`다. 구현 담당은 Codex 어울 개발 한 곳이다.

## 문제와 선택 이유

기존 Worker는 역할만 HTML에 붙이고 모든 로그인에서 같은 localStorage/사진 IndexedDB를 열었다. 같은 브라우저에서 회원이 들어오면 본인의 옷장을 읽는 것을 합성 브라우저 검사로 재현했다. 오래 열린 탭은 바뀐 회원 쿠키로 유료 API까지 요청할 수 있었다.

소유자가 이미 쓰는 원본 키/사진 DB를 이동하면 복구 위험이 크다. 따라서 본인 `owner`는 원래 바이트/DB 이름을 보존하고, 회원만 별도 물리 보관소를 연다. 서버가 인증한 회원 id의 SHA256 앞16바이트로 만든 불투명 태그 `m-<32hex>`를 쓰고 id/이메일/쿠키를 HTML/백업에 싣지 않는다. 태그 자체는 인증 수단이 아니다.

## 바뀐 경계

- `src/domain/account-scope.js`: 태그/namespace 규칙. 본인은 기존 이름, 회원은 `hangit-account:<scope>:` 접두사.
- `src/browser/account-storage.js`와 `tools/build-core.mjs`: 저장소를 읽기 전에 계정 경계를 설치한다. 논리 get/set/remove/key/length만 노출하고 다른 계정 물리 키와 계정 표식에 접근하지 못하게 한다. `EOUL_UI_STORAGE`도 같은 어댑터를 쓴다. 디자인 설정도 이를 따른다.
- `src/photos/index.js`: 회원별 DB/잠금 namespace, 계정이 바뀐 뒤 사진 명령 차단. 본인 원본 DB/사진 digest는 그대로다. 미리보기는 개인 DB를 열지 않는다.
- 백업 내부는 기존 논리 키/format 그대로다. 회원B 내보내기→회원A의 명시적 미리보기/복원이 가능하고 B/본인 물리 원본은 그대로 남는다. `BackupSheet` 복구 journal 조회도 host storage로 통일했다.
- 새 온라인 HTML만 현재 기기 계정을 정한다. 캐시의 `hangit-offline` 문서는 다른 계정을 주장하지 못한다. 다른 계정이면 옛 화면을 가리고 재열기 안내를 보인다. 원래 계정으로 돌아오면 같은 탭 자료를 다시 읽는다. 같은 계정 탭의 storage 갱신은 논리 이벤트로 연결한다.
- 같은 출처 `/api/`만 scope 헤더를 붙인다. 회원의 쓰기 요청은 헤더 누락/다름을409로 거절해 paid handler/한도 원장까지 가지 않는다. 구형 본인 클라이언트 헤더 없음은 호환하며, 새 클라이언트의 잘못된 헤더는 거절한다. 외부 요청에는 헤더를 보내지 않는다.
- 본인/회원 로그인 성공과 로그아웃에서 상대 종류의 쿠키를 함께 지운다. 회원 로그인 성공의 태그 응답은 기기 현재 계정을 갱신한다. 실패한 로그인/로그아웃은 현재 자료/화면을 바꾸지 않는다. 계정 삭제 전 백업과 재가입 시 자동 연결 안 됨을 안내한다.

## 운영 확인·한계

기존 본인 로그인으로 초대 관리 표를 읽었고 '아직 만든 초대가 없어요'였다. 조회는 사용/취소 내역도 포함한다. 초대/실제 가입/계정 삭제는 실행하지 않았다. 자동 검사는 합성 id·2×2 생성 PNG만 사용하며 개인 사진은 전송하지 않았다.

이 변경은 앱 계정의 우발적 자료 혼합을 막는다. localStorage/IndexedDB 암호화나 기기 개발자 도구 접근 차단을 제공하지 않는다. 계정 간 자동 동기화/자동 계정 연결도 제공하지 않는다. 기존 회원이 있었더라도 본인 legacy 자료를 자동으로 귀속시키지 않는다. 필요한 이전은 원래 계정에서 명시적으로 백업/복원한다.
