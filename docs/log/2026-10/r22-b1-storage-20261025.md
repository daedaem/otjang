# R22 B1 옷 정보 저장 계약 — 2026-10-25

대표의 #75 검사 후 병합·B1부터 순차 구현 지시에 따라 #75 병합 master c20e03e에서 시작한다. 초기 새 검사9개를 먼저 실행해8실패·1통과를 확인했다. 사진은 이 단계에서 받지 않는다.

## 설계 경계

lite 코어 snapshot은 v2로 올리고 기존 v1은 쓰기 없이 읽는다. 저장 키는 그대로다. 첫 명시적 저장부터v2를 쓴다. garment.profile의 출처·실측·선택 정보와 등록 영수증·입력 초안을 함께 검증한다. 미래/모르는 profile 형식은 자동 삭제·정규화하지 않고 기존 unreadable/BK 원문 보관 계약으로 보호한다. 개인 사진·외부 API·모델 실행은 없다.

기존 종류/색 코디 엔진의 WARDROBE_SCHEMA7은 lite의 영속 DTO와 구분한다. B1의 profile은 코어가 먼저 검증하고 엔진 입력에서는 제외해 기존 규칙을 유지한다. read-model에는 실제 저장 profile과 브랜드·생성 시각을 다시 연결하며 원본을 React에서 직접 읽게 하지 않는다. 엔진만의 스키마 번호를 올리는 것으로 lite snapshot 이전을 대신하지 않는다.

같은 draftId는 원래 등록 입력(profile 포함)으로 멱등 처리한다. 사용자가 나중에 profile을 편집한 뒤 원래 등록을 재시도해도 편집을 되돌리지 않는다. 종류별 기준 옷 전환은 같은 snapshot 쓰기에 포함하고 실패하면 두 옷 모두 이전 상태·구독 버전을 유지한다.

## 구현과 호환성

- core snapshot2·등록 영수증2·입력 초안2를 쓰며 기존1을 받는다. localStorage 키는 변경하지 않는다. `readLiteInputDraft`를 실제 호스트와 BK가 공유한다. 초안의 단독 시험용 fallback은 새 profile을 판독기 없이 받아 지우지 않고 거절한다.
- 구형 snapshot을 읽을 때 쓰지 않으며, 초기 화면의 검색 이력 저장도 첫 명시적 코어 변경 전에는 메모리에만 둔다. 이 경로를 새 실패 검사로 재현한 뒤 실제 브라우저에서도 구형 원문이 그대로임을 확인했다. 첫 명시적 저장부터 snapshot2로 이전하며 과거 추가 최상위 속성을 유지한다.
- profile 편집은 기존 등록 영수증의 최초 입력을 고치지 않는다. 현재 정보는 read-model의 profile을, 재시도/충돌은 최초 영수증을 쓴다. 현재 profile·brand·addedAt·photoId는 read-model의 추가 필드이며 복사본을 반환한다. 기존 검색/판단 golden은 그 추가 필드만 제외하고 원래 후보 ID·판단 전체를 대조하고 새 필드는 별도로 검사한다.
- 미래 snapshot 보호 fixture는 새로 지원한2 대신99를 쓰고, 새로 시작의 저장 버전 기대는2로 바꿨다. 기존 실패·보상 검사는 제거하지 않았다. 실제 #66 BK fixture를 실행할 때는 v1 전용 엔진 판독 조건과 v1 자료를 주어 새 코어의 v2 지원이 구버전 검증을 대신하지 않도록 했다. 새 format2 봉투를 구 #66이 거절하는 경계는 그대로다.
- #74의 apply 보상·stash·undo 본문이 실제 #66 fixture와 같은지 검사한다. 이전 정리용 `check-preserved.py --backup-validation`은 코어 원문이 바뀌지 않은 #74/#75까지의 도구이며 B1 코어 이전의 허용 여부를 판단하는 도구로 확대하지 않는다. B1의 호환·실패·golden 행동 검사를 따른다.

## 브라우저 엔진 오류와 검증

새 React 초안 재개→저장→reload에서 WebKit1.56.1이 두 번 같은 지점에서 종료됐다. Mac 충돌 기록의 EXC_BREAKPOINT/SIGTRAP 최상단은 WebCore::Navigation::initializeForNewWindow였다. [공식 Playwright #37766](https://github.com/microsoft/playwright/issues/37766)은1.56의 동일 reload 회귀와1.57 수정 포함을 설명하며 [WebKit #300402](https://bugs.webkit.org/show_bug.cgi?id=300402)에 연결한다. 도구만1.57.0으로 고정 갱신했고 검사·reload·retry0·timeout·워크플로는 완화하지 않았다. 같은 새6개가 통과한 뒤 전체50개를 실행해 통과했다. 구형 도구 충돌을 임의 불안정으로 넘기거나 실제 iPhone Safari를 검사했다고 쓰지 않는다.
