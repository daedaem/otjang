## 설계 경계

lite 코어 snapshot은 v2로 올리고 기존 v1은 쓰기 없이 읽는다. 저장 키는 그대로다. 첫 명시적 저장부터v2를 쓴다. garment.profile의 출처·실측·선택 정보와 등록 영수증·입력 초안을 함께 검증한다. 미래/모르는 profile 형식은 자동 삭제·정규화하지 않고 기존 unreadable/BK 원문 보관 계약으로 보호한다. 개인 사진·외부 API·모델 실행은 없다.

기존 종류/색 코디 엔진의 WARDROBE_SCHEMA7은 lite의 영속 DTO와 구분한다. B1의 profile은 코어가 먼저 검증하고 엔진 입력에서는 제외해 기존 규칙을 유지한다. read-model에는 실제 저장 profile과 브랜드·생성 시각을 다시 연결하며 원본을 React에서 직접 읽게 하지 않는다. 엔진만의 스키마 번호를 올리는 것으로 lite snapshot 이전을 대신하지 않는다.

같은 draftId는 원래 등록 입력(profile 포함)으로 멱등 처리한다. 사용자가 나중에 profile을 편집한 뒤 원래 등록을 재시도해도 편집을 되돌리지 않는다. 종류별 기준 옷 전환은 같은 snapshot 쓰기에 포함하고 실패하면 두 옷 모두 이전 상태·구독 버전을 유지한다.
