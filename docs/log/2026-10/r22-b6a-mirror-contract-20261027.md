# R22 B6a — 거울 초안·수치 배치·전신 사진 백업 기반

기준 master는 B5b #84의 최종59361e30을 CI11개·Node336개·실제220개 두 작업·미해결 검토0 확인 후 병합한 `aaca4e8904231aa55a7b20b58c34a4b1d10df2b2`다. B6a는 개인 사진을 받는 화면보다 먼저 저장/읽기·숫자 배치·백업 연결을 나눈 기반 후보다. 실제 사진 선택·두 점·드래그/콜라주 화면은 B6b이며 가상 착용/핏 검증을 완료한 것이 아니다.

## 저장 형태와 보호

`eoul-d12-hang:mirror:v1`의7개 필드는 `{v:1,body,heightRaw,head,feet,layers,updatedAt}`다. body는 사진ID와 원문 표시 공간의 너비/높이만, head/feet는 그 공간의 x/y 또는 null, layers는 최대12개의 `{garmentId,dx,dy}`다. 사진 bytes/URL/상품 후보/서버 키를 넣지 않는다. heightRaw는 미완성 문자열도 보관하며 읽기에서172.를172로 확정하지 않는다. 빈 초안의 시각은 null로 두어 가짜 생성 시각/기본 키를 만들지 않는다.

미래/손상·중복 JSON 이름·모르는/누락 필드·사진 밖 점·머리 위 발끝/50px 미만 간격·중복 레이어·무한 좌표를 거절한다. 초안의 사진 메타는12,000,000픽셀·변당30,000픽셀로 검사하고 파일 bytes는 기존 photoRecord의8MB 경계를 따로 따른다. 이 숫자는 실물 성능 검증 결과가 아니다. 실제 신장 범위100~230cm는 확인/계산 단계에 적용하며 raw 조회/미완성 보관과 구분한다. 원문을 지우거나 정상값으로 바꿔 쓰지 않는다.

## 읽기 전용 수치 배치

코어의 `mirrorCalibration`은 본인 입력 키와 머리/발끝의 y로 기존 `bodyScale`을 사용한다. 시작 중심은 두 x의 평균이며 평균 어깨/허리 비례선은 편집 규칙이다. `mirrorPlacement`는 실제 내 옷·내 기기 photoId·같은 사진 메타만 받는다. 기존 `placeGarment`의 실측 총장/범주/레이어에 사용자가 고른 offset만 더한다. 기록된 총장이 없으면 `assumedLength`로 남기며 정확한 길이/핏으로 바꾸지 않는다. 지원하지 않는 신발/소품은 임의 body 위치를 만들지 않는다.

판매처 사진만 있는 보유 상품·체험용·사진ID가 다른 입력은 레이어가 될 수 없다. B6b의 구매 후보는 원문 사진을 옆에 표시하고 이 계산/캔버스 입력에 넣지 않아야 한다(R20). 모든 계산 결과의 고정 문구는 **‘분위기 미리보기 · 핏 근거 아님’**이다. 원본 사진을 재현/가공하거나 외부에 보내는 코드가 아니다.

## 사진 포함 백업

새 코덱은 JSON 중복 이름 검사만 의존하는 경량 모듈이다. 사진 백업에 카탈로그/엔진을 다시 묶지 않도록 geometry 의존성과 분리했다. B2a 사진 보관소는 이미 role body를 지원하므로 DB/사진/봉투 버전을 다시 올리지 않는다. 사진 ID는 bytes 해시이며 같은 bytes의 원본/처음 metadata를 덮지 않는다.

BK는 거울 원문 사전 검증·출처·조건부 초안/선택 배치 건수만 확장했다. 형식2·5MB·원문 보관/충돌/활성 유지·apply/restore/undo·사진 IDB2/바이너리2 계약은 유지한다. 새 body.photoId도 사진 묶음의 missing/orphan 연결로 센다. 미래/손상 거울 원문의 사진ID는 활성 참조로 실행하지 않고 보관만 한다. 참조가 없어져도 원본 사진을 자동으로 지우지 않는다.

## 검증과 미연결 범위

- 실패 우선2fff495의6개가 미구현으로 모두 실패했다. 최종 새6개 포함 Node342개·빌드 통과. 미완성 키/한 점·기본값 미추정·엄격 원문·좌표/실측/offset·가정 표시·merchant/trial/wrongphoto 거절·미래 활성 유지·사진 missing/orphan·바이너리 원본 bytes를 확인했다.
- 기존 사진 백업22개는 그대로 통과했다. 새 브라우저 전신 사진2개는 실제 IDB 원문/사진 포함 파일 내려받기→빈 context 미리보기 missing0/orphan0→복원한 raw/role/bytes 동일→undo 후 초안 제거/원본 bytes 유지로 통과했다. 초기 새2개 실패는 연결 수 문구를 다른 보고 요소에서 찾은 검사 선택자 오류였으며 실제 연결 요약으로 수정했다. 복원 코드를 변경하거나 검사를 건너뛰지 않았다.
- 기존220개+새2개=전체222개 구성과 최종 head CI는 별도 확인한다. 새 화면이 없으므로 이전 코디 캡처를 거울 UI 증거로 쓰지 않는다. 사진 묶음 entry는 로컬 빌드30.40KB였으며 실물 성능 수치가 아니다.
- [원문 대조14개](evidence/b6a/preserved.json)는 BK 적용/복원/undo·구매 command·photoRecord/사진 복구 알고리즘/보관소/UI controller·AI gateway/한도·등록 모듈이 기준 master와 같음을 기록한다. 사진 참조 수집과 새 초안 읽기만 연결했다.

B6b는 실제 body 파일의 로컬 보관/연결(실패 시 원본 유지), 캘리브레이션·배치 초안의 CAS/재시도/Back·복구, 기기 내 그림/드래그를 연결한다. 기존 사진의 한 벌/전신 재사용 metadata와 원문을 덮지 않고, 새 몸 사진을 택해 배치 공간이 바뀌면 원본·입력을 보호한다. 신체 사진이나 선택 옷을 AI 요청으로 보내지 않는다. 실제 iPhone/Galaxy·거울 효용·C4/L1 이후는 미검증이다.

## CI에서 발견한 늦은 화면 초점 경합

초기 headcd7fe32의 PR 실행40423775366은 실제222개 중221개 통과/1개 실패였다. `closet.spec.ts`의 코디로 이동→옷장 탭에 초점→Enter에서, 늦게 마운트된 코디의 effect가 탭 초점을 제목으로 다시 가져갔다. 준비 취소/백업 실패가 아니며 단순 재실행으로 성공 처리하지 않았다. 내려받을 CI artifact는 없어 실제 로그의 위치를 기준으로 모듈 응답을 보류한 결정적 반례를 추가했다.

실패 우선b1f8744의 두 브라우저2개가 모두 같은 경합으로 실패했다. 코디의 최초 제목 초점은 layout 단계에서 화면 안/빈 body에 있을 때만 옮기도록 고쳤다. 사용자가 이미 탭을 고르면 유지한다. 반례2개와 원래 옷장 복귀2개가 함께 통과했고 빌드도 통과했다. 옷장·코디·전신 백업의 관련68개도1.8분에 통과했다. 기존 초점/Enter 검사를 삭제하거나 대기 시간/재시도 설정을 늘리지 않았다. 전체 구성은224개로 늘었으며 최종 head의 CI를 별도로 확인한다.
