# 백업·복원 시트 React 이전 (WO-07)

이 작업은 WO-06을 바탕으로 한다. 담당은 Claude 패션(Opus 5.5), 브랜치는 `claude/wo-07-backup-20261027`이다. 범위는 백업·복원 시트(글자 백업과 사진 영역)를 React로 옮기는 것이다. 백업 형식(BK format 2), 원문 격리, 복원·되돌리기 규칙, 사진 묶음 형식과 사진 백업 컨트롤러는 바꾸지 않았다. 새 복구 알고리즘이나 형식을 UI에 다시 만들지 않는다는 작업 요청 조건을 지켰다.

## 기준선 검사

백업 시트는 이미 다른 검사가 많이 덮고 있었다. 입력·진열장·실측·코디·정보 편집·상품 등록 검사에 복사, 붙여넣기 복원, 되돌리기, 파일 복원이 있고, 사진 백업 10개와 거울 백업 1개 검사도 있다. 빠진 부분만 `e2e/backup.spec.ts` 3개로 보충했다(`53df2c8`, 바닐라에서 3번 반복 통과).

- 메뉴로 열면 "파일로 내보내기"에 초점이 간다. 개수 줄과 보고 줄이 보인다. Esc로 닫히고, 두 번 열어도 시트는 하나다.
- 내보내기는 날짜가 붙은 JSON 파일이다. 붙여 넣은 글자로 미리보기를 해도 저장소에 아무것도 쓰지 않는다.
- 5MB를 넘거나 읽을 수 없는 파일은 거절한다. 새로 고르면 이전 복원 확인 버튼이 사라진다.

## 무엇을 바꿨나

- **React 시트:** `src/backup/`(`EOUL_BACKUP_LOAD` 섬). 바닐라 `sheet()`와 같은 배경·대화상자 구조, 저장소 경고보다 위인 z-index, 여닫는 애니메이션, Esc·배경 닫기를 쓴다. 사진 작업이 진행 중이면 닫히지 않는다.
- **글자 백업:**
  - 개수·보고 줄
  - 파일 내보내기(공유 창 → 다운로드 → 글자 표시 순으로 시도), 글자 복사
  - 파일·붙여넣기 미리보기: 오래된 선택은 막는다.
  - 복원: `M.withStorageLock` + `BK.restore`. 부분 적용이나 정리가 남으면 시트를 다시 열어 알린다.
  - 되돌리기: `BK.undo`
- **사진 영역:**
  - 복구 마치기, 장기 보관 요청
  - 사진 포함 파일 내보내기와 복원 미리보기: 격리 목록과 진단을 보여 주고, 오래된 선택은 막는다.
  - 사진 백업 되돌리기
  - 사진이 있으면 첫 내보내기 버튼을 사진 포함 파일로 바꾸고, 복사·붙여넣기를 "추가 백업 옵션"으로 옮긴다. 이 동작은 바닐라 `mountPhotoBackup`과 같다.
  - 사진 작업 중에는 시트의 모든 버튼과 입력을 막는다.
- **같은 저장소·컨트롤러:** 사진 모듈에 `photoBackupSession()`을 추가했다. `mountPhotoBackup`과 같은 저장소·`createPhotoBackup` 컨트롤러를 같은 방식으로 등록한다(`currentPhotoClient`가 그대로 찾는다). 바닐라 `mountPhotoBackup`은 그대로 남아 있다.
- **같은 표시 훅:** `data-bk-*`, `data-photo-*`, `#bkfile`, `.bk-msg`, `.bk-preview` 같은 표시 훅을 바닐라와 같은 값으로 둔다. 기존 검사가 이 훅을 그대로 쓴다.
- **바닐라 경로 유지:** `?ui=vanilla`이거나 섬을 불러오지 못하면 바닐라 시트(`vanillaBackupSheet`)를 쓴다. 이때 "새 백업 화면을 열지 못해 기존 화면으로 열었어요."라고 알린다. 저장소 경고의 "전체 백업 열기"와 각 화면의 백업 진입은 같은 함수를 지난다.
