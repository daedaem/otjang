# 세일 정보·자유게시판 후속

2026-10-29. 검토 채팅의 직접 사용자 요청 "안된거 다 반영ㅎ줘요"를 읽어 대조했다. 코디 공유 다음으로 세일 정보·자유게시판을 확장한다는 맥락이다. 구현은 Codex 어울 개발 한 곳이다. #130의 최종 head8d0f9b4·CI15개·미해결0 뒤 masterfb2ca8a에 병합한 상태에서 시작한다. 다른 채팅은 읽기 전용 검토다.

## 이번 범위와 이유

현재 검증기는 사진/옷 없는 글과 본문 URL을 거절한다. 버튼만 세 개로 늘려서는 자유 글과 세일 출처가 저장되지 않는다. 공유 도메인 검증·실제 API/호환·화면을 순서대로 붙인다.

- 기본은 코디 공유이며 기존 본문/옷/사진 규칙과 코디 공유 단축 진입을 보존한다. 옛 게시물은 코디로 읽는다.
- 자유게시판은 제목/본문만으로 작성하고 선택한 사진만 기존 동의/상한 아래 붙인다. 옷장 등록이 필요하지 않다.
- 세일 정보는 작성자가 직접 적은 제목·판매처·가격 또는 할인율·선택적 종료일/출처 주소를 표시한다. 작성 시점 기준의 미확인 제보이며 자동 수집/현재 가격·재고·최저가 확인이 아니다. 출처는 명시적 입력만 받고 읽어 오거나 미리보기하지 않는다.
- 작성자가 자기 글의 글자 정보를 수정하는 흐름도 잇되 사진/게시판 변경과 타인 수정은 허용하지 않는다. 동시 수정 충돌·신고/숨김 상태 보존과 기존 한도를 확인한다. 이는 구현자가 정한 기본 사용 흐름이며 대표가 세부 수정 계약을 직접 지정한 것으로 쓰지 않는다.
- 세 게시판의 전체/내 글·작성/목록·이동/직접 주소/Back·빈 상태·실패를 한 흐름으로 맞춘다. 코디 공유 초안을 다른 게시판으로 자동 보내지 않는다.
- 회원/운영자·신고/차단·삭제/탈퇴·사진 소유권/동의·용량/횟수·private/초대/public 조건은 함께 쓴다. 계정/원본/백업/비밀값은 초기화하지 않는다.
- 세일 정보 제보와 금지되는 상업 광고/무단 홍보의 안내를 맞춘다. 약관/운영 정책은 공개 전 초안이며 법률 검토 완료로 쓰지 않는다.

## 나누어 진행

1. 게시판 도메인·서버 API·오래된 코디 호환과 두 합성 회원/SQLite 검사. 통과·검토/병합 뒤 다음 단계.
2. 기존 디자인의 작성·편집·목록/내 글·이동과 모바일/PC/키보드·실패/공유 초안·직접 주소·Back. 같은 합성 상태의 화면 증거와 마지막 head 검사/리뷰 뒤 병합.
3. 기존 비공개 Worker의 실제 새 메뉴/진입만 읽어 확인하고 인수인계를 갱신한다. 실제 회원·게시·사진·법적 동의·공개 전환/새 비용·키/권한은 자동 실행하지 않는다.

## 현재 상태

API/호환 후보를 로컬에서 검증했다. 새 화면과 최종 PR/CI·병합/배포는 아직이다. 기존 제품 #129와 생성 셔츠를 포함한 실제 AI3회는 이미 완료됐으며 추가 유료 호출을 하지 않는다.

## API/저장 계약 후보

- `community_post_details` 보조 테이블에 게시판·제목·제보·수정 버전/시각만 둔다. 기존 `community_posts`와 사진 테이블을 ALTER/초기화하지 않는다. 보조 정보 없는 옛 글은 코디/버전0으로 읽고, 명시적 첫 수정 때만 보조 행을 만든다.
- `GET feed?board=outfits|sale|free&mine=1&cursor=...`는 선택한 게시판만 읽는다. 판 없는 예전 호출은 코디다. 새 페이지 커서는 게시판을 포함하며 옛 코디 커서도 읽는다. 알 수 없는 게시판/다른 판 커서는 거절한다.
- 자유 글은 제목/본문만으로, 세일은 제목·판매처와 원(KRW) 단위 가격 또는 할인율로 쓴다. 종료일/공개 HTTPS 출처는 선택 입력이다. 입력 가격·할인·출처를 수집/검증한 사실로 바꾸지 않는다. 본문에 URL을 섞는 기존 금지는 유지하며 출처는 전용 필드로만 받는다.
- `PATCH posts/:id {post,revision}`는 작성자의 한마디/제목/세일 정보만 수정한다. 게시판·옷 조각·사진은 고정이다. 사진이 있으면 기존 동의 조건을 유지한다. 원래 버전과 다르면409이며 신고/숨김/사진은 그대로다. 내부 수정 토큰·회원 id는 응답에 없다.
- 작성과 수정을 합쳐 기존 시간당10회다. 횟수/사진 바이트 조건을 같은 `batch`의 조건부 삽입에 포함해 동시 제출도 상한을 지킨다. 중간 쓰기 실패는 본문/제목/버전/한도 예약을 되돌린다. 이 설계는 [Cloudflare D1 batch의 트랜잭션/전체 롤백 계약](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)과 같은 SQL의 메모리 SQLite 검증에 근거한다.
- 삭제/운영자 삭제/탈퇴가 부가 정보도 함께 지운다. 전체·내 글/사진의 기존 신고·상호 차단·숨김·작성자/운영자 권한과 공개 준비 조건을 공유한다. 새 공급처/AI/출처 페이지/사진 외부 전송은 호출하지 않는다.

## 실행한 검증

수정 전 신규10개 모두 실패한 커밋은 `2cb1c3b`다. 이후 원래 코디 응답 검사의 허용 필드에 공개되는 게시판/제목/제보/버전/시각5개를 명시적으로 추가했고, 내부 id/원문 없는 조건과 기존 행동 검사는 삭제하지 않았다. 신규 검사는 이후 동시 수정·동시 사진 상한·부가 정보 삭제·Worker 인증/계정 게이트·수정 중 실패 보존을 더했다. 최종 전체 Node·빌드·브라우저/원격 결과는 마감 전에 아래에 갱신한다.
