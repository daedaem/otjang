# R22 B2b — React 옷장 레일·내 사진·조합대

기준은 B2a #77 병합 master `0a9b35ea72ea7bba464ce64ab500674ba1484f81`이다. 이 단계는 R22의 옷장 화면 연결이며 전체 React 전환·실측 입력·AI 코디 품질 검증·실제 서비스 출시 완료가 아니다. 사진 원문과 기존 저장 계약을 유지한 채 화면을 바꾼다.

## 구현과 선택 이유

- `src/closet/`에 React 화면·레일·사진·조합대 컴포넌트와 CSS, 타입을 둔다. 기존 호스트는 진입·라우팅·등록/상세/메뉴 콜백만 연결한다. 종류·색 빠른 등록과 브랜드 검색, 기존 상세·백업 경로를 유지한다. 정렬·필터·꺼낸 옷은 메모리 상태이며 저장 자료를 변경하지 않는다.
- `railLayout`의 아우터/상의/하의와 신발·소품 선반, 정렬 5가지를 연결한다. 레일의 표시 높이는 실제 총장 cm의 같은 축척이며 없는 값은 **실측 없음**이다. 30cm/140cm의 실제 DOM 높이도 비교한다. 이전 최소 높이 60px가 비례를 깨는 문제를 읽기 전용 교차 검토에서 찾아 제거했다. 그림이 착용감이나 핏의 증거인 것은 아니다.
- 코어에는 읽기 전용 `railLayout`, `railCategory`, `railSortChoices`만 더한다. 저장/등록 명령·snapshot2·초안2·영수증2는 바꾸지 않는다. 도메인을 React에서 직접 import했을 때 카탈로그가 다시 묶이던 문제를 기존 코어 공유로 해결했다. 옷장 JS는 중간 빌드 약440KB에서 약13KB로 줄었으며 별도 공통 React JS 약192KB는 함께 필요하다. 파일 크기 관찰이며 기기 속도 측정이 아니다.
- 가로 레일은 보이는 카드와 인접 범위만 마운트한다. 사진은 세로 화면에 들어올 때만 읽고 표시한다. 화면 밖이나 해제 시 객체 URL을 반납한다. 썸네일 생성용 원본 읽기/디코딩은 동시에 최대2개로 제한한다. 현재 저장 계약의 최대 **200벌**에서 카드가 20개 미만으로 유지되고 마지막 실제 옷으로 이동하는지 확인한다. 300벌 fixture는 기존 저장 한도를 위반해 200벌로 바로잡았으며 제품의 한도를 올리거나 검사를 삭제하지 않았다.
- 아우터를 상의 위에 배치하고 선택 종류마다 한 벌씩 꺼낸다. 모바일은 빈 조합대를 숨기고, 꺼낸 옷을 함께 보는 버튼은 조합대가 화면에 나타나면 내려간다. 실제 코디 이동 버튼을 가리지 않는지도 검사한다. WebKit의 실제 클릭 검사에서 고정 버튼이 transform이 있는 화면 조각을 따라가 클릭 전에 사라지는 문제를 찾았다. 버튼을 body portal로 옮겨 기존 화면 애니메이션을 유지하면서 강제 클릭 없는 코디 이동과 하단 탭 키보드 이동을 검사한다. PC에는 옆 조합대를 둔다. 배치 예시이며 체형·착용감을 반영하지 않는다. 조합 최종 순위/이유를 엔진으로 정하는 기능은 넣지 않았고 R2의 B5 AI 연결이 남아 있다.

## 개인 사진과 백업 경계

내가 찍은 PNG/JPEG/WebP 또는 iPhone에서 직접 만든 투명 PNG를 넣는다. 원본은 기존 B2a 해시 ID·MIME·바이트로 보관하며 사진 참조는 B2a의 공유 잠금 아래 코어 명령으로 연결한다. 실패/삭제 경합으로 참조가 못 붙어도 원본을 자동 삭제하지 않는다. 화면 입력 상한은 한 장8MB/1,200만 화소다. HEIC 수신과 실제 대형 iPhone 사진 성능은 미검증이다.

썸네일은 개인 원문에서만 만드는 최대320px의 파생 캐시이며 기존 IDB2의 `meta`에 `thumb:<photoId>`로 둔다. Blob 저장이 어려운 브라우저를 위해 바이트로 보관한다. 캐시 실패로 원본을 지우지 않고, 사진 백업은 원문을 담으며 썸네일은 복원 뒤 다시 만든다. 판매처 사진 URL을 내려받아 가공하는 경로는 없다. 원본이 없는 옷은 도형/사진 없음으로 표시한다. 개인 사진 참조가 붙은 옷은 기존 화면에서도 다른 상품 사진으로 대체하지 않는다.

`?photos=0`은 사진 표시를 끄고 `?preview=1`은 개인 저장/사진 DB와 분리한다. 일반 앱의 명시적 파일 선택은 기기에서만 처리하며 서버·AI·공용 카탈로그로 사진을 보내지 않는다. 개인 자료나 실제 주문/대화/키는 Git에 넣지 않았다.

B2a 기준 BK 객체 구간과 현재 구간의 SHA256은 모두 `cacfe0e8847770a461a83b09b5f5f0e7dd9cece42b2cb00d9869d0328f6b520b`였다. #66/#74의 글자 백업 적용·보상·undo 코드를 수정하지 않았다는 원문 대조이며 사진 및 실제 동작 검사를 대신하지 않는다.

## 진입·복귀·오프라인

`?ui=vanilla#/closet`은 기존 옷장이다. `?input=vanilla`의 기존 직접 입력 복귀도 유지한다. React 코드/스타일을 못 열면 자동으로 기존 옷장을 보여 주므로 메뉴·백업을 계속 열 수 있다. 오래된 캐시를 삭제하거나 자료를 초기화하지 않는다.

처음 방문에서 SW가 화면 로드보다 늦게 제어권을 얻을 수 있다. 방문한 옷장 파일과 실제 공유 JS/CSS만 제어권 획득 후 요청해 캐시에 넣는다. 미방문 입력 화면을 미리 받지 않는다. origin을 실제 정지한 재진입과, React 파일을 막은 기존 화면 복귀를 별도로 검사한다. 직접 옷장 진입은 홈을 먼저 그리지 않는다. 홈 예시 검색이 최근 검색에 저장되던 부작용을 실제 원문 비교로 찾아 고쳤다.

## 검증과 실제 근거

- 실패 우선 `9ed456d`: 미구현 레일/사진/조합대/대량 표시 8실행 모두 실패했다.
- 기존72개 브라우저 검사를 유지하고 옷장18개(9사례×2엔진)를 더한다. 등록→재실행→브랜드/품명, 실제 원문 바이트와 사진 해시, 사진 교체 실패, 객체 URL 정리, 실제 표시 비례, 대량 가로 이동, 백업, 두 종류 오프라인 경로를 검사한다. 중간 전체 검사에서 브랜드 노출·탭 장식 아이콘의 접근성 이름·첫 방문 캐시·예시 검색 저장 회귀를 찾고 고쳤다. 실패를 skip/retry/timeout 변경으로 넘기지 않았다.
- 텍스트 확대는 주요 옷장 요소의 computed font-size가 정확히 두 배인지를 먼저 확인한 뒤 페이지 넘침과 저장 불변을 검사한다. 단순 body 글자 크기 변경만으로 모든 고정 px 텍스트가 커졌다고 주장하지 않는다. 실제 OS 확대·화면 읽기 도구·iPhone/Galaxy 검증은 별개다.
- 로컬/CI의 최종 수와 head는 PR 결과를 따른다. Node 기존278개에 읽기 전용/대체 사진 금지2개를 추가했다. 전체 React 전환과 실제 기기 성능은 완료로 표시하지 않는다.

## 이어갈 일

B3·B4의 실측/속성 입력·기준 옷·후보 사이즈표 비교·수집 진열장, B5의 반응/AI 최종 조합 이유, B6 로컬 거울 콜라주를 순서대로 연결한다. 기존 홈·검색·결과·기록·날씨·상담·백업 화면의 React 전환도 개발 계획 표대로 남아 있다. C1/C2와 B5 블라인드20, C4 착용 품질은 대표의 실제 판단이 필요하다. 새 공개 배포·유료 호출·모델 다운로드·실사용 모집은 하지 않았다.
