# 게시판 체험용 샘플 데이터

대표의 2026-10-29 직접 요청: “게시판들이 비어있어서 … 몇가지 테스트데이터로 이미지같은것들 만들어서 넣어놔요”. 작업 #139, 시작 기준 master bff52db. 원래 개인 체크아웃은 보존하고 검증용 체크아웃에서 진행했다. 날씨 #137의 코드/브랜치는 변경하지 않았다.

## 실제 반영 범위

현재 비공개 앱의 COMMUNITY_DB(otjang-community)에 코디 공유2건·세일 정보2건·자유게시판2건을 삽입했다. 생성 이미지4장을6개 사진 행으로 저장했다. 개인 사진·실제 사용자 글·실제 브랜드·상품 가격·할인 행사·후기는 사용하지 않는다.

표시 이름 ‘운영 샘플’인 비로그인 합성 게시자1개를 만들었다. 이것은 community_members의 표시용 행이며 회원 로그인/관리자 계정이 아니다. 회원 이메일·비밀번호·세션·관리자 테이블에는 쓰지 않았다. 샘플 본문은 `[샘플 · AI 생성 이미지]` 또는 `[테스트 데이터 · AI 생성 이미지]`로 시작한다. 세일/자유 글 제목도 `[샘플]`이다. 코디는 기존 계약상 제목이 없으므로 본문에 표시한다.

세일 게시판의10%·20%는 가상의 카드 예시다. 실제 행사가 아님을 제목/판매처/본문에서 밝히고, 실제 가격·기간·구매 링크는 넣지 않았다. 실제 이용자·할인·구매/후기 실적에 포함하지 않는다. 앱 공개 범위·회원 인증·관리자 권한·AI 한도·상품 공급권은 바뀌지 않는다. 게시판 글과 생성 사진을 저장한 작업이며 상품 사진 권리나 사업 효용을 검증한 것이 아니다.

## 명세와 재현

- [콘텐츠·사진 해시·전체 생성 프롬프트](../../../app/lite/sample-data/community-20261029/manifest.json). 생성 방식은 built-in image_gen이다. 각 이미지 별도 프롬프트로4장 생성했으며 참조/개인 사진 전송은 없다.
- JPEG는640×800, 메타데이터 없이 각53KB 미만이다. 원래 생성 PNG는 사용자 Codex 생성 폴더에 보존했다. Git에는 선별된 생성 JPEG4장만 넣는다.
- [운영 도구](../../../app/lite/tools/community-samples.mjs)는 원격 연결을 하지 않는다. 실제 도메인 검사·사진 바이트/해시 검사 후 명시적 SQL 파일만 만든다.

```bash
cd app/lite
node tools/community-samples.mjs --verify
node tools/community-samples.mjs --sql /private/tmp/community-samples.sql
node tools/community-samples.mjs --hide-sql /private/tmp/community-samples-hide.sql
```

원격 실행은 별도 단계다. 이번에는 이미 인증된 Cloudflare D1 콘솔에서 올바른 전용 DB를 대조한 뒤 실행했다. 빈 테이블 만들기/초기화·기존 행 수정·일괄 삭제·계정 생성/법적 동의 대신 제출은 하지 않았다. 생성 SQL은25개의 INSERT OR IGNORE이며 글·사진 UUID와 합성 게시자 id가 고정돼 재시도해도 중복되지 않는다. 각 문장은100KB 미만이다. 사전 조회에서 해당 합성 게시자와 샘플 id가 없는 것을 확인했다. 조건부 삽입으로 다른 작성자/본문과 충돌한 글에는 부가 정보·사진을 붙이지 않는다.

재실행 전에도 원격 샘플 id·게시자·해시를 대조한다. 합성 게시자에 로그인 계정이나 권한을 연결하지 않는다. 자동 배포·서버 시작 때 실행하지 않는다. SQL 파일/전체 base64를 Git에 넣지 않는다.

운영 DB의 게시판별 건수는 [실제 콘솔 화면](evidence/community-samples/live-db-counts.png)으로도 확인했다. 이 화면에는 계정 정보가 없도록 조회 결과 주변만 캡처했다. 렌더링 캡처는 로컬 QA이며 인증된 운영 피드 스크린샷으로 쓰지 않는다. 실제 검증 Chrome은 이메일 로그인 화면이어서 로그인 뒤 피드/사진 HTTP 경로 및 실물 폰은 직접 확인하지 못했다. 비밀번호를 읽거나 임의 세션을 발급하지 않았다. 실제 글을 보는 데 필요한 기존 로그인/커뮤니티 가입 조건을 우회하지 않는다.

추가 유료 추천·상담·사진 분석은0회다. 이번4장 생성은 built-in image_gen이며 앱의 Anthropic 호출/한도 변경과 다르다. API 키·개인 원본·기존 옷장/백업에는 접근·변경하지 않았다. 앱 코드 배포는 필요 없는 데이터 작업이다.

## 숨기기와 이후 운영

체험이 끝나면 --hide-sql로 만든 정확한6개 id/합성 게시자 조건의 UPDATE를 검토 후 해당 전용 DB에서 실행하면 보이는 피드에서 빠진다. 삭제 대신 숨김이므로 사진/글은 보존되고 운영자의 신고·숨김 화면에서 복구할 수 있다. 이번에는 숨김/삭제를 실제로 실행하지 않았다. 실제 회원·글/사진을 포함하는 조건으로 넓히지 않는다.

프로필/게시 수로 성장이나 활동을 보고할 때 manifest의 게시자·글 id를 제외한다. 앱의 ‘내 글’에는 운영자 개인 글로 나오지 않는 것이 정상이다. 인수 기록의 Git 저장/PR 상태와 이미 적용된 운영 DB 데이터를 구분한다.
