## 3. 개인 모바일 테스트 출시의 차단 사안

출시 목표는 "대표 본인 휴대폰에서, 대표 PC에 데이터가 남는, 본인만 아는 https 주소". 공개 배포가 아니다.

**차단이 아닌 것:** 홈 길이, 첫 화면 성별 버튼, 여성 카탈로그, 상품 재분류, 사진 핫링크(개인 테스트 범위), 실주문 연동.

## 4. 접속 링크 만드는 방법 (이미 저장소에 있음)

`deploy/try-local.ps1`(Windows) / `deploy/try-local.sh`(macOS·Linux)이 **혼자 시험용**으로 만들어져 있다. PC에서 서버를 켜고 Cloudflare 임시 터널로 휴대폰용 https 주소를 만든다. 데이터는 `server/data-try/`에만 남고, 스크립트를 끄면 주소가 사라진다.

```
# Windows PowerShell (저장소 폴더에서)
powershell -ExecutionPolicy Bypass -File deploy\try-local.ps1
# macOS/Linux
bash deploy/try-local.sh
```

- 처음 실행하면 Node 22.13+와 cloudflared 설치를 물어본다(winget/brew).
- 화면에 뜨는 `https://….trycloudflare.com` 주소를 휴대폰에서 연다. **https라서 홈 화면 설치(PWA)·안드로이드 공유 받기가 동작한다.**
- 스크립트가 매번 임의의 초대 코드를 만들어 화면에 보여 준다(`EOUL_INVITE_CODE`). 그 코드를 아는 사람만 가입할 수 있으니 주소와 코드는 본인만 쓴다.
- Docker 운영 묶음(`deploy/docker-compose.yml`, 이름 있는 터널, Litestream 백업)은 **지인 파일럿 단계**에서 쓴다. 지금은 과하다.
- 미검증: Windows에서 이 스크립트의 실제 실행(문서 `deploy-kit-20261015.md`에 Windows 미검증으로 적혀 있음). 막히면 `-Local`로 같은 와이파이 `http://PC주소:8787`로 대신 열 수 있다(이때 PWA 설치·공유 받기는 꺼진다).

## 5. 휴대폰에서 직접 확인할 목록 (출시 뒤, 대표)

1. 홈 화면 설치 → 다시 열기. 앱이 새 빌드인지(상세 안내 문구 "검색 조건(…)" 보이면 새 빌드).
2. "원피스", "셔츠 말고 출근 니트", "코트 1만원 이하" 검색과 칩 ×.
3. 상품 → 내 옷 넣고 비교(예시 상태) → 사진 없이 한 벌 → 같은 상품 판정으로 복귀.
4. **안드로이드 뒤로가기**: 상세 → 결과 → 홈 순으로 닫히는지. 아이폰은 스와이프.
5. 아이폰 HEIC 사진 등록.
6. 안드로이드: 무신사 앱 → 공유 → 어울로 보내기(아이폰은 안 되는 것이 정상).
7. 통합 전 앱에서 받아 둔 백업 파일 복원.
8. 구매내역 가져오기(시험) 진입점에 시험 표시가 보이는지.
