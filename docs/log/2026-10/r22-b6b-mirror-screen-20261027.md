# R22 B6b — 기기 내 거울 화면

기준은 B6a #85를 병합한 master `990cbbe733eab585d784e149e55d603e51e06c94`다. #85 최종 head36af840은 Node342개·CI11개·실제224개 두 실행(7.7분/8.1분)과 미해결 검토0을 확인한 뒤 병합했다. 초기222개 중 초점1개 실패는 재현/수정 후 새224개 전체 통과와 구분한다.

## 연결한 사용자 흐름

옷장 조합대의 ‘내 사진 거울 보기’, 상품 상세의 ‘내 사진 거울 옆에 놓고 보기’ 또는 직접 `#/mirror`로 연다. 내 전신 사진 → 키 → 머리 끝·발끝 → 내 옷 사진 선택 → 끌거나 방향키로 위치 조정 순서다. 키 입력은 미완성 문자열도 보관하며 두 점이 부족하면 겹쳐 그리지 않는다. 고정 문구 **‘분위기 미리보기 · 핏 근거 아님’**을 표시한다. 키보드로도 지점을 이동/Enter 선택할 수 있다.

기존 `bodyScale`·`placeGarment`를 읽기 통로로 재사용한다. 어깨·허리 시작점은 평균 비례이고, 총장이 없으면 **‘총장 모름 · 보통 길이로 놓았어요’**를 표시한다. 도메인 계산/사진 백업/구매·등록 명령은 바꾸지 않는다. 지원하지 않는 신발/소품이나 체험용·판매처 사진만 있는 옷은 배치 대상으로 만들지 않는다. 없어진 내 옷/사진은 대체 상품으로 채우지 않는다.

구매 후보의 판매처 원본 사진은 배치 영역 밖 옆/아래에만 둔다. 겹쳐 그리는 이미지는 기기 원본에서 읽은 전신 사진과 내 옷의 로컬 썸네일뿐이다. 상품 사진을 다운로드·배경 제거·합성하거나 사진/ID/bytes를 AI에 보내지 않는다. 자동 누끼·사진 식별·실사 착용 생성·핏 검증·이미지 내보내기는 이번 구현이 아니다.

## 저장·실패·다른 창

- B6a `mirror:v1`을 그대로 쓴다. 새 화면을 열거나 읽는 것만으로 키/가짜 시각을 만들지 않는다. 미래/손상 초안은 원문 보호와 백업으로 안내한다.
- 좌표·body·선택은 하나의 문서다. 다른 사진의 점/offset을 합치지 않도록 전체 문서 CAS를 공유 잠금 안에서 검사한다. 다른 창의 최신 값은 실패한 이전 입력으로 덮지 않는다. 실패 입력은 RAM에 남고, 다시 보관/Back 경고를 제공한다. 확인 읽기만 실패한 실제 저장도 중복 쓰기 없이 재확인한다.
- 사진 해시/원본/첫 metadata는 기존 보관소가 유지한다. 새 파일을 해독·준비한 뒤 원본 저장 전후에 연결의 최신 상태와 복구 표식을 다시 확인한다. 원본이 저장되고 글자 연결만 실패하면 원본 보관과 연결 미완료를 따로 안내한다. 다시 보관으로 같은 원본을 연결하며 고아 사진을 자동 삭제하지 않는다.
- 사진 교체 중 일반 편집을 막고 이동은 완료/실패를 기다린다. 배치가 있으면 교체를 먼저 확인받는다. 다른 사진/크기면 두 점·offset만 초기화하고 키·선택·앞선 원본은 보존한다. 같은 사진/크기는 JSON 필드 순서가 달라도 점/offset을 유지한다.
- 드래그 중에는 시각 위치만 바꾸고 끝날 때 한 번 보관한다. 취소하면 수락하지 않은 이동을 되돌린다. 방향키는1픽셀, Shift+방향키는10픽셀이다. 위치/사진 크기는 원문 좌표이고 화면 비율에서 환산한다. 드래그 중 외부 storage 갱신으로 좌표 기준을 갈아 끼우지 않는다.

## 사진·런타임 경계

기존 사진 모듈에 `prepareBodyPhoto`만 더해 PNG/JPEG/WebP·8MB·1,200만 화소 검사와 role body 준비를 재사용한다. body 사진 ID가 옷 사진과 같아도 기존 role/시각/bytes는 덮지 않는다. 전신 이미지는 하나만, 옷은 최대12개 선택과320픽셀 파생 썸네일을 사용한다. 파생 캐시는 백업 원본이 아니며 URL은 교체/이탈 때 해제한다. 실제 파일 크기/대량 기기 성능은 이 제한으로 증명되지 않는다.

React 거울은 별도 지연 entry로 전체 static graph/CSS 로딩·캐시를 사용한다. 이전 화면을 지나지 않는 직접 진입과 후보ID 새로고침을 보존한다. 화면이 살아 있는 동안 배경 갱신으로 RAM을 remount하지 않는다. 메모리 체험에서는 실제 사진 보관소를 열지 않는다. 런타임 실패는 자료를 그대로 두고 복귀를 제공한다. 기존 바닐라 옷장/코디와 복귀 플래그는 남긴다.

## 검증과 한계

실패 우선0d6bc2f의 새7개는 미구현으로 실패했다. 이후 같은 사진의 필드 순서 회귀를 더해 Node350개가 통과했다. 거울 브라우저 기본10개·확장16개 통과 뒤 실제 두 창을 포함한 최종18개도29.9초에 통과했다. 모바일/PC·글자 두 배·키보드·포인터·새로고침·사진 교체 취소·손상 파일·원본 후 연결 실패/재시도·미래 초안·체험 격리·동일 bytes 재사용·실제 origin 중단 후 원문/사진 bytes 동일을 확인한다. 개인 자료나 실제 API 응답 대신 합성 PNG만 사용한다.

초기 새 화면 검사의 문제도 구분한다. 문서 재실행 없는 해시만 변경을 직접 진입으로 본 검사, 아래 레이어를 끌려던 검사, 중복 오류 안내를 수정했다. 작은 화면의 안내 가림을 피하도록 사진 높이를 제한하고, WebKit에서 암묵적 버튼을 Tab이 건너뛰는 동작에 새 버튼의 명시 tabIndex를 적용했다. 검사 assertion·대기/재시도 설정을 약하게 바꾸지 않았다. [보존 근거](evidence/b6b/preserved.json)는 기존 코어/BK/사진 복구/인증·한도·등록/AI 화면의 원문 동일 범위다. 993191d의 전체242개는8.4분에 통과했다. 아래 검토 보완 후 전체 구성은244개이며 최종 CI·PR·병합 상태는 따로 기록한다.

이 기능은 L0 사진 배치다. 실제 아이폰/갤럭시·사진10벌 등록 시간(C1/C2)·AI 블라인드20·C4/L1·실사/핏 품질·사업 효용·전체 React 전환·공개 출시를 완료한 것으로 쓰지 않는다. 사진 외부 전송·실제 모델 호출·새 배포는 실행하지 않았다.

재현: `npm --prefix app/lite test`, `npm --prefix app/lite run build`, `npm --prefix app/lite run test:e2e -- e2e/mirror.spec.ts e2e/mirror-backup.spec.ts`. `CAPTURE_B6=1`은 합성 사진 상태의 모바일/PC 캡처만 `evidence/b6b`에 남긴다.

모바일/PC 캡처4장은 합성 PNG로 만든 사진 배치 상태다. [캡처·소스 해시](evidence/b6b/manifest.json)에서 실물 검증이 아님을 표시한다. [모바일](evidence/b6b/mirror-calibrated-mobile-chromium.png)·[PC](evidence/b6b/mirror-desktop-mobile-chromium.png)를 직접 확인했다.

## 검토 보완 — 실측 변경과 배치 크기

PR #86의 P2 검토에서, 다른 창이 선택 옷의 총장을 바꾸면 목록 수치는 갱신되지만 사진ID/거울 초안이 같은 Layer의 memo는 옛 크기/가정 표시를 유지하는 문제가 확인됐다. 실패 우선45a2f85의 두 브라우저2개가 ‘총장100cm 표시 뒤에도 assumed=true’로 실패했다. 배치 memo가 갱신된 garment 자체를 의존하도록 수정해, 다른 창에서100→60cm로 바꿀 때 실제 DOM 사진 높이도0.6배가 되고 가정 표시가 해제되는 것을 검증했다. 거울 원문/두 점/offset은 이 외부 실측 변경만으로 다시 쓰지 않는다. 포인터 이동은 로컬 delta만 바꾸므로 그때마다 코어 계산을 반복하지 않는다.

마지막 빌드와 거울20개가32.9초에 통과했다. 4장 캡처도 이 소스로 다시 생성했고 manifest의 소스 해시를 갱신했다. 993191d의 로컬242개/원격 결과는 최종244개 결과와 구분하며, 검토 미해결 상태를 처리한 뒤 마지막 head CI를 확인한다.
