# R22 B3c — 후보 실측·사이즈표 비교

기준 master는 B3b #80 병합 `7493826d5e77a31e75502ebb6117ef5583f24c3f`다. 상품 상세에서 ‘내 기준 옷과 실측 비교’로 들어간다. 숫자는 두 옷의 차이이며 착용감/핏 보장이 아니다. B4 진열장·B5 최종 AI 이유·B6 거울 및 남은 전체 화면 전환은 별개다.

## 입력과 판단

- 후보 실측은 숫자 또는 사이즈표 글자로 입력한다. iPhone 라이브 텍스트로 복사한 글자도 같은 붙여넣기 경로를 쓴다. 자동 사진 OCR·판매처 표 수집은 하지 않는다.
- 기존 `parseSizeChart`/`sizeChartOptions`가 읽은 단위·둘레→단면·인치→cm 경고를 그대로 보여 준다. 모르는 단위나 열 충돌을 추측해 채우지 않는다.
- 비교에는 실제 보유한 같은 종류의 옷만 쓴다. 고르면 이 종류의 저장된 기준도 바뀐다는 설명을 둔다. 기준 옷이 없어도 후보 입력과 상품 원문 이동은 가능하다. 기록할 때는 ‘가지고 있는 한 벌’이라는 명시 행동으로만 보유 옷을 추가한다.
- 가장 가까운 표기는 기존 `closestSize`를 따른다. 공유 실측2개 미만·동점·사이즈별 비교 항목이 다르면 이름을 고르지 않는다. 중복 사이즈명은 모호한 행을 제외하고 알린다. 선택했던 사이즈가 현재 표에서 없어져도 다른 이름으로 바꾸지 않는다.
- 수치 차이 표·문장·같은 축척의 두 SVG path와 `NOTE`를 함께 보여 준다. 어깨/소매 등 그림용 가정이 있으면 반드시 그 이름을 표시한다. 후보 사진을 도식으로 변환하거나 상품 사진을 가공한 것은 아니다.

## 보유 기록과 후보 메모를 분리

새 메모는 `eoul-d12-hang:measure-drafts:v1`의 `{v:1, entries:{productId: draft}}`다. draft는 상품ID·종류·기준ID·입력 모드·숫자 원문·출처·표 원문·선택한 표기·수정 시각을 가진다. `72.` 같은 미완성 입력은 그대로 보관하며 읽기에서 수치를 확정하지 않는다. 다른 상품/종류/미래 형식·중복 이름·누락 필드를 거절하고 원문을 덮지 않는다. 최대1000개/표 원문2만자/숫자20자의 읽기 한도는 기존 옷장200벌 한도를 늘리는 것이 아니다.

`measurement-draft.js`는 코덱과 읽기 전용 계산을 맡는다. 기존 profile 초안과 함께 쓰는 JSON 중복 이름 검사를 `json-members.js`로 분리했으며 기존 입력/백업 검사도 유지한다. 프론트는 코어 통로를 사용해 도메인/카탈로그를 다시 내려받지 않는다. 계산은 현재 실제 기준 옷의 실측을 읽고, 후보 메모는 실제 보유 옷이나 구매 결정으로 만들지 않는다.

`src/measure/session.js`는 변경 큐·현재 메모 대조·기존 저장 잠금을 사용한다. 나중에 성공한 보관은 이전 오류 안내를 지운다. 다른 창의 같은 비교 메모가 바뀌면 현재 입력을 남긴 채 덮어쓰지 않는다. 원문이 미래/손상이면 백업 경로를 보여 주고 빈 값으로 바꾸지 않는다.

## 기준 한 벌과 저장 실패

옷장이 없는 사용자가 실제로 가진 기준 옷을 기록할 때 `addGarment`의 선택 profile 인자를 사용한다. 브랜드는 모름(null)이고 종류/기준 표시를 한 snapshot 쓰기로 저장한다. 동종 기존 기준 해제도 같은 쓰기에 포함해, 실패하면 새 옷/이전 기준을 모두 원래대로 둔다. 기존 인자가 없는 빠른 등록은 그대로다. 체험용에는 이 경로로 실측 기준을 붙이지 않는다.

기준 선택/정보 수정은 기존 profile 명령을 사용한다. 실패한 기준 전환은 이전 표시와 후보 원문을 유지한다. 기준 편집 modal을 닫아도 React 비교 화면을 불필요하게 remount하지 않아, 아직 보관하지 못한 후보 입력도 조용히 버리지 않는다. Back/내부 이동은 미보관 입력을 확인하고 사용자 선택 전에는 제거하지 않는다.

## 백업과 오프라인

BK 검사/출처 이름/조건부 건수를 새 코덱에 연결했다. 미래/손상 비교 메모는 원문 보관하며 보관 전용 수입은 현재 정상 활성 메모를 유지한다. ‘실측 비교 초안 N개’로 따로 집계하고 옷 수나 등록 이력으로 세지 않는다. 기존 format2·텍스트5MB·사진 IDB2·원본 사진/전체 백업을 유지한다. 적용/복원/되돌리기 알고리즘은 수정하지 않는다.

방문한 새 JS/CSS는 기존 런타임 그래프/공유 스타일 Promise를 통해 캐시한다. 실제 origin 정지 뒤 저장한 사이즈표와 수치 비교가 다시 열리는지 확인한다. 권한/실제 iPhone 키보드·라이브 텍스트·대량 성능 검증을 대신하지 않는다.

## 코드 분할과 검증

입력은 `CandidateInputs.tsx`, 수치/도식은 `Comparison.tsx`, 상태·기준 선택·이동 확인은 `index.tsx`, 저장은 `session.js`로 나눈다. UI가 실제 저장소를 정규화하거나 가상의 소유 옷을 만들어 결과를 맞추지 않는다.

- 실패 우선 `2a3eacb`: 미구현5개 모두 실패했다. Node는 기존295개+새8개=303개가 통과했다. 미완성 원문·모호한 표·단위/NOTE·미래/손상/중복·기준 생성 원자성·새 키의 백업 활성 유지/별도 집계·메모 재개와 이전 편집자 거절을 포함한다.
- 브라우저는 기존122개에 비교24개(12사례×2엔진)를 더했다. 집중24개·전체146개가 통과했고 같은 최종 head CI는 PR에서 별도 대조한다. 숫자 차이/동점/명시 선택/재실행/기준 한 벌 추가/이름 중복/선택 사라짐/기준 편집 뒤 RAM/미래 복구/단위와 가정/보관 실패 Back/기준 쓰기 실패/비교 항목 불일치/백업·undo/origin 정지 오프라인을 포함한다.
- 중간 로컬 검사 중 빌드를 겹쳐 beforeEach에 index404를 일으킨 실행은 제품 실패/통과 근거로 쓰지 않는다. 실제 trace의404를 확인하고 빌드가 끝난 고정 산출물에서24개를 다시 통과했다. skip/retry/timeout을 바꾸지 않았다.
