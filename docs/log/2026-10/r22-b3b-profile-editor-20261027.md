# R22 B3b — 보유 옷 React 편집·초안 재개

기준 master는 B3a #79 병합 `77bfebb7a05041d3f61f504a9fba1138b99313d9`이다. 보유 옷의 실측·출처·기준 표시·소재/디테일·소장 목적/컬렉션을 React에서 편집한다. 후보의 사이즈표 비교 B3c·진열장 B4·최종 AI 이유 B5·거울 B6 및 기존 나머지 화면 전환은 아직 별개다.

## 구조와 선택 이유

- `src/profile/index.tsx`는 modal 수명·초점·이동 확인·저장 동작을 맡고, `Fields.tsx`, `Summary.tsx`, `Outfits.tsx`로 입력·출처/원문 링크·기존 조합 미리보기를 나눈다. 화면 전체를 하나의 큰 JSX 블록으로 두지 않는다.
- `draft-session.js`는 초안 큐와 저장/정리 상태를 맡는다. 파싱/출처 변환/최신 기록 대조/실제 옷 정보 저장은 B3a 코어 통로를 재사용한다. 렌더나 열기에서 개인 자료를 자동 이전하지 않는다.
- React는 코어 version을 구독하고 그 version별 옷장/메타데이터를 읽는다. 입력할 때마다 전체 옷장/등록 이력을 다시 해석하거나 도메인/카탈로그를 다시 묶지 않는다. 옷 정보 입력은 선택사항이고, 종류·색의 빠른 등록과 옷장 없는 검색을 그대로 둔다.
- `OwnedPhoto.tsx`는 레일과 편집 화면의 개인 사진 읽기를 공유한다. 원본/기기 저장소와 화면의 썸네일/객체 URL을 구분한다. 원본을 수정하거나 서버·AI로 전송하지 않는다.

## 초안과 실제 저장

새 초안은 B3a의 `eoul-d12-hang:profile-drafts:v1`이며 별도 등록 초안을 건드리지 않는다. 원문 form을 비동기 큐로 저장하므로 `72.`에서 멈춰도 다음에 그대로 이어 쓴다. 확정된 옷 정보는 **옷 정보 저장**에서만 바뀐다. 현재 입력이 아직 보관되지 않았으면 상태를 표시하고, 늦게 성공한 저장 뒤 앞선 오류 안내가 남지 않도록 한다.

초안 쓰기와 실제 저장은 기존 저장 잠금/사진 복구 표식을 확인한다. 같은 옷의 초안이 다른 화면에서 바뀌면 이전 편집자가 덮어쓰지 않는다. B3a 실제 저장 통로는 현재 옷장 원문과 메모리를 대조하고, 대상 profile이 바뀌어도 거절한다. 이 단계가 모든 구형 일반 편집의 서버급 동시성을 구현한 것은 아니다.

실제 옷 정보 저장이 성공하고 초안 정리만 실패할 수 있다. **저장됨/정리 미완료**를 표시하고 ‘초안 정리 다시’를 제공한다. 다시 저장해도 같은 옷 정보/등록 이력을 추가로 쓰지 않는다. 정리 실패 뒤 다른 필드를 계속 고칠 때도 방금 저장된 profile을 새 기준으로 삼는다. 사라진 옷의 편집을 새로 시작하려다 원문 초안을 먼저 지우지 않는다. 모바일에서 결과 안내가 화면 아래로 밀리는 것을 실제 viewport 검사로 재현해, 명시적 저장 후 결과 안내를 화면 중앙으로 보여 주도록 했다. 입력 중 자동 보관 때마다 화면을 옮기지는 않는다.

미래/손상 초안은 읽기 전용 경고와 전체 백업 진입을 보여 준다. 빈 값으로 초기화하지 않는다. AI 추정은 원래 출처로 남고 해당 확인/직접 편집 뒤에만 사용자 값이 된다. 종류별 기준 옷 전환은 B1의 원자 명령을 사용한다. 등록 영수증·사진 참조는 편집 중 다시 만들지 않는다.

색 선택은 기존과 같이 눌러 바로 저장한다는 안내를 둔다. profile 초안은 유지하고, 최신 코어를 읽어 색/제거 명령을 수행한다. 옷장에서 빼기는 명시 확인 뒤 기존 구매 연결 거절을 재사용한다. 사진 원본/등록 이력/남은 편집 초안은 보관된다고 설명하며 옷 제거를 개인 자료 전체 삭제로 표현하지 않는다.

## 닫기·뒤로가기·로더

Native dialog를 사용하며 열 때 제목, 닫을 때 기존 옷 버튼으로 초점을 돌린다. Escape와 직접 닫기는 초안 큐가 끝난 뒤 보관 여부를 확인한다. 저장 공간 문제로 화면에만 남은 입력이 있으면 사용자의 선택 전에는 버리지 않는다. 일반적인 보관 완료 초안은 정상적으로 닫고 다시 이어 쓸 수 있다.

브라우저 뒤로가기/앱 내부 이동도 같은 확인을 거치도록 K에 이동 guard를 추가했다. guard가 없는 기존 화면 이동은 동기 경로를 유지한다. 보관 실패 상태의 back/route가 강제로 unmount하던 실패를 양쪽 브라우저에서 먼저 재현했다. 취소하면 이동 전 경로/입력을 유지하고, 배경 새로고침은 열린 편집 modal을 제거하지 않는다. fragment 변경도 입력을 조용히 버리지 않는지 검사했다. 이것을 실제 iPhone 키보드·화면 읽기 도구 전체 검증으로 확대하지 않는다.

공통 사진 컴포넌트의 CSS가 별도 공유 chunk가 될 수 있어 정적 의존 JS/CSS 전체를 로드한다. 같은 CSS를 첫 closet/profile 로더가 동시에 기다리면서 onload를 덮어써 한 Promise가 영구 대기하던 경합을, 실제 새 문서/느린 공유 CSS 응답으로 재현해 href별 공유 Promise로 수정했다. 초기 검사 시작점이 hash만 바뀌어 등록 화면으로 새로 들어가지 못하던 부분은 query를 달리해 실제 새 문서로 바로잡은 뒤 경합을 확인했다.

방문한 런타임만 SW 제어권 획득 뒤 캐시에 요청한다. 개인 사진 읽기 코드도 같은 로더를 사용해 첫 방문의 제어권 획득 시점을 처리한다. 미방문 등록 화면을 미리 받지 않는다. 서버 origin을 실제 정지한 뒤 편집/공유 CSS/개인 사진/미완성 초안 재개와 원본 바이트 일치를 확인한다. 새 모듈을 못 열면 기존 옷 정보 화면으로 복귀하며 `?ui=vanilla`도 유지한다.

## 기존 읽기 기능과 사진 경계

선택한 옷이 들어간 기존 엔진의 조합 후보 수, 중복 제거 첫2개 미리보기, 색/조합 재료 부족 안내를 React에서 유지했다. 규칙 후보 목록이라는 출처를 표시하고 최종 AI 순위라고 부르지 않는다. 실제 보유 항목과 체험용을 구분한다.

편집 화면의 내 사진은 실제 photoId로만 읽는다. 연결이 빠져도 다른 상품을 개인 사진으로 대신하지 않는다. 개인 사진이 없고 사용자가 등록한 정확한 productId가 있을 때의 헤더 판매처 사진은 원문을 별도 표시한다. 판매처 사진의 배경 제거/파생 캐시/레이어 합성은 하지 않는다. 상품·OPF 원문 링크와 ODbL 안내를 유지한다. 레거시의 장식 meter HTML은 React에 삽입하지 않고 텍스트 정보로만 표시한다.
