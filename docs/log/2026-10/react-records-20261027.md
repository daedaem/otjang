# 구매 기록 React 이전 (WO-05)

이 작업은 WO-04를 바탕으로 한다. 담당은 Claude 패션(Opus 5.5), 브랜치는 `claude/wo-05-records-20261027`이다. 범위는 기록 탭의 구매 기록 화면을 React로 옮기는 것이다. 상세 화면의 구매 판단 바는 WO-04에서 이미 옮겼다. 반품 사유 시트는 공통 시트라 WO-08에서 다룬다. 이 기록은 사용자가 직접 남기는 메모이며, 확인된 거래가 아니다.

## 기준선 검사 (먼저 추가)

기록 화면에는 전용 브라우저 검사가 없었다. 그래서 바닐라의 현재 동작을 `e2e/records.spec.ts` 7개로 먼저 고정했다(`c5b2baf`, 바닐라에서 3번 반복 통과).

- 아무것도 정하지 않으면 "아직 정한 옷이 없어요"라고 보여 주고, "옷 찾으러 가기"로 홈에 간다.
- 보류만 있으면 "보류 1벌 · 아직 정하지 않았어요"라고 보여 준다.
- 요약에 살게요·보류·안 살래요 수와 산 옷의 수집가 합계를 보여 준다. 기록은 날짜별로 묶이고, 누르면 상품 상세가 열린다.
- 산 옷은 주문했어요 → 받았어요 → "계속 입을게요 · 걸기"로 넘어가고, 마지막 단계에서 옷장에 들어간다.
- 받은 옷은 "반품했어요"를 누르고 사유를 고를 수 있다. 타임라인에는 짧은 사유("· 색")가 표시된다.
- 단계 기록이 실패하면 이유를 알림으로 보여 주고, 단계는 그대로 둔다.
- 후보 메모에 소장 목적이 있으면 버튼이 "계속 소장할게요 · 걸기"로 바뀌고, 타임라인에 메모 줄이 붙는다.

## 무엇을 바꿨나

- **계산은 한 곳:** `screen.html`의 `recordsModel()`이 기록 화면 내용을 만든다. 바닐라 `V.records`는 이 모델로 예전과 같은 HTML을 만든다. 리팩터링 전후 10개 상태의 HTML을 비교했고 모두 같았다.
- **React 화면:** `src/records/`(`EOUL_RECORDS_LOAD` 섬). 위 막대, 제목, 요약, "사기로 한 옷" 줄(다음 단계와 반품 버튼), 날짜별 타임라인을 그린다.
- **기존 명령 재사용:** 단계는 기존 원자 명령 `M.advance`로 기록하고, 실패하면 바닐라와 같은 위치에 알림을 띄운다. 반품은 기존 반품 사유 시트를 그대로 쓴다. 같은 상품 ID와 단계 규칙은 코어가 지킨다.
- **이중 처리 방지:** React 버튼은 `data-adv`, `data-ret`, `data-pid`, `data-tabgo`, `data-disclose`를 쓰지 않는다.
- **스크롤·새로고침:** 상품에서 돌아오면 스크롤을 복원한다. `K.refresh()`가 오면 그 자리에서 갱신한다(아래 띠 포함).
- **바닐라 경로 유지:** `?ui=vanilla`이거나 섬을 불러오지 못하면 바닐라 기록 화면을 쓴다. 이때 "새 기록 화면을 열지 못해 기존 화면으로 열었어요."라고 알린다.
