# 시안 2판 디자인 명세 — 10개 시안 화면 설계 (2026-10-19)

이 문서와 `app/mockups/ux10v2/shared/tokens.css`만 보고 10개 시안을 그대로 구현할 수 있게 쓴다. 동작·검증 기준은 `docs/ux10v2-review-20261019.md`, API·흐름 표시는 `app/mockups/ux10v2/README.md`.
목표·품질 기준은 세계 최고 수준의 UX/UI(목표, 달성 검증 아님). AI 역할 설계이며 실제 수상 디자이너는 참여하지 않았다. 각 시안의 근거 id는 `research/refs.json`.

## 0. 쓰는 법
- 모든 시안은 `<link rel="stylesheet" href="../shared/tokens.css">` + `<html data-team="NN">`. 값은 토큰으로만 쓴다(직접 색·px를 새로 만들지 않는다. 예외는 이 문서가 적은 치수).
- 치수는 휴대폰 390×844, PC 1280×800 기준. 360px에서도 넘치지 않게 `minmax(0,1fr)`.
- 03·08·09는 이미 있는 파일을 6장의 '수정 사항'대로 고친다. 01·02·04·05·06·07·10은 새로 만든다.
- 그림(SVG 옷) 금지. 아이콘은 24px 선 아이콘(검색·비교·옷장·기록·뒤로·닫기·확대·외부 링크)만, 글자 이름과 함께.

## 2. 공통 부품 (모든 시안이 같은 모양을 쓴다. 시안 고유 부품은 3장)
**C1 검색칸** 높이 48, 테두리 1.5px `--ink`, 반경 `--r-control`, 왼쪽 검색 아이콘, 글자 16px(iOS 확대 방지), 오른쪽 ‘찾기’ 버튼 48×64(검정 바탕). 포커스 시 아래로 제안 목록(C2).
**C2 검색 제안** 칸 아래 흰 판, 줄 높이 48, 왼쪽 꼬리표(최근·예시·종류, 12px `--mute`) + 요청 15px. 최대 6줄. 최근이 있으면 맨 아래 ‘최근 지우기’.
**C3 범위 칩** 높이 36, 반경 알약, 테두리 `--line-2`, 글자 14px. 뺄 수 있는 칩은 오른쪽 ✕(누르는 곳 36×36, 칩 전체가 버튼, aria-label ‘출근 조건 빼기’). 종류 칩은 ✕ 없이 굵게. 칩 줄 아래 13px `--sub` 한 줄: ‘12개 · 가격: 10월 13일 수집가’.
**C4 상품 카드(그리드)** 사진 4:5(`--photo-bg`, 반경 4, `object-fit: cover`) → 8px → 브랜드 13/700 → 품명 14/400 2줄 말줄임 → 4px → 가격 15/800 → (옷장 있을 때만) 꼬리표 C10. 카드 전체가 `#/p/<id>` 링크. 비교 담기는 사진 오른쪽 위 44×44 원형 버튼(흰 92% 바탕, 아이콘 + aria-label ‘비교 담기’), 담기면 검정 바탕.
**C5 상세 머리** 휴대폰: 사진 화면 폭 100%(4:5), 오른쪽 아래 ‘크게’ 버튼(36 높이 알약, 확대 아이콘+글자). PC: 7열 사진(최대 640) + 5열 정보(sticky top 88).
정보 순서: 브랜드 14/700 → 품명 18/400(PC 22) → 가격 24/800(PC 28) + 같은 줄 13px `--sub` ‘10/13 수집가 · 무신사’ → 평점 13px ‘★ 4.7 · 후기 21,040’ → 이유 한 줄 15px(왼쪽 3px 선).
**C6 판정 블록** 테두리 1px `--line`, 반경 12, 안쪽 16. 위 12px `--sub` 기준(‘옷장 없이 판단했어요’·‘체험용 옷 8벌 기준’) → 판정 제목 20/700(색은 판정 의미색, 앞에 아이콘: 겹침 ⚠︎·새 코디 ✓·정보 ⓘ — 색만으로 뜻 전달 금지) → 설명 15px 최대 2줄 → 겹치는 내 옷 사진 줄(56×70 썸네일, ‘비슷한 상품 사진’ 표시) → 보조 버튼 ‘가진 셔츠 넣고 비교’(높이 44, 테두리).
**C7 결정 버튼 묶음** 3칸 같은 폭, 높이 48(10번 56), 간격 8. 순서 보류 · 안 살래 · 사기로 함. 강조는 하나: 판정이 `lean: 'buy'`면 ‘사기로 함’, `'hold'`면 ‘보류’를 검정 바탕, 나머지 테두리. 판정이 없으면 강조 없음. 휴대폰 상세에서는 하단 고정 결정 바(높이 68, 위 경계선, 안쪽 10/16, 탭바 숨김).
**C8 판매처 버튼** ‘무신사에서 보기 ↗’ 높이 44, 테두리(결정보다 약하게), 바로 위 12px 한 줄 ‘사이즈·소재·착용 사진은 무신사에서 확인해요’.
**C9 새 상품/중고** 두 칸 표(휴대폰도 2열): 왼쪽 ‘새 상품’ 가격 16/800 + ‘10/13 수집가 · 판매처 대표 사진’, 오른쪽 ‘중고’ ‘가격·상태는 매물마다 달라요’ + ‘어울은 확인하지 않았어요’ + 링크 칩(번개장터·당근·중고나라·후루츠패밀리 / eBay·메루카리). 중고 칸에 숫자 가격 금지. `data-flow="used-search"`는 오른쪽 칸에만.
**C10 꼬리표** 높이 22, 반경 4, 12px/700, 의미색 글자 + 의미색 배경 + 아이콘(겹쳐요 ⚠︎, 색만 달라요 ◐, 새 코디 ✓, 체험용 ⓘ).
**C11 사진 크게 보기** `#/p/<id>?view=photo`, 화면 전체 흰 바탕, 사진 `contain`, 위 오른쪽 닫기 44×44, 아래 ‘판매처 대표 사진’ 12px. 두 손가락 확대는 브라우저 기본.
**C12 옷 넣기 시트** `#/p/<id>?add=1`. 시트 1장, 반경 위 16, 그림자 `--shadow-sheet`, 손잡이 36×4. 제목 ‘가진 셔츠 색을 골라 주세요’ 18/700, 부제 ‘종류는 이 상품과 같은 옥스퍼드 셔츠로 넣어요’ 14px. 색 칩 4열 그리드(높이 48, 왼쪽 18px 색 점 + 이름). 아래 고정 ‘넣고 이 상품으로 돌아가기’(48, 검정, 색 고르기 전 비활성). 넣은 뒤 판정 블록에 3초 동안 ‘방금 바뀜 · 전에는: 옷장 없이 고른 후보예요’.
**C13 비교 바(트레이)** 결과·상세 아래 고정(탭바 위), 높이 72: 담은 사진 48×60 최대 4 + ‘n/4’ + ‘비교하기’ 버튼(44, 검정). 담은 것이 없으면 숨김. 한도 시 토스트 ‘4개까지예요. 하나를 빼면 담을 수 있어요’.
**C14 비교 화면** `#/compare`. 위 사진 줄(휴대폰 2열 고정, 3~4개는 가로로 넘김 + 점 표시, PC 최대 4열), 스크롤하면 사진이 56px 미니 머리로 붙음. 표는 `compareRows()`: 주요 5줄, 같은 값 줄은 `--mute`로 흐리게 + ‘같은 값 n줄’ 접기. 줄 이름 13px `--sub`, 값 15px. 각 열 아래 보류·사기로 함(높이 44) + ‘빼기’ 글자 버튼.
**C15 빈 결과** 제목 20/700(‘맞는 상품이 없어요’ / ‘‘꾸안꾸 느낌으로’는 아직 찾을 수 없어요’), 이유 15px 1~2줄, 그 아래 `relax()` 카드(최대 3개): ‘‘1만원 이하’ 빼고 12개’ 16/700 + 사진 3장(64×80) + 버튼 ‘이 조건으로 보기’. 아래 예시 요청 칩(`data-flow="example"`). 자동 적용·자동 대체 금지.
**C16 토스트·되돌리기** 하단 바 위 16, 검정 바탕 흰 글자 14px, 높이 48, 오른쪽 ‘되돌리기’(결정 직후 5초). role=status.
**C17 기록 줄** 높이 88: 사진 56×70, 브랜드·품명 2줄, 단계 칩(글자+색), 오른쪽 가격(tnum). 누르면 다음 단계 버튼 펼침(주문했어요·받았어요·계속 입을게요·반품했어요(사유)). 머리에 13px ‘직접 남긴 기록이에요’ 한 번.
**C18 옷장 칸** 사진 4:5(비슷한 상품 사진 표시), 이름 14px, 출처 12px(체험용·내 옷·기록에서 산 옷).

공통 문구: 가격은 ‘수집가’만(현재가·최저가·할인·특가 금지). 판매처 버튼은 ‘무신사에서 보기’. ‘AI 추천’ 대신 ‘규칙으로 골랐어요’를 필요한 곳에 한 번.

### 01 답 먼저 — "첫 후보가 곧 답"
테마: 기본. 근거: baymard-query-types, hig-search-fields, baymard-list-info, Webby 2023 Google Store(수상 부문만).
**결과(휴대폰)**
```
[머리글 56]
[C1 검색칸 48]              ← 위 16, 아래 12
[C3 칩 36] 12개 · 가격: 10/13 수집가
┌ 답 카드 (높이 ≤ 340, 테두리 1.5 --ink, 반경 12, 안쪽 12) ┐
│ [사진 132×165] │ 첫 후보 · 1/12 (12 --accent)       │
│               │ 무신사 스탠다드 (13/700)             │
│               │ 베이식 옥스포드 셔츠 [화이트] (15)    │
│               │ 33,890원 (18/800)                   │
│ 판정 한 줄: ⓘ 옷장 없이 고른 후보예요 (16/700)         │
│ [보류][안 살래][사기로 함]  44 높이                     │
│ 가진 셔츠 넣고 비교 →  (14, 글자 버튼)                  │
└───────────────────────────────────────────────┘
다른 후보 11개 (16/700)
[C4][C4]   ← 첫 화면에 사진 윗부분 2개 이상 보이게
```
- 답 카드의 사진·이름을 누르면 상세. 다른 후보 카드를 길게 누르지 않는다(첫 후보 바꾸기 버튼 없음 — 답은 정렬 1위로 고정, 대신 다른 후보 탭 → 상세).
- 0건: 답 카드 자리에 C15의 `relax()` 카드.
**결과(PC)**: 위 검색·칩 한 줄. 아래 12열: 답 카드 5열(사진 220×275 위, 정보 아래, 결정 버튼) sticky + 오른쪽 7열 다른 후보 3열 그리드.
**상세**: 공통(C5→C6→C7 고정 바→C8→C9→같은 조건 다른 선택 2열→코디 C18 타일 2×2).

### 02 세 번 탭 — "타이핑 없이 세 번"
테마: 기본. 근거: govuk-question-pages, govuk-one-thing-per-page, wcag22-3.3.7.
**시작(휴대폰)** `#/`: C1 검색칸(늘 첫 화면) → 아래 ‘또는 눌러서 찾기’ 16/700 → ‘무엇을 찾나요?’ 타일 2열×3 + ‘상관없음’ 넓은 1칸.
```
[C1 검색칸]
또는 눌러서 찾기                1/3
무엇을 찾나요? (24/700)
┌────────┐┌────────┐
│ 사진4:5 ││ 사진4:5 │  타일: 사진(그 종류 1위 상품) + 아래 이름 16/700, 전체 높이 ≥ 200
│ 셔츠    ││ 니트    │
└────────┘└────────┘ … ×3줄
[ 상관없음 ]  (48, 테두리)
```
- 고르면 바로 `#/start?step=when&kind=셔츠`(계속 버튼 없음). 2단계 ‘언제 입나요?’: 글자 타일 2열(출근·데이트·주말·하객·여행·상관없음, 높이 64, 16/700). 3단계 ‘얼마까지?’: 5만·10만·20만·상관없음(높이 64). 위 왼쪽 ‘← 이전’ 44, 오른쪽 ‘2/3’.
- 3단계를 고르면 `#/search?q=출근용 셔츠 10만원 이하`. 결과 위에 13px ‘이렇게 찾았어요’ + 16/700 문장 ‘출근용 셔츠 10만원 이하’ + ‘다음엔 말로 적어도 돼요’ 12px. 칩을 누르면 그 질문 단계로(다른 답 유지).
**PC**: 왼쪽 3열 진행 레일(① 무엇 ② 언제 ③ 얼마, 고른 답 표시), 가운데 9열 질문(타일 4열). 결과는 왼쪽 레일 유지 + 4열 그리드.
**상세**: 공통.

```
[머리글]  [칩 줄]
3 / 12  ───●──────────   [목록으로 보기 ▦] (44)
┌ 카드 (폭 358, 반경 20, 그림자 --shadow-2) ┐
│ 사진 4:5 (358×448)                      │
│ 무신사 스탠다드 13/700                     │
```

- 마지막 다음: 정리 카드 ‘보류 3 · 사기로 함 1 · 안 살래 2’ + ‘보류 3개 다시 보기’ + ‘사기로 한 상품 수집가 합 33,890원 · 결제 금액 아님’.
- ‘목록으로 보기’: 2열 C4 그리드(`data-flow="result"`).
**PC**: 왼쪽 3열 후보 목록(사진 48×60 줄, 현재 표시), 가운데 6열 카드(사진 420×525), 오른쪽 3열 결정 묶음 + 결정한 것 목록. 방향키는 카드에 포커스가 있을 때만(←→ 이동, 결정 키 없음).
