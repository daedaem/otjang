## 유지하는 원스톱 목표

[제품·개발 계약](onestop-product-contract-20261014.md)의 목표를 유지한다.

> 고객의 옷 등록 → 부족·중복 발견 → 취향과 커뮤니티에서 실제 상품 탐색 → 내 옷과 조합·가상 착용 → 같은 상품·옵션·가격 비교 → 구매 → 수령·착용·반품 결과를 다음 옷장과 추천에 반영한다.

고객이 같은 정보를 반복해서 쓰거나 여러 앱에서 비교를 처음부터 다시 하지 않게 만드는 것이 목적이다. 이번 UX 작업은 이 흐름을 이해하고 진행하기 쉽게 만드는 작업이며, 미구현 외부 연동까지 생겼다고 표시하지 않는다. Acloset보다 나은지 여부는 같은 사진·옷장·구매 후보로 과제를 수행해 확인한다. 수상작을 참고했다는 사실, 자동 검사 수, 내부 점수를 경쟁 우위나 출시 완료의 증거로 쓰지 않는다.

## 기준 화면에서 확인한 문제

기준 커밋의 `app/src/main.js`와 `app/styles.css`를 읽어 확인한 구조다. 시선 이동·과제 성공률·만족도는 아직 사용자 실험 결과가 아니다.

| 문제 | 기준 소스에서 확인한 내용 | 고객에게 생길 수 있는 부담 |
| --- | --- | --- |
| 홈에서 사진과 코디가 늦게 나옴 | `renderHome()`은 계획, 커뮤니티, 상품 링크 비교를 먼저 배치하고 오늘의 코디를 뒤에 표시함 | 앱을 열자마자 내 옷을 보는 경험보다 안내와 기능 선택을 먼저 해석해야 함 |
| 등록 확인과 보조 도구가 한 화면에 섞임 | 사진 다음에 배경 처리·사진 분석 패널을 거쳐 종류 확인과 저장으로 이어짐. 색·브랜드·이름은 이미 선택 입력이지만 도구 설명이 핵심 동선에 남아 있음 | 옷 한 벌 저장하기 전에 분석 도구를 모두 써야 하는 것으로 오해할 수 있음 |
| 모바일 옷 사진이 작음 | `.closet-items`와 `.closet-grid`가 기본 3열 | 360~430px 화면에서 옷의 형태·무늬와 이름을 함께 구별하기 어려울 수 있음 |
| 데스크톱 공간을 활용하지 못함 | `.app`, `.nav-inner`, `.sheet`에 560px 상한 | 큰 화면에서도 옷장과 상품을 좁은 세로 화면 안에서 번갈아 확인해야 함 |
| 추천과 구매 기록에 정보가 몰림 | 후보 판단, 옵션·가격 확인, 구매 후 기록을 같은 흐름 안에서 제공함 | 지금 해야 할 행동과 나중에 쓸 기록을 구분하기 어려움 |

단순히 모든 설명을 없애는 것으로 해결하지 않는다. 사진 처리의 동의, 데이터 보존, 불확실한 상품 정보, 실제 거래 여부처럼 고객의 결정을 바꾸는 정보는 해당 행동 가까이에 남긴다.

색상이나 둥근 카드만 바꾸는 작업으로 끝내지 않는다. 화면의 정보 순서, 사진과 텍스트 비중, 입력 순서, 오류 뒤 복구까지 같은 설계 기준으로 확인한다. 수상작의 브랜드 자산·레이아웃·애니메이션을 그대로 복제하지 않는다.

## 현재 구현과 선택 이유

2026-10-15의 1차 구현부터 `03272a2`, `7a19c84` 후속 수정까지의 내용이다. 추가 차단 문제 2건의 검증 범위는 아래 별도 표에 기록한다. 구현 여부와 실제 사용 검증 범위는 다르므로, 이 표만으로 출시 완료를 판정하지 않는다.

| 구간 | 반영한 변경 | 선택 이유·남은 범위 |
| --- | --- | --- |

### 실제 브라우저에서 발견해 고친 문제

옷장을 검색 중인 상태에서 새 옷을 저장하면 기존 검색 조건 때문에 방금 저장한 옷이 목록에 보이지 않는 문제가 나왔다. 저장 실패로 오해할 수 있으므로 저장 후 새 옷을 찾을 수 있도록 수정하고 회귀를 보강했다. 보강 후 앱 전체 510개 검사가 통과했다.

390px 등록 확인에는 개인 사진 대신 공개 상품 JPG를 사용했다. 화이트는 수동으로 선택한 확인값이며 자동 색 인식의 성공 사례가 아니다. 1차에서 관찰한 예시 체험의 구매 기록 생성은 이후 문제로 판정해 수정했다. 후속은 등록 시트를 열었다가 닫아도 실제 구매 여정이 0건으로 남는 것까지 확인했다. 기존 구매 기록을 열어 판단 버튼을 확인한 후속 과제도 앱 내부 시험 기록이며 판매처가 확인한 실제 거래가 아니다. 화면 폭은 데스크톱 Chrome의 모바일 크기 설정으로 실제 휴대폰의 카메라·HEIC·키보드·탭 재생성 확인을 대신하지 않는다.

시각 확인에서 가로 넘침을 보지 못했다는 결과와 DOM의 `scrollWidth`/`clientWidth` 등을 측정해 넘침이 없음을 검사한 결과도 구분한다. 현재 위 모바일 폭 검증은 전자이며, 수치 기반 검사를 했다고 기록하지 않는다.

배포 전에는 최신 형식의 사진 포함 백업과 복원 경로를 확인한다. 기존 저장 스키마·계정 교체·사진 ID·구매 이력을 시각 변경에 맞춰 임의로 바꾸지 않는다. 새 버전에서 문제가 생기면 공개 변경을 되돌리는 절차와 사용자 자료 복구를 별도로 다룬다. 이전 앱에 새 자료를 강제로 쓰거나 기존 사진·기록을 지워서 화면 문제를 해결하지 않는다.

검증용 사진·합성 판매처와 실제 개인 자료는 구분한다. 개인 사진, 토큰, 계정, 메일 설정을 PR과 공개 화면 증거에 포함하지 않는다. 화면을 직접 확인하지 못한 항목은 이유를 적고 미검증으로 유지한다.
