## 유지하는 원스톱 목표

[제품·개발 계약](onestop-product-contract-20261014.md)의 목표를 유지한다.

> 고객의 옷 등록 → 부족·중복 발견 → 취향과 커뮤니티에서 실제 상품 탐색 → 내 옷과 조합·가상 착용 → 같은 상품·옵션·가격 비교 → 구매 → 수령·착용·반품 결과를 다음 옷장과 추천에 반영한다.

고객이 같은 정보를 반복해서 쓰거나 여러 앱에서 비교를 처음부터 다시 하지 않게 만드는 것이 목적이다. 이번 UX 작업은 이 흐름을 이해하고 진행하기 쉽게 만드는 작업이며, 미구현 외부 연동까지 생겼다고 표시하지 않는다. Acloset보다 나은지 여부는 같은 사진·옷장·구매 후보로 과제를 수행해 확인한다. 수상작을 참고했다는 사실, 자동 검사 수, 내부 점수를 경쟁 우위나 출시 완료의 증거로 쓰지 않는다.

## 기준 화면에서 확인한 문제

기준 커밋의 `app/src/main.js`와 `app/styles.css`를 읽어 확인한 구조다. 시선 이동·과제 성공률·만족도는 아직 사용자 실험 결과가 아니다.

| 문제 | 기준 소스에서 확인한 내용 | 고객에게 생길 수 있는 부담 |
| --- | --- | --- |
| 홈에서 사진과 코디가 늦게 나옴 | `renderHome()`은 계획, 커뮤니티, 상품 링크 비교를 먼저 배치하고 오늘의 코디를 뒤에 표시함 | 앱을 열자마자 내 옷을 보는 경험보다 안내와 기능 선택을 먼저 해석해야 함 |
| 등록 확인과 보조 도구가 한 화면에 섞임 | 사진 다음에 배경 처리·사진 분석 패널을 거쳐 종류 확인과 저장으로 이어짐. 색·브랜드·이름은 이미 선택 입력이지만 도구 설명이 핵심 동선에 남아 있음 | 옷 한 벌 저장하기 전에 분석 도구를 모두 써야 하는 것으로 오해할 수 있음 |
| 모바일 옷 사진이 작음 | `.closet-items`와 `.closet-grid`가 기본 3열 | 360~430px 화면에서 옷의 형태·무늬와 이름을 함께 구별하기 어려울 수 있음 |
| 데스크톱 공간을 활용하지 못함 | `.app`, `.nav-inner`, `.sheet`에 560px 상한 | 큰 화면에서도 옷장과 상품을 좁은 세로 화면 안에서 번갈아 확인해야 함 |
| 추천과 구매 기록에 정보가 몰림 | 후보 판단, 옵션·가격 확인, 구매 후 기록을 같은 흐름 안에서 제공함 | 지금 해야 할 행동과 나중에 쓸 기록을 구분하기 어려움 |

단순히 모든 설명을 없애는 것으로 해결하지 않는다. 사진 처리의 동의, 데이터 보존, 불확실한 상품 정보, 실제 거래 여부처럼 고객의 결정을 바꾸는 정보는 해당 행동 가까이에 남긴다.

## 원칙에서 실제 변경 요구사항으로

아래 항목은 구현의 설계 기준이다. 실제 반영 내용과 확인 범위는 이어지는 구현·검증 기록에서 구분한다.

| 원칙 | 이번 구현 요구사항 | 보존할 사실과 동작 |
| --- | --- | --- |
| 옷 사진을 먼저 보고 다음 행동을 이해한다 | 홈 첫 영역을 사진 중심 코디와 현재 옷장 맥락으로 구성한다. 추천 이유와 상품으로 이어지는 행동을 가까이 둔다. 기능·설정 설명이 첫 화면을 차지하지 않게 한다. | 예시 옷장은 예시임을 분명히 표시하고 실제 보유 기록에 섞지 않는다. 사진 중심 표현을 3D 옷장이나 가상 착용이 구현된 것처럼 부르지 않는다. |
| 내 옷을 찾는 데 입력을 반복하지 않는다 | 옷장에 검색과 종류별 분류를 제공한다. 모바일 사진은 충분히 크게, 데스크톱은 넓은 공간을 활용한다. 비어 있는 검색 결과에는 검색 지우기·분류 바꾸기 경로를 둔다. | 검색·분류는 보는 목록만 바꾼다. 보유·반품·처분 상태나 추천 근거를 변경하지 않는다. |
| 추천 상품을 판단할 핵심 정보를 먼저 본다 | 브랜드, 정확한 품명, 확인한 가격 정보, 내 옷과의 연결 이유를 상품 카드와 상세에서 쉽게 찾게 한다. 상세 근거와 관리 기능은 필요한 때 펼쳐 본다. | 수집가와 현재 확인한 총액, 미확인과 확정을 구분한다. 종류·색이 비슷하다는 이유로 동일 상품을 만들어 내지 않는다. |
| 등록은 최소 확인으로 끝낸다 | 사진 선택 뒤 종류 확인과 저장을 중심에 둔다. 자르기·배경 제거·분석·라벨 확인 등 보조 도구는 별도 펼침 영역으로 정리한다. 이름·브랜드·색의 추가 입력은 선택 사항으로 유지한다. | 필수 입력은 기존 종류 1개 수준을 유지한다. 모델 다운로드·외부 처리 동의와 비용/처리 안내를 숨기거나 자동 동의로 바꾸지 않는다. 모르는 브랜드·품명은 모른다고 남긴다. |
| 구매 단계마다 필요한 행동을 구분한다 | 후보 비교·구매 판단, 주문 정보, 수령·착용·반품 기록을 단계에 맞춰 접고 펼친다. 현재 상태와 다음 행동은 항상 드러낸다. | 작성한 옵션·이유, 기존 이력, 사진, 연결 옷 ID와 저장 보호를 유지한다. 직접 주문 기록을 확인된 거래로 표현하지 않는다. |
| 화면이 커져도 작아져도 같은 과제를 끝낸다 | 모바일의 터치 동선과 데스크톱의 넓은 비교 공간을 각각 설계한다. 아이콘·텍스트·버튼·초점 표시를 일관되게 맞춘다. | 기존 접근성 이름과 키보드 조작을 약화하지 않는다. 움직임 감소 설정과 내용 확대를 지원하는 방향으로 검증한다. |

색상이나 둥근 카드만 바꾸는 작업으로 끝내지 않는다. 화면의 정보 순서, 사진과 텍스트 비중, 입력 순서, 오류 뒤 복구까지 같은 설계 기준으로 확인한다. 수상작의 브랜드 자산·레이아웃·애니메이션을 그대로 복제하지 않는다.

## 현재 구현과 선택 이유

| 구간 | 반영한 변경 | 선택 이유·남은 범위 |
| --- | --- | --- |
| 홈 | 다음에 비교할 실제 상품의 큰 사진과 내 옷 썸네일을 함께 배치하고, 브랜드·품명·가격 정보·추천 이유와 비교 행동을 우선함. 한 벌 등록 뒤 코디가 부족한 상태에서는 재등록을 반복 유도하는 설명 대신 코디 조건이 부족하다는 안내와 내 옷 썸네일을 보여 줌 | 설명을 읽은 뒤 사진을 찾던 순서를 바꾼다. 홈의 썸네일을 가상 착용이나 핏 예측으로 표현하지 않는다. |
| 옷장 | 모바일 2열 사진 목록, 검색, 종류 분류, 정렬을 제공함 | 옷을 구별할 면적을 확보하고 이미 등록한 옷을 다시 찾는 부담을 줄인다. 검색·분류는 보유 상태를 바꾸지 않는다. |

### Opus의 기준 화면 검토와 반영

Opus는 기준 화면을 390px 환경에서 검토했고, 유용한 결과까지 약 8번의 조작이 필요했던 흐름과 이미 선택한 후보의 4개 필드를 다시 확인하게 하는 부담을 지적했다. 이 수치는 **Opus가 검토한 기준 흐름의 보고**이며 새 화면의 입력 횟수나 사용자 성과 측정값이 아니다.

- 자주 쓰는 세부 종류를 한 번에 고르는 등록, 카탈로그 상품의 바로 비교, 핵심 확인과 보조 도구의 분리로 중복 조작을 줄였다.
- 색을 자동으로 확정하는 제안은 반영하지 않았다. 기존 사진 실험에서 흰 셔츠를 어두운 색으로 잘못 제안한 근거가 있으므로, 색은 확인하지 않은 상태를 유지하거나 사용자가 직접 확인하게 한다. 입력 감소를 위해 추정을 확정 보유 정보로 바꾸지 않는다.
- 두 상품을 함께 제안하는 경우 각 상품을 원래 추천 문맥과 연결해 이어서 비교하는 흐름은 별도 잔여 작업이다. 현재 바로 비교가 모든 복수 후보 문맥까지 해결했다고 표시하지 않는다.
- 새 구현의 최종 Opus 리뷰는 아직 완료로 기록하지 않는다.

### 실제 브라우저에서 발견해 고친 문제

옷장을 검색 중인 상태에서 새 옷을 저장하면 기존 검색 조건 때문에 방금 저장한 옷이 목록에 보이지 않는 문제가 나왔다. 저장 실패로 오해할 수 있으므로 저장 후 새 옷을 찾을 수 있도록 수정하고 회귀를 보강했다. 보강 후 앱 전체 510개 검사가 통과했다.

390px 등록 확인에는 개인 사진 대신 공개 상품 JPG를 사용했다. 화이트는 수동으로 선택한 확인값이며 자동 색 인식의 성공 사례가 아니다. 구매 기록 1건은 앱 내부 기록이고 판매처가 확인한 실제 거래가 아니다. 화면 폭은 데스크톱 Chrome의 모바일 크기 설정이며 실제 휴대폰의 카메라·HEIC·키보드·탭 재생성 확인을 대신하지 않는다.

시각 확인에서 가로 넘침을 보지 못했다는 결과와 DOM의 `scrollWidth`/`clientWidth` 등을 측정해 넘침이 없음을 검사한 결과도 구분한다. 현재 위 모바일 폭 검증은 전자이며, 수치 기반 검사를 했다고 기록하지 않는다.

배포 전에는 최신 형식의 사진 포함 백업과 복원 경로를 확인한다. 기존 저장 스키마·계정 교체·사진 ID·구매 이력을 시각 변경에 맞춰 임의로 바꾸지 않는다. 새 버전에서 문제가 생기면 공개 변경을 되돌리는 절차와 사용자 자료 복구를 별도로 다룬다. 이전 앱에 새 자료를 강제로 쓰거나 기존 사진·기록을 지워서 화면 문제를 해결하지 않는다.

검증용 사진·합성 판매처와 실제 개인 자료는 구분한다. 개인 사진, 토큰, 계정, 메일 설정을 PR과 공개 화면 증거에 포함하지 않는다. 화면을 직접 확인하지 못한 항목은 이유를 적고 미검증으로 유지한다.
