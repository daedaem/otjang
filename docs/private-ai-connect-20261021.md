# 본인 전용 AI 연결·운영 기록 (2026-10-21)

## 사용자 결정과 방식 변경

출처는 2026-10-21 현재 대화다. 대표는 무료 D1 생성·연결, 본인 전용 Cloudflare Access, master 비공개 배포를 승인했고 실제 AI 연동을 요청했다. API 키는 노출하지 않도록 요청했다. 앞선 master 검토의 "Cloudflare 설정·DB 연결을 변경하지 않음"은 **이번 승인 범위 안에서만 바뀌었다**.

Access 설정 과정에서 기존 Zero Trust 조직이 없음을 확인했다. Free 0원 플랜을 선택한 다음 화면에서 카드 등록과 약관 동의가 필수로 표시됐다. **카드·약관·계정 활성화는 진행하지 않았다.** 대표가 "결재를왜등록해요?"라고 이의를 제기한 뒤 화면을 닫았고, Codex는 카드 없는 앱 자체 본인 로그인으로 전환한다고 안내했다. Cloudflare Zero Trust 조직 생성이나 결제 등록을 완료한 것으로 기록하지 않는다.

보안 목표는 계속 "본인만 접속"이다. **Cloudflare Access만 유일한 인증 수단이어야 한다는 운영 조건은 철회**한다. 자체 로그인 모드 `PRIVATE_AUTH_MODE=session`을 구현하되 인증과 공유 D1 한도 확인은 계속 필수다. 이 문서에서 자체 로그인은 기술 선택이며, 여러 사용자용 계정·회원가입 기능이나 결제 서비스 신청이 아니다.

외부 일반 공개, 유료 가입, 크레딧 충전, 자동 유료 전환, 개인 사진 외부 전송은 승인하지 않았다. 상품 사진 사용 권리는 여전히 미확인이다. 공개용 배포·자동 미리보기 차단을 무조건 해제하지 않는다. 앱 자체 인증을 모든 앱·API·정적 자산 경로에 먼저 적용하고 검증해야 한다.

API 키·로그인 비밀 값·세션 쿠키·개인 식별 정보는 문서, 저장소, PR, 채팅, 명령행 인수, 테스트 로그에 남기지 않는다. 키 값을 보여 주는 화면을 캡처하지 않는다. 아래에는 설정 **이름과 존재 여부**, 검사 결과만 기록한다.

## 문제와 확인한 사실

- master 검토 병합본은 `f067c89d503cb3e4e235971d1087252f5d86056f`다. 원래 개인 작업 폴더 대신 `/private/tmp/otjang-master-review-20261021`의 `codex/private-ai-connect-20261021`에서 작업을 시작했다.
- 기존 대시보드에는 `ANTHROPIC_API_KEY`가 일반 빌드 변수에 있었고, 런타임 Secret은 비어 있었다. 빌드 변수는 실행 중인 Worker의 `env.ANTHROPIC_API_KEY`를 채우지 않는다. 키 값을 문서·Git·채팅에 복사하지 않았다.
- 기존 `/api/rank`에 `Content-Type: text/plain`, 본문 `not-json`을 **1회** 보냈다. HTTP 503과 `{"code":"not_configured","message":"ANTHROPIC_API_KEY가 설정되지 않았어요."}`가 돌아왔다. 실제 AI 호출에 도달할 수 없는 입력이다. 이 응답은 구형 서버의 런타임 키 누락 분기와 일치한다. master는 같은 입력을 Content-Type 검사에서 415로 거절한다.
- 이 검사로 확인한 것은 당시 구형 서버가 런타임 키를 읽지 못했다는 점이다. API 키 자체의 유효성·잔액·실제 AI 품질은 확인하지 않았다.
- 구형 설치 앱에는 상담 배열을 문자열 전용 순위 API에 보내는 문제도 있다. master는 rank/consult 구조화 요청으로 수정했다. 키 설정만으로 구형 상담도 해결됐다고 보고하지 않는다.
- **무료 D1 생성 완료:** 기존 DB 0개에서 새 DB 1개를 만들었다. 이름 `otjang-private`, UUID `e3b0965b-a661-4ef0-b6a0-2ed1c12eed99`. 이 ID는 비밀 값이 아니다. DB 생성과 Worker 바인딩·테이블 생성·실제 기능 검증은 별도 단계다.
- **Access 중단:** Free 플랜 선택 뒤 카드·약관 필수 화면에서 멈췄다. 결제 정보 등록·약관 수락·활성화는 실행하지 않았다.

## 자체 로그인 설계와 이유

| 항목 | 설계 | 이유·검증할 경계 |
|---|---|---|
| 인증 모드 | `PRIVATE_AUTH_MODE=session` | 카드·별도 Zero Trust 가입 없이 기존 Worker 안에서 본인만 접속 |
| 로그인 비밀 값 | 런타임 Secret `PRIVATE_APP_ACCESS_KEY`, 무작위 32자 이상 | 코드·빌드 변수·브라우저 자산에 포함하지 않음. 공유 링크 자체를 비밀번호로 쓰지 않음 |
| 제공자 키 | 런타임 Secret `ANTHROPIC_API_KEY` | 로그인 비밀 값과 용도 분리. 클라이언트에 제공하지 않음 |
| 세션 | 유효기간 7일, `HttpOnly; Secure; SameSite=Strict` 쿠키 | HTTPS에서만 전송하고 JS에서 읽지 않음. 만료·변조·로그아웃·비밀 값 교체 후 거절 여부 검증 |
| 로그인 시도 제한 | 공유 D1에서 IP별 분당 5회 + 전체 분당 60회 | Worker 재시작·여러 인스턴스에서도 무차별 대입을 제한. DB 실패 시 무제한 허용하지 않음 |
| 앱 경로 보호 | 로그인에 필요한 경로 외 앱·정적 자산·API 전체 보호 | API만 잠그고 상품 사진·옷장 화면이 공개되는 우회 방지. 서비스 워커 캐시도 따로 검사 |
| AI 사용량 | 공유 D1 원자 예약. **이번 배포 설정은 UTC 일 100회·월 300회·분 5회** | 인증 후에도 호출 수를 제한. 실패·취소에도 예약을 반환하지 않음. 모듈의 미지정 기본값 300/300/10과 실제 배포값을 구분 |

세션·Worker 경로 보호·클라이언트의 401 로그인 이동은 소스 구현과 로컬 통합 검사 83/83을 통과했다. 독립 보조 검토의 세션·Worker·배포 정책 27/27은 이 검사 범위의 부분집합이며 합산하지 않는다. 이는 원격 배포·Secret 입력·실제 AI·아이폰 검증 완료를 뜻하지 않는다. 로그인 IP는 원문 대신 분마다 달라지는 HMAC 태그로 저장하고, 다음 로그인 시도에서 2분보다 오래된 행을 정리한다. 사용이 없을 때도 정확히 2분 뒤 자동 삭제되는 TTL은 아니다.

## 연결 순서

1. **만든 D1의 바인딩 설정을 준비한다.** 소스 설정의 `RANK_DB`와 `CROWD_DB`는 둘 다 같은 `otjang-private` DB(`e3b0965b-a661-4ef0-b6a0-2ed1c12eed99`)를 가리킨다. 두 개의 별칭이며 DB 두 개를 만드는 설정이 아니다. 원격 바인딩·테이블 생성 성공은 배포 후 별도로 확인한다. 새 유료 요금제로 전환하지 않는다.
2. **카드 없는 본인 로그인을 구현·검증한다.** `PRIVATE_AUTH_MODE=session`, 세션·경로 보호·D1 로그인 제한·401 클라이언트 이동 구현을 로컬 83/83으로 검증했다. 인증·DB 설정이 없으면 로그인이나 유료 AI를 허용하지 않는다. Access 가입 화면이나 카드 등록을 다시 진행하지 않는다.
3. **새 비공개 진입점이 적용된 master를 먼저 배포한다.** 루트 `app/lite`, 모든 정적 자산이 Worker를 먼저 거치는 설정, 대상 이름·빌드·미리보기 차단을 확인한다. **사용자에게 런타임 Secret을 넣어 달라고 하기 전에** 새 인증 코드가 실제 배포됐고 미인증 앱·API·자산 요청이 거절되는지 확인한다. 그래야 구형 공개 프롬프트 프록시에 제공자 키부터 연결되는 일을 피할 수 있다. 비공개 배포를 일반 공개 허가로 바꾸지 않는다. 커밋·배포 버전을 기록한다.
4. **기존 API 키를 교체·폐기한다.** 일반 빌드 변수에 사용했던 키는 대표가 발급처에서 교체·폐기한다. 빌드 변수 제거와 발급처 폐기는 별도로 확인한다. 새 키 값이나 기존 값의 일부를 문서·채팅으로 받지 않는다.
5. **보호된 새 배포에 런타임 Secret 2개를 채운다.** `PRIVATE_APP_ACCESS_KEY`와 `ANTHROPIC_API_KEY`를 사용한다. 현재 관리 CLI 권한으로 일반 빌드 변수의 값을 읽어 Secret으로 자동 이동할 수 없다. 값을 추출·출력하지 않으며 사용자가 대시보드에서 직접 입력해야 할 수 있다. Secret 이름 존재·입력 주체·현재 배포 반영 여부를 구분한다. 로그인 비밀 값을 바꾼 경우 기존 세션 무효화도 확인한다.
6. **무비용 검사 후 최소 실제 AI를 확인한다.** 먼저 형식 오류·미인증·한도 미연결을 제공자 호출 없이 거절하는지 확인한다. 이후 본인 로그인과 기존 크레딧 범위가 확인된 경우에만 합성 텍스트·서버 상품 후보로 필요한 최소 rank/consult 검사를 한다. 이 문서 갱신 시점에는 실제 API를 호출하지 않았다. 개인 사진은 보내지 않는다.
7. **아이폰 결과를 따로 남긴다.** 서비스 워커 갱신, 로그인 유지·만료, 저장된 옷장, 상담·추천을 확인한다. 기존 자료를 지우지 않는다. 서버 성공을 아이폰 검증이나 추천 정확도 완료로 대신하지 않는다.

AI 한도는 호출 횟수 제한이고 통화 금액의 절대 상한이 아니다. 기존 크레딧 만료 뒤 충전·비용 발생은 별도 대표 결정이다.

## 장애 구분과 복구

| 증상 | 의미·조치 |
|---|---|
| `503 not_configured` | 키·인증 모드·로그인 Secret·D1·한도 설정 중 누락/오류 가능. 값 없이 설정 이름·실제 배포 버전부터 확인 |
| `401 unauthorized` 또는 로그인 화면 | 본인 세션 없음·만료·변조 가능. 로그인 상태와 보호 경로 확인. 인증 우회 금지 |
| `503 budget_unavailable` | 공유 D1 예약 실패. 바인딩·DB·스키마 확인. 메모리/KV 무제한 대체 금지 |
| `429` | 로그인 시도·AI 일/월/분 한도 또는 제공자 제한. 제한 종류를 구분하고 자동 상향하지 않음 |
| `400/413/415 bad_request` | 요청 형식·크기·타입 불일치. 앱/서버 버전과 구조화 요청 확인. 원문 prompt 경로 복원 금지 |
| HTML 오류·403 | 프록시·기존 Access·보안 경로도 가능. 선택 헤더·리다이렉트 호스트로 구분하고 API 키 오류로 단정하지 않음 |
| `502 error/parse` | 제공자 실패·시간 초과·출력 검증 실패 등. 민감 정보 없이 코드로 구분. 무제한 재시도·검증 완화 금지 |

복구는 마지막으로 확인한 **접근 제한된** 배포를 기준으로 한다. 필수 인증이나 D1을 제거해 성공시키지 않는다. 기존 개인 자료와 구매 기록은 초기화하지 않는다.
