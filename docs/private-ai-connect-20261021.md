## 사용자 결정과 방식 변경

출처는 2026-10-21 현재 대화다. 대표는 무료 D1 생성·연결, 본인 전용 Cloudflare Access, master 비공개 배포를 승인했고 실제 AI 연동을 요청했다. API 키는 노출하지 않도록 요청했다. 앞선 master 검토의 "Cloudflare 설정·DB 연결을 변경하지 않음"은 **이번 승인 범위 안에서만 바뀌었다**.

Access 설정 과정에서 기존 Zero Trust 조직이 없음을 확인했다. Free 0원 플랜을 선택한 다음 화면에서 카드 등록과 약관 동의가 필수로 표시됐다. **카드·약관·계정 활성화는 진행하지 않았다.** 대표가 "결재를왜등록해요?"라고 이의를 제기한 뒤 화면을 닫았고, Codex는 카드 없는 앱 자체 본인 로그인으로 전환한다고 안내했다. Cloudflare Zero Trust 조직 생성이나 결제 등록을 완료한 것으로 기록하지 않는다.

보안 목표는 계속 "본인만 접속"이다. **Cloudflare Access만 유일한 인증 수단이어야 한다는 운영 조건은 철회**한다. 자체 로그인 모드 `PRIVATE_AUTH_MODE=session`을 구현하되 인증과 공유 D1 한도 확인은 계속 필수다. 이 문서에서 자체 로그인은 기술 선택이며, 여러 사용자용 계정·회원가입 기능이나 결제 서비스 신청이 아니다.

**로그인 사용성 정정:** 최초에는 사용자가 무작위 32자 이상 접속 키를 직접 넣도록 설계했다. 대표가 매번 입력하기 어렵다고 지적했고 Codex는 이 요구가 불편한 설계였음을 인정했다. **수동 32자 키 조건은 바뀜:** 기존 `PRIVATE_APP_ACCESS_KEY`에는 사용자가 쓰는 8~128자 ASCII 비밀번호를 그대로 두고, 빈 값·공백뿐인 값은 받지 않는다. 서버는 별도 32바이트 난수를 만들고 비공개 D1 단일 설정 행에 원자적으로 저장한다. 내부 키와 비밀번호 세대별 HMAC을 분리해 비밀번호 변경 시 기존 쿠키를 무효화한다. 내부 키는 사용자가 입력·기억할 항목이 아니다. 비밀 값 추가 입력·카드 등록은 필요하지 않다. **새 방식은 PR #29로 배포했고 화면·미인증 401을 확인했다. 이 단계에서는 실제 본인 로그인과 AI 성공을 아직 확인하지 않았다.**

외부 일반 공개, 유료 가입, 크레딧 충전, 자동 유료 전환, 개인 사진 외부 전송은 승인하지 않았다. 상품 사진 사용 권리는 여전히 미확인이다. 공개용 배포·자동 미리보기 차단을 무조건 해제하지 않는다. 앱 자체 인증을 모든 앱·API·정적 자산 경로에 먼저 적용하고 검증해야 한다.

API 키·로그인 비밀 값·세션 쿠키·개인 식별 정보는 문서, 저장소, PR, 채팅, 명령행 인수, 테스트 로그에 남기지 않는다. 키 값을 보여 주는 화면을 캡처하지 않는다. 아래에는 설정 **이름과 존재 여부**, 검사 결과만 기록한다.

## 문제와 확인한 사실

- master 검토 병합본은 `f067c89d503cb3e4e235971d1087252f5d86056f`다. 원래 개인 작업 폴더 대신 `/private/tmp/otjang-master-review-20261021`의 `codex/private-ai-connect-20261021`에서 작업을 시작했다.
- 기존 대시보드에는 `ANTHROPIC_API_KEY`가 일반 빌드 변수에 있었고, 런타임 Secret은 비어 있었다. 빌드 변수는 실행 중인 Worker의 `env.ANTHROPIC_API_KEY`를 채우지 않는다. 키 값을 문서·Git·채팅에 복사하지 않았다.
- 이후 확인한 대시보드에서 같은 이름은 **암호화된 Build Secret**으로 표시됐다. 최초 일반 빌드 변수 관찰과 나중 암호화 표시를 구분하며, Codex가 암호화 전환을 실행했다고 기록하지 않는다. 암호화된 빌드 값도 런타임 Secret은 아니다. 키 값은 읽지 않았다.
- 기존 `/api/rank`에 `Content-Type: text/plain`, 본문 `not-json`을 **1회** 보냈다. HTTP 503과 `{"code":"not_configured","message":"ANTHROPIC_API_KEY가 설정되지 않았어요."}`가 돌아왔다. 실제 AI 호출에 도달할 수 없는 입력이다. 이 응답은 구형 서버의 런타임 키 누락 분기와 일치한다. master의 rank 함수 내부는 같은 입력을 Content-Type 검사에서 415로 거절한다. 이후 배포한 Worker는 그 함수보다 먼저 본인 인증을 확인하므로 현재 미인증 요청의 503과 구분한다.
- 이 검사로 확인한 것은 당시 구형 서버가 런타임 키를 읽지 못했다는 점이다. API 키 자체의 유효성·잔액·실제 AI 품질은 확인하지 않았다.
- 구형 설치 앱에는 상담 배열을 문자열 전용 순위 API에 보내는 문제도 있다. master는 rank/consult 구조화 요청으로 수정했다. 키 설정만으로 구형 상담도 해결됐다고 보고하지 않는다.
- **무료 D1 생성 완료:** 기존 DB 0개에서 새 DB 1개를 만들었다. 이름 `otjang-private`, UUID `e3b0965b-a661-4ef0-b6a0-2ed1c12eed99`. 이 ID는 비밀 값이 아니다. DB 생성과 Worker 바인딩·테이블 생성·실제 기능 검증은 별도 단계다.
- **Access 중단:** Free 플랜 선택 뒤 카드·약관 필수 화면에서 멈췄다. 결제 정보 등록·약관 수락·활성화는 실행하지 않았다.
- **원격 D1 바인딩 확인:** Worker UI에 `CROWD_DB`와 `RANK_DB` 두 바인딩이 표시된 것을 확인했다. 같은 무료 DB의 별칭이며, 원격 테이블·사용량 예약·실제 기능 성공까지 확인한 것은 아니다.

| AI 사용량 | 공유 D1 원자 예약. **이번 배포 설정은 UTC 일 100회·월 300회·분 5회** | 인증 후에도 호출 수를 제한. 실패·취소에도 예약을 반환하지 않음. 모듈의 미지정 기본값 300/300/10과 실제 배포값을 구분 |

기존 32자 접속 키 방식의 로컬 83/83과 그 부분집합인 독립 27/27은 합산하지 않는다. **8자 이상 비밀번호·D1 내부 키 변경 후 전체 lite 86/86, build, Wrangler 4.151 dry-run을 통과했다.** 새 방식의 배포·화면·미인증 상태는 확인했으며 실제 본인 로그인·AI·아이폰 검증은 남았다. 로그인 IP는 분마다 달라지는 HMAC 태그로 저장하고 다음 로그인 시도에서 2분보다 오래된 행을 정리한다. 정확히 2분 뒤 자동 삭제되는 TTL은 아니다. 세션은 7일 유지하고 저장된 비밀번호 자동 완성으로 반복 입력을 줄인다.

## 최초 연결 순서 기록 (이미 저장한 키의 재입력 지시 아님)

1. **만든 D1의 바인딩 설정을 준비한다.** 소스 설정의 `RANK_DB`와 `CROWD_DB`는 둘 다 같은 `otjang-private` DB(`e3b0965b-a661-4ef0-b6a0-2ed1c12eed99`)를 가리킨다. 두 개의 별칭이며 DB 두 개를 만드는 설정이 아니다. 원격 바인딩·테이블 생성 성공은 배포 후 별도로 확인한다. 새 유료 요금제로 전환하지 않는다.
2. **카드 없는 본인 로그인을 구현·검증한다.** `PRIVATE_AUTH_MODE=session`과 경로 보호를 유지하며 8자 이상 비밀번호·자동 내부 키로 수정해 86/86과 배포·화면 갱신을 확인했다. 인증·DB 설정이 없으면 로그인이나 유료 AI를 허용하지 않는다. Access 가입 화면이나 카드 등록을 다시 진행하지 않는다. 실제 본인 로그인은 다음 사용자 확인 단계다.
3. **새 비공개 진입점이 적용된 master를 먼저 배포한다.** 루트 `app/lite`, 모든 정적 자산이 Worker를 먼저 거치는 설정, 대상 이름·빌드·미리보기 차단을 확인한다. **사용자에게 런타임 Secret을 넣어 달라고 하기 전에** 새 인증 코드가 실제 배포됐고 미인증 앱·API·자산 요청이 거절되는지 확인한다. 그래야 구형 공개 프롬프트 프록시에 제공자 키부터 연결되는 일을 피할 수 있다. 비공개 배포를 일반 공개 허가로 바꾸지 않는다. 커밋·배포 버전을 기록한다.
4. **기존 API 키를 교체·폐기한다.** 일반 빌드 변수에 사용했던 키는 대표가 발급처에서 교체·폐기한다. 빌드 변수 제거와 발급처 폐기는 별도로 확인한다. 새 키 값이나 기존 값의 일부를 문서·채팅으로 받지 않는다.
5. **보호된 새 배포에 저장된 런타임 Secret 2개를 유지한다.** 사용자가 이미 `PRIVATE_APP_ACCESS_KEY`와 `ANTHROPIC_API_KEY`를 Secret으로 저장했다. 새 로그인 방식은 입력된 비밀번호를 재사용하며 내부 키를 서버가 생성한다. 값 추출·출력·재입력을 요청하지 않는다. 비밀번호 변경 시 기존 세션 무효화를 새 코드로 검증한다.
6. **무비용 검사 후 최소 실제 AI를 확인한다.** 먼저 형식 오류·미인증·한도 미연결을 제공자 호출 없이 거절하는지 확인한다. 이후 본인 로그인과 기존 크레딧 범위가 확인된 경우에만 합성 텍스트·서버 상품 후보로 필요한 최소 rank/consult 검사를 한다. 이 문서 갱신 시점에는 실제 API를 호출하지 않았다. 개인 사진은 보내지 않는다.
7. **아이폰 결과를 따로 남긴다.** 서비스 워커 갱신, 로그인 유지·만료, 저장된 옷장, 상담·추천을 확인한다. 기존 자료를 지우지 않는다. 서버 성공을 아이폰 검증이나 추천 정확도 완료로 대신하지 않는다.

AI 한도는 호출 횟수 제한이고 통화 금액의 절대 상한이 아니다. 기존 크레딧 만료 뒤 충전·비용 발생은 별도 대표 결정이다.

## 장애 구분과 복구

### 로그인 후 응답과 Console 사용량의 불일치

대표가 앱에 로그인했고 보호된 화면을 확인했다. 새로고침 후 새 상담에서는 스타일 답변과 실제 후보 상품 두 개가 표시됐다. 기존 상담의 400 안내는 질문 길이만을 원인으로 지목했으나, 실제 엔진/체험 옷장으로 실행한 로컬 요청에서는 정상 형식이 검증됐다. 이 사실만으로 이전 오류의 원인이 캐시였다고 확정하지 않는다. 기존 상담 자료는 삭제하지 않았다.

그 뒤 대표가 제시한 Console 화면은 전체 워크스페이스·키·모델, 최근 30일의 입력/출력 토큰 0이었다. 직접 새로고침해도 0이었다. 대표는 현재 Console에서 발급한 키라고 확인했다. [공식 사용량 안내](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)는 통상 요청 완료 후 5분 내 집계되며 더 늦어질 수 있다고 설명하지만, 이번 원인을 지연 또는 다른 조직이라고 단정하지 않는다. 이후 동일 요청 ID가 같은 Console 로그에 나타난 사실은 위 최신 확인 결과에 기록했다.

이를 검증하려고 SDK의 실제 `model`, `id`, `usage.input_tokens`, `usage.output_tokens`와 선택적 캐시/요청 ID만 성공 JSON의 `ai`로 전달한다. 필수 정보가 없거나 유효하지 않으면 메타데이터 전체를 생략한다. 모델명·0토큰·ID를 추정하지 않고 키·쿠키·질문·오류 원문을 내보내지 않는다. 상담에는 기본 접힌 'AI 응답 정보'를 추가하며 기존 이력은 유지한다. 메타데이터 표시는 추가 API 호출을 만들지 않는다. 전체 lite 93/93, build, Wrangler 4.151 dry-run을 통과했고 PR #30 배포 후 실제 제공자 응답과 Console 로그 대조도 완료했다. 합계 화면과의 불일치만 원인 미확인이다.

배포 모델은 `claude-haiku-5-5`, effort `low`다. 이 문서의 최초 검증 당시 짧은 답변은 서버의 5문장/700자 규칙이었으며 최대 출력 설정은 2,000토큰이다. 매 요청에는 최근 메시지 6개만 전달한다. 앱 한도는 상담·AI 순위 합산 일100/월300/분5이며, 제공자에 도달한 실패도 예약 횟수를 돌려주지 않는다. 이 설정과 금액의 실제 잔액은 서로 다른 제한이다. 10-21 검증에서는 모델·분량·기억·한도를 변경하지 않았다. 이후 PR #45는 상담 표시 상한을 550자로 바꾸었고 PR #47도 이를 유지했다.
