# 상품 정보·이미지 확보 대책 (2026-10-19)

대표 질문: "지금은 API 없이 이미지를 받아 오는 것 같다. 사업으로 진행하려면 어떻게 해야 하나. 쿠팡 판매 이력이 없어 쿠팡 파트너스는 불가능할 것 같다."

## 1. 지금 상태 (코드에서 확인)
- 상품 891개는 무신사 상품 페이지·브랜드 목록 화면에서 **직접 읽어 온 값**이다(`app/src/data/products.js` 머리말, `app/tools/catalog/`). 무신사의 허락을 받은 적은 없다.
- 상품 사진은 우리 서버에 저장하지 않고 무신사 이미지 서버(`image.msscdn.net`) 주소를 그대로 `<img>`로 건다(핫링크). 이때 `referrerpolicy="no-referrer"`로 **우리 앱에서 불러온다는 사실을 숨긴다**(`main.js` 354행). 기술적으로는 동작하지만 사업으로 가면 가장 먼저 문제가 되는 부분이다.
- 가격은 수집일 가격이고, 화면에서도 그렇게 적는다. 이 원칙은 유지한다.

## 2. 왜 이대로는 안 되나
- 상품 사진과 상세 설명은 저작권법·부정경쟁방지법으로 보호될 수 있다는 판례 해설이 있다([디지털데일리](https://m.ddaily.co.kr/page/view/2022050215534167671), [로톡](https://www.lawtalk.co.kr/posts/157464)). 창작성 여부가 쟁점이라 모든 상품 사진이 보호되는 것은 아니지만, **우리가 그 판단을 대신할 수 없다.**
- 핫링크는 상대 서버 비용을 우리가 쓰는 것이고, 상대가 주소를 바꾸거나 차단하면 앱의 사진이 한꺼번에 깨진다. 참조 주소를 숨기는 설정은 "알고 했다"는 인상을 준다.
- 가격비교 서비스의 수집 적법성은 이번 조사에서 정리된 자료를 찾지 못했다. **지식재산권 변호사 1회 상담이 필요하다(확인 필요).**

## 4. 추천 순서 (1인·30만원 기준)

**0단계 · 지금 (0원, 이번 주)**
1. **공개 배포 금지를 유지**한다. 지인 파일럿(비공개, 사진·링크 외부 전송 없음)까지는 지금 자료로 간다.
2. 앱의 모든 상품 사진에 "무신사 상품 사진 · 수집일 기준"을 이미 적고 있다. 여기에 **사진이 안 뜨면 색 카드로 대체**되는 동작(이미 있음)을 그대로 둔다. 핫링크가 끊겨도 앱은 산다.
3. `referrerpolicy="no-referrer"`는 공개 전에 뺀다. 숨길 이유가 없는 방식으로 가야 한다. (지금 당장 빼면 무신사가 차단할 수 있어 파일럿 사진이 깨질 수 있다. **공개 전 교체와 함께** 뺀다.)

**1단계 · 제휴 신청 (0원, 2주 안)**
4. 쿠팡 파트너스 가입. 채널은 앱 소개 페이지·블로그·인스타 중 **글이 3~5개 이상 있는 것**으로. 사업자가 없어도 개인으로 가입 가능하다는 안내가 있다(확인 필요).
5. 무신사 큐레이터, 에이블리 크리에이터 신청. 떨어져도 손해 없다.
6. 링크프라이스 어필리에이트 가입 후 패션 머천트·상품 DB 제공 여부 문의.
7. **변호사 1회 상담**(비용 확인 필요, 추정 10~30만원). 질문은 세 개로 좁힌다: ① 사용자가 붙여 넣은 링크의 OG 미리보기를 그 순간 읽는 것, ② 제휴 링크 승인 뒤 그 플랫폼 상품 사진을 우리 화면에 거는 것, ③ 제휴 전에 수집 상품을 비공개 파일럿에 쓰는 것. 30만원 예산의 가장 큰 지출이지만, 이 답 없이 공개하면 안 된다.

**2단계 · 사용자 검증 통과 뒤 (공개 전 필수)**
8. 수집 카탈로그를 **제휴 허용 자료로 교체**한다. 쿠팡은 최종 승인 뒤 API, 링크프라이스는 상품 DB, 무신사·에이블리는 승인된 링크 범위. 허용 근거가 없는 상품은 **공개 빌드에서 뺀다**(사진 없이 종류·색만 남기거나 삭제).
9. 사용자가 붙여 넣은 링크는 OG 미리보기 방식으로 바꾼다. 서버가 그 페이지 한 번을 읽고 글자만 돌려준다(사진 주소는 저장하지 않는다).
10. 브랜드 직접 제휴 메일. 사용자 기록에서 가장 많이 찾은 브랜드 5곳.

**3단계 · 사업자 등록 뒤**
11. 플랫폼 공식 제휴 제안(무신사 파트너그로스비즈 등). 데이터 제공 조건은 상대가 정하므로 사용자 수가 있어야 대화가 된다.

## 5. 제품 쪽 결론
- 사업 모델을 **"우리 카탈로그에서 골라 준다"에서 "사용자가 가져온 상품을 판정하고, 추천은 제휴 허용 범위에서만"**으로 조금 옮기면 법적 위험이 가장 작다. 지금 앱 구조(링크 붙여넣기 → 비교 → 기록)가 이미 이 방향이다.
- "대충 말해도 실제 상품 추천"은 제휴 상품 안에서만 약속한다. 상품 수가 줄어도, 없는 상품을 만들어 채우지 않는다.

## 6. 대표가 정할 것
1. 변호사 상담 비용을 쓸지(추정 10~30만원).
2. 쿠팡 파트너스 채널로 무엇을 등록할지(앱 소개 페이지를 만들지, 기존 SNS를 쓸지).
3. 사업자 등록 시점(제휴 정산·플랫폼 제안에 필요).
4. 공개 전 "허용 근거 없는 상품은 뺀다"는 원칙에 동의하는지.

## 7. 확인이 필요한 것
- 네이버 쇼핑 API 종료의 공식 공지, 쿠팡 파트너스 최종 승인·API 한도의 현행 조건, 무신사 큐레이터의 앱 운영자 승인 가능성, 링크프라이스의 패션 머천트·상품 DB 제공 여부, 제휴 약관이 상품 사진 사용을 어디까지 허락하는지.
