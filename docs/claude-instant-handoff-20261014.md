# Claude 새 앱 검토와 즉시 체험 변경 인계

이 문서는 `2494c09`의 체험 모드 변경 시점 기록이다. 이후 실제 옷·사진 등록과 저장·백업 변경은 [후속 인수인계](instant-garments-handoff-20261014.md)가 현재 상태를 설명한다. 아래의 "사진 등록 없음"은 이 초기 커밋의 상태다.

## 사용자 요구와 작업 기준

- 사용자 결정: 옷을 전부 입력하기 전에 기능을 써볼 수 있도록 기본 옷을 넣고 복잡한 흐름을 줄인다.
- 사용자 결정: `claude/fashn-vton-m1-test-3ox240`의 커밋을 확인한다.
- 확인한 커밋: `272ef5a395cc74177df34fad18380e8d11e3b4d8` (`feat: rebuild app around instant real-brand recommendations`).
- 이 커밋은 FASHN 실험 외에 새 정적 앱을 포함한다. 상품 데이터는 157개이며 상품별 브랜드·품명·확인 시점 가격·판매 링크·이미지 주소를 갖는다. Claude 데이터의 확인 날짜는 2026-10-13이다. 이번 검토는 157개 판매 페이지의 현재 가격·재고를 재검증한 것이 아니다.
- 기존 공개 `preview/core-flow/`는 다른 브랜치의 앱이다. 두 앱은 구현과 저장 키가 다르며, Claude 변경이 기존 미리보기에 반영되어 있지 않았다.

## 이번 구현과 이유

새 코드의 기준은 Claude 커밋이다. `feat/instant-wardrobe-demo-20261014`에서 아래 변경만 이어간다.

1. 새 방문자는 남성 클래식 예시 옷 6벌로 추천을 즉시 본다. 남성 기본값은 이번 사용자 체험의 시작점이며 성별 추정 결과가 아니다. 프로필에서 여성으로 바꾸면 여성 예시 6벌을 쓴다.
2. 예시 모드는 배너, 코디 카드, 추천 이유, 옷장 이름에 표시한다. 기존 `eoul:v1` 개인 기록에는 기본 옷을 추가하지 않는다. `내 옷으로 바꾸기`를 누르면 예시 보유 목록을 비우고 직접 선택하게 하며, 다시 열어도 예시 옷이 재삽입되지 않는다.
3. 옷장은 선택한 옷부터 보여 준다. 전체 종류 목록은 `옷 추가하기` 안으로 접고, 모든 종류를 채워야 하는 것처럼 보이던 진행률을 제거했다.
4. 검색의 기준 아이템을 보유 사실로 간주하던 오류를 고쳤다. 빈 옷장에서 `청바지에 어울리는 신발`을 검색하면 청바지는 구매 후보이며, 실제 목록에 있을 때만 보유로 표시한다. 이에 따라 총 구매 금액도 계산한다.
5. 상품 상세에서 `이 아이템으로 만든 코디`에 선택한 상품과 다른 브랜드 상품이 들어가던 오류를 고쳤다. 선택한 상품 ID와 가격을 코디에 고정한다.
6. 상세 화면의 `비슷한 옷이 이미 있어요`는 추가 동작이다. 이미 있는 옷을 다시 누르면 목록에서 지워지던 토글 동작을 막았다.

## 실행 검증

Node 22.23.2로 실행했다.

```sh
cd app
node --test
node tools/build.mjs
git diff --check
```

- 원본 Claude 커밋: 테스트 15/15와 단일 HTML 빌드 성공.
- 이번 변경: 테스트 23/23 성공. 기존 추천/검색 15건, 검색 보유 판정과 정확한 상품 코디 2건, 체험/저장/개인 모드 전환 6건.
- 체험 검증은 빌드된 실제 JavaScript를 Node VM에서 저장소와 최소 DOM 대역으로 실행한다. 실제 브라우저 렌더링·스마트폰 터치·상품 이미지 로딩을 검증한 결과가 아니다.

## 남은 범위

- 추천은 아이템 종류와 편집된 코디 공식에 기반한다. 사용자가 가진 실제 옷의 사진·핏·소재를 판독한 결과가 아니다.
- 이번 새 앱에는 사진 등록, 기존 사진 옷장 가져오기, 서버·계정·동기화, 구매·착용·환불 기록, 3D 옷장, VTON 합성이 연결되어 있지 않다. 기존 구현을 삭제하거나 해당 기능의 개발 완료를 의미하지 않는다.
- 원본 앱의 localStorage 저장 오류 알림, 저장 데이터 검증과 복구, 실기기 접근성/대화상자 포커스는 후속 확인 대상이다.
- `preview/instant-wardrobe/`는 이 앱을 검토할 별도 미리보기 경로다. 기존 `preview/core-flow/`의 사진과 저장소를 자동 변환하지 않는다.
- 원본 Claude 브랜치와 기존 통합 브랜치는 병합하지 않는다. 기존 통합 체크아웃의 미완성 기록 동기화 변경도 이번 배포에 포함하지 않는다.

## 이후 통합 원칙

첫 화면에서 코디와 구체적인 추천 상품을 바로 보는 흐름을 유지한다. 사진 등록을 연결할 때 필요한 속성만 나중에 확인하고, 상품 종류 선택을 사진 자동 인식이나 정확한 핏 판정으로 표현하지 않는다. 두 저장 모델 사이의 가져오기는 별도의 변환·보존 검증을 거친 뒤 연결한다.
