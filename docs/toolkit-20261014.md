### 이번 검사 결과 (`34f218a` 빌드, axe는 `80dbd13`에서 다시 검사)

**Lighthouse 모바일** (모의 느린 4G + CPU 4배 감속, 무신사 이미지 차단, gzip 전송, 2회)
- 성능 78·84점, 첫 화면 표시 1.6초, 가장 큰 요소 1.9~2.0초, 입력 막힘 합계 580~910ms
- 접근성 100점, 권장 사항 96점
- gzip 없이 재면 성능 37점(첫 화면 6.1초)이다. GitHub Pages는 gzip으로 보내므로 앞의 숫자가 실제에 가깝다고 본다(추론, 실기기 미측정).
- 남은 개선점: 첫 실행 때 한 번에 1.2초 걸리는 작업(스타일·배치 계산 약 2초가 큼), 쓰지 않는 JS 약 232KiB
- 미리보기 링크용 빌드는 상품 사진을 넣어서 7MB다. 실제 배포본(835KB, 사진은 무신사 주소)과 다르다.

**axe-core** (첫 화면, 옷장, 옷 추가 창, 사진 고른 뒤, 상품 창)
- 심각: 아래쪽에서 올라오는 창(옷 추가, 상품, 구매 여정 등)에 이름이 없어서 화면 낭독기가 "대화상자"라고만 읽었다. → **Claude가 고침** (`80dbd13`, 창의 첫 제목을 이름으로 연결, 검사 1개 추가). 다시 검사하니 창 3곳 모두 위반 0건.
- 보통(남음): 페이지에 1단계 제목(`h1`)이 없다. 예시 옷 안내와 저장 안내가 화면 구역(`header`/`main`) 밖에 있다. 화면 뼈대를 바꾸는 일이라 Codex 작업과 겹치므로 Codex에 넘긴다.
- 작음(남음, Lighthouse): 상품 사진을 못 불러와 색 카드로 바뀌면, 보이는 글자("셔츠")가 버튼의 읽는 이름("브랜드 이름 자세히")에 없다.

## 3. 앱에 넣을 후보 (라이선스 확인 결과)

2026-10-14에 공개 문서만 읽어서 확인했다(Hugging Face 모델 카드, GitHub `LICENSE`, npm, WebKit 버그 기록). 아무것도 올리거나 설치하지 않았다. 모델 코드와 가중치(학습된 값) 라이선스가 다른 경우가 많아서 따로 적었다. ✔는 Claude가 원문을 한 번 더 직접 확인한 항목이다.

### 배경 분리·옷 오려 내기 (Codex 스파이크 후보)

| 후보 | 코드 / 가중치 라이선스 | 상업 사용 | 브라우저용 크기 | 판단 |
|---|---|---|---|---|
| **SlimSAM** (`Xenova/slimsam-77-uniform`) | Apache-2.0 / Apache-2.0 ✔ | 가능 | 압축판 13.8MB(8.9 + 4.9) ✔ | **1순위**. 옷을 손가락으로 누르면 그 부분만 오려 낸다. 입은 사진·여러 벌 사진에도 쓸 수 있다. 원 SAM의 학습 데이터(SA-1B)는 연구용 조건이 있다. 모바일 처리 시간은 미측정 |
| U-2-Netp (커뮤니티 변환본) | Apache-2.0 / 가중치 별도 표기 없음 | 아마 가능(미확인) | 4.6MB | 2순위. 자동으로 가운데 물체를 오린다. 변환본 품질 미확인 |
| BiRefNet_lite | MIT / MIT | 라이선스상 가능 | fp16 114.5MB | 보류. 너무 크다. 학습 데이터 일부(DIS5K)가 비상업 조건 |
| MediaPipe 다중 분류 | Apache-2.0 / Apache-2.0 | 가능 | 16.4MB + WASM 약 13MB | 보류. "옷" 구역이 있지만 사람이 입은 옷만 대상이다. 착용 사진 분할은 1·2단계 뒤로 미뤘다 |
| MODNet | Apache-2.0 / Apache-2.0 | 가능 | 6.6MB | 제외. 사람 윤곽용이다 |

**넣으면 안 되는 것**
- RMBG-1.4, RMBG-2.0(BRIA): 가중치가 비상업 전용이다.
- segformer_b2_clothes: 가중치가 NVIDIA SegFormer 라이선스(비상업·연구 전용)를 따른다.
- `@imgly/background-removal`, `onnx-community/ISNet-ONNX`: AGPL-3.0이다. 한 HTML 파일에 넣으면 앱 전체를 AGPL로 공개해야 한다.

### 아이폰 HEIC 사진

- WebKit 버그 기록(292350)에 따르면, `accept`가 `image/jpeg, image/png, …`처럼 HEIC를 빼고 형식을 제한하면 Safari가 사진을 **목록 첫 형식(JPEG)으로 바꿔서** 넘긴다 ✔. 앞선 수정(267277, 2024-03)도 같은 방향이다.
- 그래서 HEIC 해독 라이브러리는 **넣지 않는다**. `libheif-js`는 LGPL-3.0이고 2.0MB이며, `heic2any`도 안에 LGPL 해독기가 들어 있다. HEVC 특허 문제도 확인되지 않았다.
- 이 변경이 어느 iOS 버전부터 들어갔는지는 확인하지 못했다. **사용자 아이폰에서 직접 확인**이 여전히 필요하다.

### 수동 자르기 (Codex)

- Cropper.js v1(1.6.2): MIT, 약 14KB(gzip). v2(2.3.0)는 2026-10-07에 나온 지 일주일 된 판이라 지금은 쓰지 않는다.
- 사각형 자르기만 필요하면 라이브러리 없이 canvas로 직접 만드는 쪽도 괜찮다. Codex가 고른다.

### 스파이크 통과 기준 (`focus-plan-20261014.md`의 기준을 숫자로)

- 라이선스: 코드와 가중치 모두 상업 사용 가능(위 표의 "가능"만)
- 내려받기: 처음 한 번 20MB 이하, 사용자가 동의한 뒤에만 받는다(기존 사진 분석 동의와 같은 방식)
- 처리 시간: 사용자 아이폰에서 사진 1장에 5초 이내
- 실패하면 원본 사진을 그대로 쓰고 등록은 계속된다

20MB와 5초는 Claude가 제안한 값이다. 스파이크를 시작하기 전에 사용자가 확정한다.

## 4. 쓰지 않는 것

| 도구·방법 | 이유 |
|---|---|
| REA 등으로 에이클로젯 앱 역분석 | 앱 약관·저작권법(역분석은 호환 목적만 허용) 위험. 핵심 처리는 서버에 있는 것으로 보여(추론) 얻을 것도 적다. 직접 써 보며 화면을 녹화하는 비교 시험으로 대신한다 |
| 온라인 데모·유료 API (배경 제거 사이트, 가상 착용 API, Hugging Face Spaces) | 사진이 기기 밖으로 나간다 |
| 유료 실기기 클라우드(BrowserStack 등) | 비용. 사용자 아이폰으로 직접 확인한다 |
| 비상업 전용 모델 | 상업화하면 쓸 수 없다. 처음부터 넣지 않는다 |
