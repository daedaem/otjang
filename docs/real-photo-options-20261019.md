# 시안에 실제 상품 사진 넣기 검토 (2026-10-19)

대표 피드백: 옷 그림은 실제 상품 사진과 다르게 느껴진다. 사용 권한이 확보된 실제 사진을 넣는 방법을 검토한다.
이번 범위에서 제휴 신청·문의·구매는 하지 않았다.

## 1. 결론
- **기술적으로는 바로 바꿀 수 있다.** 10개 시안 모두 그림을 공통 코어의 `EoulMock.art()` 하나로만 그린다. 사진 출처가 정해지면 코어만 고쳐 다시 묶으면 10개 시안이 모두 사진으로 바뀐다. 시안을 다시 만들 필요는 없다.
- **막히는 것은 권리다.** 지금 상품 사진 891장은 모두 무신사 이미지 서버(image.msscdn.net)를 직접 불러오는 것이고, 사용 권리가 확인되지 않았다(`CATALOG.rights: 'unverified'`). 그래서 시안에서는 뺐다.

## 2. 권리가 확보된 사진을 얻는 경로 (추천 순)
| 순위 | 경로 | 권리 | 비용·조건 | 한계 |
|---|---|---|---|---|
| 1 | **제휴 프로그램의 상품 자료**(링크프라이스 머천트 상품 DB, 무신사·에이블리 등 파트너 프로그램) | 약관이 홍보용 이미지 사용을 허락하면 확보(확인 필요) | 신청 무료로 알려짐(확인 필요), 대표 신청·승인 필요 | 승인 전에는 못 씀. 이미지에 제휴 링크·표기 의무가 붙을 수 있음 |
| 2 | **브랜드 서면 허락** | 허락 범위 안에서 확실 | 무료~협의, 대표가 브랜드에 요청 | 브랜드 수가 적어 데모 범위로만 |
| 3 | **직접 촬영**(대표 본인 옷 또는 산 상품) | 촬영자 권리라 확실 | 시간·구매 비용 | 상품 수가 적고, 카탈로그 상품과 다를 수 있음 |
| 4 | 무료 공개 사진(CC0 등) | 라이선스 범위 안 | 0원 | 실제 그 상품이 아니라 오해 위험. 추천하지 않음 |

쿠팡 파트너스는 앞서 대표가 불가로 정해 제외했다.

## 3. 권리 확보 전의 선택지 (대표 결정 사항)
- **비공개 시험 링크에서만 '수집 사진 보기'를 켜는 방법.** 현재 개인 시험 앱이 이미 같은 사진을 같은 방식(무신사 서버 직접 불러오기)으로 쓰고 있어 범위가 같다. 기본은 꺼짐, 켜면 화면에 "권리 미확인 · 비공개 시험용"을 표시, 공개 빌드 차단(`EOUL_PUBLIC_BUILD`)은 그대로 둔다.
- **위험:** 링크가 대표 밖으로 전달되면 권리 미확인 자료가 퍼진다. 사진을 불러오는 순간 외부 요청이 생긴다(개인정보는 보내지 않음). 그래서 Claude가 임의로 켜지 않고 대표가 정한다.
- 켜기로 하면 작업은 코어 한 곳이다. `art()`가 사진이 있으면 사진을, 불러오지 못하면 지금 그림을 보여 주게 바꾸고 다시 묶는다.

## 4. 대표 결정과 적용 (2026-10-19)
대표 결정: "비공개에서만, 사진 몇 개만".
- **켜는 법:** 갤러리 맨 위 '사진 몇 개(비공개 시험용)'를 체크하거나, 시안 주소에 `?photos=1`을 붙인다(예: `teams/01-answer.html?reset=1&photos=1`). 기본은 꺼짐이다.
- **범위:** 갤러리 예시 요청 4개의 상위 3개씩, 상품 12개만 사진 주소를 남겼다. 나머지 879개는 목업 묶음에서 사진 주소를 뺐다. 사진이 없는 상품·옷장 옷·코디 칸은 그림 그대로다.
- **표시:** 켜면 각 시안의 목업 표시 줄에 '사진 일부 · 권리 미확인 · 비공개 시험용'이 붙는다.
- **확인:** 10개 시안 모두 꺼짐일 때 외부 요청 0, 켬일 때 무신사 이미지 서버 요청만 2~3건, 페이지 오류 0, 360px 가로 넘침 0. 사진을 못 불러오면 그림이 보인다.
- **바뀌지 않은 것:** 권리는 여전히 미확인이다. 링크를 대표 밖으로 전달하지 않는 것이 전제다. 공개 빌드 차단은 그대로다.

## 5. 앞으로의 시안 기준
- 시안은 처음부터 **눌러 볼 수 있는 실행 링크**로 낸다. 스크린샷은 갤러리 카드의 미리보기일 뿐이다.
- 이번 10개 시안도 실제 검색·버튼·화면 이동·기록이 동작한다(흐름 검사로 확인). Codex가 갤러리를 받아 휴대폰 링크로 제공한다.
