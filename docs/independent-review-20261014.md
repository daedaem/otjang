## 고객이 이 서비스를 쓸 이유와 비교 기준

시험할 첫 과제는 **최근 실제로 고민한 구매 후보 한 개를, 본인이 가진 옷과 놓고 산다/보류/안 산다를 판단하는 것**이다. 후보를 더 많이 보여 주는 것으로 성공을 대체하지 않는다. [Acloset 공식 소개](https://www.acloset.app/)는 상품 페이지 저장·쇼핑 중 옷장 확인·가상 착용을, [Whering 현재 공식 사이트](https://www.whering.co/)는 사진/DB/브라우저 확장 등록과 친구 옷장·스타일링 커뮤니티를 안내한다. 소개를 읽은 것이며 비교 품질·한국 판매처 지원을 실행 검증한 것은 아니다. 외부 후보 입력도 이미 존재하는 기능이므로 그 자체를 독점 차별점으로 삼지 않는다.

가설은 특정 고객이 기존 방법·사진 나란히 보기·판매 앱·기존 옷장 앱보다 적은 입력으로 **정확한 자기 옷 근거**를 이해하고 결정하기 쉽다는 것이다. 기존 방법이 충분하면 추가 서비스의 필요성이 낮다. 같은 종류의 교체/추가 구매와 새 종류 구매는 이유가 다르므로 분리한다. 사진·핏·소재를 실제로 판독한 것처럼 설명하지 않으며, ‘사지 않아도 됨’도 유익한 결과로 남긴다.

## 실행 전 고정할 파일럿 — 아직 수행하지 않음

5~10명은 사용성 반례와 가설의 경계를 찾는 제안 규모이며 시장 성공률을 추정할 표본이 아니다. 클래식은 첫 시나리오이고 제품 전체를 제한한 결정은 아니다. 동의한 범위만 관찰하며 원본 사진·구매 내역을 자동 수집하지 않는다.

기존 [출시 전 평가 기준](prelaunch-evaluation-20261014.md)의 비율·시간은 사전 제안이다. 변경하면 새 실험 버전을 만들고 결과를 본 뒤 소급 조정하지 않는다. 데이터 유실·예시/실제 혼동·선택 옷 바뀜·핏 보증 오해가 나오면 원인 수정 후 해당 과제를 다시 검증한다. 원래 후보 부재, 대부분이 기존 방법과 차이를 설명하지 못함, 입력 전에 포기하는 반복 사례는 흐름/차별화 가설 수정 근거다. 이번 검토에는 참가자 결과가 없다.

## 전체 서비스 출시 조건 — 계속 열려 있음

1. **정확한 핵심 판단:** 위 실제 반례가 최종 통합판 회귀로 통과하고 선택 옷/상품·가격 조건·분류·확정/미확인이 일치한다. 미등록을 실제 부족으로 단정하지 않는다. 검토 10건이나 테스트 수를 고객 효용 대신 쓰지 않는다.
2. **상품 공급·비용:** 판매처 자료의 저장/가공/표시/갱신 범위를 확인하고 허용된 소규모 공급원에서 가격·옵션·품절·정정 작업을 운영한다. 무료 API가 재이용 허락은 아니다. [ADPICK 가이드](https://biz.adpick.co.kr/?ac=api&sub=guide)는 이를 구분하며 [네이버 공지](https://developers.naver.com/notice/article/32530)는 쇼핑 검색이 2026-07-31 종료되고 대체 API가 없음을 명시한다. 정적 엔진 비용과 VTON 계산·커뮤니티 운영·지원·갱신 노동을 별도 측정한다.
3. **저장·삭제·복구:** 지원 기기의 사진 등록→재시작→장기 재방문→백업→별도 브라우저 복원, 실패/충돌/용량 부족, 전체 삭제 범위·부분 실패 정책을 확인한다. [WebKit ITP](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/)의 조건은 Safari 사용일·상호작용·홈 화면 실행 맥락이며, [저장 정책](https://webkit.org/blog/14403/updates-to-storage-policy/)의 persist 요청과 승인은 다르다. 8일 보존 한 번으로 정책 전체를 반증한다는 기준은 Claude가 철회했다.
4. **디자인·운영:** 실제 모바일에서 대비·고지·터치·포커스·미확인 확인/취소/모름·첫 저장을 확인한다. 전용 서비스 origin, 기존 같은 origin의 앱/탭, 배포 SHA·파일 일치·되돌리기·문의·상품 갱신 중단 절차를 운영자가 재현한다.
5. **원래 서비스 범위:** 최신 Claude b0f 형식의 사진·저장·백업 통합, 3D/VTON, 발견/커뮤니티, 실제 구매·착용·반품 기록 연결은 별도 미완료 항목이다. 판매처 링크나 VTON 그림을 실제 거래·착용·반품 처리로 바꾸어 표시하지 않는다. 연구용 후보 비교 실험이 이 조건들을 해제하지 않는다.
6. **사업·수익 검증:** 동일 실제 후보의 효용과 자발적 재사용을 확인한다. 제휴 수수료와 추천 순위를 분리하고 비구매 효용을 유지한다. 실제 수수료·확정/취소·획득·운영비 없이 수익 불성립이나 흑자를 단정하지 않는다.

관련 [서비스 출시 검토](service-release-review-20261014.md)의 출시 조건을 유지한다. 최종 통합 SHA·변경 목록·회귀 결과·실기기/파일럿 수행 상태를 이 문서에 갱신한 뒤 완료 상태를 판단한다.

## 이번 통합판의 개선과 남은 경계

- 선택 옷 ID·사진·색을 검색에 고정하고 결과에서 기준 옷을 표시한다. 삭제된 선택 ID는 다른 옷으로 바꾸지 않는다. 자유 텍스트의 기준 색도 확인된 보유 옷 또는 실제 상품 근거가 있어야 한다.
- 가격 이상/이하·초과/미만·넘는/넘지 않는·범위를 구분하고 높은 가격순도 전체 후보에서 정렬한다. 비싼/싼티/1만보/폴로셔츠/봄버의 부분 일치를 고쳤다. 품질 자료 미확인을 표시하며 가격을 품질 근거로 쓰지 않는다.
- 코디의 미확인 행은 해당 실제 옷의 세부 종류 편집을 바로 연다. 저장 후 같은 코디 공식을 다시 계산하며 사진과 편집 충돌 보호를 유지한다. 종류가 달라 그 공식에 맞지 않으면 명시하고 옷 상세로 돌아간다.
- 미등록을 미보유로 단정하는 구매 표현을 구매 후보로 바꾸고 비슷한 보유 옷 등록 경로를 유지한다. 실제 미보유/모름의 저장 모델과 구매/보류/안 삼 후속 기록은 아직 없다.
- 작은 고지 토큰 대비는 라이트 4.97/5.20/4.60, 다크 5.80/5.32/4.80으로 계산됐다. fine은 14px로 늘렸다. 이는 토큰 계산이며 실제 화면 가독성/색 구성/레이아웃 사용성 확인을 대신하지 않는다.
- 손상 사진은 MIME·크기·JPEG 서명·내용 해시를 읽기에서 검사하고 부팅 실패 때 저장 준비 상태를 해제한다. 비JSON 원문은 진단 파일에서 조용히 바꾸지 않고 내보내기를 거절해 DB 원본을 유지한다.
- 이전 사진 가져오기 전체에 작업 잠금을 적용하고 취소된 이전 확인의 늦은 오류를 무시한다. 부분 삭제는 비개인 미완료 표시를 유지해 재시작 후 자동 이전을 차단한다. 삭제 재시도가 모든 범위를 확인한 때만 해제한다. 표시 자체를 저장할 수 없으면 데이터 삭제를 시작하지 않는다.
- 정상 교체에 현재 옷·사진·찜 수와 먼저 백업할 버튼을 추가했다. Claude 최신 자료의 삭제 포함/현재 앱 백업 미지원 범위도 명시했다.

반복 성공 복구의 사본 증가와 1MB manifest 제한은 미해결이며, 원문 다운로드를 항상 보장하는 문구를 제거했다. 최대 200장의 부팅 해시 비용, 실제 휴대폰에서의 파일 저장/복원, 브라우저 조건별 보존 정책은 미측정이다. 이전 eoul:v2 자료·JSON 백업의 호환, 실제 외부 구매 후보 및 후속 기록, 상품 이용 권한과 운영 검증도 출시 조건으로 유지한다.

### 마지막 Claude 통합판에서 확인한 추가 사항

438500b 코드의 상품 사진·현재 취향에 맞는 예시·35개 코디·취향 선택·ZIP 경로를 병합했다. 신규 캐릭터/라이선스 프린트 일괄 제외는 종류 충돌 근거가 없으므로 채택하지 않고 정상 상품 15개를 유지했다. 하프 코트를 발마칸으로 강제 교정하는 안도 세부 형태 근거가 없어 거부했다. 기능성 바지를 모두 제외하는 규칙은 기능성 카고에 대한 반례로 범위를 좁혔다. 신발/수영복/장갑/반바지의 실제 형태 충돌 및 원문 근거가 있는 레드윙·비화이트 운동화 교정은 적용했다. 최종 화이트 스니커즈 후보 3개는 모두 확정 white 근거가 있다.

추가 코드 점검에서 취향 저장 실패 시 입력 유실, 취향 선택 중 새 자료 읽기 뒤 오래된 상태로 취소, 삭제 뒤 취향 초안 부활, 다른 상품 사진의 출처 누락, ZIP 전체 파일 메모리 읽기를 발견했다. 최신 자료를 취향 초안의 기준으로 갱신하고 저장 실패 때 선택을 유지하며 삭제 때 초안을 정리했다. 다른 상품 사진에는 상세·코디에도 출처를 표시하고 실패 색 카드는 실제 등록 색을 사용한다. ZIP은 최대 161,000,012바이트의 백업 본문을 지원하고 CRC를 최대 800KB 순차 구간으로 검사한다. 여러 파일·추가 바이트·잘못된 구조와 상한 초과는 거절한다. ZIP 통합도 실제 claude.ai 다운로드 확인창 또는 휴대폰 파일 선택을 검증한 것은 아니다.

Claude 저장소 문서의 브라우저 15항목 통과는 Claude의 보고이며 이번 Codex 직접 화면 검사로 계산하지 않는다. 5+5 초기/교차 리뷰의 기준은 c447이며 후속 합친 코드 전체를 양쪽 다섯 명이 다시 실행했다는 뜻도 아니다.
