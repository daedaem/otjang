`lookLine` 중복 함수는 제거했다. `outfitCopy`는 하나의 실제 구성에서 내 옷·예시 옷·구매 후보와 사용자 입력 이름을 구분한다. 세부 종류 미확인 행의 색을 추정해 설명하지 않는다. 기존 공식의 예시 설명을 현재 착장처럼 다시 표시하지 않는다. 공식 ID, 착용·공유 기록, 저장 스키마는 유지한다.

검색의 `searchDrop`·`searchAnchorId`는 이어 묻기에서 보존하고, 새 검색·예시 검색·검색 지우기의 초기화 동작을 유지한다. 기존 등록 종류 통일, 구매내역 시험 구현, 저장·전체 백업·복원·계정 동기화·구매 기록을 보존한다.

## 통합 화면에서 추가로 발견한 불일치

“검정 말고 출근용 셔츠 10만원 이하”의 상품 목록은 검정을 제외했지만 검색 코디에는 검정 바지가 있었다. 상세 코디는 검정 상품을 hidden으로 제외하여 두 화면의 기준이 달랐다.

- 검색·상세 코디 모두 제외색 상품과 해당 색의 보유 옷을 구성에서 제외한다. 저장된 보유 옷을 삭제하거나 변경하는 처리가 아니다.
- 기준 보유 옷의 색이 제외색과 충돌하면 검색 코디를 만들지 않는다.
- 긍정 조건인 색·밝기·브랜드는 요청 상품의 조건이다. 상세에서 모든 동반 옷에 적용했다고 오해시키지 않도록 전체 코디 조건 안내에서는 제외한다.
- 예산을 다른 구매 후보에도 한 벌당 같은 기준으로 적용한다는 기존 안내는 유지한다. 실제 코디 전체 예산을 해석하는 기능은 아니다.
- “셔츠 제외” 상세에서 고정된 “셔츠 위에 겹쳐 입기” 이유·팁이 남는 것도 확인했다. 명시적으로 제외한 종류명이 들어 있는 고정 문장은 숨긴다. 새 패션 이유를 만들어 대체하지 않는다.
