## 배포와 설정 경계

Cloudflare 실제 설정을 읽어 확인한 사실: 프로덕션 브랜치는 Claude 브랜치, 미리보기 브랜치 빌드는 켜짐, 빌드 명령은 `npm run build`, 미리보기 명령은 `npx wrangler preview`다. 단순한 새 검토 브랜치 push도 공개 미리보기를 만들 수 있다.

`app/lite/deployment-policy.mjs`는 Workers CI 빌드를 **배포/미리보기 명령 전에 실패**시킨다. 의도한 공개 배포 차단이며 테스트 실패와 구분한다. GitHub 검사와 로컬 빌드는 허용한다. 해제에는 권리 확인·별도 대표 승인과 `OTJANG_ALLOW_PUBLIC_DEPLOY=owner-approved`가 필요하다. 이번 작업에서 해제하거나 Cloudflare 설정을 바꾸지 않는다. 계정 관리자의 코드 변경까지 막는 접근 통제는 아니다. 기존 배포는 제거하지 않으며 원래 Claude 브랜치의 후속 push에는 새 차단 코드가 아직 없을 수 있다.

기존 설정에 API 키가 일반 빌드 변수로 들어 있는 점을 확인했다(키값을 파일·Git에 복사하지 않음). 대표가 발급처에서 키를 교체·기존 키를 폐기하고 **런타임 Secret**에만 넣어야 한다. 키 교체·D1 연결·Access 정책 생성·유료 요청은 이번에 실행하지 않았다. 새 AI는 필수 설정 전 503이 정상이며 기본 추천은 유지된다.

원격 검토 브랜치의 실제 Cloudflare 빌드 로그도 확인했다. 현재 미리보기 루트가 `/`라서 `/opt/buildhome/repo/package.json`을 찾지 못해 **배포 단계 전에 ENOENT로 중단**됐다. 이 외부 실패를 배포 차단 코드 실행 성공으로 보고하지 않는다. 빌드 차단 코드 자체는 로컬 Workers CI 모의 실행에서 검증했다. 미리보기 루트를 고치는 일은 향후 공개 승인 시 별도 설정 작업이며 이번에는 건드리지 않는다.

실행 조건은 [설치 앱 안내](lite-app-setup-20261020.md)를 따른다. 기존 등록·백업·동기화·개인 옷장 형식은 바꾸지 않았다.
