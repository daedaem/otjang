# 상품 데이터(사진·가격·링크)를 0원으로 얻는 길 — 조사 기록 · 2026-10-12

연결: Codex 이슈 #2(실제 상품·후기 근거 확보 경로 검증), PRD v0.3 「데이터는 사람이 올린다」, 10-10 결정(기본 운영비 0원, 자동 유료 전환 없음).
목적: 앱·서버가 "직접 넣은 상품"만 쓰는 지금 방식을 넘어 상품 자료를 자동으로 얻을 길이 있는지 **실제로 확인**한다. 가격·재고·링크를 지어내지 않는다는 원칙은 그대로다.

표기: **검증 사실**(이 날 직접 열어 본 것) / **2차 출처**(다른 글이 전하는 것) / **미확인** / **제안**.

**의미:** 0원 + 이용 조건 안에서 "실제 상품을 자동으로 추천"하는 길은 2026-10-12 기준으로 **열려 있지 않다.** 네이버 쇼핑 검색 API 가 사라져(2차 출처) 가장 유력했던 무료 경로가 막혔고, 쇼핑몰 크롤링은 robots 와 약관 문제가 있다. 그래서 PRD 의 ② "실제 구매 상품 추천"은 당분간 **사람이 넣은 상품 목록 안에서의 순위**로만 간다. 이는 미검증 가설("직접 넣는 목록만으로 구매 판단에 충분하다")을 사용자가 써 보며 확인해야 한다.

## 1. 네이버 쇼핑 검색 API → NAVER API HUB

- **검증 사실(2026-10-12):** `https://api.ncloud-docs.com/docs/naver-api-hub-overview.md`(문서 갱신 2026-09-17)를 열어 봤다. NAVER API HUB 의 검색 분류에는 뉴스·백과·블로그·이미지·웹문서·지식iN·지역·카페글·성인 질의·오타 교정이 있고 **쇼핑 검색은 없다.** 쇼핑 인사이트(분야·기기·성별·연령·키워드 클릭 추이)는 있다. 인증은 `X-NCP-APIGW-API-KEY-ID`/`X-NCP-APIGW-API-KEY` 헤더, 기본 주소 `https://naverapihub.apigw.ntruss.com`. 요금·한도 수치는 그 문서에 없고 429 = "하루 허용량 초과"만 있다.
- **접근 불가(2026-10-12):** `developers.naver.com` 의 쇼핑 검색 API 문서와 검색 API 목록 페이지는 이 작업 환경에서 열 수 없었다(차단). 그래서 종료 공지 원문은 확인하지 못했다.
- **2차 출처:**
  - waffleboard.io 「네이버 검색 API 종료? …」(2026-08-08): 2026-06-25 API HUB 정식 출시, 2026-07-31 개발자센터 신규 신청 종료와 **쇼핑·책·전문자료 검색 완전 종료(대체 엔드포인트 없음, 유예 없음)**, 2027-06-30 기존 방식 지원 종료. HUB 는 한시적 무료, 검색 API 월 775,000회(합산), 초당 50회. 개발자센터 공지 article/32530, article/32564 를 인용.
  - keyword-lab(2026-08-24 수정): 같은 내용(쇼핑 검색 "대체 없이 종료", 2026-07-31, 한시적 무료). 공지 번호·URL 인용 없음.
- **판단:** 두 2차 출처가 같은 날짜와 내용을 전하므로 종료가 맞을 가능성이 높다 [추정]. 1차 공지를 사용자 PC 에서 한 번 확인해 두면 좋다(`developers.naver.com/notice`).

## 2. 무신사 robots.txt (검증 사실, 2026-10-12)

`https://www.musinsa.com/robots.txt`(파일 안에 "last updated 2026.09.10"): 이름이 있는 봇 약 30개(Googlebot, Bingbot, Applebot, GPTBot, ClaudeBot, PerplexityBot, CCBot 등)에는 `Allow: /` 와 일부 경로 `Disallow`(/auth/, /like/, /mypage/, /showcase/ 등). `Baiduspider` 는 `Disallow: /`. **`User-agent: *` 는 `Disallow: /`** — 이름을 밝히지 않은 자동 수집은 전부 금지. 사이트맵 4개 공개.
→ 이 프로젝트의 수집기는 이름 있는 검색 엔진이 아니므로 **자동 수집 불가.**

## 3. 29CM robots.txt (검증 사실, 2026-10-12)

`https://www.29cm.co.kr/robots.txt`: `Baiduspider`·`Baiduspider-render` 는 `Disallow: /`. `User-agent: *` 는 `Allow: /` 에 `/embed/`, `/home/embed/`, `/my-page/`, `/order/`, `/auth/`, `/inbox/`, `/content/post/preview` 만 `Disallow`. 사이트맵 공개.
→ robots 만 보면 막혀 있지 않다. **그러나** 이용약관의 자동 수집 금지 조항, 상품 이미지·설명의 저작권, 가격 표시 의무 등은 확인하지 않았다(미확인). 0원·개인 프로젝트에서 크롤러를 돌리는 것은 법률·운영 리스크가 커서 **하지 않는다** [제안]. 하더라도 사용자 결정이 먼저다.

## 4. 쿠팡 파트너스 (2차 출처, 2026-10-12)

digitalmarketer.co.kr 「GEO, SEO 시대 쿠팡과 네이버의 검색 전략 분석」(2026-09-03 게시, 10-04 수정)이 쿠팡 파트너스 FAQ(2026-10-04 확인)를 인용: 제휴 프로그램이며 링크·배너로 발생한 구매(클릭 후 24시간)에 분야별 수수료. 같은 글에 따르면 `www.coupang.com/robots.txt` 는 검색 엔진 봇은 허용, GPTBot·OAI-SearchBot·ChatGPT-User 와 `*` 는 `Disallow: /`(글의 요약, 원문 인용 아님).
파트너스 Open API(상품 검색·딥링크)의 제공 범위·승인 조건·캐시·표시 규칙은 **1차 문서를 열지 못해 미확인**(`developers.coupangcorp.com` 링크가 판매자 API 로 넘어갔다). 제휴 API 는 "링크를 통한 구매 유도"가 전제라서 이 프로젝트의 "내 옷장에 맞는지 판단" 목적과 맞는지도 사용자 판단이 필요하다.

## 5. 그래서 지금 할 수 있는 것 [제안]

1. **지금 방식 유지**: 사용자가 고민 중인 상품을 직접 넣는다(이름·가격·확인일·링크·사진). 앱·서버는 그 안에서만 순서를 매기고 14일 지난 가격은 "재확인 필요". 가격·재고를 지어내지 않는다.
2. **사람이 만드는 작은 카탈로그**: 첫 영역(예: 아메리칸 클래식 셔츠·치노 10~20개)을 사용자가 직접 확인해 넣는다. 이것이 PRD 0단계(실제 판정 3건)를 채우는 가장 빠른 길이다. 영역·개수는 사용자 결정.
3. **자동화는 조건이 생기면**: 판매처가 공식 API 나 제휴 데이터를 이용 조건 안에서 제공하고, 그 비용이 0원이거나 월 2만원 한도 안에서 사용자가 그때 고를 때만. 크롤링은 하지 않는다.
4. **사용자 PC 에서 확인할 것**: developers.naver.com 공지(쇼핑 검색 종료 원문), 쿠팡 파트너스 API 문서. 이 둘이 바뀌면 이 표를 고친다.
