# Codex 로컬 0572caa 와 이 브랜치 병합 안내 (2026-10-19)

Codex가 공통 기준 bc34898에서 가상 병합한 결과, `app/src/main.js`에 내용 충돌 5구간이 있다. 이 문서는 Claude 쪽 변경의 **의도와 지켜야 할 동작**을 적어, 병합하는 사람이 어느 줄을 살릴지 판단할 수 있게 한다. 이 브랜치의 Claude 커밋은 bc34898 이후 `1feb8a2 → a516d9c → 4e59e4a → 13580da`다. 0572caa는 로컬에만 있어 Claude가 직접 볼 수 없다.

**원칙:** 어느 쪽 `main.js`도 통째로 덮지 않는다. 구간마다 아래 "지켜야 할 동작"을 양쪽에서 합친다. 합친 뒤 `npm test`(이 브랜치 기준 599개, Codex 611개 중 겹치는 수는 미확인)와 아래 화면 확인을 다시 한다.

## 구간별 안내 (줄 번호는 이 브랜치 13580da 기준)

### ① `lookLine` / `lookCard` (main.js 452~)
- Claude: `lookLine(r)`이 실제 배치된 옷으로 한 줄("내 화이트 옥스퍼드 셔츠 + 후보 브라운 로퍼")을 만든다. `lookCard`는 사진 4칸에서 `i.focus`(지금 보고 있는 상품·내 옷)를 절대 빼지 않는다.
- Codex: 실제 구성 기반 제목·설명, `data-look-id`.
- **합칠 때:** 제목·설명 생성은 **Codex 것을 쓰고 `lookLine`은 버려도 된다.** 단 `focus` 처리(이너 역할이어도 보고 있는 옷은 사진 칸에 남김)와 `data-look-id`는 둘 다 살린다. `focus`를 다는 곳: `itemSheet`(2014행), `ownSheet`(2096행).

### ② `FOLLOW_UP` / `followUpQuery` (1084~)
- Claude: "더 싼/비싼 걸로"는 이전 조건을 그대로 두고 가격순만 바꾼다. **"더 좋은/나은/괜찮은 걸로"는 가격순으로 바꾸지 않고** 조건·순서를 유지하며 품질 자료가 없다고 알린다. 새 검색이 아니면 `searchDrop`(칩으로 뺀 조건)과 `searchAnchorId`를 유지한다.
- Codex: 반복 가격 정렬 요청과 품질 요청에서 원래 검색을 보존.
- **합칠 때:** 방향이 같다. Codex 구현을 기준으로 하되, (a) "더 좋은 걸로"가 비싼 순이 되지 않을 것, (b) 이어 묻기에서 `searchDrop`·`searchAnchorId`를 비우지 않을 것, (c) 새 검색(`example`, `clear-q`, 종류가 있는 입력)에서는 `searchFollowUp`/`searchDrop`을 비울 것. 검사: `test/condition-keep.test.mjs`의 칩 빼기 검사, 화면 확인 "출근용 셔츠 10만원 이하" → "더 싼 걸로" → "더 좋은 걸로".

### ③ `followNote` (1130~)
- Claude: `‘더 싼 걸로’ → 이전 조건을 그대로 두고 낮은 가격순으로 다시 찾았어요. 새로 찾으려면 종류까지 적어 주세요.` 품질 요청이면 `품질을 비교할 자료가 없어서 조건과 순서는 그대로 뒀어요(평점·후기는 참고만)`.
- **합칠 때:** 문구는 어느 쪽이든 되지만 **"그렇게 했다"를 화면에 쓰는 것**은 유지한다(몰래 바꾸지 않기).

### ④ 검색 결과의 코디와 0건 안내 (1148~)
- Claude: 상품이 먼저, 코디는 아래. 코디 제목 "이 조건으로 한 벌 맞춰 보면", 예산이 있으면 "예산은 상품 한 벌 기준이에요(코디 합계 아님)". 코디를 시도했는데(`r.outfitTried`) 상황·뺀 종류 때문에 없으면 `검색 조건(출근 · 셔츠 제외)을 지키는 코디 공식은 없어요. 조건을 풀지 않았어요.` 0건이면 `kindUnavailable`/`kindNowhere`에 따라 "남성 상품에는 원피스가 없어요" / "상품 목록에 아직 반바지가 없어요", 그 외는 "조건을 자동으로 넓히지 않았어요. 위 조건 칩의 ×를 눌러…".
- **합칠 때:** 엔진 쪽(`engine.js`: `criteria`, `conds`, `dropped`, `outfitTried`, `kindUnavailable`, `kindNowhere`, `strictOccasion`, `excludeSlot`)은 충돌이 없다고 하니 그대로 두고, 화면에서 위 네 문구가 나오게 한다. 검사: `test/condition-keep.test.mjs`(31개), `test/ask-search.test.mjs`.

### ⑤ `lookSheet` (2061~)
- Claude: 첫 줄은 `lookLine(r)`, 둘째 줄 `공식 설명: {look.note}`(접지 않고 작은 글씨).
- **합칠 때:** ①과 같이 Codex의 실제 구성 설명을 쓰면 된다. `lookLine` 호출을 Codex 함수로 바꾼다.

## 충돌은 없지만 함께 지켜야 할 Claude 동작 (자동 병합된 부분)
- `itemSheet`(1990~2060): 검색에서 열면 `searchCriteria`로 대안(`productCriteria`)과 코디(상황·계절·스타일·뺀 종류·뺀 색·가격, `strictOccasion`, `excludeSlot`)를 거른다. 문구 "검색 조건(…)을 코디의 다른 옷에도 그대로 적용했어요", 없으면 "…지키면서 만들 수 있는 코디가 없어요. 조건을 풀지 않았어요".
- `compareCatalogProduct`(1353): 예시 옷장이면 `draft.returnProductId`를 두고 등록 화면으로, `addSheet`(2805)에 돌아갈 상품 띠, 저장 후(2941) 그 상품 비교로 복귀.
- `close-sheet`: 판매처 가격 시트를 닫으면 `journeySheet`로 복귀.
- `journeySheet`: 받음·보유 단계에서 자기 자신을 비교에서 뺌, 판정 아래 `candidateLookRows`, 버튼 강조 `lean`.
- `gridCard`: `productReasons`(상품명 기준 줄), `ownedLine`(보유 표시).
- 뒤로가기 `ensureBackGuard`/`popstate`.

1. "원피스" → 원피스만, 여성 전환 안내. "남자 원피스" → 0건 안내.
