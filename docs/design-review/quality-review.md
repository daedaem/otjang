# 옷이 주인공인 공간으로: 시각 품질 재검토

**최신 개선:** [Claude 비교 후 실제 화면·조작 개선](current-improvements.md). [Claude 시안 4와 WearNext 8c20afa — 실제 화면 8장·양방향 개선안](current-comparison.md)은 이전 버전 비교이며, 아래 문서는 초기 개선 과정과 진단의 기록이다.

2026-10-11, 한국 시간. 상태: **두 번째 시각 개선 반영, 사용자 검토 전**. 기능 검사 통과는 디자인 품질 승인이나 사용자 만족을 의미하지 않는다. 사용자는 현재 결과의 품질을 지적했고 해외 3D 웹사이트·디자인 수상작과 Claude 원본을 참고하도록 요청했다. 첨부 자료는 참고이며 동일한 배치를 복제하라는 요구는 아니다.

[이전 화면 비교 보드](comparison.html)는 제공된 Claude 원본과 개선 전 구현의 실제 브라우저 캡처를 나란히 보여 준다. 아래 초기 진단도 개선 전 상태를 기준으로 한다. 새로운 디자인 시안이 아니라 차이를 확인하는 검토 자료다.

## 이번 개선과 남은 한계

[현재 웹 옷장 화면](../../prototype/preview.png) · [한 벌 살펴보기](../../prototype/preview-detail.png) · [모바일 옷장](../../prototype/preview-mobile.png) · [모바일 상세](../../prototype/preview-mobile-detail.png). 모두 샘플 옷을 사용하는 실제 브라우저 캡처다.

옷장 폭과 선반 비중을 줄이고, 창 개구부와 사선 시점을 구성했다. 정적 공간에 베이크한 AO와 웹의 GTAO를 조합하며 색상·법선·거칠기 텍스처를 분리 보존한다. 선택한 옷에는 독립 조명을 적용하고 배경 대비를 낮추며, 드래그하면 카메라 대신 옷 자체가 회전한다. 모바일 첫 화면은 셔츠 구역에 가까이 접근한다.

실제 웹 화면에서 옷장 안쪽 명암, 네이비·올리브 색 구분, 한 벌을 살피는 집중도가 개선됐다. 그러나 재킷의 균일한 굴곡, 목재 질감과 접힌 옷은 여전히 간소화된 3D 모형이다. 실사·디자인 수상작 수준에 도달했다거나 사용자가 품질을 승인했다고 표시하지 않는다. 최종 기능 검증 결과는 [검증 기록](../../prototype/VALIDATION.md)에 별도로 기록한다.

사용자는 이후 **구매 전에 자신의 얼굴·체형과 실제 상품을 유지한 착장 모습을 보는 것**을 핵심으로 명확히 했다. 이를 위해 3D 방식이 필수인 것은 아니다. 현재 3D 옷장은 보유 기록을 탐색하는 기능이며, 실제 신체의 가상 피팅은 구현하지 않았다. 가상 피팅은 생성 사진과 실제 착장을 비교하는 별도의 검증 대상이다.

## 초기 진단에서 실제 확인한 것

- 제공된 `prototypes/otjang-sian4.html`을 Chromium에서 실행했다. 데스크톱 1440×1000, 모바일 390×844에서 전체 공간·파란 셔츠 선택 화면을 확인했다.
- 원본의 옷 선택·확대·돌려놓기와 옷 자체의 회전을 확인했다. 선택 후 가로 드래그에서 원본의 옷 회전값이 0→0.99 rad로 변하고, 방 카메라를 돌리는 동작과 구분된다.
- `prototypes/otjang-sian4-src.zip`의 `src/main.js`, `src/garments.js`를 읽어 화면 연출과 재질을 확인했다.
- 제공된 A/B 이미지의 **A: 시안 4(Claude)**, `blender/renders/hero-blue.png`, `web-1440.png`를 현재 `prototype/preview.png`와 상세·모바일 화면에 비교했다.
- Claude 원본의 화면과 셔츠 모델은 원래 작업의 기여다. 현재 Blender 셔츠는 제공된 `gscene.py`와 `shirt-3.pkl`을 재사용했다. 이를 이번 구현에서 새로 제작한 것으로 소개하지 않는다.

## 개선 전 코드에서 확인한 원인

원본 `src/garments.js` 28–47행은 원단 조직과 실제 크기에 따른 타일링을 구분한다. `src/main.js` 229–253행은 화면의 옷 표시 영역을 데스크톱·모바일별로 계산하고, 선택한 옷을 620ms 동안 앞으로 이동하며 scrim의 불투명도를 올려 배경 대비를 낮춘다. 원본의 기본 카메라는 약 11°의 사선이고, 선택한 옷을 드래그하면 옷 자체가 회전한다.

개선 전 `prototype/src/room.js`에서 다음 원인을 확인했다. 현재 변경에서는 텍스처 보존·AO·모바일 구도·선택 조명을 수정했으며, 아래 내용은 수정 배경을 설명한다.

- 등록한 색을 맞추기 위해 색상 텍스처를 bump 용도로 바꾸고 기존 map/normalMap을 제거한다. 색·거칠기·미세 법선을 분리해서 보존해야 한다.
- 범용 환경 조명과 방향광을 구성하지만 Blender의 정지 렌더에 있는 간접광·접촉 그림자는 전달하지 않는다. 포스터보다 라이브 화면이 회색이고 평면적인 이유 중 하나다.
- 모바일 카메라를 전체 가구 폭에 맞춰 뒤로 보내므로 옷이 작아진다.
- 선택은 옷 이동과 카메라 확대에 그치고, 배경과 선택하지 않은 옷을 충분히 물리지 않는다.

수정은 렌더 샘플 수나 소품 수를 늘리는 것으로 끝나지 않는다. 정적인 공간의 조명 전달, 원단별 재질, 의류 형태, 화면별 카메라를 함께 다뤄야 한다.

## 다음 시각 방향 제안

**개인 드레싱룸을 패션 화보처럼 보는 경험.** 아메리칸 클래식에 어울리는 목재·크림색 벽·자연광을 바탕으로 옷의 네이비·인디고·올리브가 읽히게 한다. 색상과 가구 디자인 자체는 제안이며 사용자 승인이 끝난 브랜드 가이드가 아니다.

1. 첫 화면은 옷 가까이의 사선 구도로 잡는다. 가구 전체 정면도는 필요할 때 보는 별도 시점으로 둔다.
2. 한 벌을 꺼내면 실루엣 전체·깃·주머니·원단을 살핀다. 옷 자체를 회전하고 제자리로 돌려놓는다.
3. 사진 등록·코디·구매 비교 기능은 기존 구현을 유지하되 공간을 차지하는 상시 UI를 줄인다.
4. 대표 셔츠·블레이저와 옷장 한 구역의 실제 WebGL 품질을 먼저 비교한다. 장면 전체와 기능을 다시 늘리기 전에 재질·조명·카메라의 기준을 확인한다.

## 시각 품질 확인 기준

- 실제 WebGL 화면을 확인한다. Cycles 포스터만 좋고 실제 조작 화면에서 색·깊이가 크게 약해지면 미달이다.
- 데스크톱과 모바일에서 선택한 옷의 전체 실루엣이 보이고 다른 옷·패널과 겹치지 않아야 한다.
- 확대했을 때 부서진 듯한 소매, 종이 같은 재킷 면, 덩어리 같은 신발이 없어야 한다.
- 같은 거리에서 면 셔츠·울 재킷·가죽 신발의 재질 차이를 눈으로 확인할 수 있어야 한다.
- 원본 Claude의 선택·회전·복귀와 나란히 비교해 적어도 그 명료함을 유지해야 한다.
- 기능 테스트 결과와 시각 품질 평가를 별도로 기록하며, 사용자 평가 전 디자인 완성으로 표시하지 않는다.

## 해외 레퍼런스 조사 상태

이 세션에서 Awwwards, FWA, Lusion, Moooi에 대한 직접 HTTPS 요청은 관리 프록시의 `CONNECT 403`으로 차단됐다. 지원되는 승인 경로로 Awwwards 읽기를 재시도했지만 같은 결과였다. **실제 사이트를 방문했다거나 수상명·연도·평점·화면을 확인했다고 주장하지 않는다.**

접속 후 확인할 후보는 [Moooi](https://www.moooi.com/), [Lusion](https://lusion.co/), [Immersive Garden](https://immersive-g.com/), [Bruno Simon](https://bruno-simon.com/)이다. 수상 사실은 [Awwwards](https://www.awwwards.com/websites/webgl/), [FWA](https://thefwa.com/), [CSS Design Awards](https://www.cssdesignawards.com/)의 해당 작품 페이지로 별도 확인한다. 각 후보의 현재 화면·수상 여부는 여기서 미검증이다.

기존 허용 도메인을 보존하면서 위 조사 도메인을 환경 설정 초안에 추가했다. 설정 도구는 저장 성공과 게시 필요를 반환했으며, 이는 현재 런타임에 적용되었다는 뜻이 아니다. 환경 설정의 검토·저장·게시 후 접근을 다시 확인해야 한다.
