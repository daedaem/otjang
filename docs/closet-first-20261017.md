# 옷장에서 시작하는 첫 경험 (2026-10-17)

> 문서 시점: 2026-10-17. 당시의 검토·구현 기록을 보존한 자료입니다. 현재 결정·우선순위·운영 상태는 [최신 문서 목차](README.md)를 확인합니다. 아래의 “지금·완료·다음”은 별도 갱신 표시가 없으면 당시 기준입니다.

## 왜 바꿨나

- 대표 의견: "옷장에 꽂혔다. 쇼핑몰 같은 게 지루하다."
- 같은 날 실제 앱 점검(`persona-walkthrough-20261017.md`)에서 나온 근거:
  - 첫 화면이 남의 예시 옷장과 판매 상품이었다.
  - 예시 옷으로는 살까 말까 판정을 볼 수 없었다.
  - 옷 등록은 종류·세부 종류·색을 하나씩 고르는 일이었다.
- 코드 확인에서 나온 근거: 코디 공식 23개(남성 기준)는 계절·스타일·색 조건이 좁다.
  - 흰 티 + 청바지 + 흰 스니커즈처럼 옷이 몇 벌뿐이면 "가진 옷만으로 완성되는 코디"가 0개였다.
  - 그래서 옷장 중심으로 바꿔도 첫 사용자는 빈 결과를 만날 가능성이 높았다.
- 가설(검증 전):
  - 내 옷을 직접 고르고 꺼내는 동작이 상품 나열보다 덜 지루하다.
  - 몇 벌만 골라도 첫 효용(가진 옷 조합)을 볼 수 있다.
- 개수(예: 1분·10벌)는 약속하지 않는다. 한 벌만 골라도 시작할 수 있다.

## 사용 흐름

1. **처음 방문**: 홈 맨 위에 "가진 옷을 눌러 주세요"가 나온다.
   - 기본 종류 12개(남성/여성 전환 가능)를 누르고 색을 고른다. 색은 "모름"도 된다.
   - "고른 N벌로 옷장 시작"을 누른다. 사진으로 넣기, 고민 중인 옷 비교하기 입구도 같은 자리에 있다.
2. **저장 직후**: 고른 옷 한 벌이 열리고 "이 옷을 꺼내면"이 위쪽에 보인다.
   - 가진 옷만으로 되는 코디 공식이 있으면 그것을 먼저 보여 준다.
   - 공식이 없으면 **가진 옷 기본 조합**(상의+하의+신발 또는 원피스+신발, 겉옷이 있으면 추가)을 보여 준다. 종류와 색 조화로만 맞춘 조합이라고 밝힌다.
   - 그 아래 **"더 있으면 완성되는 코디 · 추천 가설"**이 나온다.
     - "등록하지 않았을 뿐 이미 가진 옷일 수 있어요"를 함께 쓴다.
     - "○○ 이미 있어요 · 옷장에 넣기" 버튼이 있다.
3. **홈**: 실제 옷이 있으면 맨 위가 "오늘은 어떤 옷을 꺼낼까요?" 옷장 줄이다.
   - 자주 입은 옷이 앞에 온다. 누르면 2로 간다.
   - 그 아래 기존 추천·구매 후보·회원 코디는 그대로 둔다(발견 입구 유지).
4. **새 상품 비교**: 가설 코디의 후보 상품 → 상품 화면 → "내 옷과 비교" → 판정(겹치는 옷 → 생기는 코디 → 확인 안 된 정보) → 살게요/보류/안 살게요 → 기존 구매·착용·반품 기록.

## 지킨 원칙

- **고른 기본템은 종류와 색만 저장한다.** 브랜드·품명·상품 번호·사진은 비워 둔다(검사로 확인).
- **사진을 구분한다.** 내 사진이 없는 옷은 기존과 같이 "비슷한 상품 사진" 캡션과 "실제 옷의 모양·핏과 다를 수 있어요" 안내가 붙는다.
- **빈자리는 가설이다.** "없어요"가 아니라 "더 있으면 완성"으로 쓰고, "이미 있어요" 경로를 같이 둔다.
- **기본 조합은 쇼핑에 쓰지 않는다.** 가진 옷끼리만 만들며 구매 추천·부족한 옷 판단에는 쓰지 않는다.
- **기존 자료·백업·동기화·구매 기록 형식은 바꾸지 않았다.** 새 옷은 기존 `makeGarment` 형식 그대로 저장된다.

## 변경 범위

- `app/src/main.js`
  - 홈 맨 위 `closetStart()`: 처음 방문이면 가진 옷 고르기, 실제 옷이 있으면 옷장 줄.
  - `starter-pick`·`starter-color`·`starter-save` 동작.
  - 옷 한 벌 화면(`ownSheet`): "이 옷을 꺼내면"을 위로 올림. 가진 옷 코디 → 기본 조합 → 추천 가설 순서.
- `app/src/engine.js`
  - `basicOutfits()`: 가진 옷 기본 조합.
  - `recommendLooks()`에 `anySeason`·`anyStyle` 선택 옵션 추가(기본값은 기존과 같음, 현재 화면에서는 쓰지 않음).
- `app/styles.css`: 고르기 타일, 옷장 줄 스타일.
- 검사 3개 추가: 처음 방문 → 고르기 → 저장 → 꺼내기, 색 모름 한 벌로 시작, 기본 조합 규칙.

## 확인한 것

- `npm run build`, `npm test` 554개 통과.
- 휴대폰 크기 브라우저(클라우드, Playwright)에서 실제로 눌러 확인한 흐름: 처음 방문 → 셔츠·치노·스니커즈·니트 고르기 → 저장 → 셔츠 화면에서 기본 조합 → 추천 가설 코디 → 후보 상품 → 내 옷과 비교 판정.

## 남은 한계

- **실기기 미검증.** 아이폰·안드로이드에서 직접 쓰지 않았다.
- **사진 권리.** 대표 사진은 기존처럼 수집한 상품 사진을 빌려 쓴다. 상업 공개 전에는 자체 그림이나 권리를 확인한 사진으로 바꿔야 한다.
- **코디 공식이 적다.** 기본 조합으로 빈 결과는 막았지만, 스타일 코디는 공식 23개(남성)·여성 수준에 묶여 있다.
- **링크 없이 확인한 결과**는 아직 기록으로 남지 않는다(구매 기록 형식이 판매 링크를 요구).
- 세 가지 재미(꺼내 입기·보기·정리)는 아직 가설이며, 측정 이벤트는 구현하지 않았다(`validation-kit-20261017.md`).
- 레일·3D·A/B/C 시안은 채택하지 않았다.
