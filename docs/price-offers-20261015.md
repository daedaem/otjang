# 판매처·총액 비교와 가격 출처 (2026-10-15, Claude)

## 요청

사용자 요청(Codex 전달)에서 이 문서가 다루는 부분:
- 같은 상품·색·사이즈를 기준으로, 판매처별 배송비를 포함한 총액을 비교한다.
- 가격을 갱신하고, 실제 상품 공급원과 연결한다.
- 계약이나 키가 없어 연결하지 못한 공급원은 미연동으로 분명히 남긴다.
- 갱신 실패, 품절, 오래된 가격, 옵션 불일치를 처리하는 구조와 화면을 먼저 완성한다.
- 수집일 가격을 현재 최저가라고 하지 않는다.

## 비교 규칙 (`app/src/offers.js`)

**판매처 가격 한 건(offer)에 담는 것**
- 판매처, 상품 링크(https), 상품 가격, 배송비(모르면 비움)
- 색·사이즈, 재고(있음·품절·모름)
- 같은 상품인지(확인함·미확인)
- 출처(목록 수집가·직접 기록·네이버 쇼핑 검색), 확인 시각

**총액 비교에 넣는 조건** (모두 맞아야 한다)
- 같은 상품으로 확인됨
- 사려는 색과 사이즈를 둘 다 정했고, 판매처의 옵션이 그와 같음(사이즈가 없는 상품은 'FREE')
- 재고 있음으로 확인됨(새로 입력하거나 받아 온 판매처는 재고 미확인으로 시작)
- 배송비 확인됨
- 3일 이내에 확인함

**조건이 안 맞는 가격**
- 화면에 남기고, 빠진 이유를 표시한다: 품절, 재고 미확인, 원하는 색·사이즈 미정, 오래된 가격, 옵션 다름, 옵션 미확인, 배송비 미확인, 같은 상품인지 미확인.
- 판매처 기록은 상품마다 12개까지다. 다시 확인해서 받아 온 결과가 상한을 넘기면 받아 온 기록 중 오래된 것부터 빼고, 직접 남긴 기록은 지우지 않는다.

**결과 문구**
- "확인한 판매처 n곳 중 총액이 가장 낮은 곳"이라고만 쓴다. 바로 옆에 "지금 이 가격이거나 현재 최저가라는 뜻은 아니에요"를 붙인다.
- 쿠폰, 카드 할인, 적립금은 넣지 않는다.

**목록 수집가(무신사)**
- 목록에 넣은 날의 표시가로 보여 준다(예: `2026-10-13 수집`).
- 배송비를 모르므로 총액 비교에는 들어가지 않는다.
- "오늘 가격 기록"을 누르면 그 판매처의 오늘 가격·배송비·옵션·재고를 직접 기록할 수 있다.

**목록에 없는 링크**
- 무신사 5755268 같은 링크도 그 링크 그대로 비교한다.
- 서버는 목록 수집가나 다른 상품으로 대신 채우지 않는다. 시험으로 확인했다.

|---|---|---|
| 어울 상품 목록 수집가 | 연결됨(수집가) | 없음. 현재 가격이 아님 |

**네이버 쇼핑 검색 API 종료 보도 (2026-10-16 추가)**
- 여러 2차 출처는 쇼핑·책·전문자료 검색 API가 NAVER API HUB로 옮겨지지 않고 2026-07-31에 끝났으며, 기존 키도 차단됐다고 전한다.
  - 출처: tokenpost.kr/news/ai/403521, brunch.co.kr/@ainote/123
  - 같은 조사가 옛 줄기 `docs/data-sources-2026-10-12.md`(feat/personal-app-v0.4)에도 있다.
- 검증 사실: API HUB 문서(api.ncloud-docs.com/docs/naver-api-hub-overview.md)의 검색 분류에 쇼핑 검색은 없다. 쇼핑 인사이트(클릭 추이)는 상품·가격을 주지 않는다.
- 미확인: 네이버 개발자센터의 1차 공지. 운영자가 한 번 열어 확인해야 한다.
- 맞다면 이 경로는 쓸 수 없다. 실제 가격 경로는 공식 제휴(쿠팡 파트너스 등)와 사용자가 직접 넣는 가격만 남는다.

**네이버 쇼핑 검색 결과**
- 브랜드와 상품명으로 검색하므로 다른 상품일 수 있다. 그래서 "같은 상품인지 미확인"으로 들어온다.
- API가 배송비와 옵션을 주지 않으므로 배송비는 미확인으로 둔다. 응답 필드는 3자 자료 기준이라 공식 문서로 재확인이 필요하다.
- 사용자가 "확인·수정"에서 같은 상품·옵션·배송비를 확인하면 비교에 들어간다.
- 다시 갱신해도 그 링크에 대한 사용자 확인은 유지한다.

**실패 처리**
- 한 출처가 실패해도 다른 출처와 이전 기록은 남는다.
- 화면에 "마지막 갱신 시각 · 실패 이유(이전 기록은 그대로 두었어요)"를 보여 준다.
- 실패한 조회는 캐시하지 않는다. 성공한 조회는 10분 동안 캐시한다.

**호출 제한과 노출**
- `/v1/offers`는 로그인한 사용자만 쓴다(10분에 30회). 외부 API 호출 한도를 이 서버 사용자만 쓰게 하기 위해서다.
- `/v1/health`가 출처마다 연결 상태와 필요한 것을 알려 준다. 앱은 이것을 "가격 출처 연결 상태"에 그대로 보여 준다.

## 저장 위치 (`app/src/offer-store.js`, schema 7)

- 판매처 기록은 `state.offerRecords`에 상품별로 보관하며, 옷장과 같은 원자 저장·revision 충돌 보호를 거친다.
- `.eoul` 백업·복원과 계정 동기화에 포함한다. 계정이 없으면 기기에 저장한다.
- 상품 100개·상품당 12곳·전체 가격 기록 200KiB. 한도에서 직접 기록을 자동으로 지우지 않고 명시적 상품별 정리를 제공한다. 가격·착용 기록 합계의 증가 쓰기는 미래 구매 기록 680KiB와 옷 몫 64KiB를 함께 예약한다.
- 저장 실패 시 초안과 이전 스냅샷을 유지한다. 이전 계정·이전 스냅샷의 편집/늦게 도착한 조회 결과를 새 옷장에 쓰지 않는다.
- 구버전 `localStorage(eoul:offers:v1)`은 최초/구버전 승급 때 원문을 남긴 채 이전한다. 손상·한도 초과로 이전할 수 없으면 가격 기록만 보류하고 원문 받기·명시적 재시도를 제공한다. 백업/계정 교체 뒤 자동 재수입은 하지 않는다.
- schema 6 이하 백업은 가격 기록이 없으므로 교체 복원 시 가격 기록도 비운다. schema 7 백업은 포함한 가격 기록으로 교체한다. 로그아웃은 기기 기록을 유지하고 전체 삭제는 구버전 원문까지 지운다.
- 상세 수용 기준과 검증: [Codex 구현 인수인계](codex-continuation-20261015.md).
