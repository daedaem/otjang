# 원스톱 목표 완성 판정 (2026-10-19, 기준 커밋 080c47f)

대표 요청: "목표 달성을 해야죠." 원래 목표 **대충 요청 → 실제 상품 추천 → 내 옷과 비교 → 구매 → 받음 → 착용/반품**을 현재 코드와 대조해, 지금 구현할 것과 객관적 완료 기준, 외부 제휴·자격·유료 승인 없이는 완료할 수 없는 것을 나눈다. 옷장은 선택이며, 목표를 장부나 링크 입력으로 줄이지 않는다. 나중 과제(무신사 대체, 플랫폼 내 결제)를 원래 필수 범위로 넓히지도 않는다.

## 1. 단계별 현재 상태 (코드 기준)

| 단계 | 구현 | 완료 판정 | 남은 것 |
|---|---|---|---|
| ① 대충 요청 | 규칙(정규식) 해석. 종류·상황·계절·스타일·색·밝기·예산·브랜드·부정·"편한"·이어 묻기. 미이해·미반영은 알림. 회귀 문장 20개 | **부분** | 실제 사용자 문장으로 넓힐 때 정확도가 유지되는지 검증되지 않음 |
| ② 실제 상품 추천 | 무신사 수집 상품 891개(남 705·여 186), 브랜드·품명·수집일 가격·링크·이유(맞춘 조건 + 상품명 기준). 0건이면 몰래 넓히지 않음 | **동작은 완료, 자료는 임시** | 상품 자료가 무허가 수집본이고 여성 186개뿐. **자료 교체는 외부 제휴 필요** |
| ③ 내 옷과 비교 | 같은 상품·같은 종류·색·새 코디 공식·기준 옷 판정. 카탈로그 밖 링크는 종류·색만 묻고 판정. 옷장 없이는 비교 생략, 한 벌 넣고 복귀 | **완료** | — |
| ④ 구매 | 판매처 링크로 이동 + "사기로 함" 기록. 앱 안 결제 없음 | **완료(원래 범위)** | 플랫폼 내 결제는 원래 범위가 아님 |
| ⑤ 받음 | "직접 주문했다고 기록 → 받았어요 → 계속 입을게요(옷장 반영)". 구매내역 가져오기는 시험 기능 | **완료(수동 기록)** | 자동 주문 연동은 외부 제휴 필요 |
| ⑥ 착용/반품 | 착용 기록(옷·코디), 반품 기록과 사유, 핏 결과, 반품한 옷은 추천 제외 | **완료** | 반품 기록이 다음 판정에 "경고 문장"으로 돌아오는 것은 같은 상품에만 |

**결론:** 흐름 여섯 단계는 코드로 모두 이어져 있다. 끊기지 않고 끝까지 가는 것은 확인됐다(이 문서 3장). 완성되지 않은 것은 두 가지다. **①의 정확도 증거**와 **②의 자료 출처**. 이 둘이 원스톱 목표의 "정확히"와 "실제 상품"을 받치는 기둥이다.

## 2. 미완성으로 거론된 5개 항목의 필요성 검증

| 항목 | 원래 목표에 필요한가 | 판정 |
|---|---|---|
| 사진으로 상품 식별 | **아니다.** 목표는 "대충 말해도"이지 "사진 찍으면"이 아니다. 옷장 등록에서 사진은 선택이고, 상품 비교는 링크·종류·색으로 된다 | 범위 밖. 하지 않는다 |
| 실시간 가격·최저가 | **아니다.** 수집일 가격을 밝히는 것이 원칙이고, 판매처 링크에서 현재 가격을 본다. 최저가 표기는 금지 원칙 | 범위 밖. 하지 않는다 |
| 주문 자동 연동 | **아니다(편의).** "구매 → 받음"은 수동 기록으로 이어진다. 자동 연동은 입력 부담을 줄이는 개선이고, 구매자용 주문 API는 확보된 것이 없다 | 외부 제휴 없이는 불가. 시험 기능 그대로 둔다 |
| 플랫폼 내 구매·반품 | **아니다.** 원래 흐름은 "판매처로 이동 → 기록"이다. 대표도 임의 확대를 금했다 | 범위 밖 |
| 상시 운영(서버 24시간, 고정 주소) | **개인 테스트에는 아니다. 지인 파일럿부터는 맞다.** 운영 묶음(Docker·이름 있는 터널·백업)은 이미 있고 실제 터널만 미연결 | 파일럿 단계 과제. Cloudflare 계정·도메인 필요 |

## 3. 지금 구현할 것 (외부 승인 없이, 완료 기준 포함)

| 순서 | 작업 | 담당 | 객관적 완료 기준 |
|---|---|---|---|
| 1 | **흐름 전체 자동 확인 1개** — 옷장 없이 "출근용 셔츠 10만원 이하" → 상품 → 판매처 링크 존재 → 사기로 함 → 주문 기록 → 받음 → 계속 입음 → 오늘 입었어요 → 반품 기록 → 반품한 옷이 추천·코디에서 빠짐. 두 번째 줄기: 옷장 3벌 → 비교 판정 → 같은 흐름 | Codex | 검사 1개가 위 단계를 한 번에 통과. 중간에 끊기는 화면(버튼 없음·시트 닫힘)이 0 |
| 2 | **실제 사용자 문장 회귀 세트 30~50개** — 지금 20개를 대표 본인·지인이 실제로 칠 법한 문장으로 늘린다(한 줄씩 기대 종류·조건을 적음) | 대표가 문장 제공, Codex 구현 | 세트 통과율 90% 이상(추정 기준, 미달 문장은 "이해하지 못한 말"로 정직하게 표시돼야 함) |
| 3 | **홈 길이 축소** — 첫 화면이 약 5화면. 아래 구역(옷장 시작·브랜드·회원 코디)을 접거나 줄인다. 전면 재설계 아님 | Codex | 첫 방문 홈이 2화면(약 1,700px) 이하, 검색창과 예시가 첫 화면 안 |
| 4 | **반품 경고의 범위** — 같은 상품만이 아니라 같은 종류·같은 브랜드에도 "이 브랜드 셔츠를 반품한 적 있어요"로 돌려준다. 사유 추정은 하지 않는다 | Codex | 반품 기록 뒤 같은 브랜드·종류 상품 비교 화면에 과거 기록 줄이 보임(검사 1개) |
| 5 | **대표 실기기 확인 8개**(release-gate 5장) | 대표 | 막힌 항목 0 또는 목록으로 회신 |

1·2가 끝나면 "흐름이 끝까지 간다"와 "대충 말해도 알아듣는다"가 **검사로 증명된 상태**가 된다. 그것이 지금 코드로 할 수 있는 완성이다.

## 4. 외부 제휴·자격·유료 승인 없이는 완료할 수 없는 것

| 항목 | 막는 것 | 대표가 할 일 |
|---|---|---|
| 상품 자료의 정당한 출처(②) | 수집 상품·핫링크 사진은 공개 불가. 제휴 승인된 자료로 교체해야 함 | 쿠팡 파트너스·무신사 큐레이터·에이블리·링크프라이스 신청, 변호사 1회 상담(`product-data-plan-20261019.md`) |

| 주문 자동 연동(⑤ 편의) | 구매자용 주문 API 없음 | 제휴 뒤에도 제공 여부 불확실. 시험 기능 유지 |
