# 원스톱 목표 완성 판정 (2026-10-19, 기준 커밋 080c47f)

> 문서 시점: 2026-10-19. 당시의 검토·구현 기록을 보존한 자료입니다. 현재 결정·우선순위·운영 상태는 [최신 문서 목차](README.md)를 확인합니다. 아래의 “지금·완료·다음”은 별도 갱신 표시가 없으면 당시 기준입니다.

대표 요청: "목표 달성을 해야죠." 원래 목표 **대충 요청 → 실제 상품 추천 → 내 옷과 비교 → 구매 → 받음 → 착용/반품**을 현재 코드와 대조해, 지금 구현할 것과 객관적 완료 기준, 외부 제휴·자격·유료 승인 없이는 완료할 수 없는 것을 나눈다. 옷장은 선택이며, 목표를 장부나 링크 입력으로 줄이지 않는다. 나중 과제(무신사 대체, 플랫폼 내 결제)를 원래 필수 범위로 넓히지도 않는다.

## 1. 단계별 현재 상태 (코드 기준)

| 단계 | 구현 | 완료 판정 | 남은 것 |
|---|---|---|---|
| ① 대충 요청 | 규칙(정규식) 해석. 종류·상황·계절·스타일·색·밝기·예산·브랜드·부정·"편한"·이어 묻기. 미이해·미반영은 알림. 회귀 문장 20개 | **부분** | 실제 사용자 문장으로 넓힐 때 정확도가 유지되는지 검증되지 않음 |
| ② 실제 상품 추천 | 무신사 수집 상품 891개(남 705·여 186), 브랜드·품명·수집일 가격·링크·이유(맞춘 조건 + 상품명 기준). 0건이면 몰래 넓히지 않음 | **동작은 완료, 자료는 임시** | 상품 자료가 무허가 수집본이고 여성 186개뿐. **자료 교체는 외부 제휴 필요** |
| ③ 내 옷과 비교 | 같은 상품·같은 종류·색·새 코디 공식·기준 옷 판정. 카탈로그 밖 링크는 종류·색만 묻고 판정. 옷장 없이는 비교 생략, 한 벌 넣고 복귀 | **완료** | — |
| ④ 구매 | 판매처 링크로 이동 + "사기로 함" 기록. 앱 안 결제 없음 | **사용자 기록 단계.** 계약의 완료 기준인 "확인된 주문 이벤트"는 **미확보** | 확인된 주문은 외부 제휴 필요. 자체 결제는 장기 확장 |
| ⑤ 받음 | "직접 주문했다고 기록 → 받았어요 → 계속 입을게요(옷장 반영)". 구매내역 가져오기는 시험 기능 | **사용자 기록 단계.** 확인된 수령 이벤트는 **미확보** | 주문 자동 연동은 외부 제휴 필요 |
| ⑥ 착용/반품 | 착용 기록(옷·코디), 반품 기록과 사유, 핏 결과, 반품한 옷은 추천 제외 | **완료** | 반품 기록이 다음 판정에 "경고 문장"으로 돌아오는 것은 같은 상품에만 |

**결론:** 흐름 여섯 단계는 코드로 모두 이어져 있고, 끊기지 않고 끝까지 가는 것은 자동 검사(8f00c12)로 확인됐다. 다만 **완성이 아니다.** 지금 코드로 메울 수 있는 것은 ①의 정확도 증거(실제 사용자 문장은 아직 0개)와 ②의 자료 출처다. 그 밖에 계약의 완료 기준 중 **확인된 주문·수령 이벤트, 권리가 확인된 다중 판매처 가격·옵션 비교, 사진 식별 정확도, 가상 착용**은 외부 의존으로 미확보이며, 이 문서는 이것들을 완료로 세지 않는다(2장·4장).

## 2. 미완성으로 거론된 5개 항목의 필요성 검증 (2026-10-19 정정)

**정정:** 처음 판정에서 "범위 밖으로 확정"이라고 쓴 것은 틀렸다. `onestop-product-contract-20261014.md`의 전체 완료 기준에는 조합·가상 착용, 정확한 상품·옵션·가격 비교, 확인된 주문 이벤트가 들어 있고, 대표도 사진 인식과 최저가 링크를 여러 번 요청했다. 가상 착용 보류와 "수집일 가격" 표기 원칙은 **영구 삭제 승인이 아니라** 조건이 갖춰질 때까지의 보류다. 아래 구분으로 바로잡는다.

|---|---|---|---|

## 5. 보류·외부 조건 대기 (삭제가 아님)
사진 상품 식별, 다중 판매처 실시간 비교, 주문 자동 연동, 가상 착용은 **계약상 목표에 남긴다.** 지금 코드로는 조건이 없어 보류이며, 조건이 갖춰지면 다시 연다. 자체 결제는 장기 확장. LLM 해석은 유료·외부 전송 승인이 있어야 검토한다.

## 5-1. 회귀 세트의 한계 (Codex 지적 반영)
실제 사용자 문장 30~50개 통과는 **그 문장들에 대한 통과**이지 일반적인 자연어 정확성의 증명이 아니다. 세트는 (a) 대표·지인이 실제로 친 문장과 (b) AI가 만든 사례를 **파일에서 분리해** 기록하고, 통과율도 따로 센다. 실사용 검증(관찰·재요청)은 별도 항목으로 남긴다.

## 5-2. 네이버 쇼핑 검색 API 종료 반영 (Codex 확인: 공식 1차 공지 https://developers.naver.com/notice/article/32564, 현행 약관 부칙 제2조 3항)
`server/src/supply.js`는 키가 있으면 종료된 API를 `connected`로 표시하고 호출한다. **바로잡는다(Codex 담당).** 완료 기준: 키 유무와 관계없이 상태 `discontinued`(서비스 종료), 호출 경로 비활성(네트워크 요청 0), 안내 문구에 종료일과 공식 공지 링크, 검사 1개(키가 있어도 호출하지 않음). 기존 기록된 판매처 가격 자료는 삭제하지 않는다.
