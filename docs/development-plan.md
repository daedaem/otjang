## 범위와 진행 원칙

옷장 없는 첫 추천부터 선택적 옷장 비교, 새 상품·중고 구매, 구매 후 기록까지가 전체 목표다. 장부만의 서비스로 바꾸거나 가상 착용·정확한 가격 비교·확인된 주문을 영구 삭제하지 않는다. 사용자 원본, 알 수 없는 속성, 백업·복원과 기존 기록 형식을 보존한다. 로컬 구현·자동 검사·Git 병합·배포·실제 호출·사용자 효용은 별개의 완료 상태다.

일정과 점수부터 확정하지 않고 아래 순서의 차단 문제를 해결한다. 기존 승인 안의 비공개 수정·로컬 검증은 진행할 수 있다. 외부 공개·모집·새 계정·새 비용·사진 전송·약관 범위 확장은 별도 결정이 필요하다. 담당이 Claude/Codex로 표시된 과거 제안은 실제 외부 전문가의 승인이나 현재 구현 완료를 뜻하지 않는다.

### 별도 검토 중인 실행 오류

기준 master의 `app/lite/dev.mjs`는 `.mjs` MIME 매핑이 없는데 빌드는 OPF module script를 넣는다. PR #48 브랜치에 `.mjs → text/javascript` 매핑이 있고, 10-23에 `node dev.mjs --fake`를 띄워 `dist/shared/open-products.<hash>.mjs`가 `200 text/javascript; charset=utf-8`로 내려오는 것을 확인했다(master 코드에는 매핑 0건). master 반영은 PR #48 병합 뒤다.

## 대표 아이폰에서 확인할 과제

lite의 개인 백업·복원 UI는 10-23에 브랜치에 구현했고 데스크톱 자동 검사만 통과했다. master 병합·배포 전까지 운영 앱에는 없으며, 아이폰에서 내보내기·복원이 실제로 되는지는 과제 7에서 확인한다. 기존 자료를 바꾸는 과제는 그 확인 뒤 진행한다. 그 전에는 기존 기기에서 읽기 중심으로 확인하고 쓰기·복원 검사는 별도 QA 자료로 한다. 저장소 삭제·초기화로 검증하지 않는다.

1. 현재 설치 앱의 빌드 확인, 재실행·로그인·세션 유지와 기존 옷장·기록 확인. 데스크톱 390px 검사를 실물 아이폰 결과로 쓰지 않는다.
2. 옷장을 등록하지 않고 자연어 검색→실제 후보·출처·가격 기준→판매처 이동. 0건·미지원 조건·API 실패는 서로 다르게 안내하는지 확인한다.
3. 검색 제출 한 번의 국내 상품 표시, OPF 후보 비교, Rakuten의 일본어 검색어 확인 흐름을 각각 확인한다. 제공 순서 결과에 AI 순위 라벨이 붙지 않아야 한다.
4. 실제 옷 한 벌 추가→같은 후보 비교로 복귀→동일 후보·옵션 기록 보존. 예시 옷과 공개 정보 선택을 실제 보유로 세지 않는다.
5. 상담→같은 상담의 이어 묻기→새 상담 시작. 조건·예산 설명, 상담 이력 보존, 다른 상담 맥락 혼입 여부를 확인한다.
6. lite와 기존 앱에서 지원하는 단계를 먼저 구분하고 직접 주문 기록→수령→보유 확정→착용→반품 뒤 옷장·추천 반영을 검증한다. lite에 없는 단계는 미구현으로 기록하고 구현 뒤 확인한다. 판매처 방문을 주문으로 자동 확정하지 않는다.
7. 개인 백업·복원 기능을 구현한 앱에서만, 격리된 QA 자료로 내보내기/복원 후 원문·개인 사진·옵션·과거 이력 보존을 검증한다. OPF 내보내기로 이 과제를 통과 처리하지 않는다. 기존 자료를 지우거나 덮어쓰지 않는다.

현재 상태는 **미검증**이다. 실제 사용자가 수행한 기기·브라우저·버전·입력·결과·남은 문제를 근거 문서나 이슈에 붙여야 상태를 바꾼다. 새 테스트 계정을 실제 이용자 수로 세지 않는다.

## 후속 목표와 출시 전 판단

| 목표 | 현재 경계 | 다시 진행할 조건 |
|---|---|---|

## 작업마다 남길 것

문제와 실제 입력 → 요구사항 번호 → 대안·선택 이유 → 변경 파일·커밋/PR → 로컬/CI/배포/실제 호출의 각각의 증거 → 남은 한계 순서로 기록한다. 새 대표 결정은 같은 작업의 [대표 요구사항](owner-requirements.md)에 날짜·출처와 함께 반영한다. API 키·쿠키·개인 사진·전체 요청 ID·개인 구매내역은 공개 이슈·PR·문서에 넣지 않는다.

완료된 PR과 운영 반영은 실제 상태를 확인한 뒤 [시스템 인수인계](system-handover.md)에 갱신한다. PR #48 같은 열린 시안은 검토 대상으로 남기고 master 기준 기능이나 대표 선택으로 조용히 바꾸지 않는다.
