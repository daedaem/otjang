# 어울 (가칭)

**예시 옷장으로 바로 둘러보고, 내 옷 한 벌부터 다음 아이템을 찾아보는 앱입니다.**

내 스타일과 가진 옷을 바탕으로 "다음에 무엇을 사면 좋을지"를 실제 판매 상품(브랜드·가격·평점·판매 링크)으로 보여 주는 개발 중인 원스톱 패션 플랫폼입니다. 전체 목표와 현재 미완료 범위는 [제품 계약](docs/onestop-product-contract-20261014.md)에 적었습니다.

## 제품 원칙

1. **입력은 최소로.** 첫 방문은 예시 6벌로 추천을 바로 봅니다. 개인 옷을 넣을 때 필수는 종류 하나이며 사진·색·브랜드·이름은 선택입니다. 스타일 최대 3개, 선호 브랜드, 상황·예산은 나중에 바꿀 수 있습니다.
2. **추천은 실제 상품으로.** 색이나 종류를 제안하는 데서 끝내지 않고, 실제 브랜드 상품을 가격대별로 보여 줍니다.
3. **이유를 한 줄로.** "가진 치노·로퍼와 함께 쓰는 코디 공식이 있어요"처럼 실제 보유 기록과 연결합니다. 종류 규칙과 인기 지표는 실제 핏 판단과 구분합니다.
4. **물어보듯 찾기.** "출근용 셔츠 10만원 이하", "청바지에 어울리는 신발"처럼 한 줄로 찾습니다. 앱이 이해한 조건은 칩으로 보여 줍니다.
5. **현재 체험 버전은 내 기기에 저장.** 가입 없이 옷장·찜·취향·사진을 브라우저에 저장합니다. 사진 분석 도구는 외부에서 다운로드하지만 사진은 로컬 Worker에 전달합니다. 계정·서버·동기화는 출시 전 과제입니다.

## 화면 구성

| 탭 | 하는 일 |
|---|---|
| 추천 | 한 줄 검색, 상황·예산·내 브랜드만 칩, 오늘의 코디(실제 상품 조합), 내 브랜드에서 고른 상품, 내 옷과 비교할 구매 후보 |
| 내 옷장 | 한 벌씩 사진·이름을 저장하고 수정·삭제. 보유 종류를 쓰는 코디와 추가 후보. 기본템 체크는 접어서 표시 |
| 구매 여정 | 가져온 상품을 내 옷과 비교하고, 결정·주문·수령·착용·반품을 직접 기록. 기존 찜과 합계도 보관 |

### 스타일과 브랜드

- 스타일: 남성 6가지(아메리칸 클래식, 아메카지, 시티보이, 미니멀, 댄디, 고프코어), 여성 5가지(아메리칸 클래식, 아메카지, 미니멀, 프렌치 시크, 데일리 캐주얼). 세 개까지 고르고, 먼저 고른 스타일을 더 반영합니다.
- 독립 검토와 Claude 통합 후 목록은 891개 상품, 115개 브랜드, 68개 세부 종류, 35개 코디 공식입니다. 고른 브랜드를 먼저 추천하고, "내 브랜드만"을 켜면 그 브랜드 상품만 보여 줍니다. 상품 수는 분류 정확도나 판매 가능성의 검증 수치가 아닙니다.


### 내 옷장에 옷을 넣는 세 가지 방법

1. 종류 사진을 누르고 저장합니다. 색·브랜드·이름은 선택입니다.
2. 사진을 고르면 기기에서 종류 후보와 라벨 글자를 분석합니다. 맞는 종류를 누르고, 라벨 사진이나 읽힌 글자로 브랜드·상품 후보를 확인할 수 있습니다. 사진만으로 정확한 브랜드·상품·색을 확정하지 않습니다.
3. 추천 상품 화면에서 "이 상품 있어요"를 누르면 그 상품 그대로 옷장에 들어갑니다.

첫 개인 저장이 성공할 때 예시 옷을 개인 옷장과 교체합니다. 저장 실패 시 초안은 유지됩니다. 사진과 기록은 같은 IndexedDB 트랜잭션으로 저장하며, 프로필에서 사진 포함 `.eoul` 백업과 확인 후 복원을 제공합니다. 이전 `eoul:v1` 및 Claude 사진 DB는 읽기 전용으로 이전합니다. 서로 다른 사이트/브라우저의 자료를 자동으로 가져오지는 않습니다.

## 실행

```bash
cd app

python3 -m http.server 8000      # http://localhost:8000
node --test                      # 별도 터미널: 추천·저장·이전·복원 검사

```

구성과 데이터 출처는 [app/README.md](app/README.md), 변경 이유·복구 절차·검증 한계는 [인수인계](docs/instant-garments-handoff-20261014.md), 새 분석 기능은 [사진 인식 설계](docs/photo-recognition-20261014.md)에 정리했습니다. 사진 분석 때는 고정 버전의 공개 JS·모델·언어 자산을 다운로드합니다. 모델 ONNX만 약154MB이며 첫 실행과 휴대폰 속도는 미검증입니다.

## 지금 할 수 없는 것

- 가격·재고는 실시간이 아닙니다. 무신사 상품 페이지에서 확인한 시점의 판매가이며, 앱에 확인 날짜를 표시합니다.
- 사이즈·핏은 판단하지 않습니다.
- 추천은 편집자가 정리한 스타일 규칙(아이템 종류별 스타일 점수, 코디 공식 35개, 색 조화 규칙)으로 계산합니다. 같은 입력·계절이면 같은 결과가 나오며, 대화형 AI를 쓰지 않습니다.
- 사진의 종류 후보·라벨 OCR은 구현했지만, 라벨이 안 보이는 사진의 정확한 브랜드·상품 식별과 의류 분할·배경 제거는 없습니다. 색 추론은 실제 오분류로 제외했습니다. 미확인 색·브랜드는 null로 보관합니다. 상품 사진에서 추정한 색은 색 조화 점수에서 제외합니다.
- 브랜드 목록 화면에서 모은 상품은 이름의 단어로 종류를 자동 분류했습니다. 일부 상품은 종류나 색이 실제와 다를 수 있습니다.
- 자동 검사 303개와 빌드는 통과했습니다. 실기기 카메라·모바일 화면·장기 저장은 미검증이며 출시 완료를 뜻하지 않습니다.

## 이전 작업과의 관계

이 통합은 `claude/fashn-vton-m1-test-3ox240`의 `580a543` 화면·추천을 기반으로 `feat/instant-wardrobe-demo-20261014`의 예시 체험·사진 저장·백업 보호를 연결합니다. 기존 7개 탭의 `core-flow` 앱 전체를 가져오지 않습니다. 구매 판단과 사용자 직접 주문·수령·보유 확정·착용·반품 기록은 같은 구매 여정과 옷장에 연결합니다. 3D 옷장, 서버·계정·동기화, 커뮤니티, 가상 착용, 실시간 판매처 비교, 확인된 주문·자체 결제는 미완료입니다. 이전 브랜치와 실험은 보존합니다.

`experiments/vton-fashn-1.5/`는 로컬 가상 착용 모델을 시험하는 별도 실험이며, 앱에는 포함하지 않았습니다.

작업 규칙은 [CONTRIBUTING.md](CONTRIBUTING.md)를 따릅니다.

사업·서비스·디자인을 포함한 5+5 독립 검토와 반박 근거는 [검토 요약](docs/independent-review-20261014.md)에 기록했습니다. 전체 원스톱 목표와 완료 기준, Claude 교차 검토, schema 5의 당시 값 보존·옵션 정정·저장 예산과 구매 후 보유 정책은 [원스톱 제품·개발 계약](docs/onestop-product-contract-20261014.md)에 기록했습니다. 현재 미리보기는 구매 여정과 옷장 연결 단계이며 전체 원스톱 서비스 완성·실시간 최저가·핏을 보장하지 않습니다.

## 원스톱 구매 여정 연결

추천 화면의 “상품 링크로 비교하기” 또는 상품 상세의 “내 옷과 비교”에서 시작합니다. 외부 후보는 원래 주소를 유지하고, 정확한 카탈로그 상품이 있을 때만 저장된 정보로 연결합니다. 모르는 종류·색은 모르는 상태로 보관합니다.

“구매 여정”에서 사기/보류/안 사기, 옵션과 이유, 직접 주문 기록, 잠정 수령, 계속 입기, 착용, 반품을 같은 ID로 이어갑니다. 계속 입기로 확인한 옷만 보유 추천에 반영합니다. 반품·교체 옷은 원문과 사진을 보존하며 추천에서 제외합니다. 다른 옵션은 독립 기록을 만들고 처음 후보 ID에 연결합니다. 판매처 링크 클릭은 구매가 아니며 현재 주문·반품은 판매처에서 확인한 데이터가 아닌 사용자 기록입니다.
