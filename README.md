# 어울 (가칭)

**앱을 열면 바로, 나에게 어울리는 실제 브랜드 아이템과 코디를 추천합니다.**

내 스타일과 가진 옷을 바탕으로 "다음에 무엇을 사면 좋을지"를 실제 판매 상품(브랜드·가격·평점·판매 링크)으로 보여 주는 개인 사이드프로젝트입니다.

## 제품 원칙

1. **입력은 최소로.** 처음 열면 예시 옷 6벌로 추천을 바로 보여 줍니다. "내 옷으로 바꾸기"에서 종류 하나를 고르고 저장하면 됩니다. 사진과 이름은 선택이며 저장 성공 뒤 실제 옷장으로 전환합니다. 상황·예산은 칩 하나로 바꿉니다.
2. **추천은 실제 상품으로.** 색이나 종류를 제안하는 데서 끝내지 않고, 실제 브랜드 상품을 가격대별로 보여 줍니다.
3. **근거를 구분합니다.** 내 옷 종류와의 코디 공식, 상품 평점·후기 수를 구분해 설명합니다. 사진의 색·핏을 알아낸 것처럼 표현하지 않습니다.
4. **물어보듯 찾기.** "출근용 셔츠 10만원 이하", "청바지에 어울리는 신발"처럼 한 줄로 찾습니다. 앱이 이해한 조건은 칩으로 보여 줍니다.
5. **내 정보는 내 기기에.** 가입이 없고, 옷장·찜·취향은 브라우저에만 저장합니다. 서버가 없습니다.

## 화면 구성

| 탭 | 하는 일 |
|---|---|
| 추천 | 한 줄 검색, 상황·예산 칩, 오늘의 코디(실제 상품 조합), 지금 사면 좋은 아이템 |
| 내 옷장 | 사진·종류·선택 이름으로 한 벌씩 저장 → 실제 옷을 코디에 반영 |
| 찜 | 찜한 상품과 합계 |

## 실행

```bash
cd app
npm ci --ignore-scripts           # 테스트용 의존성 설치 (Node 22)
python3 -m http.server 8000      # http://localhost:8000
node --test                      # 추천·저장·실제 번들 콜백 테스트
node tools/build.mjs             # app/dist/index.html (파일 하나로 묶은 배포본)
```

구성과 데이터 출처는 [app/README.md](app/README.md)에 정리했습니다.

## 지금 할 수 없는 것

- 가격·재고는 실시간이 아닙니다. 무신사 상품 페이지에서 확인한 시점의 판매가이며, 앱에 확인 날짜를 표시합니다.
- 사이즈·핏은 판단하지 않습니다.
- 추천은 편집자가 정리한 스타일 규칙(아이템별 스타일 점수, 코디 공식)으로 계산합니다. 같은 입력이면 같은 결과가 나오며, 대화형 AI를 쓰지 않습니다.
- 사진은 선택해서 보관할 수 있지만, 옷 종류·브랜드·색·핏의 자동 인식은 제공하지 않습니다.
- 구매·착용·환불 기록과 기존 core-flow 사진 옷장 가져오기는 새 앱에 아직 연결되지 않았습니다.

## 이전 작업과의 관계

`feat/editorial-mobile-20261013`, `feat/beta-eoul`, `feat/personal-app-v0.4`, `feat/wearnext-prototype` 브랜치와 `gh-pages`의 미리보기들은 이 재작업 이전의 시도입니다. 이번 재작업은 "핵심 가치(실제 상품 추천)가 화면에 바로 보이지 않는다"는 검수 결과에 따라 첫 화면과 등록 흐름을 단순하게 만들었습니다. 이전 브랜치는 지우지 않았고, 이 브랜치에 병합하지도 않았습니다. 3D 옷장, 서버·계정·동기화, 옷장 구경은 이 새 앱에 아직 연결되지 않았으며, 해당 제품 목표가 완료되거나 취소된 것은 아닙니다.

`experiments/vton-fashn-1.5/`는 로컬 가상 착용 모델을 시험하는 별도 실험이며, 앱에는 포함하지 않았습니다.
