# 어울 서버 (직접 운영)

계정(이메일 가입·로그인)과 옷장·사진 동기화를 맡는 서버입니다. 운영자의 PC나 클라우드 VM 한 대에서 돌립니다.

- 외부 서비스, 유료 API, npm 패키지를 쓰지 않습니다. 필요한 것은 Node.js뿐입니다.
- 계정, 옷장 기록, 사진은 모두 이 서버의 SQLite 파일 하나(`server/data/eoul.db`)에 저장됩니다.
- 앱은 이 서버 없이도 지금처럼 기기 안에서만 동작합니다. 서버를 켜면 앱에 "계정에 저장"이 나타납니다.

## 필요한 것

- **Node.js 22.13 이상**
  - 내장 `node:sqlite`를 씁니다.
  - 이 저장소에서는 22.22.0으로 확인했습니다.
  - 실행할 때 `ExperimentalWarning: SQLite is an experimental feature`가 뜨는데, 정상입니다.
- 휴대폰에서 쓰려면 **https 주소**가 필요합니다.
  - 앱은 사진 이름을 만들 때 브라우저 암호화 기능(`crypto.subtle`)을 쓰고, 이 기능은 https나 `localhost`에서만 켜집니다.
  - 그래서 `http://192.168.x.x` 같은 집 안 주소로는 사진을 저장할 수 없습니다.
  - https 주소를 붙이는 방법은 아래 "휴대폰에서 접속하기"에 있습니다.

> **실제 운영(집 PC 상시 운영, 나중에 클라우드로 이전)은 [운영 묶음](../deploy/README.md)을 쓰세요.** Docker로 서버, Cloudflare Tunnel, 자동 백업(Litestream)을 한 번에 띄웁니다. 아래는 개발·시험용으로 Node를 직접 실행하는 방법입니다.

## 처음 실행

```bash
cd server
npm start          # 앱을 빌드(app/dist/index.html)하고 http://127.0.0.1:8787 에서 서버를 켭니다
```

브라우저에서 `http://localhost:8787`을 열면 앱이 뜨고, 프로필에 "계정" 칸이 보입니다.

### 설정 (환경 변수)

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `EOUL_PORT` | `8787` | 서버 포트 |
| `EOUL_HOST` | `127.0.0.1` | 이 PC 안에서만 받습니다. 터널을 쓰면 바꿀 필요가 없습니다. |
| `EOUL_DATA_DIR` | `server/data` | 데이터베이스 폴더. 저장소에 올라가지 않도록 `.gitignore`에 들어 있습니다. |
| `EOUL_INVITE_CODE` | 없음 | **시험 기간에는 꼭 설정하세요.** 이 코드를 아는 사람만 가입할 수 있습니다. |
| `EOUL_TRUST_PROXY` | 없음 | Cloudflare Tunnel 뒤에서는 `cloudflare`로 설정합니다. 이렇게 해야 시도 횟수 제한이 실제 접속자 기준으로 동작합니다. |
| `EOUL_TRUSTED_PROXIES` | 없음 | cloudflared가 다른 컨테이너에서 돌 때 그 고정 IP(쉼표로 여러 개). 같은 PC의 cloudflared(127.0.0.1)는 적지 않아도 됩니다. [운영 묶음](../deploy/README.md)은 자동으로 채웁니다. |
| `EOUL_ALLOWED_ORIGINS` | 없음 | 앱을 다른 주소(예: GitHub Pages)에 올렸을 때 그 주소를 적습니다. 쉼표로 여러 개를 적을 수 있습니다. |
| `EOUL_SESSION_DAYS` | `60` | 마지막으로 쓴 뒤 로그인이 유지되는 날수 |
| `EOUL_SCRYPT_LOG2N` | `17` | 비밀번호 해시 강도. 바꾸지 않아도 됩니다. |

설정 방법:

- Windows PowerShell: `$env:EOUL_INVITE_CODE="친구들끼리만"; npm start`
- macOS·Linux: `EOUL_INVITE_CODE=친구들끼리만 npm start`

비밀 값은 저장소 파일에 적지 마세요. 서버에는 서명 키가 없고, 로그인 토큰은 해시로만 저장합니다. 그래서 따로 관리할 비밀은 초대 코드뿐입니다.

## 휴대폰에서 접속하기 (https 주소 붙이기)

**1순위 (시험용): Cloudflare Quick Tunnel**
- 계정도 도메인도 필요 없습니다.
- 실행할 때마다 `https://…trycloudflare.com` 주소가 새로 생깁니다.
- 이 서버 PC에서 실행합니다.

```bash
# 터미널 1
EOUL_TRUST_PROXY=cloudflare EOUL_INVITE_CODE=... npm start
# 터미널 2 (cloudflared 설치 후)
cloudflared tunnel --url http://localhost:8787
```

- 터미널 2에 나온 https 주소를 휴대폰 Safari나 Chrome에서 엽니다.
- Cloudflare 문서(2026-10-15 확인)에 따르면 Quick Tunnel은 이렇습니다.
  - 시험·개발용입니다.
  - 가동 시간 보장이 없습니다.
  - 동시에 처리하는 요청은 200개로 제한됩니다.
  - 주소는 만들 때마다 바뀝니다.
- **주소가 바뀌면 휴대폰 브라우저에는 다른 사이트로 보입니다.** 그래서 이 기기 저장 공간도 따로입니다.
  - 새 주소에서 한 번 로그인하면 계정에 저장된 옷장을 다시 받습니다.
  - 계정에 저장하지 않은 옷장은 이전 주소에 남아 있습니다.

**2순위 (주소를 고정하고 싶을 때)**
- **Tailscale Funnel**
  - Tailscale 문서에 따르면 모든 요금제에서 쓸 수 있습니다.
  - 주소는 `https://<기기 이름>.<tailnet 이름>.ts.net` 형식입니다.
  - 주소가 계속 같은지는 문서에서 확인하지 못했습니다. 써 보면서 확인이 필요합니다.
- **Cloudflare 이름 있는 터널**
  - 자기 도메인을 Cloudflare에 연결해야 하는 것으로 알고 있습니다(확인 필요).
  - 도메인 비용이 들 수 있어서, 쓸지는 따로 결정해야 합니다.

**앱을 GitHub Pages 같은 다른 곳에 올린 경우**
- 앱을 `node app/tools/build.mjs --server https://서버주소`로 빌드합니다.
- 서버에는 `EOUL_ALLOWED_ORIGINS=https://앱주소`를 설정합니다.
- 다만 주소가 매번 바뀌는 Quick Tunnel과는 맞지 않습니다. 이 경우는 서버가 앱도 함께 내보내는 위 방식을 권합니다.

## 서버에서 하는 배경 지우기 (선택)

로그인한 사용자가 "배경 지우기"를 누르면, 이 서버의 큰 모델(U-2-Net, 176MB)로 처리합니다. 켜려면 이 PC에 한 번만 설치합니다.

```bash
cd server
npm install            # onnxruntime-node 1.22.0 (약 240MB). .npmrc가 쓰지 않는 GPU 파일 내려받기를 건너뜁니다
npm run fetch-model    # U-2-Net 모델을 받아 고정한 SHA-384와 맞을 때만 server/models/에 저장합니다
npm start              # 로그에 "사진 배경 처리 켜짐"이 보이면 켜진 것입니다
```

- 모델을 내려받지 못하면, 다른 방법으로 받은 `u2net.onnx`를 `node cli.mjs fetch-model <파일>`로 넣을 수 있습니다. 이때도 해시를 확인합니다.
- 앱은 사진 원본이 아니라 **320×320으로 줄인 픽셀(약 307KB)**만 보냅니다. 서버는 영역 정보만 돌려주고, 흰 배경 사진은 앱이 만듭니다.
  - 서버는 받은 픽셀과 결과를 저장하거나 로그에 남기지 않습니다.
- 한 번에 한 장만 처리합니다. 4장이 기다리고 있으면 "바쁨"으로 답합니다.
  - 그러면 앱은 그 세션 동안 기기 도구(약 7MB 내려받기, 사용자 동의 후)로 지웁니다.
  - 서버가 꺼져 있거나 로그인하지 않은 경우도 같습니다.
- 스레드 수는 `EOUL_MASK_THREADS`로 정합니다. 기본값은 CPU 코어 수이고, 최대 4입니다.
- 측정과 근거: [서버 배경 처리](../docs/server-photo-mask-20261015.md)

## 이메일 확인·비밀번호 재설정 (메일 발송 설정)

- 링크는 한 번만 쓸 수 있습니다. 확인 링크는 24시간, 재설정 링크는 30분 뒤 만료됩니다.
- 서버에는 링크 토큰의 해시만 저장합니다.
- 비밀번호를 재설정하면 그 계정의 모든 기기가 다시 로그인해야 합니다.
- 메일을 보내는 방법은 설정으로 고릅니다.

| `EOUL_MAIL` | 동작 | 필요한 것 |
|---|---|---|
| `off` (기본) | 메일을 보내지 않아요. 앱이 "운영자에게 문의"를 안내해요. | 없음 |
| `console` | 메일 대신 링크를 서버 로그에 찍어요. **개발용이라 실제 사용자에게 쓰지 마세요.** | `EOUL_PUBLIC_URL` |
| `smtp` | 운영자의 메일 계정으로 보내요. | `EOUL_PUBLIC_URL`, `EOUL_SMTP_HOST`, `EOUL_SMTP_PORT`(587 STARTTLS, 465 TLS), `EOUL_SMTP_USER`, `EOUL_SMTP_PASS`, `EOUL_SMTP_FROM` |

- `EOUL_PUBLIC_URL`은 사용자가 여는 https 주소입니다(예: 고정 터널 주소). 메일 링크가 이 주소로 열립니다.
- Quick Tunnel처럼 주소가 바뀌면 이전 메일의 링크가 열리지 않습니다.
- SMTP 계정과 비밀번호는 환경 변수로만 넣고, 저장소에 적지 마세요.
- 메일 발송 업체는 개인정보 처리 위탁에 해당할 수 있습니다. [처리방침 초안](../docs/privacy-policy-draft-20261015.md)에 적어야 합니다.
- 실제 SMTP 업체로 보내 보지는 않았습니다. 가짜 SMTP 서버로 대화 순서와 메시지 형식만 시험했습니다.

## 가격 출처 연결 (선택)

- 앱의 "판매처·총액 비교"에서 "연결된 출처에서 다시 확인"을 쓰려면 운영자 서버에 가격 출처를 연결합니다.
- 네이버 쇼핑 검색 API는 2026-07-31에 종료됐습니다. [공식 종료 공지](https://developers.naver.com/notice/article/32564). 기존 키도 연결이나 호출을 활성화하지 않습니다. 출처 상태는 `discontinued`이며 과거에 저장한 가격 자료는 유지합니다.
- 현재 자동으로 갱신할 수 있는 외부 가격 출처는 없습니다. 실제 사용 권한이 확인된 별도 공급원을 연결해야 합니다.
- 무신사 실시간 가격과 쿠팡 파트너스는 미연동입니다. 제휴, 승인 또는 이용약관 확인이 먼저입니다.
- 규칙과 한계는 [판매처·총액 비교](../docs/price-offers-20261015.md)에 있습니다.

## 회원 코디 (커뮤니티, 기본 꺼짐)

- 이 서버에 가입한 회원끼리 코디를 나누는 기능입니다. `EOUL_COMMUNITY=on`일 때만 켜집니다.
- **켜기 전에 운영자가 정해야 할 것**
  - 커뮤니티 규칙: 앱에 보이는 규칙은 `app/src/community-post.js`의 `COMMUNITY_RULES`입니다. 바꾸면 `COMMUNITY_RULES_VERSION`도 올려야 회원이 다시 동의합니다.
  - 신고를 받는 연락처 `EOUL_COMMUNITY_CONTACT`(필수, 없으면 서버가 켜지지 않음)와 확인 기한 `EOUL_COMMUNITY_REVIEW_DAYS`(기본 7일). 둘 다 앱의 규칙과 신고 화면에 보입니다.
  - 처리방침의 "회원 코디" 항목을 채우는 것.
- **올라가는 것**
  - 코디의 모양: 역할, 종류, 색, 회원이 적은 브랜드, 목록에 있는 상품 번호.
  - 한마디(300자).
  - 회원이 글마다 고르고 동의한 옷 사진(최대 4장, JPEG, 장당 800KB 이하).
- **올라가지 않는 것**: 이메일, 옷 ID, 구매 링크, 메모, 옷장 사진 이름.
- **신고와 숨김**
  - 신고하면 신고한 회원에게는 바로 안 보입니다.
  - 서로 다른 회원 3명이 신고하면 운영자가 확인할 때까지 모두에게 숨겨집니다. 작성자에게는 숨겨진 이유가 보입니다.
  - 신고한 회원에게 "운영자가 N일 안에 확인해요"를 보여 줍니다. 운영자 화면(`community review`)은 기다리는 신고를 오래된 순서로 먼저 보여 주고, 기한이 지나면 표시합니다.
  - 운영자가 숨기거나 지울 때 사유(privacy·rights·spam·abuse·other)를 고르면 작성자에게 그 사유가 보입니다.
  - 숨김·복구·삭제와 신고 수에 따른 자동 숨김은 `community log`에 남습니다. 글 번호, 처리, 사유, 신고 수, 첫 신고와 처리 시각만 남고 작성자·글·사진은 남기지 않습니다.
- **차단**
  - 회원은 글에서 "이 회원 차단"을 두 번 눌러 차단합니다. 그러면 서로의 글이 보이지 않고, 사진·신고도 막힙니다. 상대에게는 알리지 않습니다.
  - "차단한 회원"에서 언제든 풀 수 있습니다. 한 회원은 500명까지 차단할 수 있고, 커뮤니티를 나가면 내 차단도 지워집니다.
- **지우기**
  - 작성자는 언제든 지울 수 있습니다. 커뮤니티를 나가거나 계정을 지우면 그 회원의 글과 사진이 모두 지워집니다.
  - 운영자가 `EOUL_COMMUNITY`를 꺼도 회원은 남긴 글을 지울 수 있습니다.
- **사진 정보 지우기**: 앱이 올리기 전에, 서버가 저장하기 전에 위치·시각·기기 정보(EXIF, XMP, IPTC, 주석)를 지웁니다.
- **저장 상한**
  - 회원 한 명당 글 300개, 사진 120장, 40MB입니다.
  - 서버 전체는 `EOUL_COMMUNITY_MAX_MB`(기본 2048)입니다.

```bash
node cli.mjs community review                  # 신고되거나 숨겨진 글. 기다리는 신고가 먼저, 기한 지난 것 표시 (이메일 없음)
node cli.mjs community hide <글 번호> [사유]     # 운영자가 숨김. 사유: privacy|rights|spam|abuse|other (작성자에게 보임)
node cli.mjs community restore <글 번호>        # 다시 보이게 함 (그 신고 기록은 정리)
node cli.mjs community delete <글 번호> [사유]   # 글과 사진 삭제
node cli.mjs community log                     # 처리 기록과 첫 신고부터 처리까지 걸린 날수
```

- 서버 로그에는 글 내용, 이름, 이메일을 남기지 않습니다.
- 설계와 한계는 [회원 코디](../docs/community-20261015.md)에 있습니다.

## 백업과 복구

```bash
cd server
node cli.mjs backup ../../eoul-backup-2026-10-15.db   # 서버를 켠 채로 만들어도 일관된 사본
node cli.mjs stats                                     # 계정·옷장·사진 수 (개인 정보는 보여 주지 않음)
node cli.mjs metrics                                   # 파일럿 지표 (아래 "파일럿 지표")
```

- 백업 파일에는 이메일, 비밀번호 해시, 옷장 기록, 사진이 모두 들어 있습니다.
  - 저장소 폴더 밖, 암호화된 위치에 보관하세요.
  - [개인정보 처리방침 초안](../docs/privacy-policy-draft-20261015.md)에 적은 보관 기간(초안: 30일)이 지나면 지우세요.
- 복구하는 방법:
  1. 서버를 끕니다.
  2. 백업 파일을 `server/data/eoul.db`로 복사합니다.
  3. 서버를 다시 켭니다.
- 복구하면 서버가 그 시점으로 돌아갑니다. 그 뒤에 바뀐 기기는 앱이 "어느 옷장을 쓸까요?"라고 묻습니다. 서버가 과거로 돌아간 것을 앱이 알아채기 때문입니다.

## 약관·처리방침과 운영자 정보

- 서버는 `/privacy`(개인정보 처리방침)와 `/terms`(이용약관)를 누구나 열 수 있는 페이지로 보여 줍니다. 앱의 가입 화면과 "내 설정 → 약관과 운영자"가 이 주소로 이어집니다.
- 내용은 `EOUL_POLICY_DIR`(기본 `server/policy/`, 저장소에 올라가지 않음)의 `privacy.md`, `terms.md`입니다. 없으면 `server/policy-templates/`의 초안을 "초안" 표시와 함께 보여 줍니다.
- `{{OPERATOR_NAME}}` 같은 칸은 아래 설정으로 채워집니다. `[[채울 칸: …]]`은 운영자가 직접 써야 하는 곳이고, 하나라도 남아 있으면 계속 "초안"으로 표시합니다.
- 페이지는 정해진 Markdown 일부(제목, 문단, 목록, 표, 굵게, https·mailto 링크)만 그리고, 나머지 HTML은 모두 글자로 바꿉니다.

| 이름 | 뜻 |
|---|---|
| `EOUL_OPERATOR_NAME` | 운영자 이름(상호). 앱과 문서에 보임 |
| `EOUL_OPERATOR_EMAIL` | 문의 이메일 |
| `EOUL_PRIVACY_OFFICER` | 개인정보 보호책임자. 비우면 운영자 이름 |
| `EOUL_BUSINESS_NUMBER` | 사업자등록번호(있으면) |
| `EOUL_POLICY_DATE` | 시행일 |
| `EOUL_AFFILIATE_HOSTS` | 수수료를 주는 제휴 링크의 호스트(쉼표로 여러 개). 이 호스트로 가는 판매처 링크 옆에 "제휴 링크 · 이 링크로 사면 어울이 수수료를 받을 수 있어요"를 표시합니다. 실제 제휴 링크를 쓰기 전에는 비워 두세요 |

## 파일럿 지표

```bash
node cli.mjs metrics                               # 전체와 가입 주(월요일, 한국 시각)별 합계
node cli.mjs metrics --exclude me@example.com      # 운영자·시험 계정 빼기(쉼표로 여러 개)
node cli.mjs metrics --json                        # 표 대신 JSON
# Docker 운영 묶음에서는: docker compose exec eoul node server/cli.mjs metrics --exclude me@example.com
```

- **보여 주는 것**
  - 가입 수
  - 옷 등록, 활성화(7일 안에 5벌 이상), 7일 안의 "내 옷과 비교", 착용 기록
  - 7일·21일 뒤 재방문
  - 구매 판단·주문·보관·반품 건수, 회원 코디 활동
- **보여 주지 않는 것**: 이메일, 계정 ID, 옷, 상품, 메모, 사진. 출력에는 수와 비율만 있습니다.
- **작은 묶음**: 계정이 5개 미만인 묶음은 인원수만 보여 줍니다. 몇 명뿐이면 누구의 기록인지 알 수 있기 때문입니다. 운영자 본인만 볼 때는 `--show-small`로 비율까지 볼 수 있습니다.
- **재방문을 세는 방법**
  - 계정마다 "마지막 사용 시각"을 1시간 단위로 하나만 남깁니다(데이터베이스 4판).
  - 4판 이전 데이터베이스는 처음 켤 때 남아 있는 로그인 기록으로 채웁니다.
  - 4판 데이터베이스는 이전 버전 서버로 열 수 없습니다.
- 계정 없이 기기에만 저장하는 사용자는 세지 못합니다.
- 지표 정의와 목표: [사업 로드맵](../docs/business-roadmap-20261015.md#파일럿-지표)

## 운영 시 알아 둘 것

- **PC가 꺼져 있어도 앱은 계속 동작합니다.**
  - 저장은 언제나 기기에 먼저 합니다.
  - 서버에 연결되면 그때 올립니다.
  - 프로필에 "서버에 연결하지 못했어요"가 보입니다.
- **앱과 서버는 같은 버전으로 함께 업데이트하세요.**
  - 서버는 앱의 옷장 형식 검사(`app/src/wardrobe.js`)를 그대로 씁니다.
  - 버전이 다르면 새 형식의 옷장을 거부할 수 있습니다.
- **계정 삭제**
  - 사용자가 앱에서 비밀번호로 확인하면 그 계정의 로그인 기록, 옷장, 사진을 한 번에 지웁니다.
  - 지운 자리는 0으로 덮어씁니다(`secure_delete`).
  - 이미 만든 백업 파일에는 남아 있습니다.
- **로그**
  - 요청 경로, 결과 코드, 걸린 시간만 남깁니다.
  - 이메일, 비밀번호, 토큰, 본문은 남기지 않습니다.
- **아직 없는 것**
  - 실제 메일 발송: 위 메일 설정(SMTP 계정)이 필요합니다. 코드는 연결 가능한 상태입니다.
  - 카카오·구글 로그인: 계정 구조는 준비돼 있고, 각 개발자 콘솔에 앱을 등록해야 합니다.
  - 여러 서버로 나누기
