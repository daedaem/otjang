# 개인판 v0.4 (화면 이름 "옷장들이"는 가칭)

오래 입는 옷의 기록을 남기고, 살까 고민 중인 옷을 가진 옷에 비춰 보고, 3D 옷장에 걸어 보고, 직접 넣은 상품 목록 안에서 살 만한 것을 고르는 도구다.
서버가 없다. `dist/index.html` 파일 하나를 브라우저로 열면 된다. 인터넷으로 아무것도 보내지 않는다. 가격·재고·링크를 찾아오지 않는다. AI를 쓰지 않는다(같은 입력이면 같은 결과).

v0.3에서 더해진 것 (PRD v0.3 「남은 작업」 1·2·4·6):
- **사진 상태·출처·확인일** (옷장 파일 스키마 2): 옷마다 속성 출처(사진 초안 / 주인 입력 / 주인 확인), 사진 상태(내 사진 / 확인된 동일 제품 / 미확인 후보 / 대체 이미지 / 없음), 상품 매칭 정보를 내 옷 기록과 따로 둔다. 상태는 사용자 동작으로만 바뀐다.
- **옷 등록 질문 단계**: 무엇인가 → 색과 느낌 → 어떤 상품인가. 아는 칸은 묻지 않고 "모름"을 고를 수 있다. 상품 주소·사진은 직접 넣는다(열거나 긁어 오지 않는다).
- **사진에서 색·밝기 초안** (v0.4.1): 내 사진을 넣으면 사진 가운데 색으로 색 계열·밝기를 미리 채운다(브라우저 캔버스만, AI·외부 요청 없음). 그대로 두고 저장하면 "사진에서 뽑은 초안"(photo-draft)으로 남고, 손대거나 확인 체크를 하면 주인 입력·확인이 된다. 종류·무늬·격식은 추정하지 않는다.
- **3D 옷장 탭**: Blender로 빛을 미리 구운 옷장에 종류별 형태(셔츠·블레이저·필드 재킷·트러커 재킷)의 옷을 건다. 미리 만든 원단 5종, 또는 옷의 색·무늬로 브라우저에서 만든 원단(근사). 끌어 자리 바꾸기, 눌러 크게 보기, 흔들림.
- **살 만한 옷 탭**: 사람이 직접 넣은 상품 목록. 내 옷장에 비춰 조합·겹침·빈틈으로 순서를 매긴다. 오래된 가격은 "재확인 필요". 목록 밖 상품을 지어내지 않는다.
- 저장은 IndexedDB(안 되면 localStorage). v0.3 저장소는 처음 열 때 읽어 옮기고 그대로 둔다.

저장소의 옷장 자료는 **합성 예시**다(`data/sample-wardrobe.json`, 13벌, 모두 `attrSource: "photo-draft"`, 사진 없음, 가상의 브랜드 후보 2벌은 `matchCandidates`에만). 개인 옷장 자료와 사진은 공개 저장소에 넣지 않는다(CONTRIBUTING.md). 본인 자료로 만들려면 `data/wardrobe.json`(.gitignore에 있음)을 두면 빌드가 그것을 쓴다.

## 화면

| 탭 | 하는 일 |
|---|---|
| 옷장 | 가진 옷과 기록. 배지: 보유/구매 후보, 사진에서 뽑은 초안, 사진 상태, 브랜드 후보. 버튼: 기록(편집), 확인하기(모르는 것만 묻기), 상품 사진(대체 이미지·후보·확인·취소·떼기) |
| 3D 옷장 | 걸린 옷(최대 6벌)을 3D로. 걸 옷 고르기, 형태(종류)와 원단 고르기. 카드에 실제 정보와 "종류로 그린 모습, 상품 재현 아님" |
| 살까 말까 | 후보를 넣고, 보기 전 마음을 적은 뒤 판정(겹치는 보유 옷, 새로 생기는 조합, 걸리는 점, 확인 전 속성 표시). 결정 기록, 보유로 옮기기 |
| 코디 | 가진 옷으로 만든 조합 3개와 이유. 초안 옷이 쓰이면 표시 |
| 살 만한 옷 | 상품 추가·수정, 목록 파일 열기·내보내기, 계절·빈틈 기준, 순위와 이유, 후보로 넣기 |
| 옷장 구경 | 기본 옷장 초안이나 다른 사람의 옷장 파일(스키마 1·2)을 열어 견주기. 빠진 것을 후보로 넣기 |
| 기록 | 판정 기록, 사진·속성 상태 요약, 옷장 주인, 파일 내보내기(내 사진 / 남의 상품 사진 / 후보 목록 / 가격·링크 / 체형 / 판정 기록 선택)·가져오기, 처음 상태로 |

## 실행

```bash
npm install                  # three 0.160.1, esbuild, playwright (+ glb 압축용 gltf-transform, meshoptimizer)
npm test                     # 규칙·스키마·상품·색 초안 테스트 46개 (Node 22, 추가 패키지 없음)
npm run assets               # assets/closet → src/closet/assets.gen.js
npm run build                # dist/index.html (약 9MB, 3D 포함). NO3D=1 이면 3D 없이, NO_MESHOPT=1 이면 WebAssembly 없이(더 크다)
npm run build:empty          # dist/otjang-empty.html (빈 옷장)
npx playwright install chromium && npm run check   # 헤드리스 브라우저로 핵심 흐름 확인: 환경당 65항목 × 두 환경(3D 탭 포함. NO3D=1로 건너뛸 수 있음, QUICK=1이면 한 환경). 기대값은 예시 옷장 기준
npm run golden               # 규칙 결과 스냅샷 다시 만들기 (규칙을 일부러 바꿀 때만)
npm run compress             # assets/closet-src/*.glb → assets/closet/*.glb (meshopt 압축)
```

옷장 자료 고르기: `WARDROBE` 환경 변수 > `data/wardrobe.json`(있으면, 저장소에 넣지 않음) > `data/sample-wardrobe.json`. 예: `WARDROBE=data/wardrobe.json OUT=dist/otjang-mine.html node build.mjs`. 사진이 든 결과 파일(dist/)도 저장소에 넣지 않는다.

## 옷장 파일 (스키마 2)

기록 탭에서 내보내는 JSON이다. `schema: 2`, `owner`, `items`, `decisions`. 옷 한 벌의 필드는 `src/wardrobe.js` 머리말에 있다.
내보낼 때 내 사진, 남의 상품 사진, 미확인 브랜드 후보, 가격·링크, 키·사이즈, 판정 기록을 넣을지 고른다(기본: 내 사진만 포함). 구매 후보와 처분한 옷은 내보내지 않는다. 스키마 1 파일도 읽는다.

상품 사진의 세 상태와 규칙:
- 확인된 동일 제품: 사용자가 같은 상품이라고 확인했다 → 브랜드·상품명·사진 출처·확인일이 내 옷 정보가 된다
- 미확인 후보: 같은 상품일 수 있다 → 후보 정보는 `matchCandidates`에만 둔다
- 대체 이미지: 다른 상품의 사진을 임시로 걸었다 → 사진 출처만 남긴다. 그 상품의 브랜드·가격은 내 옷 정보가 아니다
- 파일에 "확인됨"이라고 적혀 있어도 확인 기록(`product.confirmedAt`)이 없으면 후보로 내린다. 자동으로 올라가는 길은 없다.

## 하지 않는 것

- 가격, 재고, 링크를 찾아오지 않는다. 직접 넣은 값과 확인 날짜만 보여 준다. 상품 주소를 열거나 긁어 오지 않는다.
- 어울림을 확률로 말하지 않는다. 규칙 점수는 가산과 감점의 합이다.
- 사라거나 사지 말라고 하지 않는다. 규칙이 본 사실과 근거만 보여 준다.
- 3D 옷은 종류로 그린 모습이다. 브랜드나 상품 모양을 추측하지 않고, 로고·그래픽·패치를 그리지 않는다. 바지·신발·니트·블루종 형태는 아직 없다.
- 사진으로 옷을 입혀 보는 기능이 없다. 핏과 소재는 판단하지 않는다. 사진에서 뽑는 것은 색 계열·밝기 초안뿐이고 종류·무늬·격식·브랜드는 추정하지 않는다.
- 여러 사람이 함께 쓰는 서버, 공개 옷장, 아이템 사전은 아직 없다.

## 알려진 한계

- 3D 형태는 5종이다(셔츠·블레이저·필드 재킷·트러커 재킷·크루넥 스웻셔츠, 스웻셔츠는 v0.4.2). 다른 종류(바지, 신발, 니트·카디건, 블루종, 후디)는 "3D 형태 없음"으로 목록에만 보인다. 다른 종류로 대신 그리지 않는다.
- 브라우저에서 만든 원단은 근사치다(옥스퍼드·능직·홉색 결에 색을 곱함). 코듀로이 결은 미리 만든 원단에서만 쓴다.
- 3D 옷장 자리는 6곳이다. 7벌 이상은 걸 옷을 바꿔 가며 본다.
- 파일이 약 9MB다. 실제 휴대폰과 Safari에서는 확인하지 않았다(헤드리스 Chromium에서 1280px·390px 확인).
- 예시 옷장의 속성·조합 결과는 규칙 설명용이다. 사용자 효용(실제 살까 말까 판정 기록)은 아직 0건이다.
- 흔들릴 때 빛과 그림자는 구운 것이라 따라 바뀌지 않는다. 옷끼리 부딪히지 않는다.
