# 어울 앱

서버 없이 브라우저에서 동작하는 정적 웹앱입니다. 빌드 도구나 패키지 설치 없이 실행됩니다.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html`, `styles.css` | 화면 뼈대와 디자인(밝은·어두운 화면 모두 지원, 휴대폰 폭 기준) |
| `src/main.js` | 화면 그리기, 시작 화면, 탭, 상세 시트, 사진 저장(IndexedDB), 백업 받기·불러오기 |
| `src/store.js` | 이 기기 저장(localStorage `eoul:v2`): 이전 버전 옮기기, 저장 실패 알리기, 백업 파일 만들기·검사 |
| `src/engine.js` | 추천 계산: 아이템 점수, 코디 채우기, 한 줄 검색 결과 |
| `src/query.js` | 한 줄 요청 해석: 아이템·상황·계절·색·예산·"X에 어울리는 Y" |
| `src/data/slots.js` | 스타일 8가지, 색 17가지, 아이템 종류 68가지(예: 옥스퍼드 셔츠): 스타일별 점수, 상황, 계절, 추천 이유, 입는 법 |
| `src/data/looks.js` | 코디 공식 32개: 역할(아우터·상의·이너·하의·신발·소품)별 아이템 종류와 권장 색 |
| `src/data/products.js` | 실제 상품 목록(자동 생성) |
| `src/icons.js` | 아이콘, 사진을 쓸 수 없을 때의 색 카드에 얹는 옷 실루엣 |
| `tools/build.mjs` | 모듈을 HTML 파일 하나(`dist/index.html`)로 묶음 |
| `tools/catalog/` | 상품 목록 갱신 도구와 편집 기록 |
| `test/` | 추천 엔진·카탈로그 테스트(`engine.test.mjs`), 저장·백업 테스트(`store.test.mjs`). `app/` 안에서 `node --test` |

## 추천이 정해지는 방식

1. **아이템 점수**: 고른 스타일에서의 중요도(첫 번째 스타일 100%, 나머지 85%), 지금 계절, 고른 상황, 그리고 가진 옷과 같은 코디에 들어가는 횟수를 더합니다. 가진 종류는 다시 추천하지 않습니다.
2. **상품 고르기**: 선호 브랜드를 먼저, 그다음 `평점 × log10(후기 수 + 좋아요/8 + 10)` 순서로 고릅니다. "내 브랜드만"이면 선호 브랜드 상품만 씁니다.
3. **코디**: 코디 공식의 역할마다 가진 옷이 있으면 그 옷을 쓰고(같은 종류가 여러 벌이면 색이 가장 잘 맞는 옷), 없으면 품질·권장 색·색 조화·선호 브랜드를 함께 보고 실제 상품으로 채웁니다.
4. **색 조화**: 포인트 색(그린·레드·핑크 등)은 한 코디에 하나까지, 상·하의는 밝기 차이가 있을 때 가점입니다. 미니멀 스타일은 비슷한 톤끼리 맞추는 것을 가점으로 봅니다.
5. **내 옷장 코디**: 가진 옷만으로 모든 필수 역할이 채워지는 코디("오늘 뭐 입지?")와, 하나만 사면 되는 코디를 따로 보여 줍니다.
6. **한 줄 검색**: 요청에서 아이템·상황·계절·색·예산을 뽑아 칩으로 보여 주고, 같은 점수 체계로 상품을 고릅니다. "청바지에 어울리는 신발"처럼 기준 아이템이 있으면, 그 아이템과 같은 코디 공식에 들어가는 상품을 먼저 보여 주고 그 아이템을 넣은 코디도 함께 만듭니다. 기준 아이템은 옷장에 있을 때만 '내 옷'으로 쓰고, 없으면 살 상품으로 넣어 합계에 더합니다.
7. **상품 상세의 코디**: 보고 있는 상품을 그대로 넣고(가진 상품이면 내 옷으로) 나머지를 채웁니다.
8. **예시 옷장**: 고른 스타일의 대표 코디에서 옷 몇 벌을 골라(그 종류의 대표 색으로) 예시로 넣습니다. 예시일 때 추천 이유는 "가진 …"이 아니라 "예시 옷장의 …"로 씁니다.
9. **사진이 없는 옷의 사진**: 화면에 그림과 상품 사진이 섞이지 않도록, 사진 없는 내 옷·예시 옷은 같은 종류·같은 색의 상품 사진(고른 브랜드 → 사계절 상품 → 평점·후기 순)으로 보여 주고 "비슷한 사진"이라고 표시합니다. 가까운 색(아이보리↔화이트, 네이비↔인디고 등)까지만 허용하고, 그래도 없으면 색 카드로 보여 줍니다. 종류를 고르는 칸과 기본템 체크도 그 종류의 실제 상품 사진을 씁니다.

스타일 점수와 코디 공식은 편집자 판단입니다. 사용자 반응으로 검증한 값은 아닙니다.

## 상품 데이터

- 출처 1: 편집자가 고른 상품 157개. 무신사 상품 페이지의 구조화 데이터(schema.org `Product`)에서 상품명·브랜드·판매가·평점·후기 수·이미지를 읽었습니다.
- 출처 2: 브랜드 목록. 브랜드(또는 "브랜드 + 대표 아이템")로 무신사를 검색한 결과 화면에서 상품 번호·이름·판매가·평점·후기 수·좋아요 수·이미지를 읽고, `tools/catalog/classify.mjs`가 이름의 단어로 종류와 색을 분류합니다. 신발을 가리키는 이름은 신발 종류로만, 옷 이름은 옷 종류로만 분류합니다. 색 표기가 없는 데님은 인디고로 보고, 나머지는 사진 가운데에서 색을 짐작합니다(`image-colors.json`). 아동·중고·그래픽·캐릭터·세트·트레이닝·반바지·수영복·장갑·신발 관리 용품(구두주걱 등)은 뺍니다. 브랜드·종류마다 인기 순으로 3개까지 씁니다.
- 이름이 다른 종류를 가리키는 상품(예: 신발 종류인데 이름에 "팬츠")이 없는지 `engine.test.mjs`가 확인합니다.
- 확인 날짜는 상품마다 `checkedAt`에 남기고, 앱 하단과 상세 화면에 표시합니다.
- 가격은 확인 시점의 판매가입니다. 회원 할인·쿠폰·배송비는 반영하지 않습니다.
- 이미지는 무신사 이미지 주소를 그대로 불러옵니다. 불러오지 못하면 옷 그림으로 바꿔 보여 줍니다.
- 상품 선택은 편집자가 했습니다. 크롭·과한 그래픽처럼 기본 아이템 역할에 맞지 않는 상품은 뺐고, 아이템마다 가격대가 다른 상품을 2~4개 골랐습니다(`tools/catalog/curation.json`).

### 갱신 방법

```bash
cd app/tools/catalog
npm i -D playwright                                      # 처음 한 번
node search-musinsa.mjs queries.json candidates.json     # 아이템별 검색 후보 수집 (편집용)
node read-musinsa.mjs curation.json snapshot.json        # 고른 상품의 페이지에서 값 읽기
node scan-brands.mjs brand-queries.json raw.json         # 브랜드 목록 화면 수집
node classify.mjs raw.json brands.json                   # 브랜드 목록 결과 분류
node make-products.mjs                                   # src/data/products.js 생성
# 잘못 분류된 상품은 exclude.json(빼기) 또는 fixes.json({번호: {slot, color}})으로 바로잡는다
```

수집 도구는 개인 프로젝트용으로 요청 사이에 간격을 두고 소량만 읽습니다. 공개 서비스로 운영하려면 판매처의 제휴·상품 API나 이용 약관에 맞는 방식으로 바꿔야 합니다.

## 개인정보

가입·서버·분석 도구가 없습니다. 취향, 가진 옷, 찜 목록은 브라우저의 localStorage(`eoul:v2`)에, 옷 사진은 IndexedDB에만 저장되고(긴 변을 720px로 줄인 JPEG), 프로필 화면의 "모두 지우고 처음부터"로 지울 수 있습니다. 첫 버전이 쓰던 `eoul:v1`은 다른 브랜치의 앱도 쓰는 이름이라 읽어서 옮기기만 하고 덮어쓰지 않습니다. 백업 파일은 사용자가 "백업 파일 받기"를 누를 때만 만들어지며, 사진이 들어 있으므로 사용자가 직접 보관합니다. 외부로 나가는 요청은 상품 이미지 불러오기와, 사용자가 누른 판매 페이지 링크뿐입니다. 이미지 요청에는 `referrerpolicy="no-referrer"`를 붙입니다.
