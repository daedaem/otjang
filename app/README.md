# 시험판 0.9.0-beta (화면 이름 "어울(EOUL)"은 가칭)

사기 전에 고른 기준으로 상품 하나를 골라 주고, 보던 상품을 같은 기준으로 견주고, 산 뒤 사이즈 답으로 다음 추천을 고치는 도구다. 옷장 기록, 살까 말까 판정, 코디, 3D 옷장도 들어 있다.
서버 없이 돈다. 웹판(`dist/web/`)은 https://daedaem.github.io/otjang/beta/ 에 올라가 있고, `dist/index.html` 파일 하나로도 열린다. 앱은 인터넷으로 아무것도 보내지 않는다(보안 정책으로 막음). 가격·재고를 실시간으로 찾아오지 않는다: 추천은 운영자가 공식 판매처에서 확인해 넣은 `data/picks.json` 안에서만 하고 확인일을 함께 보인다. AI를 쓰지 않는다(같은 입력이면 같은 결과).

## 0.6~0.8에서 더해진 것 (추천)

- **기준으로 딱 하나 추천** (`src/pick.js`, 추천 탭): 용도(상관없음·카디건·셔츠 안에·한 장으로), 꼭 지킬 조건(로고 안 보이게·얇게·목 립 좁게·박시하지 않게·카디건보다 짧게·비치지 않게), 중요한 기준(가성비·품질·브랜드·내 핏·스타일)을 누른 순서. 결과는 상품 하나, 1위보다 나은 점이 있는 대안 최대 둘, 두 문장 결론, 확인한 것/모르는 것(근거 세기 6단계), 추천 사이즈, 확인일, 판매처 링크. 규칙은 `../docs/rules-explained.md` 10절.
- **검증 카탈로그** (`data/picks.json`): 공식 판매처 페이지에서 확인한 흰 크루넥 티 17개. 값마다 출처(공식·공지·공식 무게·직접 잼·사진·브랜드 설명·이름·직접 적음·판매처)가 있다. `npm run check:catalog` 가 검사하고 빌드도 오류·30일 지난 상품이 있으면 멈춘다. 정책은 `../docs/catalog-policy.md`.
- **보던 흰 티 견주기**: 다른 곳에서 보던 상품의 값·치수를 적으면 같은 기준으로 몇 위인지와 1위와의 두 칸 비교. 직접 적은 값은 약한 근거로 센다. 링크는 열지 않는다.
- **결정 고리**: 판매처에 다녀오면 "샀나요?" → 산 사이즈 → 옷장(치수 함께) → 2주 뒤 사이즈 답을 바로 다음 추천에 반영.
- **의견 보내기와 운영자 지표** (`src/feedback.js`): 옷 이름 없는 사용 요약 줄 `EOUL1|…`, 받은 줄을 모아 추천 깔때기·PMF·NPS를 계산(5명 미만이면 판단 보류).
- **재확인 도구** (`tools/recheck.mjs`): 운영자가 실행할 때만. robots.txt 를 지키고, 못 읽은 값으로 확인일을 바꾸지 않는다.

v0.3~0.5에서 더해진 것: 사진 상태·출처·확인일(옷장 파일 스키마 2), 옷 등록 질문 단계, 사진에서 색·밝기 초안, 3D 옷장 탭, 직접 넣는 상품 목록, 빠른 시작(기본 옷 골라 넣기), 고민 중인 옷 바로 판정, 친구에게 물어보기, 결정 2주 뒤 물음, 서비스 워커(끊겨도 열림). 저장은 IndexedDB(안 되면 localStorage).

저장소의 옷장 자료는 **합성 예시**다(`data/sample-wardrobe.json` 13벌, `sample-wardrobe-b.json`). 개인 옷장 자료와 사진은 공개 저장소에 넣지 않는다(CONTRIBUTING.md). 본인 자료로 만들려면 `data/wardrobe.json`(.gitignore에 있음)을 두면 빌드가 그것을 쓴다.

| 살까 말까 | 후보를 넣고(붙여 넣은 글에서 종류·색 짐작) 판정: 겹치는 보유 옷, 새로 생기는 조합, 걸리는 점. 결정 기록, 2주 뒤 물음, 친구에게 물어보기 |

| 옷장 구경 | 예시 옷장이나 다른 사람의 옷장 파일(스키마 1·2)을 열어 견주기 |
| 기록 | 추천 기록, 판정 기록, 백업·가져오기, 의견 보내기, 베타 운영자 지표, 처음 상태로 |

## 실행

```bash
npm install                  # three 0.160.1, esbuild, playwright, axe-core (+ glb 압축용 gltf-transform, meshoptimizer)
npm test                     # 규칙·스키마·추천·카탈로그 검사·재확인 도구·의견 줄·골든 등 테스트 100개 (Node 22)
npm run check:catalog        # data/picks.json 검사 (오류 0이어야 빌드가 된다. 14일 지난 확인은 주의, 30일은 오류)
npm run recheck -- plan      # 다시 확인할 상품 목록 (fetch·apply 는 ../docs/catalog-policy.md)
npm run assets               # assets/closet → src/closet/assets.gen.js
npm run build                # dist/index.html (약 11.6MB, 3D 포함). NO3D=1 이면 3D 없이, NO_MESHOPT=1 이면 WebAssembly 없이(더 크다)
npm run build:web            # dist/web/ 베타 웹판: index.html 516KB(gzip 약 141KB) + 3D 탭용 closet.js 11.7MB(gzip 약 6.3MB) + sw.js·manifest
npm run build:empty          # dist/otjang-empty.html (빈 옷장)
npx playwright install chromium && npm run check   # 한 파일 빌드의 핵심 흐름: 환경당 72항목 × 두 환경(1280 밝은 화면, 390 어두운 화면)
npm run check:web            # 웹판을 로컬 HTTP로: 환경당 90항목 × 2 (추천·결정 고리·보던 상품·서비스 워커·CSP·외부 요청 0)
npm run check:a11y           # axe-core WCAG 2.1 A·AA 자동 규칙: 22개 화면 × 2
npm run check:perf           # 흉내 회선(느린 4G·LTE)에서 첫 화면·3D 탭 시간 (서비스 워커는 막고 첫 방문 기준)
npm run golden               # 규칙 결과 스냅샷 다시 만들기 (규칙을 일부러 바꿀 때만)
npm run compress             # assets/closet-src/*.glb → assets/closet/*.glb (meshopt 압축)
```

옷장 자료 고르기: `WARDROBE` 환경 변수 > `data/wardrobe.json`(있으면, 저장소에 넣지 않음) > `data/sample-wardrobe.json`. 웹판은 빈 옷장(`data/empty.json`)으로 만든다. 사진이 든 결과 파일(dist/)은 저장소에 넣지 않는다. 카탈로그 확인이 30일 넘으면 빌드가 멈춘다(`ALLOW_STALE=1` 은 개발용으로만).

## 옷장 파일 (스키마 2)

기록 탭에서 내보내는 JSON이다. `schema: 2`, `owner`, `items`, `decisions`. 옷 한 벌의 필드는 `src/wardrobe.js` 머리말에 있다. 백업 파일에는 후보·추천 설정·추천 기록·사용 횟수도 들어간다.

상품 사진의 세 상태와 규칙:
- 확인된 동일 제품: 사용자가 같은 상품이라고 확인했다 → 브랜드·상품명·사진 출처·확인일이 내 옷 정보가 된다
- 미확인 후보: 같은 상품일 수 있다 → 후보 정보는 `matchCandidates`에만 둔다
- 대체 이미지: 다른 상품의 사진을 임시로 걸었다 → 사진 출처만 남긴다. 그 상품의 브랜드·가격은 내 옷 정보가 아니다
- 파일에 "확인됨"이라고 적혀 있어도 확인 기록(`product.confirmedAt`)이 없으면 후보로 내린다. 자동으로 올라가는 길은 없다.

## 하지 않는 것

- 가격·재고를 실시간으로 찾아오지 않는다. 카탈로그는 확인일의 값이고, 14일이 지나면 가격·재고를 이유로 쓰지 않으며 30일이 지나면 추천에서 뺀다. 사용자가 붙여 넣은 상품 주소는 열거나 긁어 오지 않는다.
- 어울림이나 맞을 확률을 숫자로 지어내지 않는다. 모르는 값은 "모름"으로 보인다.
- 판매처에서 수수료를 받지 않고, 순서를 돈으로 바꾸지 않는다.
- 3D 옷은 종류로 그린 모습이다. 로고·그래픽을 그리지 않고 상품 모양을 추측하지 않는다.
- 사진으로 옷을 입혀 보는 기능이 없다. 사진에서 뽑는 것은 색 계열·밝기 초안뿐이다.
- 여러 사람이 함께 쓰는 서버는 아직 없다.

## 알려진 한계

- 추천 품목은 흰 크루넥 티 하나다. 목 립 폭은 17개 중 5개만 정보가 있고, 직접 잰 상품은 아직 없다.
- 3D 형태는 6종(셔츠·블레이저·필드 재킷·트러커 재킷·크루넥 스웻셔츠·V넥 카디건)이다. 다른 종류는 "3D 형태 없음"으로 목록에만 보인다.
- 실제 휴대폰과 Safari에서는 확인하지 않았다(헤드리스 Chromium 1280px·390px, 사용자 맥의 Chrome 152).
- 실제 사용자 기록은 아직 0건이다.
