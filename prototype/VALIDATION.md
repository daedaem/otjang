# 프로토타입 검증 기록

**사용자 시각 품질 평가: 미달.** 아래 통과 항목은 기능·오류 처리·배치 확인이며, 디자인 품질 승인으로 해석하지 않습니다. [원본과의 비교 및 재설계 기준](../docs/design-review/quality-review.md)을 따릅니다.

확인일: 2026-10-11. 검증 자료는 합성 옷·사진·상품·후기이며 실제 개인 사진은 사용하지 않았다.

## Blender와 웹 자산

Python 3.13.16 / bpy 5.2.2 LTS에서 `wardrobe.py --final`을 실행했다. 원본 `.blend` 재오픈, 카메라, 내장 텍스처, 10개 의류 슬롯과 GLB 좌표를 확인했다. Cycles 최종 이미지는 1600×1050, 64 samples, CPU 4 threads로 렌더했다. 옷장·옷 크기·조명·옷걸이를 이미지로 검토했다.

최종 GLB는 7,810,016 bytes, 260,779 triangles, 138 primitives이며 이미지 5개를 내장한다. 단일 HTML은 약 10.79 MiB로 Three.js와 GLB·텍스처·미리보기를 포함한다. HTML에서 외부 CDN이나 사진 API를 호출하지 않는다. 시작 화면의 정지 렌더와 실제 WebGL 화면은 조명·재질 처리 방식이 달라 서로 동일하지 않다.

데스크톱 1440×1000과 모바일 390×844 Chromium에서 실제 화면을 검토했다. 클라우드에는 하드웨어 GPU가 없어 SwiftShader를 사용한다. 이는 기능·배치 검증이며 사용자의 실제 기기 FPS나 로딩 시간 측정은 아니다. 브라우저 검증은 순차 실행한다. 동시에 소프트웨어 WebGL과 Blender를 실행하면 CPU 경쟁으로 스크린샷이 지연될 수 있었다.

검증 중 발견해 수정한 동작은 다음과 같다.

- GLB 파싱 완료와 첫 화면 렌더를 구분해, 빈 캔버스를 준비 완료로 표시하지 않는다. 테스트에서 캔버스 중앙의 색 변화를 확인한다.
- 흰색/파란색 셔츠 슬롯과 등록한 색을 대응하고, 원단 텍스처가 등록색을 덮지 않도록 한다.
- 모바일에서 꺼낸 옷을 하단 상세 패널 위에 배치한다.
- 선택한 옷이 코디에서 빠지지 않으며, 사용할 수 없거나 삭제한 옷이면 조합을 만들지 않는다.
- 사진의 종류가 미확인이면 파일명으로 모형 종류를 단정하지 않는다. 사용자가 종류를 확인하면 같은 기록에 모형이 연결된다.
- 빈 개인 옷장에 샘플 옷을 섞지 않는다. 공간에 놓이지 않은 항목을 선택하면 이전에 꺼낸 옷은 돌려놓는다.

3D·일반 흐름·사진 처리 검증에서 페이지 실행 오류 0건·외부 HTTP 요청 0건을 확인했다. 판매처 링크는 사용자가 누르면 외부로 이동하며, 검증에서 실제 구매나 결제를 수행하지 않았다.

## 경계와 미검증 항목

사진 모듈은 합성 단색 배경에서 검증했다. 실제 복잡한 옷장 사진 정확도, 실제 상품·후기 자동 확보, 사용자 실측·착용감·얼굴 분석, 실사 가상 피팅은 완료로 표시하지 않는다. 모형은 일반적인 의류 유형이며 실물 제품의 정확한 재현이 아니다.

관리형 Chromium은 `file://` 탐색을 정책으로 막으므로 동일 HTML을 로컬 HTTP로 검증했다. 개인 기기의 파일 직접 열기, 실제 모바일 카메라, iOS Safari, 기기별 저장 용량·성능은 미검증이다. 브라우저 데이터 삭제 전 개인 백업이 필요하다.

환경의 설치·시작 지침은 설정 초안으로 저장했다. 저장한 설치 스크립트를 현재 인스턴스에서 재실행해 고정 버전 설치·Blender import·HTML 빌드·26개 단위 테스트 통과를 확인했고, 시작 지침대로 서버의 응답과 브라우저 동작을 확인했다. 현재 인스턴스의 실행 확인과 다른 작업에서의 새 환경 복원 검증은 구분한다. 전체 PRD 수용 기준·사업성·사용자 시각 품질 승인·공개 서비스 준비 완료를 뜻하지 않는다.
